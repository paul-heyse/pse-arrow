# ADR-0227: Own scientific permission and versioned operation facts

## Context

Completion already owns original assessments, but consumers reconstruct aggregate permission or
promote locally valid fit products without it. Lifecycle matches and parallel replay constructors
also reconstruct kind meaning; immutable scientific values retain the entire Runtime.

## Scope

Plan56b B01–B06 and only the required C/F adoption slices. Completion v2, stored completion v3
and replay v5 replace their current interpretations together. The standalone fit-profile document
also advances to v2 because chain/point qualifiers are now required. Existing receipt framing and file
placement remain; RC01–RC06 are not adopted. Accepted records remain immutable.

## Drivers

Preserve original scientific scope, local mathematical validity, candidate/seed permission and
publication effects as distinct facts. Expose exact reusable products and explicit services.

## Options

Retain consumer conjunctions and optional constructors: rejected because consumers can disagree.
Add a second policy/runtime framework: rejected because existing owners suffice. Extend the
completion and paired-operation owners with typed facts and explicit services: selected.

## Outcome

Completion records the governing decision, scope, coverage, reasons and qualifiers once. Product
permission composes it with independent local validity. Diagnostic bytes do not authorize a
QualifiedFit input. Existing kind-owned projections feed durable/public consumers; replay has one
closed tagged constructor. Scientific values retain immutable data and necessary leases, while
effectful Rust entry points receive narrow services from the existing composition root.

### Consequences

All current producers, readers and generated consumers migrate together. Direct PETSc settings
exclude composed-only options; working scientific composition takes its internal settings explicitly
and authenticates them in its identity. Native iteration and physical checks remain library-owned.

### Compensating controls

Original-fit failure, external covariance, exact hydration, scope/coverage, all-kind replay,
no-store/no-solver scientific decisions and transient-versus-deterministic refusal controls.

### Confirmation

**Implemented/Tested:** B01–B06 and necessary C/F adoption are complete at the local Linux
conditions in [Plan56b's Outcome](../plans/56b-scientific-operations-and-permission.md#verification-and-outcome--2026-10-25).
Native/canonical failed-fit product refusal, replay, binding/issuer and typed effects pass with
original failures and exact affected reruns retained. Actual installed Python, STDIO MCP and CLI
agree on original permission and retained diagnostics. No full matrix, fleet or measured benefit
is claimed. Execution was explicitly authorized; formal ADR status remains proposed.

## Pros and cons

One authority supplies each meaning and no compatibility production path remains. The coordinated
wire and Rust service migration is broader than adding another local permission predicate.

## More information

Plan56b owns execution; blueprint §19.2/§19.4/§19.8/§21.1 own enduring contracts. The fresh owned
deployment is qualified independently; the existing selected canonical store is preserved.

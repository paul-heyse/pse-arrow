# ADR-0220: Compose selected closure and fresh-authority project exchange through existing owners

## Context

The maintainer authorized all remaining Plan51e–51g scope after targeted delivery of the project, research and evidence workbenches. Existing diagnostic packs require frozen/analysis members and cannot be treated as editable project archives. Existing source publication already owns staged edits, atomic visibility and exact acknowledgement.

## Scope

Versioned logical project manifests, import intents/origin mappings and composed lifecycle/health consumers within blueprint §19.3/§20.6/§24.1. No storage topology, result backend, numerical engine, host resource authority or foundational Python-boundary replacement.

## Drivers

Retain exact science and original ownership while making copied closure independently useful. Avoid duplicate traversal/copying, transactions spanning bulk work, transferred live grants and inferred receiving qualification.

## Options

Select one owner-based closure resolver with shared contained-copy/publication primitives. Keep project manifests and diagnostic review-pack interpretation separate. Extend original project/source publication for fresh import rather than creating another admission or activation engine. Retain existing application backup and explicit retention owners instead of a universal lifecycle service.

## Outcome

A logical manifest v1 records exact selected membership, origin identities/codecs/digests, scientific qualifiers, provider requirements, copied extent and omissions. Original protection spans copying and destination verification; complete manifests publish last. Offline reading resolves only contained validated members and performs no execution or provider installation.

Import binds original operation, receiving authority, bundle digest and fresh destination identities. Ordinary local admission and bulk staging precede original source/project guarded activation and atomic origin mapping. Unknown replies settle the original intent. Historical results, studies and publication receipts remain origin-qualified evidence, never receiving producer receipts, terminals, protection grants or seed eligibility. Imported copied bytes acquire receiving artifact ownership.

Application backup manifest v4 includes required new catalogue/reference closure and retains quiesce/drain/stop, fresh restore identity and semantic validation. Retention explanations are observations; explicit release rechecks the current original owner's references, generations, protection and borrowers. Health composes authentic service/engine/host observations with unknown and approximate fields explicit, never automatic repair or causal claims.

### Consequences

New contracts generate through existing declaration owners. Bulk work remains outside short metadata transactions. Metadata or index presence grants no payload lifetime. Existing generated data need no legacy compatibility/migration route.

### Compensating controls

Use exact origin namespaces, private imported publication bindings, original immutable acknowledgements, current borrower guards, finite selected copy allowances and independently verified destination membership. Unsupported/incomplete closure never becomes an executable or newly qualified result.

### Confirmation

Interface-checked: current review-pack publication, original source/project CAS and acknowledgement, protected result readers, application backup/recovery and selected native metrics at 66bfbc369; implementation and qualification remain at Plan51.

Targeted controls and assembled Rust/Python/CLI/offline journeys remain required by the owning plans. No test, security, speed or whole-series completion claim follows from this proposal.

## Pros and cons

Reuses original scientific and operational authority and makes partial work explainable; requires explicit origin/copy/receiving identity distinctions and protected lifetime integration across owners.

# ADR-0031: Commit every generated source and diff it in CI; never generate in build.rs

## Context

Blueprint §4.2 generates typed relation views, builders, validators, migrations, the Python contract classes, documentation and the Ipopt bindgen output from the registry, and requires the emitted source to be committed.

## Scope

Binds where generated code lives, how it is regenerated and how drift is detected. What is generated is §4.2's subject.

## Drivers

A `build.rs` generator makes the build depend on the host and hides the diff; a generated file that is not committed cannot be reviewed, and the Python contract classes are part of the public API.

## Options

Generate in `build.rs` — rejected: no reviewable diff, and the bindgen step needs the solver container's headers. Generate on demand and gitignore — rejected: the diff is the review.

## Outcome

`cargo xtask codegen [--only relations|python|docs|bindgen]` writes the four generated paths; every generated file carries `// @generated by pse-schema <fingerprint>`, `#![rustfmt::skip]` and a blanket lint allow with a reason. `cargo xtask codegen --check` runs `git diff --exit-code` plus an untracked-file check.

### Consequences

A registry change is a two-part commit: the registry edit and the regeneration. A `prettyplease` upgrade is itself a regeneration commit.

### Compensating controls

`.gitattributes` marks the generated paths `linguist-generated`; the agent settings deny edits under them; `check_generated.py` holds a sha256 manifest of `python/pse/contracts/`.

### Confirmation

`rust / codegen-diff` is a required check and runs in the solver container so the bindgen output is regenerated against the pinned headers.

## Pros and cons

Committing generated code inflates diffs; not committing it removes the only place the generator's output is reviewed.

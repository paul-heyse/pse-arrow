# ADR-0166: Coordinate bounded parallel scientific execution

## Context

The parallel-execution review identifies canonical contention, capacity charged as demand,
unaccounted persistent teams and serial ordinary study dispatch. The maintainer accepted
Parallel RC01-RC04 and authorized Plan 28 execution. The execution choices are sixteen local
case lanes sharing one runtime, one primary supervised durable group and a thirty-second
admission-only bound for entries without a finite enclosing clock.

## Scope

Plan 30's confirmed RC02/RC03 preserve the exact reference primary/observer qualification profile while adding separately bounded functional receivers, resident storage services and coordinated host admission. Fixed host lanes and short allocation bookkeeping replace independent invocation ceilings; systemd/actual affinity enforce placement and actual descendant drain controls capacity release. Nested work borrows an authenticated owner and original clock. CPU/memory ceilings are not physical reservations and do not control unmanaged host activity.

This amends blueprint §18.8, §19.3 and §20.6. Scientific authority, exact occurrence/start
lineage, native thread affinity, original-model assessment and canonical claim authority remain.
Any selected predicate-guard change requires its complete writer/predicate argument before
implementation; this record does not prescribe an unexamined finer guard topology.

## Drivers

Independent work must progress without multiplying maximum reservations, native teams or
per-process budgets. Queueing cannot hold compute capacity needed to release memory.
Cancellation must distinguish undispatched work from native teardown. Ordinary Rust/Python
studies must consume the same bounded execution target as focused conformance controls.

## Options

More retries or workers alone retain the causal contention and ownership errors. Sixteen
independent processes duplicate caches and rigidly partition resources. A finite lane group
sharing the existing runtime preserves one pool and CPU owner; supported native exclusion
may serialize a phase. Existing whole-operation process isolation remains eligible for
incompatible native mixtures, with explicit partitions and receiver reconstruction.

## Outcome

Use the common engine pool as memory authority. `worker_bytes` is capacity, with temporary
construction admitted by a safe bound or reserve-before-allocation. Release notification
retries actual reservation and grants no independent bytes. One bounded population ticket
covers each pending request, running job or retained session. A failed memory attempt releases
compute and temporary dispatch state; issued native owners retain their ticket through join.
All retries retain cancellation and the original finite deadline. Only an entry without that
clock receives the policy's thirty-second admission-only bound; it never becomes a native
execution deadline. Individually oversized work refuses before dispatch.

Reserve every actually created native team before entry and retain its extent through idle
scope and teardown. Ordinary independent cases and optimizers initially use one inner thread.
Larger selected teams and compatible process partitions consume the same declared allocation.

Compose ready independent occurrences concurrently with private mutable state and exact
completion placement. Preserve real predecessor/seed dependencies and suitable native bulk
operations. The primary durable group uses one shared runtime; observing callers add no
unbudgeted execution. Discovery/coalescing remains distinct from canonical atomic claim.

### Consequences

Entry clocks, group width and receiver budgets have typed owners. Adapter-visible native
exclusion releases compute while waiting; actual guard/destruction stays on its thread.
Pinned Ipopt's private MUMPS mutex has no admission callback: the supported one-thread profile
retains its own compute allowance through those bounded foreign sections. The current mutex
holder already owns its core, so progress does not depend on an unadmitted helper. Preserve
that native guard and artifact; no additional outer gate or default factorization switch is
introduced. This restriction does not claim that every opaque library wait releases CPU.
Supervision materializes finite placement for server, group, observer and selected tests.
The original reference 128 GiB pool is preserved; the default 120 GiB command cap cannot
provide its full-capacity placement. Insufficient placement refuses launch.

### Compensating controls

Bounded population, queues and extents; complete protected predicates and effect-sized
acknowledgment settlement; stale-generation refusal; heartbeat through settlement; native
drain and process readback. Unknown library coexistence premises constrain that combination,
without silently changing solver selection or scientific tolerances.

### Confirmation

The review supplies source-backed design evidence. Plan 28 owns current implementation and
the actual sixteen-case, admission, team-lifetime, ordinary study, restart and cancel/drain
controls. E3/E4/E5 remain necessary for assembled acceptance and quantitative claims.

## Pros and cons

Shared ownership avoids duplicated reconstruction and resource authorities. It requires
explicit native coexistence and deployment lifetimes; exclusion may limit simultaneous native
phases even while independent cases remain concurrent.

# ADR-0192: Preserve producer-scoped coherent operation evidence

## Context

Plan43's reviewed F01–F04 expose mixed callback populations, independently projected numerical tuples, disabled native timers reported as zero and mismatched benchmark populations. The maintainer accepted RC01/RC02/RC10 and authorized Plan43a with its required supporting observation slices. Existing operation identities, native Progress, bounded copied observation and work/publication owners remain the foundations.

## Scope

Amend blueprint §23.1 and its generated Rust/Python document consumers under §21.1. Producer identities and record sequences are diagnostic locators, never new scientific authority. Numerical methods, original qualification, scientific work charging, cancellation and artifact publication permission remain with their existing owners.

## Drivers

An operator must inspect current work and recent numerical progress without evaluating the model or entering a foreign solver. Nested same-demand callbacks must retain distinct producer populations. Selected detail must state actual source coverage; invocation comparisons must join compatible timing, work and outcomes. Low observation and interpretation tests need no runtime, solver or store.

## Options

Retaining shared metric names with generation resets cannot distinguish nested producers. Reconstructing numerical rows from per-field histories cannot establish membership. An independent recorder would duplicate lifecycle and coverage authority. Select operation-local producer descriptors, prepared fact handles and atomic bounded record publication in the existing hub; native adapters supply their family meanings and existing Progress/writers carry the same source identity.

## Outcome

Each performing owner declares its producer and populations. Source sequence is issued before lossy fan-out; durable append sequence is separate. Current compact records survive optional history zero subject to explicit admission. Selected detail declares finite bounds and family/interval coverage; a dropped or unacknowledged prefix is incomplete. Invocation evidence references existing work and separates qualification, terminal completion, requested products, response readiness and later related access.

### Production-completeness correction — 2026-10-17

**Implemented / Tested, 2026-10-17:** Plan43's production-completeness correction gives explicit numerical diagnostic operations one deadline across declaration, preparation, admission and execution, plus optional originating run/attempt/step/operation/failure attribution. Standalone diagnostics have no invented origin. Origin is diagnostic context, never scientific permission. Scientific product availability follows each product's governing original completion; retained raw/partial data and caller readiness remain distinct.

Explicit launch profiling returns separate command and capture owners. A fresh command process waits behind an exec gate until an independently attached profiler acknowledges sampling enablement. Capture startup failure releases the gate with explicit failed telemetry; capture stop/drop never cancels the command. The command owner alone cancels and reaps its work. Launch evidence is process-scoped until an actual operation link exists. Changed documents/relations migrate directly through their existing generators; no fake operation or compatibility reader is introduced. Selected functional checks and public consumers are recorded in [43g’s remediation Outcome](../plans/43g-qualification-and-design-publication.md#production-completeness-remediation-2026-10-17); formal proposed status remains separate.

### Plan44 invocation boundary — 2026-10-17

**Implemented under accepted Plan44/RC01:** one invocation recorder is established inside the entered activity owner before synchronous native dispatch, transferring that same context to workers and supervision. Invocation evidence version 2 starts its monotonic wall clock at this establishment, excludes earlier preparation, and preserves synchronous admission/refusal, nested invocation identity and actual cancellation/drain. Version-1 supervisor-only documents are not interpreted as version-2 coverage. All actual document, comparison and export consumers migrate together; no compatibility execution path or scientific permission is added. **Tested — 2026-10-17:** targeted native invocation/transfer/comparison/failure controls and Python invocation-endpoint projections passed; the [Plan44 Outcome](../plans/44-pipeline-performance-optimization.md#outcome-specified-changes-and-test-setup) records commands and boundaries. The worker interval is inclusive and actual, not exclusive CPU attribution; assembled live/durable journeys remain with Plan44f.

### Plan48 ordinary observation extension — 2026-10-20

**Proposed / Interface-checked:** accepted RC03 selects batching prepared ordinary
facts at the existing safe-return boundary, with one source time and one optional
publication decision for the coupled count/time tuple. This removes repeated lock
and formatting work without a new timer cadence. A refused optional batch remains
explicitly lost: its live metrics can be stale/incomplete; the exact local owner and
final native report retain performed counts and time. Lost intervals are never
synthesized from cumulative elapsed time. Current phase retirement is independent
of that optional batch. Compiler event counters bind the current operation's prepared
population; query-key formatting is selected detail rather than ordinary work.
Blueprint §23.1 owns the ordinary freshness contract; Plan48g owns migration and
qualification. This amendment precedes dependent implementation and does not change
this record's formal proposed status.

### Consequences

Changed document encodings are versioned and all actual Rust/Python/CLI, durable, timeline, report and benchmark consumers migrate together. Owner-issued native facts preserve activation, phase, coordinates, units and inclusive scope. Ordinary diagnostics remain bounded and store-independent. No callback backpressure, subscriber replacement or unbounded native collector is introduced.

### Compensating controls

Independent admission covers descriptors, records, copies and selected output. Contention and loss never become zero. Optional telemetry failure cannot alter scientific permission. Existing cancellation/drain and immutable publication safeguards remain. Observational settings leave mathematical preparation identity only after their actual effects and consumers establish a sound boundary; conservative identity remains a supported investigation result.

### Confirmation

The review and execution planning inspected the existing producer, Progress, native callback/timer, runtime publication, workflow and benchmark contracts. Plan43a's Outcome records scoped Tested support for independent nested producers, coherent current/history-off records, finite selected coverage and stop/drain failure controls, native activation, workflow invocation endpoints and actual Python/managed consumers. It distinguishes selected acceptance from unexercised contexts and the remaining Plan43 packages; Plan43 owns finding dispositions. A05 retains full Controls identity because history changes report-memory admission, while existing narrower native-session and mathematical compatibility remain sound. Environment/provenance proof and a mandatory repeated benchmark campaign remain eliminated. Implementation evidence does not change this ADR's formal proposed status.

## Pros and cons

Prepared handles and grouped records make ownership and event membership explicit and keep hot updates local. They add bounded descriptors and require a coordinated wire migration; existing generators and writers absorb that cost rather than a second telemetry system.

# ADR-0186: Own lazy workflow inputs, scientific context and demanded products

## Context

Plan38a–38c supply immutable local preparation, shared governing policy and bounded native owners. Study refill, eligible seed search, causal units, live integrators and fitting caches already exist. Their workflow interfaces still materialize every study point, share block settings, retain incomplete inner-context evidence and sometimes compute undemanded fitting derivatives. The maintainer authorized Plan38d and selected lazy variants, public block overrides, frozen inner recycle context and live samples through current storage.

## Scope

Amend blueprint §13.6/§17/§19/§21 for D1–D5 and I-D1–I-D3. The target preserves current store topology and only extends its necessary occurrence and prefix acknowledgement interfaces. No new solver family, physical model, generic iteration algorithm, native checkpoint serialization or compatibility path is selected. Accepted ADRs remain unchanged; this proposed record governs the scoped amendment pending its decision PR.

## Drivers

Value edits, independent studies and fitting trials should reuse valid preparation and allocations while requesting only useful scientific products. Changing lane order must not change numerical causality, branch authority or floating reduction order. Live output must be bounded and truthful about physical completion and recording. Unit/solver extension should remain local to its scientific and native owners.

## Options

Retain explicit lists/shared profiles/post-run projection everywhere; materialize broader convenience products eagerly; or extend existing owners with bounded reconstructible inputs, contextual profiles, demand and output production. Select the last. It preserves working policy, frontier, seed, native and result seams without another end-to-end planner or store.

## Outcome

### Scientific input and execution

Lazy study inputs are immutable reconstructible descriptors over an admitted source and finite structural alternatives, with deterministic selected ordinals and explicit predecessor/start policy. Descriptor and selected-occurrence cardinality are bounded without compiling the Cartesian space. The source owner constructs selected revisions; each actual variant obtains complete physical/provider/source admission before dispatch. Occurrence identity/recovery is independent of preparation timing, lane count and completion order. Unsupported or invalid selected science is an attributable occurrence refusal, never a fabricated result or silently ready dependency. Current explicit-point inputs remain a distinct supported input form through the same executor, not a compatibility adapter.

Block overrides are keyed by compiler-issued stable block IDs, not schedule positions. They vary native selection/settings and finite work controls, never original physical acceptance, mathematical intent or branch/start permission. Contextual assessment derives each actual effective profile. Unknown IDs or incompatible settings refuse; implicit defaults still come from the one solve owner. Ready parallel work requires complete numerical/execution/provider/validity independence; successful overlays commit in canonical order, downstream bindings see committed predecessors, and every exit restores authored specification. Full original assessment remains mandatory. Tear choices/costs/groups remain globally coupled across SCC-local rows.

A recycle map freezes its actual inner authored starts, branch context and accuracy, retaining only neutral allocations across map calls. Available producer context is recorded with raw G(x)-x; unavailable and inapplicable facts remain distinct. Repeatability/noise observations support only their named envelope, not global uniqueness. Libraries own damping, delayed Anderson and numerical history. Optional finite restarts reset actual acceleration history, use an authorized screened start and preserve original aggregate caps and terminal vetoes. Defaults do not gain universal acceleration or restart. Stateful inner continuation is not selected.

### Dynamics, fitting and owned output

Live integrator history persists across ordinary samples and safe output waits on its owning thread; new-IVP, parameter/mode/event/start changes reinitialize or rebuild under backend-specific semantics. A saved state is not a native-history checkpoint. Context retention uses qualified reset or fresh native fallback while preserving valid compiled workers. Event/jump and derivative/closure checks remain mandatory at the achieved order.

An opt-in live sample producer is bound before launch to the existing run lifecycle. It emits owned bounded batches at completed sample boundaries, carries original locators and independently recorded completeness, and obeys original cancellation/deadline through backpressure and drain. Computed/provisional samples, recording acknowledgement and terminal complete/partial/unknown recording are separate from scientific acceptance. The existing cursor/append/close owner supplies storage effects; no new storage topology is implied. No second full trajectory is retained merely to stream. Full terminal retention remains charged to actual demand; compact streaming retains mandatory completion and coverage facts. Dropping a subscriber releases its own ownership rather than independently changing scientific completion.

Fitting demand includes selected native-solve internals, requested objective/derivative/statistical products and original assessment. Value-only calls avoid unused response Jacobians/sensitivity trajectories. Same-point upgrades preserve exact parameters/event/start/provider meaning and check physical agreement. Per-experiment workers/contexts remain owner-affine; new parameter trials remain new IVPs with reset/fallback. Independent experiments use admitted workers and declared ordered reduction; profile chains preserve causal seeds. Covariance rank/bound withholding, exact/Gauss–Newton distinctions, surrogate RNG and charged snapshots remain intact.

Optional effort adaptation extends the existing bounded StepControl. It is off by default. Qualified endpoints alone can change the next displacement using comparable effective-profile counters; unknown/zero/foreign counters use the declared baseline. Existing displacement/growth/rejection/work/deadline bounds and connected-path/branch/original checks remain authoritative.

### Consequences

Plan46 dynamic action consumers use admitted assembly JVP/VJP products and physical
chain maps; a completed current-effect-compatible matrix may satisfy either action.
Diffsol's adjoint sign and selected segment parameter axes remain adapter semantics.
Direct factor callbacks use precompiled CSC refill offsets and retain full derivatives.
The outer dynamic value cache cannot bypass current provider or mode-guard effects.

Migrate Rust/Python inputs, prepared products, reports and recording consumers together; regenerate registry-owned contracts and compiled stubs. Delete replaced single-profile assumptions, eager point expansion, redundant derivative work and duplicate output copies once their replacements pass targeted controls. Existing mechanisms with a distinct supported purpose remain. The root owns shared declarations, generation, integration and acceptance.

### Compensating controls

No scheduling decision grants scientific permission or new native resource capacity. Unsupported inner-map semantics, unavailable derivative/reset capability and failed mutation refuse or use the declared fresh fallback. Live output cannot claim acknowledged persistence, full requested horizon or native continuation from bytes alone. Original clocks, exact seeds, owner incarnation, backpressure, callback/native drain and owner-thread destruction are preserved.

## Pros and cons

Bounded descriptors, contextual execution and demanded products remove avoidable preparation and crossings. They require exact context/ordinal identity and explicit resource/output ownership; these belong in existing scientific and integration owners rather than another universal workflow framework.

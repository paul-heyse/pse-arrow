# ADR-0193: Prepare exact demanded mathematical products

## Context

F05/F06 identify selected-derivative construction amplification and broad implicit products. Exact Symbolica 3.0.1 probes establish sparse ancestor-closed shapes and symbolic weighted/action products, including qualified provider partials bound as inputs.

## Scope

Amend blueprint §14.3. The maintainer authorized complete Plan43 execution and delegated the remaining concrete choices to the coordinator. This record precedes dependent implementation; formal ADR acceptance remains separate.

## Drivers

Interactive re-solve, studies and dynamics need demanded work, explicit semantic authority, independent original scientific checks and cancellation-safe ownership. Local tests must exercise the responsibility with its actual dependencies.

## Options

Retaining Cartesian jets leaves the actual Numerica convolution-table amplification. A second host differentiation engine duplicates library authority. Select explicit library-generated products and support-driven maps in existing preparation/execution owners.

## Outcome

Prepared demand identifies SelectedPartials, JacobianAction, WeightedHessian or WeightedHessianAction separately from derivative ceiling. Selected output/coordinate order and product/layout/policy enter prepared identity; consumed runtime weights/directions enter completed-product identity. Projection is lazy and requires all original point, fixed-input, provider, applicability, configuration and scope premises. Failed upgrades publish no partial higher product; independently valid lower products survive only while those premises hold.

### Consequences

Use support-driven assembly and prepared offsets. Joint arithmetic optimization is bounded to adjacent independent siblings within one semantic scope; every original materialized value and ordered domain/derivative-eligibility check survives, alongside finite checks on the complete requested product. Direct weighted/action completion does not certify unrequested intermediate partial jets. Provider/guard/branch/domain/applicability boundaries remain barriers. Native NLP matrix consumers retain their matrix contract; action consumers request actions. Unknown-only Newton and final parameter derivatives are separate demands. Eligible derivative arithmetic can use the existing optional Symbolica C++ compile/load owner with complete artifact admission and identity.

### Compensating controls

Preserve aliases and ordered off-diagonal contributions, portable reconstruction, exact provider derivative requirements, bounded cancellation, conservative FP/ISA, owned compiler-child drain, module lifetime, exclusive scratch and original residual/IFT derivative verification. First-order requests keep unused second-order workers and compilation cold.

### Confirmation

**Tested, 2026-10-17:** independent nonlinear IFT, canonical-axis refusal, analytic/interpreted/compiled weighted/action products, source guards, first-only cold Second, projection/failure and assembled native consumer controls passed. Plan43b/43g Outcomes own exact commands and composite conditions. This is selected functional acceptance, not universal speedup or formal ADR acceptance.

## Pros and cons

The selected boundary removes incidental work and makes validity locally inspectable. It requires complete consumer migration and revealing failure controls rather than an additional compatibility path.

## Retain actual factory/registry binding

`pse-engine/src/session/factory.rs::{model_assembly,validation_context}` and `assembly.rs::ModelAssembly` establish the lifetime defect directly: the map retains only `Weak<ModelAssembly>`; a validation-only call drops its temporary assembly even though the returned validation context survives. `pse-runtime/src/workflow/mod.rs::Runtime::validation_context` repeats that call. A context retains cloned `SessionState`, not its enclosing assembly. Reacquisition can therefore assemble again and create a different native admission owner. Registry equality and `function_inventory`'s version/name hash cannot prove actual implementation equality.

Select this engine-owned public shape, with private internals:

```rust
#[derive(Clone)]
pub struct BoundModel(Arc<BoundModelInner>);
struct BoundModelInner {
    factory: Arc<EngineFactory>,
    native: Arc<ModelAssembly>, // already retains the actual Arc<Registry>
}
impl EngineFactory {
    pub fn bind_model(self: &Arc<Self>, registry: Arc<Registry>)
        -> Result<BoundModel, EngineError>;
}
impl BoundModel {
    pub fn factory(&self) -> &Arc<EngineFactory>;
    pub fn registry(&self) -> &Arc<Registry>;
    pub fn validation_context(&self) -> Arc<ValidationContext>;
    // Candidate construction always uses this retained registry/factory pair.
}
```

`bind_model` resolves the real assembly and initializes its infallible validation slot before returning. The handle owns no runtime, solver, store or executor. General `EngineFactory` registry reuse remains weak and bounded by live callers. Factory configuration methods consume a factory and refresh generation/maps, so binding follows all configuration. `with_target_partitions` produces a distinct binding for physical inventory and retains the deployment CPU admission; it must not borrow the original handle's validation context.

Preserve the exact acyclic assembly order: configured base state → `pse_checked_value` capturing the base snapshot → extension registry → `cache_service/inspection.rs::bind` creating a validation snapshot before installing its own UDTFs → assurance instrumentation → final assembly → validation snapshot. Neither `NativeValidation` nor a SessionConfig extension may retain `BoundModel` or its enclosing assembly. `assembly.rs::retained_extension` already states that prohibition. A validation snapshot may retain earlier snapshots and native function Arcs; no retained edge may point back to its enclosing assembly or the UDTF registry containing itself.

Migrate `workflow::Runtime::from_shared` to consume the bound handle (or delegate immediately to an equivalent private constructor); registry/factory accessors borrow it. Python `inspection/runtime.rs::Runtime` owns that same handle before publishing PROCESS_RUNTIME and creating consumers. Existing deployment checks still compare pool, disk/cache managers, object-store registry and CPU admission. Lower document admission consumes this binding and an operation cancellation/pool; it does not construct `SharedRuntime`, mathematical services or canonical storage. Document-source session construction and local CHECK preparation are distinct operations: source documents bind candidate providers, while `FieldCheckedBatch` admission consumes the actual snapshot's `ValidationContext`.

`engine_session.rs::bind_candidates` can use the assembly's retained validation slot because its current snapshot is exactly `native.context.state()`. `with_workspace` uses that same base snapshot and can share it only while its actual native owner is unchanged. Selected `EngineSession::validation_context` remains selection-owned: `bound_state` replaces policy configuration and catalogs, and `NativeValidation::prepare` consumes execution-start time. `session/execution.rs::NativeExecutionContext::bind` currently captures its supplied pre-extension state; pass an existing Arc only when the caller passes the very snapshot from which it was captured, otherwise retain a new execution-snapshot context. Never infer equivalence from settings/name hashes. The execution extension must capture validation before installing itself, and completed state stays weak.

Consumers to move are workflow document/package loading, modeling/pure preparation, physical admission, canonical source/edit/fit ingress, result encoders, study/objective/numeric/analysis tables, connected readers, Python physical/modeling ingress and registry reflection. No adapter may silently recreate a default validation engine. Acceptance: exact Arc reuse after unrelated sessions drop, stable `prepared_count`/assembly metrics, same-named foreign UDF refusal, changed settings/registry reprepare, distinct physical binding, and Weak-observed release after all bound/selection consumers drain. These are implementation controls, not executed product claims.

## Admission carriage, diagnostic demand and kernels

`pse-relations/src/columnar/collection.rs::Collection::finish` drops `checked.admission` while wrapping the identical buffers with `OwnedRecordBatch::from_reserved`; select a crate-private consuming `attach_reserved(self, reservation) -> Result<Self, RelationError>` that carries contract, storage and admission together. It may mint allocation ownership, never semantic evidence. `columnar.rs::BatchBuilder::append_batch` currently receives only `&RecordBatch` and consequently cannot know admission: add a distinct internal `append_checked(&FieldCheckedBatch)` route, preserving the raw route's validation obligation. Track pending/new segments separately from same-owner admitted segments. `row_checks.rs::bind` already refuses volatile/non-Boolean CHECKs; stable checks still depend on their captured configuration/execution-start scope. Final cross-row keys/references/completeness remain the relational obligation owner's job.

Structural trust belongs to private `CheckedStorage`, tied to immutable arrays and sound producer/transform premises, rather than a public certificate or the presence of `RecordBatch`. Generic `PreparedLocalContract::evaluate` retains `validate_full`; only an internal evaluation taking established storage trust can omit it. Raw Arrow, FFI and `admit_external` establish trust before kernels and keep external-copy isolation. A local admission capability alone contains no arrays (`LocalFieldAdmission` docs); callers cannot detach it and attach it to unrelated storage. Projection/casts/new values establish affected obligations; concat inherits local evidence only for equivalent contracts and the same actual native predicate owner. No scientific state or fresh store read inherits validity from an unrelated digest.

`validate/occurrences.rs::Node::root/visit` allocate locations and visibility before knowing failures. Replace `Vec<Location>` by a bounded traversal map (`RootRange`, list offsets/parent map, union active-arm map, dictionary/run-end mapping) and `Selection::{All,Range,Indices}`. Evaluate on the original array for All, a slice for Range, and checked Arrow take for Indices. Render root row/path/value only when a retained violation needs it; traverse/count every violation even when samples are full. Null-parent and tagged inactive-arm masks remain explicit. Existing `gather` already avoids copying an exact whole-array selection; do not claim that optimization is missing. Cancellation remains per chunk and material nested traversal.

`columnar.rs::take_reserved` selects per-index MutableArrayData for every column whenever a selected extent is available, even primitives/strings. Select per-column kernel routing: use native take for non-list scalar layouts whose output/scratch is covered by the reservation; retain selected-range copying for list descendants, where native take's average-input child preallocation can exceed selected extent. `check_take_indices` rejects null indices and checks the entire domain before reserving, including zero-column batches; preserve that order. Dictionary/view/encoded types need their existing conservative alias/unselected-child forecast until individually proved. The isolated primitive fixture tests duplicate ordering and null preservation; it establishes equivalence for that fixture, not performance or every type.

## IPC checker decisions at the actual pin

`pse-runtime/src/workflow/result_blocks.rs` owns result/source purpose, bounded framing and layout. `arrow-ipc-59.3.0/src/reader/stream.rs::decode/finish` supplies a useful owned-buffer decoder but no complete transport admission. `reader.rs::create_struct_array` constructs `BooleanBuffer::new` before all array validation, which can panic. `Buffer::from(bytes::Bytes)` retains the allocation; default decoder alignment may allocate aligned copies. No `with_skip_validation` call is selected.

| Existing obligation | Decision and exact reason |
|---|---|
| Total bytes/result versus canonical-source purpose; row/value/node bounds | Retain before decode. The decoder has no application purpose/row/value ceiling; negative body length is cast to usize. A 512-KiB result limit is not interchangeable with canonical-source PAYLOAD_BYTES. |
| Continuation marker, signed metadata/body lengths, bounded aligned spans | Retain checked borrowed framing before decoder buffering. The decoder accepts its own broader framing and may buffer advertised sizes; an eventual decode error is too late to prove bounded staging. |
| Verified FlatBuffer limits, schema depth/count, names/metadata/type parameters | Retain bounded verified inspection before `fb_to_schema`. Decoder conversion is recursive and uses infallible schema conversion; its generic verifier limits do not establish this schema policy or all converter panic domains. |
| Exact expected schema, one batch, row count, allowed little-endian V5 schema | Retain in admission. Generic decoder permits streams/multiple batches and does not know the selected registry/descriptor. |
| Required validity/value/offset buffer minima and nested node shape | Retain before constructors. Isolated short struct validity and huge node fixtures panic even with force_validate. Existing production witness `oversized_node_and_short_validity_buffers_are_refused_before_arrow_constructor` remains required. |
| Nonnegative checked buffer spans, nonoverlap and exact layout consumption | Retain. Probe accepts overlapping primitive value storage; validating array values does not establish disjoint transport spans. Checked spans must precede slicing. |
| Actual string/list offset monotonicity and bounds | Keep Arrow's enabled validation; malformed Utf8 final offset is rejected by native validation. Current preflight checks the required offset-buffer length, not every offset value, so there is no existing duplicated full-offset scan to delete. |
| Alignment | Keep bounded message/body alignment policy and default decoder realignment; do not impose `require_alignment=true` on arbitrary Bytes inputs. Shifted payload works with default copy and fails with required alignment. Charge aligned-copy scratch and retained backing extents. |
| Explicit EOS and no trailing bytes/messages | Retain explicit EOS. `finish()` accepts a clean Header boundary without EOS; probe confirms that acceptance. Full-feed decoder rejects bytes after EOS, so remove duplicate *postdecode* extra-next checks only after the admitted owner's exact framing and full-feed/finish path replace them. |
| Dictionaries, compression and variadic buffers | Retain refusal. Dictionary state crosses messages, compression introduces an independent decompressed-allocation bound, and variadic layouts exceed the admitted schema/layout contract. Library eligibility does not imply product admission. |
| Writer self-preflight | Select elimination only in the controlled writer-to-admitted-owner constructor after supported-schema/scratch/LimitedWriter/finish controls pass. Keep checks on external input and reopened store blobs. No raw Vec caller may claim writer admission. |
| Decoded schema/row-count/second-next comparisons | Select deletion as redundant only after exact owned admission, full decoder consumption and finish succeed. They currently protect a raw decoder path and cannot simply be removed first. |

Prepare `PreparedIpcSchema` once from the actual immutable registry schema and private Purpose: retain SchemaRef, bounded field/depth count and layout traversal. Decoder admission consumes that handle plus declared rows, so trusted expected-schema shape/layout is not rebuilt for every block; raw message schema/type/metadata and its layout still receive the checks above. It is derived transport preparation, never a second schema declaration or a substitute for local scientific admission.

Proposed transport types: private `TransportBacking { payload: Vec<u8>, lease: AllocationLease }` with immutable AsRef bytes; `AdmittedIpcBlock { payload: bytes::Bytes, purpose: private Purpose, schema: SchemaRef, rows: usize, digest: EncodingChecksum }`. `Bytes::from_owner` (1.12.1) can retain the backing charge through `Buffer::from`; alternatively a custom Buffer allocation owns that same backing. Consumers receive read-only views, never a mutable alias. A decoder returns arrays retaining the backing charge, and separately owns any realignment/decode allocations; sharing payload and output must not double-charge the same actual backing. Empty/decode-copied outputs must release unused payload when no references remain. A small slice retaining a large payload keeps the large payload charge.

Provide separate checked constructors for controlled writer output and untrusted raw/store bytes. The latter verifies digest and framing anew before allocating decoder scratch. Canonical append/descriptors may consume the writer-issued digest only within the same immutable operation and existing framing; unknown-ack replay reuses that request. `pse_model::Bytes` remains the domain byte value; no wholesale representation/serde/heap-accounting migration is selected. Consumers: canonical_codec, canonical_execution and connected result/source readers, coordinated with Plan 36b's receipt/publication owner. Accept retained arrays after input/reader drop, zero rows, nested slices, exact float bits, deterministic splitting, malformed inputs, pool refusal and fresh-store digest disagreement. Catching probe panics is discrimination only, not production recovery.

## Lazy file cache and real ordering

`NativeCacheService::new` eagerly reserves metadata/statistics/listing envelopes; `unbound_config` installs zero file-cache limits. `CacheBudget::for_memory` yields 50+16 MiB metadata/statistics at a sufficiently large pool (capacity accounting, not RSS). `bind_state_with_generation(None)` bypasses reuse; `Some` qualifies metadata/statistics but always disables listing. Therefore choose one lazy synchronized owner with optional per-family envelopes, not unconditional initialization of all three.

Proposed `FileCaches { metadata, statistics, listing }` is private behind a Mutex; `activate(FileCacheDemand::{MetadataStatistics,WithListing}) -> Result<Arc<FileCacheBinding>, DataFusionError>` stages missing envelope reservations locally and commits all newly requested families once. Source-generation admission precedes activation. Competing first binds serialize only initialization; no lock spans I/O, planning or await. On partial reservation failure, drop staged envelopes and leave published active families unchanged; return the existing typed native resource error. Select typed refusal rather than silent cache bypass on *capacity activation* failure; generation/namespace admission already has explicit bypass semantics and counters. A later retry can succeed. Publish a configured state only after activation/configuration succeeds; a failed configured state must not report a bound cache hit. Namespace records may persist if deliberately admitted before a later state failure, but cannot be mistaken for successful active cache reuse.

`report`, `details`, invalidation and cache UDTF/EXPLAIN inspection read Option values without activating; keep stable inactive rows with policy limits and zero reserved/retained/entries. Clear preserves active capacity under the existing policy and evicts retained values; it is not a capacity-disposal instruction. Preserve Namespaced generation/maintenance fences, store identity and `SharedIo` across stores. Split policy arithmetic into mandatory initial commitments and requested activation commitments, checking overflow, activated total and working/staging/predicate headroom; lazy must not turn finite budgets into optimistic oversubscription. Acceptance: default no file reservations, inspection remains inactive, qualified first bind once, None bypass, metadata-only path no listing allocation, races, refusal/rollback/retry, and clear-versus-load epoch behavior.

`session/materialized.rs::ImmutableTable::scan` currently claims no order. `MemorySourceConfig::try_with_sort_information(Vec<LexOrdering>)` validates expression/schema references and projects them, not actual row order. Retain conservative scans until the producer supplies a private order premise over actual completed buffers, comparator/null settings and batch/partition boundaries. PK uniqueness or canonical hashing alone is insufficient. A future admitted sorted producer can supply that premise directly; it must test reversed batches, nulls, projected-away keys and independent partitions before removing sorts. No optimizer-flag change is selected.

## Actual extension identity and cancellation

`justfile` py-sync/native/parity paths compile force-validate; `scripts/native_tests.py` writes hardcoded `['force-validate','native-solvers']`. `pse-py/src/lib.rs::build_info` exports BuildInfo but no authoritative cfg feature set. The installed extension identified below reports debug/nightly with empty git/lock hashes; neither that report nor a filename proves force-validation. Select an extension-owned frozen `NativeBuildMode { force_validate: bool, native_solvers: bool, build_identity: ... }`, using Rust cfg booleans and the existing build identity rather than environment flags. Runner provenance binds mode to the imported binary's canonical path and byte identity, and rejects path/mode mismatches before collection. Native and ordinary correctness sync must explicitly build/select force-validation; ordinary interactive sync selects production mode. Parity, setup/stub/contract and wheel consumers select their required modes explicitly. A binary feature report complements actual Arrow closure checks; it cannot replace target/host/dev leaf validation. Do not rebuild the shared editable extension merely to run this investigation.

D-N1's source path is `pse-py/src/inspection/stream.rs::from_canonical`: a generic Arrow callback directly calls `executor.block_on(reader.next_batch())`. Ordinary `workflow.rs::blocking_on_with_recovery` instead polls a pinned future every 100 ms, calls `py.check_signals`, requests cancel once, and keeps polling to settlement before returning the preserved Python error. GIL release alone does not add main-thread signal checks.

The isolated C-stream discriminator uses PyArrow 25.0.1/CPython 3.14.7. Its native get_next proxy marks entry through a pipe before a separate process sends SIGINT 0.2 seconds later, delays 1.5 seconds, then calls the original callback and marks settlement. A previously yielded batch remains live after reader close. A periodic C/Python bridge mirrors the source's signal/cancel/drain behavior, with a 0.2-second mock drain; it is not the production Rust bridge or a canonical RPC fixture.

| Control | Observed result |
|---|---|
| Signal after native pull entry | KeyboardInterrupt at 1.501 s, native settlement observed, no cancellation callback, no returned second batch; previously yielded arrays valid after close. |
| Signal before pull | KeyboardInterrupt at 0.208 s; no native pull settlement/cancel. This alone would not diagnose D-N1. |
| Periodic-check bridge | KeyboardInterrupt at 0.501 s, cancel and native settlement marks both observed; retained arrays valid. |

Select a Python-controlled pull route using the existing signal/cancel/drain policy; keep generic C callbacks interpreter-independent. One consumption state must choose C export or Python iteration, refusing mixed/repeated consumers. A Python pull owns its pinned future/reader until settled, polls signals on the main thread, records the first signal error, cancels the reader token once and drains before returning it; attach late native failure as cause. Do not drop a future on each timeout. Do not call a blocking stream mutex while the active callback owns it: request through the independent cancellation token, then settle/join through the pull owner. Native handle schema/EOF/failure state and arrays after close remain governed by BatchStream. An async route may be added using the same owner if an asyncio consumer requires it; no duplicate SDK cancellation mechanism is implied.

**Not established:** actual imported extension force-validation cfg; production canonical delayed-RPC cancellation consumption; renewable protection release on interruption; real production ordinary-bridge latency. Those require an exclusive seeded canonical reader fixture with an entry barrier in its read future, a known cfg-reported binary, delayed-read SIGINT and before-pull/ordinary controls. Canonical coordination owns per-RPC cancellation and settle/drain; this package owns Python signal delivery. Source/prototype evidence selects the correction but does not close D-N1.

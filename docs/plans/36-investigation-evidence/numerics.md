## F18: complete cubic selection has a viable guarded exact route

Current `pse-math/src/implicit_cubic.rs::CubicRoots` shares a mutex-protected coefficient evaluator. The guard ends after evaluating four f64 coefficients; rational conversion/isolation/refinement/original verification are outside it. `Factory::create_scoped` constructs attempt/provider state while `Nested` receives an `Arc<dyn InnerSolver>`. Select an immutable `CubicDefinition` plus factory-created exclusive `CubicWorker` containing the coefficient evaluator, parameter count and private scratch. Extend the inner-solver factory construction seam for native/affine/injected solvers and tests together. Do not put per-attempt values/cancellation into an immutable prepared solver definition.

Actual Symbolica 3.0.1 `poly/univariate/roots.rs` exposes `UnivariatePolynomial<Q>::isolate_real_root_intervals() -> Vec<(Rational,Rational,usize)>` and `refine_root_interval((lower,upper), tolerance)`. The former removes rational content and delegates to integer square-free/VAS-CF isolation in `poly/univariate.rs`, returning complete distinct real roots and multiplicities. Current `isolate_real_roots()` instead obtains a canonical general root multiset and filters real/zero roots; its cache/complex-root route has additional work, though the library has axis shortcuts. No claim that every cubic does full complex isolation or that this changes runtime by a fixed factor follows.

**Select** a guarded real-interval route for the exact polynomial formed from evaluated f64 coefficients, with the existing isolated-root route as certified fallback. It preserves complete root enumeration, unlike approximate Aberth/Newton candidates. No new application root-iteration algorithm is needed. Domain/original residual/bounds/selector checks remain authoritative after coefficient evaluation because f64 coefficient extraction is not itself a proof of the original expression.

Concrete algorithm/consumer contract:

1. Check live original scope/deadline/cancel and coefficient dimensions/finiteness; convert each coefficient exactly to Rational and trim only exact leading zeros. Constant-zero and constant-nonzero cases retain typed nondegenerate-root refusal. A tiny nonzero leading coefficient is never rounded to zero to manufacture a lower degree.
2. Obtain all distinct real intervals with multiplicity. Preserve count and exact ordering before converting to floats or applying branch selection. Multiplicity is not the number of distinct candidates. Intervals crossing a branch endpoint are refined/fallback-qualified rather than dropped by a rounded midpoint test.
3. A nonpoint interval with either endpoint evaluating to zero in the original polynomial must use the old `IsolatedRoot::refined` route. The public real-interval refiner can encounter a different root at that boundary; the executable negative control below demonstrates its endpoint-sign assertion. Likewise fall back on unresolved boundary/separation/rounding obligations. Point intervals are exact roots and do not enter that refiner.
4. Otherwise use the public real-interval refiner and its declared precision, then select a finite f64 representative and independently verify the original residual, original bounds and selector. Verify all possible branch candidates before deciding exactly one original-valid distinct root. Never accept the first small residual as completeness.
5. A repeated root can satisfy Value, but does not establish First/Second nonsingular implicit-function support. Each higher-order upgrade rechecks original Jacobian nonsingularity, provider derivative order, active branch/neighborhood and exact axes. A near-critical simple root may remain Value-valid while derivative/rank evidence is withheld.
6. Check live cancellation/time again after every uninterruptible library section and before publication. These public routines do not consume the execution stop callback; this design does not promise prompt mid-isolation cancellation. Strict interrupt-latency support requires a separate native/library cancellation seam, not a detached thread whose resources escape drain.

The bounded supported scope remains one unknown and polynomial degree at most three, finite admitted f64 coefficients, declared branch interval and current original verification tolerances. General polynomial providers and higher-dimensional algebraic isolation are not implicitly added. The guarded route is a concrete candidate for P-C3, not a faster algorithm claim. General-root fallback is deliberate within this same exact semantic path, not a compatibility API for a deleted mechanism. Repeated identical numerical products should hit the complete memo before either isolator; introducing a second unbounded coefficient cache is unnecessary.

Memo interface: `ImplicitProduct` binds exact problem/provider/solver/options identity, input bits, requested outputs/axes, starts/hints/tolerances, branch/anchor/selector premises, achieved order and qualified product. Value/First/Second validity are separate. Same-bit hits can bypass only obligations whose complete dependencies are in that key; they still observe live stop/deadline/work. Failed evaluation invalidates the product. Scalar provider fan-out requests the maximum genuine consumed order only when refusal order/attribution remain unchanged; otherwise retain stage order and reuse after an actual compatible evaluation.

### Separate public rank-method proposal

**Separate proposal**, not accepted RC14 implementation: add a method-tagged rank request and evidence while preserving the default/current singular-value method. Proposed boundary:

```text
RankMethod::SingularValues { relative_cutoff }  // svd_scaled_v1, default
RankMethod::SparseQr { policy: SpqrScaledColnormV1 }
SpqrScaledColnormV1 { rho, stability_bracket, reconstruction_limit,
                     orthogonality_limit, original_backward_limit }
RankEvidence::SingularValues { rank, absolute_singular_cutoff, relative_cutoff }
RankEvidence::SparseQr { policy_version, rank_estimate, rho, max_column_norm,
                        absolute_pivot_threshold, native_tolerance_used,
                        ordering, permutation_identity, dropped_frobenius_norm,
                        reconstruction_check, orthogonality_check, solve_checks }
```

The separate [exact SPQR research](sparse-rank.md) fixes the candidate method tag `spqr_scaled_colnorm_v1`: on the exact normalized Jacobian A=diag(1/row_scale)*Fx*diag(variable_scale), use real-double canonical CSC and requested `SPQR_ORDERING_COLAMD=2`, record returned permutation E (NULL means identity), and compute overflow-safe N=max column 2-norm and tau=rho*N. Rho is a required positive finite method parameter, with no implicit copy of an SVD relative tolerance; zero A has rank zero. Pinned SPQR treats eligible residual pivot norms <=tau as dead. Record rho,N,tau and actual `cc.SPQR_tol_used`, exact native/matrix/scale/axis identities, and the numerical-policy version. This threshold is not a singular-value cutoff. The proposal has no silent default QR policy: stability bracket k>1 and positive finite dimensionless reconstruction/orthogonality/original-backward limits are explicit required admitted policy fields, recorded in evidence. Their values require method qualification and operator approval; this investigation does not invent qualified constants. Withhold if rank(tau/k) differs from rank(k*tau), a check fails, any scale/input/result is nonfinite, rank<n for a requested full-rank response, or native/budget/lifecycle support is unavailable. No untagged fallback is allowed.

Reconstruction checks use ||AE-QR||F/max(||A||F,safe_floor); orthogonality has its own declared defect and limit. Store the check method (exhaustive, bounded blocks or sampled actions); a sampled check is not an exhaustive certificate. Record `SPQR_norm_E_fro` as drop diagnostics, not reconstruction proof. Keep independent original response residual/back-mapping, physical bounds/guards/neighborhood and per-RHS backward checks. Never materialize dense Q to claim sparse-scale support. Rust faer sparse QR does not silently supply this explicit SPQR rank-revelation contract; structural matching plus one small residual is also insufficient.

The exact pin has a concrete integration blocker: `suitesparse_sys 0.1.4` enables no SPQR today; its optional feature includes absent `spqr.h` rather than bundled public `SuiteSparseQR_C.h`, and does not express the full CHOLMOD/static C++ dependency closure. Managed native prefixes provide KLU, not qualified SPQR/CHOLMOD. R36-01 therefore proposes an owned corrected public C binding/native image, not a feature toggle or registry patch. Exact research specifies int64 versus int32 APIs, matching CHOLMOD long allocation/free, rank/statistic qualification, exclusive common/factor ownership, static closure, BLAS ABI and thread control. Global allocator hooks and common memory counters do not establish per-operation bounded fill. Native numerical/link/error/exception and hard-cap qualification remain not_run; current KLU availability is not their evidence. Both methods retain original matrix role/identity and independent response evidence; SparseQr cannot populate a singular-value-cutoff field.

The exact faer spike for A=[[1,1],[0,2^-30]] produced singular values [1.414213562373095,6.585445079827192e-10] and pivoted-QR diagonal magnitudes [1,9.313225746154785e-10]. At relative cutoff 0.75*2^-30, singular-value rank is 1 and a QR-diagonal rank rule gives 2; assertions passed. The independent closed-form oracle agrees. This is a concrete reason that automatic RC14 substitution changes public meaning, even on a structurally regular matrix.

Consumer migration for the proposal: registry/result evidence schema, Rust `Evidence`/withholding displays, Python diagnostics and serialized completion, study prediction/rank policy, fitting callers only where they actually request this Fx method, docs and any threshold-oriented tests. Old evidence decodes as SingularValues; no old payload is relabeled SparseQr. Existing callers keep singular-value default; users selecting SparseQr explicitly choose its method-specific threshold meaning. Adoption needs the numerical-method/blueprint decision and operator confirmation before this migration. Qualification includes near-cutoff/non-normal/ill-scaled/deficient fixtures versus independent SVD, perturbations and multiple RHS, reconstruction/orthogonality/backward checks, pivots/orders/permutations, ABI mismatch, fill pressure, cancellation/drain and truthful unavailable rank.

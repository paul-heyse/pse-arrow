# Sparse numerical rank: separate method proposal

Baseline: `2d6bf6ae7`, 2026-10-11. Scope: R36-01 investigation only. RC14 retains the existing public singular-value contract. No adoption, implementation or native qualification is claimed. Plan 36c owns status; this evidence does not change it.

## Decisive interface findings

**Interface-checked:** Workspace `Cargo.toml` pins `suitesparse_sys =0.1.4`, disables defaults and enables `static_libraries,klu,amd,colamd,btf`. Its vendored source defines SuiteSparse_config 7.7.0 and SPQR 4.3.3 (CHOLMOD requirement >=5.2.1). The crate has an independent, empty `spqr` feature: it does not imply `cholmod` or other dependency features. `build.rs` generates Rust declarations from `wrapper.h` and links only configuration plus named enabled libraries. It does not itself express the complete SPQR static dependency closure or C++ runtime.

A concrete blocker precedes numerical work: `wrapper.h` selects `#include <spqr.h>` under `USE_SPQR`. The entire vendored tree contains no `spqr.h`; the public C header is `SPQR/Include/SuiteSparseQR_C.h`. Therefore enabling the existing feature is not a working integration against its bundled headers. This is a pinned-source finding, not an executed Cargo feature build. A future implementation needs an explicitly reviewed binding correction/upstream release or separately owned binding to the real C header; do not silently edit Cargo registry source or add an unowned compatibility header.

**Observed:** `scripts/native_cache.py::KLU_OPTIONS` builds only `suitesparse_config;amd;btf;colamd;klu`, with CHOLMOD, CUDA and OpenMP disabled. A read-only admitted inventory found 44 `SuiteSparse_config.h` paths beneath managed `native/klu`, and zero files named `spqr.h`, `SuiteSparseQR_C.h`, `libspqr.a`, `libspqr.so`, `cholmod.h`, `libcholmod.a`, or `libcholmod.so` beneath managed `native/klu` and `native/solver`. This does not establish absence from every host location or versioned `.so.*` filename; it establishes that the inspected managed prefixes do not provide the required header/archive surface. No setup, service change or extension rebuild was performed.

The future native image must own SPQR+CHOLMOD, their configured ordering dependencies, SuiteSparse_config, the selected BLAS/LAPACK ABI, C++ runtime and applicable system libraries. Upstream `SPQR/CMakeLists.txt` links SPQR to CHOLMOD/config, BLAS/LAPACK and libm when needed. Use its generated CMake/pkg-config closure rather than assuming `-lspqr` suffices. Record header/library hashes, target/compiler, integer width and BLAS integer ABI; CHOLMOD long-index APIs do not imply ILP64 BLAS. Preserve the repository's existing selected BLAS policy and native-generation lifetime. The current KLU capability is not evidence of this enlarged ABI.

## Versioned evidence family proposed for operator decision

**Proposed:** Represent rank evidence as a discriminated, versioned family, e.g. `svd_scaled_v1` and `spqr_scaled_colnorm_v1`, with library/native versions and policy version carried as provenance. Never reinterpret the present `Evidence.cutoff` (absolute singular-value cutoff) as a QR pivot tolerance. Existing clients remain on the SVD variant until the operator approves changed semantics and the affected Rust/Python/persistence consumers migrate explicitly. Reject unsupported method versions; do not silently fall back while retaining the original tag.

The QR variant identifies the exact matrix role and identity: Root state Jacobian versus fitting observation/sensitivity matrix, physical trial point, semantic dependency revision, row/state/parameter identities and orders, guard/selector/provider context, and positive finite scale vectors. For Root retain `A_ij = Fx_ij * variable_scale_j / row_scale_i`; record this normalization version. A fitting matrix requires its own scale/role policy and cannot borrow Root rank. Numerical factors require bit-exact matrix values, scales and order; unchanged CSC pattern only licenses structural/storage reuse.

Use real-double general CSC, checked dimensions/index conversion, finite arithmetic, canonical sorted rows and explicit duplicate/zero policy. Candidate policy fixes `SPQR_ORDERING_COLAMD = 2` rather than build-sensitive DEFAULT/BEST; record requested ordering and returned permutation E (NULL means identity), and reject unsupported substitutions. Ordering and numerical rank are separate: sparse fill ordering is not singular-value ordering or a guarantee of strong rank revelation.

Candidate explicit tolerance: `tau = rho * max_j ||A[:,j]||_2`, with finite positive rho and overflow-safe norms. Record rho, the norm reference, actual tau and `cc.SPQR_tol_used`; reject nonfinite/unrepresentable scaling. Handle the zero matrix as rank zero. Equality is rejected: the source flags eligible residual pivot columns with norm `<= tau` as dead. Do not describe tau as a singular-value cutoff or copy the current SVD rho while claiming identical admission. Upstream default is `20*(m+n)*DBL_EPSILON*maxcolnorm(A)` in `spqr_tol.cpp`; a nearby older comment in `spqr_front.cpp` says `(m+1)`, so executable source wins. Do not select sentinel tolerances: `<=-2` selects default and `-2<tol<0` disables tolerance. Record estimated rank and dropped-entry norm (`SPQR_norm_E_fro`) separately from successful solves.

## Acceptance and withholding proposed

Full-rank Root response requires rank n under the declared QR policy, successful finite factors/solves and independent checks; a rank estimate alone admits nothing. Persist reconstruction defect `||A E - Q R||_F / max(||A||_F,safe_floor)` against a declared dimension/roundoff/drop-aware budget, and an orthogonality defect against a separate declared budget. Qualification fixtures compute full independent defects; production sparse checks must state whether they are exhaustive, bounded block checks, or sampled actions. Sampled orthogonality is not an exhaustive certificate. Never materialize a dense Q to claim sparse scale support. `SPQR_norm_E_fro` is useful drop diagnostics, not a replacement for independent reconstruction.

Retain independent original scaled response residual/backward error per RHS and physical back-mapping; physical residual budgets, inactive state bounds and admitted guard/selector neighborhood remain necessary. Independent perturbed-root comparisons exercise the actual response meaning. A retained LU factor and a QR evidence factor may coexist as different operations on the identical normalized matrix; QR evidence must check the solve actually returned. Factor success, reconstruction, orthogonality and a small solve residual do not prove SVD-equivalent rank or conditioning.

Withhold for native absence/version mismatch, rank deficiency, unsupported ordering, invalid input/scales/nonfinite intermediates, threshold instability, failed reconstruction/orthogonality/original residual, memory/work refusal, callback error or incomplete lifecycle. Near-cutoff qualification compares SVD and QR on exact dependencies, near dependencies, severe row/column scale changes, row/column permutations, rectangular fitting matrices and adversarial sparse fill. Report disagreements explicitly. A candidate conservative stability test repeats fixed-order rank at tau/k and k*tau (declared k>1) and withholds if estimates differ; this is an admission policy, not a proof of rank invariance. Final numerical budgets and stability policy remain an operator-approved method decision, not an invented acceptance threshold in this investigation.

## Entry points, ownership and bounded execution

`SuiteSparseQR_C` returns int64 rank or -1 and can return R,E,Householder H,HPinv,HTau without dense Q; `_i_C` is the int32 variant. `SuiteSparseQR_C_QR` returns explicit sparse Q,R,E for bounded qualification. The retained-factor path is `SuiteSparseQR_C_symbolic(ordering,allow_tol,A,cc)`, `_numeric(tol,A,QR,cc)`, `_qmult`, `_solve`, `_free`; enable tolerance in symbolic preparation. Native header declares the factorization payload opaque (`void *factors`); do not cast into C++ internals to obtain a rank. For explicit retained-factor rank diagnostics, qualify the documented `SPQR_istat[4]` statistic against rank-returning entrypoints (the pinned C demo uses it). Use `cholmod_l_start`, matching long-index allocation/free functions and `cholmod_l_finish` with the 64-bit route; never mix short/long allocations.

Every factor/common/workspace has one exclusive owner. Keep pinned input/output allocations alive for the documented call lifetime, handle every status/null result and free all outputs including permutations with matching native allocators. C entrypoints call C++ internals; an exception/ABI qualification remains necessary before a Rust boundary can claim containment. Do not install process-global SuiteSparse allocator hooks per request: `SuiteSparse_config_*_func_set` changes shared process configuration. `cc.memory_usage`, `memory_inuse` and `malloc_count` are diagnostics, not hard growth limits. Sparse input does not bound multifrontal fill, Householder storage or peak scratch; nnz guesses cannot replace admitted memory bounds. Until safe allocator/workspace bounds are established, retain bounded supported matrix scope and explicit memory withholding. A disposable native subprocess with finite memory/work admission is an investigation option, not a selected production architecture.

Record/control SPQR task and BLAS threading separately (`SPQR_nthreads=0` means auto in the pinned common header). Setting an SPQR field does not establish BLAS threading or compiled parallel-backend behavior. Optional probe runs through `scripts/pse-env --` with explicitly admitted resources and exact native image, never through implicit system fallback. Cancellation must wait for native call completion or terminate and prove drain of the disposable process/cgroup; a numeric PID/PGID, empty cache handle or dropped Rust wrapper is not drain proof. Transfer/reuse factors or reset scratch only after complete drain and owner reset.

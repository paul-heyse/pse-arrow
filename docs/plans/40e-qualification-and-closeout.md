# Plan 40e: Qualification and closeout

## Purpose and acceptance boundary

Establish that [Plan 40](40-simulation-performance-diagnostics.md)'s implemented observations, explanations, capture and affine correction compose in actual simulator journeys. This companion owns assembled acceptance and scope-end checks; it consumes focused package evidence rather than restarting every targeted check or promoting it into whole-product qualification. The coordinator owns F01–F06 disposition.

**Interface-checked baseline:** `a08f5fa09` plus the inspected working tree. **Proposed:** every future verification and package here. Plan authoring ran no fresh product qualification. Existing scientific qualification and other active plans' campaigns remain at their own owners. This is neither a comparative benchmark campaign nor a source/environment provenance exercise. Those proof targets have been eliminated permanently.

The target is useful causal insight under normal supported operation, not a numerical overhead threshold. Test actual work, interpretation, inspectability and cleanup. Preserve independent original-space assessment, numerical admission, force-validation, closed durable results, last-handle cancellation and actual native drain. Passive inspection must not introduce residual/property/derivative work or new scientific state transitions. Observation can consume time and affect elapsed limits or scheduling; do not demand bitwise equality or an identical solver trajectory where those effects are permitted.

## Revealing assembled journeys

### Early and nested operations

Inspect a preparation before a public run handle exists, after enough activity to exceed old prefix retention, and while an owner is deliberately occupied. Read current activity and an honest shortened/recent interval. Distinguish requested work from construction and reuse, show a consumed versus unconsumed value edit without a structure rebuild, and expose a structural edit's actual scope. The inspector must remain independent of the busy computation. Use small models/controlled producers where they settle the contract; a multiminute simulation is not necessary to demonstrate a recent-window data structure.

Join two waiters to one shared producer, cancel one, and establish that the other proceeds. Navigate nested callbacks/implicit work and parallel children without summing inclusive time twice. Retry/reset invalidates cross-generation deltas; missing work remains unknown; pool and process peak scopes remain distinct. Independently controlled observations challenge the explanation rather than generating expected results through the same explanation algorithm.

### Numerical meaning and contextual composition

Exercise adopted root/NLP, coefficient/conic/discrete and linear-factor projections through their distinct interfaces. Reveal attempted versus accepted state, restoration or rejected work, original versus scaled coordinates, unavailable versus unactivated statistics, factor/refactor/fallback and actual method-specific counts. Project library data at owner-safe checkpoints, including when terminal tasks have not yet stopped; tests must detect an unsafe getter path rather than merely parse a completed snapshot.

Select short context journeys for initialization/recycle retry, sensitivity/RHS or withheld premise, dynamics IC/rejected step/event/reset and forward/adjoint segments, study occurrence/frontier/skew, fitting derivative upgrade/profile failure, surrogate fidelity/original correction, shooting windows and horizon fallback/hold. Reuse existing targeted context controls when they already exercise the assembled interface; add integration only for a missing composition. A summary stating “solver iterations” across these contexts is insufficient. Required current/recent navigation applies across them; detailed optional fields may legitimately remain unsupported with a reason.

### Placements, loss and outcomes

Use Rust and installed generated Python contracts through actual local and managed/native-child boundaries. Inspect from another caller while the originating caller/worker is busy. Distinguish the caller's preparation from remote execution and correlate the actual worker/process instance without changing scientific IDs. Regenerate stubs/contracts from the authoritative declarations and exercise the loaded extension that contains the new API. This checks actual interface bytes and behavior, not compiler/launcher/installer phase proof.

Saturate bounded detail, opt out, inspect a stale or partial interval, fail an optional writer and interrupt an operation. Keep scientific, publication, diagnostic and native join outcomes separate. Test a process-death prefix only where it settles recovery semantics; it cannot prove that unflushed history survived. Observation-reader drop and capture stop must not cancel unrelated scientific work or release owned native resources early. Preserve the canonical closed-result contract on publication/read failure and do not replay a write to obtain statistics.

### Useful deeper profile and export

Establish resolved, useful Rust/native frames or the selected equivalent profile against an owned representative operation, with target/thread identity, interval, sample/loss information and known symbol gaps. The review's P02 decoded timestamps but produced no useful frames; repeating only its exit-code success is not acceptance. If no sound useful route is found, return a concrete capability decision and leave F05 unresolved rather than silently narrowing the target.

Test the chosen timeline/export's open intervals, asynchronous/shared flows, live flush behavior, interruption and optional-writer failure. Allocation/native-heap/off-CPU wait detail needs functional controls only if selected in C1; unselected optional mechanisms need a recorded decision, not a new deployment obligation. Capture cleanup stops and joins only its owned resources. Expensive profiling stays optional and cannot be required just to inspect normal current/recent facts.

### Affine locality and the historical slow case

Consume D4's independent small mathematical controls: nonlinear contribution cancellation in the original aggregate, aliases/permutations/scales/offsets, constant/zero/guarded rows, fixed-value invalidation, free-iterate reuse, incomplete support, exhausted allowance, cancellation and already-proved mixed demands. Confirm selected-row examined scope and substitution work do not grow with unrelated global coordinates. Identify necessary one-time setup separately from repeated row work. Preserve whole-program class evidence as a separate demand.

Only if a question remains decision-relevant, observe one current 32-block operation after live diagnostics are usable. A single observation can reveal where work occurs and whether construction/proof repeats; it is not a comparative performance estimate or historical-cause proof. Do not reinstate repeated cold sampling, hard latency thresholds or the former campaign. Record what actual evidence supports and leave the historical cause unestablished if it remains so.

## Verification, documentation and closure

**Proposed:** use existing scope-aware command routes through `scripts/pse-env`, selected touched-package tests and native features as required. Pure semantics stay pure; actual Arrow-consuming correctness closures require force-validation. During implementation, compile touched packages and run targeted tests. After combined functional completion, use relevant integration/component/solver/Python journeys and `just hygiene`; run `just governance`, `just docs` and relevant native/powerset lints according to the repository's qualification guide. Generator changes require `just codegen` in their implementation and `codegen-check` at scope end. Select actual filters/recipes when the implemented surfaces are known rather than inventing executable commands here. Root runs `just turn-end` when finishing a turn that changed files.

**Proposed:** final evidence labels distinguish Implemented, Tested and Measured, and name commands, conditions, scope and zero-failure baseline. Adapter projection, targeted context behavior, assembled diagnostics and scientific product qualification are different claims. Record optional omissions and actual required failures plainly. Investigations are complete when they settle the choice and the selected capability is delivered; a plan to investigate again cannot close the required target. No new statistical performance or capacity gate is introduced.

Enduring documentation should describe operation navigation, observation/clock/coverage meanings, safe native producer rules, default light collection, explicit opt-out and deep capture, causal interpretation limits and the scientific/result permission boundary. User-facing commands explain actual interpretation and operation, without exposing implementation bookkeeping unnecessarily. Install the changed observability contract at its authoritative owner under G0 and amend further enduring contracts only through the applicable design route. Accepted ADRs remain immutable.

Close only after required functional scope, selected decisions, meaningful assembled acceptance, consumer deletion and documentation transfer are complete. Respect current retention/dependency preflight; the highest numbered coordinator remains until a newer one exists. Repair inbound links before eligible plan/review/evidence retirement. Do not update another active plan's disposition or declare its campaign complete merely because this series supplied diagnostic capabilities.

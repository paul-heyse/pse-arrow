# Plan 44e: Short-run investigation and optimization rounds

## Purpose and campaign boundary

This is executable investigation and optimization scope, not merely the final validation of known findings. It covers the initial rounds of short testing needed to expose and action additional pipeline inefficiencies. [Plan44](44-pipeline-performance-optimization.md) owns finding/discovery disposition and the combined completion boundary. This document owns case questions/coverage, campaign progress and the analysis/retest loop. **Proposed:** every run and benefit claim below; historical review observations remain historical.

Use the [review's compact cases](../design_review/evidence/pipeline-performance-optimization-2026-10-17/case-notes.md) as anchors, preserving their independent assertions and explicit limitations. Do not replay all old Plan39/43 campaigns, inherit long fixtures by name, or mistake source-only inspection for a newly measured route. Broaden the review's unexamined contexts through compact representatives rather than narrowing the scope to the nine findings.

## E01 — Case specifications and decisive observations

Use existing case declarations, scientific fixture/test owners and runner/diagnostic routes. For every required cell below, specify: the physical/algorithmic question; smallest representative model and configured backend/products; cold/reuse/start role; independent original assertions; selected facts and their populations; expected discriminating comparison; actual outcome and coverage limits. Keep this information with the case's native owner and reference it here; no parallel schema registry, provenance manifest or bespoke benchmarking platform.

Initial scale ladders use 4/8 eligible algebraic or implicit unknowns, zero/four added fixed inputs, 5/25 outputs, four study points and one/two workers or shooting windows where the question fits. Rank refusal uses the existing declared 12-parameter control, not an inadmissibly smaller substitute. These are starting fixtures, not production limits. Add a short intermediate size only when counts/source leave the causal distinction unresolved. Use actual reference property/unit composition where that is the mechanism, not only scalar surrogates.

### Observation protocol

Use ordinary correctness settings with explicit Arrow force-validation and the pinned toolchain/extension. Refresh only the necessary fast editable development build when source changes; no full release wheel. Physical horizon and wall duration are different. Do not tighten practical engineering accuracies or silently reinterpret rank thresholds as solve tolerances.

First collect existing invocation/attempt facts, prepared/evaluator work, native setup/evaluation/step/search counters, integration purposes, original checks, queue/wait/resource and result endpoints. Select complete detailed families before work only where sequence/order is decision-relevant; retain actual loss/availability. Use current/recent observations during an active short case to distinguish current phase, convergence, repeated setup, callback work and waiting. Inclusive stages overlap; do not sum them as exclusive total cost or infer wait from wall-minus-thread-CPU.

CPU/stack, allocation or timeline capture is selected for a concrete unexplained owner/phase. Establish its clock/process/operation scope and partiality before attributing cost. Use existing perf/Samply, trace or allocation capabilities where fitting; unavailable/partial tools stay explicit. A clone frame alone does not justify a representation redesign. A phase-aligned source/call-count control may settle the question more cheaply.

Target seconds per case. Around 60 seconds, request cooperative stop through an actual available handle/owner, inspect progress and choose a smaller faithful case or address an obvious cause. This is an observation policy, not a hard timeout, global runtime cap or permission to kill native work. Await real joins/cleanup; synchronous APIs lacking a timer-cancellable handle retain that limitation. Build/service startup is accounted separately and must not be confused with a ten-minute simulation. Larger runs require a named question that no short representative settles and belong to the later review.

## E02 — Breadth pass with immediate cause triage

Begin once the relevant A01/A02 recording slice and E01 specifications are available. Run the shortest affirmative representatives and negative controls across all C families, including gaps left by the source review. Do not finish the entire breadth pass before correcting an already clear cause that makes a cell disproportionately slow.

For each material observation separate three questions: how much work was demanded; whether the algorithm made useful progress at standard accuracy; and the unit cost/wait/lifetime of that work. Relate an anomaly to actual source/owner behavior. Differentiate necessary nonlinear rejection, legitimate adjoint replay or original checking from duplicate preparation, unused directions, repeated conversions or missing observation coverage.

One complete observation normally settles an obvious count/ordering distinction. Repeat only where scheduling, pressure or timing ambiguity could change a decision. Report failed/refused/cancelled cases and cleanup separately; do not average them into accepted latency or stop after only the fastest family works.

## E03 — Targeted mechanism ladders

For the suspected cause, hold scientific meaning/start/accuracy constant while changing one relevant axis: support/dimension, fixed versus consumed parameters, requested outputs/products, trial acceptance, derivative cost, study width/skew/retention, cache pressure or transport. Use exact source/library contracts to interpret counts. Eligible controls and independently specified analytic/property checks prevent the same transformation from certifying itself.

Settle the B/C/D investigation branches with their discriminating cases, including a legitimate adverse case for every conditional optimization. Short stiffness and expensive-provider cases belong here even when small smooth fixtures already pass. They reveal algorithmic effectiveness that a large sample count of easy roots cannot establish. Profile only the unexplained part after work counts identify its owner.

## E04 — Implement, integrate and retest discoveries

Action supported improvements from F01–F09 and O01–O06 through their assigned owners. New material causes receive N identifiers in the coordinator's single disposition table, a concise cause/consequence/correction/preservation explanation and a concrete work package at the appropriate companion. This is part of the campaign; do not dump every new finding into the later long-run review.

Corrections within existing contracts can proceed with targeted tests. New architectural/boundary choices receive the required focused advice/review and concrete rule decision before dependent implementation. If short evidence supports no change, disprove/reject the premise explicitly. If a confirmed issue cannot be settled here, identify exactly why, the retained consequence and the required different experiment/decision; do not mark a defect resolved merely because its investigation was completed. Do not defer a clear scope-owned fix solely because it was absent from the original nine findings.

Integrate producers and actual Rust/Python/CLI/storage consumers as appropriate; delete replaced mechanisms/callers/tests/fixtures as soon as replacement controls pass. Rerun the affected matched anchor and a revealing boundary/failure control. Distinguish avoided work from elapsed benefit; a larger logical pool, fewer callbacks or smaller memory estimate does not itself establish speedup. Changes must improve the composed pipeline without duplicating caches, weakening original checks or transferring library-owned iteration to the host.

## E05 — Integrated short resweep and saturation

After selected functional changes, rerun the required matrix on the integrated tree, reusing unaffected trustworthy observations only with an explicit scope explanation. Examine whether removing one bottleneck exposes another; return to E03/E04 for newly visible material causes. No fixed round count substitutes for this check, and no repeated timing campaign is required where source/work counts already settle the cause.

Completion requires coverage of each required supported cell, settled short-test questions, addressed material opportunities and no remaining cheap discriminating observation that would change the target. It is not an assertion that all possible workloads/backends are globally optimized. Record any unsupported/unavailable route and its consequence separately. A supported required case with unproved science or failed enclosing cleanup remains unfinished unless the operator explicitly changes scope.

# Plan 43e: Diagnostic analysis, artifacts and profiling

## Purpose and foundations

This companion consumes trustworthy producer facts to deliver evidence-linked explanation, source attribution, selected numerical analysis, immutable views and question-driven profiling. It owns E-package progress and Q05/Q07 decisions; [Plan43](43-solver-diagnostics-and-performance.md) owns combined dispositions and the accepted RC01–RC11 recommendations. Product work remains **Proposed**.

**Interface-checked:** current Rust-owned inspection statements/evidence references, Python/CLI projections, capture/session outputs, source/transform maps and existing artifact/data boundaries. Passive reads, caller-owned tracing, explicit availability/loss and exact owned capture cleanup are useful foundations. They should not acquire scientific evaluation, a second scheduler/charge ledger or mandatory canonical-store writes.

The target explains which work occurred, where it belongs, what it achieved, and which observation would distinguish remaining hypotheses. It does not turn a sampled hot stack, tiny step or unchanged endpoint into a causal numerical diagnosis by assertion.

## Target packages

<a id="e01"></a>

### E01 — Pure explanations and analytical policies

Extend the Rust-owned interpretation operation over immutable snapshots/coherent records. Python/CLI render that same meaning. Support current activity/freshness and recent changes, more work versus higher cost per unit, displaced preparation/inner/postsolve work, failed/retried strategy, contention/opaque intervals and outcome differences. Explanations reference actual producer/attempt/event/metric/time/generation and coverage, with a discriminating next observation where useful.

Existing limitation/activity explanations can migrate before A03. Iteration classifiers require A02 coherent records and only the sufficient history needed by that pattern. Per-invocation comparisons consume A04. Do not impose the complete profiler stack as an interpretation prerequisite.

Retain R2's restoration origin, inertia-fraction, tiny-step, μ/primal-stall, repeated worst-row and recycle-ratio questions. Its examples—30% inertia corrections, three tiny steps, ten/twenty stagnant repetitions and ratio 0.9—are candidate analytical policies, not selected universal thresholds. Make policy/name/version and phase/norm/sequence/coverage preconditions explicit when used. Coalesced equal endpoints cannot establish continuous stagnation; accelerated raw-map samples do not prove a contraction constant. An opaque interval alone does not establish wait/hang.

Distinguish observed facts, hypotheses, limitations and selected experimental conclusions. Interpret native progress separately from original qualification/response readiness. Classifiers do not change routes, retries, stopping or scientific permission. New analysis-policy tests use controlled records with independently specified expected statements, not a replay of the same flawed interpretation.

<a id="e02"></a>

### E02 — Original source attribution through transformations

Consume prepared original/native row/column, occurrence/addend and transformation maps. Attribute residual/stationarity/bounds/domain observations, BTF blocks and shared/fused arithmetic to all relevant sources. Aggregated/eliminated/fixed coordinates, slacks, objective sign/scaling and dual recovery can need many-to-many mappings or an explicit pullback. Native stationarity is not automatically physical stationarity.

B02/B03/C02 and affected D products supply the actual mapping slices; E02 does not redefine them or wait for every numerical package. Preserve all contributing authored occurrences through shared CSE/fusion while charging shared execution once. Resolve names/locations outside hot loops where possible. Actual source IDs/ordinal mappings remain stable under formatting-only changes according to their current contract.

Migrate quality reports, selected diagnostics, live rows, detailed artifacts, result inspection and presentation together. Cheap top-one may use an already supplied native checkpoint; it must not silently re-evaluate original equations. Missing/invalid pullback stays unavailable with a cause. Source attribution is optional diagnostic interpretation, not a new qualification oracle.

Acceptance covers repeated addends, aliases, aggregation, eliminated/fixed variables, slacks, scale/sign and dual transforms, repeated occurrences and a truly unavailable mapping. Verify scientific coordinates independently of a round trip through the same recovery map.

<a id="e03"></a>

### E03 — Explicit numerical diagnostic operations

Settle Q05 by defining the actual requested product: eligible point, operator, physical/native scaling, selected rows/columns/block, residual accuracy and approximation meaning. Use the existing numerical diagnostic request/operation owner with original failure/attempt reference, explicit admission/clock/cancellation and own outcomes. Mathematical implementation remains with B/C fitting library owners.

Retain existing bounded dense matrix diagnostics where adequate. Compare PRIMME/ARPACK-ng or another established fitting partial-SVD/eigen route before bespoke Lanczos. Normal equations square conditioning; exact singularity complicates shift-invert, and an existing factor of J does not automatically fit shifted `JᵀJ`. Any reusable factor needs its actual operator/layout/scaling/state contract. Near-null direction output carries its residual/accuracy and original-coordinate lifting limits; it is not a global singularity, infeasibility or optimum certificate.

Top-k original residual/Jacobian/conditioning/near-null probes can do new science. Passive inspection never initiates them, including on failure. No eligible point, exhausted governing permission, incompatible route or missing library capability yields explicit unavailable/refused analysis. A probe failure retains the original failure; no partially completed diagnostic upgrades the scientific result. An optional separately admitted probe may have its own clock when lawful, but does not resume forbidden original work silently.

Completion is a qualified selected route, or a supported retained-dense/withheld branch after the actual requirement/library question is settled. No unconditional “on failure SVD” is scheduled. Acceptance uses independently constructed rank/near-rank operators, scaled/rectangular/singular cases, source recovery, insufficient budget, failed probe, cancellation and residual-based result qualification.

<a id="e04"></a>

### E04 — Immutable retained evidence and derived views

Export selected joined invocation/checkpoint/detail records, static census references and capture links through existing artifact/result owners. Raw evidence, derived tables and explanatory statements are separate immutable products, linked to the same actual operation/attempt/source. Ordinary live observation stays independent from store/artifact availability.

Provide Arrow/DataFusion views and reusable Perfetto Trace Processor analyses for preparation/evaluation/derivative/factor work, retries, waits, reuse, original qualification and requested analysis/publication. Verify actual version/output interchange rather than assume a native Arrow export exists. Use existing typed batch/parquet/object-store/query capabilities where fitting, preserving the one type universe and explicit schema/units/unknowns. No bespoke SQL parser or independently mutable second charge ledger.

Comparisons retain family eligibility, actual route/fallback, requested products, starts, cold/warm/retained allocations, diagnostic mode, failures and coverage. Configuration/commit/context facts identify interpretation, not an environment/provenance attestation. Counter resets/partial totals remain visible after joins. Server statement duration is not client time; shared process CPU/RSS is not exclusive operation cost.

Optional family-specific Dolan–Moré/shifted-geometric-mean/statistical views are analytical capabilities, not a mandatory benchmark campaign. Failures remain failures/unavailable, never fabricated finite performance. Incompatible endpoints/outputs cannot be ranked as one winner. A once-only complete observation with assertions can establish removed work without a comparative timing verdict.

Migrate benchmark/collector readers and documented Rust/Python selected artifact access. Artifact retention/protection/committed visibility and interruption follow their existing owner; don't make a diagnostic file sufficient scientific publication. Test missing/gapped/repeated records, failed attempts, independently withheld products and explicit export/capture failure.

<a id="e05"></a>

### E05 — Profiling capability selection and owned adapters

Settle Q07 for each concrete question using source/docs and a small feasibility observation where necessary. Extend existing capture ownership, exact process/thread identity, finite output/raw-prefix/symbol metadata and interruption. Raw samples remain available independently of a renderer. Short execution needs launch capture; later attachment cannot recover preparation samples. Long execution supports selected windows and source-linked current/recent records.

| Candidate | Decision scope and preservation |
| --- | --- |
| Perfetto/Trace Processor | Primary timeline/SQL route; scheduler tables require actual captured scheduler data; inspect loss separately |
| perf/Samply/Inferno | CPU/sample/raw/differential views with scopes, clocks, symbols/unwind, inheritance and overlap; no causal conclusion from flame graph alone |
| perf stat/perf-event2 | Selected counter groups and actual PMU/multiplexing/permissions; cache misses are not bandwidth proof |
| Heaptrack | First native/Rust allocation candidate; intercepted allocations differ from custom pools, mappings and stack; launch/attach coverage and overhead explicit |
| BCC/bpftrace/off-CPU/perf sched/c2c/branch | Selected wait/scheduler/false-sharing/branch question, exact kernel permission and attribution; not a permanent daemon stack |
| Gungraun/Valgrind/dhat | Isolated instructions/simulated cache/heap; instrumented populations are not hardware latency or universally noiseless counts |
| Coz | Optional virtual-speedup intervention at meaningful completion/progress; native scope, Python/child coverage and changed-path limitations explicit |
| Tracy | Only a justified optional view, with compatible protocol and caller-owned subscriber; no mandatory parallel event authority |
| Tokio Console | Dedicated async-scheduling question/build, not a numerical convergence monitor |
| SUNProfiler/Caliper | Exact activated native-build timing with scope/overhead; does not supply exact opaque factor counts automatically |
| AMD uProf/IBS | Verify this Ryzen/OS/kernel/event/roofline scope; do not transfer all EPYC features or infer bandwidth saturation |
| LLVM remarks/llvm-mca | Confirmed generated hot arithmetic region; not a whole-workflow optimizer |

PGO/BOLT and allocator/provider changes are F03–F05 explorations; E05 supplies their selected observation route. For each candidate record adopt existing capability, implement a selected owned adapter, supported no-adoption, or explicit unavailable with settling reason. Technical eligibility is preserved; no all-tools installation promise follows.

Selected host capability/build changes use the appropriate F route. `perf_event_paranoid=1` does not enable every raw/ftrace/CPU-wide observation; CAP_PERFMON and kernel-symbol access are different. Request the capability actually needed, not blanket system privilege. Frame-pointer versus DWARF/higher-frequency sampling needs native unwind/coverage/overhead evidence;99/499/999 Hz are not universal optimal defaults.

Preserve task/descendant overlap, concurrent operation/thread partiality, unknown sampling loss and process-wide resource scope. Wall minus one thread's CPU is not wait time. Capture failure/stop joins only its tools and files, without stopping science or reclaiming another owner's resource.

## Verification and checkpoint

**Proposed:** pure analysis tests require no store/native startup. Probe/capture tests own only their actual numerical/tool fixture; external tool absence is explicit where a selected capability is required. Generated document/API changes migrate their Rust/Python consumers. G02 checks active/terminal/postfailure end-to-end interpretation; G03 assesses evidence sufficiency and any claimed benefit separately from scientific validity.

The supporting checkpoint below records migrated inspection, timeline and finite record readers. Broader interpretation, probes, columnar products and profiler integration remain open; named tool alternatives retain conditional selection. Full source review scope and external recommendation routing remain at the coordinator; this companion is not a second findings ledger.

# Plan 53g: Qualification and publication

## Responsibility and evidence boundary

This companion owns assembled acceptance and enduring publication of the test architecture target. The [coordinator](53-test-architecture-target.md#package-state-and-execution-route) alone owns package/finding/inquiry progress. **Proposed:** qualify the composed contracts after functional work, keeping architectural fitness, scientific adequacy, implemented mechanisms and quantitative benefit separate. Plan authoring supplies no product test or benchmark evidence.

## Packages

### G01 — Qualify the assembled target at its real boundaries

Run targeted compile/unit tests during functional packages using the repository's explicit correctness force-validation routes. Do not rerun integrated suites or static bundles per document/package. Once all functional scope is implemented and replaced mechanisms deleted, select the relevant shared native graph, component/conformance/lifecycle, installed Python boundary, chosen parity and scientific/readback journeys, and the manual governance/docs/native/powerset checks plus `just hygiene` under the current execution policy. Reuse authenticated unchanged-input evidence only through the existing gate/combination owner, explicitly labelled reused; a failed/interrupted/missing combination blocks completeness. Do not revive retired automatic portable reconstruction/publication campaigns.

Use bounded interruption/interleaving controls at existing seams; no exhaustive fault campaign or mandatory fuzz/mutation/benchmark technique. Original detail, wrong-expectation/missing-closure controls, analytic primitive Hessians, clean recomputation, authentic native calls, installed extension, canonical close/reopen/downstream covariance, tamper refusal and retained-buffer ownership are preservation obligations. Keep scientific dimensions/reference state/sign, structural well-posedness, approximation/partiality, actual feasibility, derivative scaling and truthful solver statuses intact.

Select exact commands/filters when the real packages exist. Record command, mode, actual scope, zero failure baseline and result in the closing Verification/Outcome, with evidence labels. Targeted tests establish their selected boundary; they do not qualify whole product/platform/solver/formulation scope. Failures drive repairs in their owning package and the same coordinator, without a second backlog. No claim of measured speedup is required: source/consumer evidence can show repeated admission/build/read/payload work removed. A later numeric benefit claim requires an explicit measured baseline, workload and conditions.

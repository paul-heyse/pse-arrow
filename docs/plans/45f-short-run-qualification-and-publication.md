# Plan45f: Short-run qualification and publication

## Purpose and boundaries

This companion owns shared observation support, integrated short-case resweeps, final qualification and enduring publication. The [coordinator](45-pipeline-execution-optimization.md) owns finding/inquiry decisions; 45a–45e own the actual corrections and their discriminating investigations. F01 supplies an early useful slice; F03 is the scope-end assembled qualification, not a barrier before every experiment. All work is **Proposed** at authoring.

Reuse existing cases, `scripts/case_audit.py`, `scripts/audit_tools.py`, native diagnostic selection and public Rust/Python routes. The review's source/probe/evidence and Plan44's existing scientific fixtures are inputs. They are not permission to require another evidence platform, exhaustive Cartesian matrix, exact latency target, universal solver ranking, host capacity policy or environment/provenance attestation. Source-established unnecessary work can warrant removal without an elapsed benchmark.

## F01 — Shared observation and case setup

For each actual experiment, the companion records its physical/algorithmic question, unchanged versus changed dimensions, eligible route/demand, independent original assertions, decisive work facts, failure controls and outcome at its native owner. Link that definition rather than creating another schema registry or hand-maintained fixture inventory. Map existing Plan44 families to the new question; do not rerun every old cell as a prerequisite.

Before assertions can abort reporting, retain returned candidate/native/original-check observations, selected operation IDs and actual failure meaning. Paginate diagnostic catalogues and preserve operation/producer/generation identity, counter resets, loss and unavailable endpoints. Count issued/completed separately. A scientific refusal, failed original check and diagnostic collection failure remain different outcomes; telemetry cannot grant or revoke science.

Existing invocation/readiness, source/compiler/math products, native work/setup reasons, integration purposes, original qualification, pool/cache and canonical builder/statement observations come first. Add a narrow performing-owner field only where needed for a concrete decision: query-owner/call labels, encoded/decoded/checked bytes/blocks, preflight/join/export counts or candidate/retained populations. New fields use existing observation contracts and generators if applicable; inspection must not acquire the occupied scientific owner or rerun it. Targeted tests cover actual producer, partial/reset/loss and read-only behavior.

Use the pinned environment and correctness route with actual Arrow force-validation. A changed native Python surface uses the necessary **fast editable correctness build**, not a full wheel or release installation. Tests/experiments use ordinary case-owned accuracy, including the established 0.001 relative engineering policy where applicable; independent analytic/rank/derivative thresholds stay separate. No smaller numeric tolerance is a performance improvement.

**Observation policy:** aim for seconds of scientific execution and one complete initial observation per contrast. Around 60 seconds, inspect current/recent progress and request cooperative stop through a real available owner/handle; reduce to a faithful smaller case or fix an established cause. This is not a global runtime cap or permission to kill native work. Separate build/source/service startup, preparation, scientific execution, publication/readiness, test oracle and cleanup. Await actual owned drain; an unsupported timer-cancellation route remains a stated limit.

# Plan45f: Short-run qualification and publication

## Purpose and boundaries

This companion owns shared observation support, integrated short-case resweeps, final qualification and enduring publication. The [coordinator](45-pipeline-execution-optimization.md) owns finding/inquiry decisions; 45a–45e own the actual corrections and their discriminating investigations. F01 supplies an early useful slice; F03 is the scope-end assembled qualification, not a barrier before every experiment. All work is **Proposed** at authoring.

Reuse existing cases, `scripts/case_audit.py`, `scripts/audit_tools.py`, native diagnostic selection and public Rust/Python routes. The review's source/probe/evidence and Plan44's existing scientific fixtures are inputs. They are not permission to require another evidence platform, exhaustive Cartesian matrix, exact latency target, universal solver ranking, host capacity policy or environment/provenance attestation. Source-established unnecessary work can warrant removal without an elapsed benchmark.

## F01 — Shared observation and case setup

For each actual experiment, the companion records its physical/algorithmic question, unchanged versus changed dimensions, eligible route/demand, independent original assertions, decisive work facts, failure controls and outcome at its native owner. Link that definition rather than creating another schema registry or hand-maintained fixture inventory. Map existing Plan44 families to the new question; do not rerun every old cell as a prerequisite.

Before assertions can abort reporting, retain returned candidate/native/original-check observations, selected operation IDs and actual failure meaning. Paginate diagnostic catalogues and preserve operation/producer/generation identity, counter resets, loss and unavailable endpoints. Count issued/completed separately. A scientific refusal, failed original check and diagnostic collection failure remain different outcomes; telemetry cannot grant or revoke science.

Existing invocation/readiness, source/compiler/math products, native work/setup reasons, integration purposes, original qualification, pool/cache and canonical builder/statement observations come first. Add a narrow performing-owner field only where needed for a concrete decision: query-owner/call labels, encoded/decoded/checked bytes/blocks, preflight/join/export counts or candidate/retained populations. New fields use existing observation contracts and generators if applicable; inspection must not acquire the occupied scientific owner or rerun it. Targeted tests cover actual producer, partial/reset/loss and read-only behavior.

Use the pinned environment and correctness route with actual Arrow force-validation. A changed native Python surface uses the necessary **fast editable correctness build**, not a full wheel or release installation. Tests/experiments use ordinary case-owned accuracy, including the established 0.001 relative engineering policy where applicable; independent analytic/rank/derivative thresholds stay separate. No smaller numeric tolerance is a performance improvement.

**Observation policy:** aim for seconds of scientific execution and one complete initial observation per contrast. Around 60 seconds, inspect current/recent progress and request cooperative stop through a real available owner/handle; reduce to a faithful smaller case or fix an established cause. This is not a global runtime cap or permission to kill native work. Separate build/source/service startup, preparation, scientific execution, publication/readiness, test oracle and cleanup. Await actual owned drain; an unsupported timer-cancellation route remains a stated limit.

## F02 — Integrated mechanism rounds and supported follow-through

Companion investigations define the implementation choices. This package assembles cross-owner observations and reruns only the smallest revealing whole operation after changes, so individually adequate replacements do not multiply simultaneous buffers, grants, workspaces or retries. Source evidence and deterministic work counts can settle a removed pass; repeat timings when variation could change a choice. Keep cold/equal/current/historical/prepared/start roles distinct and do not use one complete source-to-read clock as an isolated-kernel baseline.

Vary causal dimensions independently where they decide the mechanism: physical states, output times, consumed derivative coordinates, parameter values, schedule, worker count, durability and retained population. Do not require their full Cartesian product. Nonzero coupled fixed inputs protect the distinction between unconsumed derivatives and omitted physical effects. Different backend step/setup counters may have different meanings.

Where CPU attribution remains decisive, select a short **phase-aligned, symbolized** client profile and, if relevant, the authenticated owned server. Preserve process/clock scope, alignment, loss and unfinished intervals. Compare ordinary diagnostics and selected detail on the same work only when observer interference changes the interpretation. Existing unsymbolicated partial captures are leads, not a reason to introduce a blanket tracing project. Do not infer waiting from wall minus thread CPU or exclusive cost from overlapping phase sums.

When an inquiry supports an improvement, its companion implements/migrates/tests that outcome inside the accepted decision boundary, then this package checks the actual composed operation. Retain supported current routes where an alternative does not qualify. Newly exposed in-bound material causes receive N identifiers and concrete owner packages in the coordinator; out-of-bound changes return as a precise proposal. An unresolved confirmed finding cannot disappear because a probe timed out or an alternative was rejected.

## F03 — Assembled acceptance and scope-end quality

Run after all selected functional implementation and required inquiry outcomes are integrated. Select complete journeys spanning the changed consumers: edit/re-solve and source import/replay; active/historical studies with retention pressure; optional compiled arithmetic; repeated sparse roots/native updates; transient fitting/shooting and forward/adjoint/dynamic boundaries; real property/implicit and recycle work; local and genuinely durable/managed result/artifact/analysis access. Include public Python streams/plans/live or recorded layouts when affected, and the actual product owners' cancellation/recovery/refusal cases. Reuse package evidence only within its conditions; a helper pass or current capability flag is not assembled behavior.

Use a compact affirmative eligible case for each changed supported mechanism, plus distinct failure/refusal controls. Preserve original physical/analytic/conservation/gradient/objective checks; compare exact transport/index/row identity where required. Show that replaced mechanisms/callers/tests/fixtures are removed after migrated targeted tests pass, without compatibility APIs or a second production path. A retained legitimate interpreter/full-reader/byte-import branch is not legacy merely because another consumer uses a different contract.

Run `just hygiene` once at functional scope end and repair failures against baseline zero, re-running failing recipes rather than the entire campaign without cause. Include complete continuing Clippy in default/no-default and linked-native scope, relevant supported powerset checks, native contract/data lints, governance and documentation/manual checks under repository routes. Run codegen as part of declaration/generator changes; final equivalence confirms generated drift rather than licensing hand edits. The exact command selection follows the then-current qualification guide and actual changed feature closures.

No product-wide quality, type or native campaign is required merely to author these documents. During product execution packages use touched-scope compile and targeted functional tests, not repeated hygiene/integration bundles. Formal ADR acceptance, focused tests, selected assembled acceptance and whole-product qualification remain separate claims. Record command/mode/scope, zero baseline and actual repaired failure boundaries at the Outcome, without per-command checkpoint diaries.

Service/resource tests use exact owned registered fixtures and normal quiesce/drain/stop/cleanup routes. Preserve other owners' data/evidence/work and warm reuse. The maintainer's existing bounded temporary cleanup authorization does not imply resetting a shared registry, deleting unknown resources or overriding a live safeguard. Test-body success with failed enclosing cleanup is not a pass.

## F04 — Enduring publication and explicit further-work handoff

Required ADR/design decisions and contract revisions occur before their dependent implementation in the originating package, not after qualification. F04 reconciles those architecture/diagnostic/operations owners with the actual implemented eligibility and final evidence, through accepted routes and the required blueprint revision. Proposed ADRs can be amended through that route; accepted records are immutable and require supersession. Publish only actual supported eligibility and evidence; do not claim adoption from a successful capability probe. No architecture/ADR edit occurs during this document-authoring task.

Update this series' package outcomes, finding/inquiry decisions and checkpoint. Each closed plan Outcome records what was built with evidence labels, an actual mistake corrected and deliberate deviations. The coordinator owns the combined boundary; companions link shared assembled results. Do not reconcile/supersede or retire older plans as an implicit part of this series. Retain review/evidence/plan material while findings or live readers depend on it; normal later retirement follows the document lifecycle, not an archive tree.

If longer or materially different testing remains necessary, identify: the observed mechanism and consequence; why the smallest faithful short/source/library analysis could not settle it; the required different shape/horizon/concurrency; prerequisites and diagnostics; deciding result; owner and observable trigger. Known unresolved F13 or other findings keep their true disposition. A supported bounded no-change result is reported separately from a required missing correction. The handoff informs a subsequent review/planning decision; it does not authorize a broad long-duration campaign or revive eliminated proof work.

# Plan 50g: Qualification and publication

## Responsibility and evidence boundary

Qualify the selected Plan50 capabilities as actual Codex/operator workflows after functional
delivery, then publish enduring meaning and reconcile scope. Package progress and opportunity/
inquiry dispositions remain at the [coordinator](50-codex-effectiveness-and-diagnostics.md).
**Proposed:** all implementation acceptance below. Plan authoring and documentation publication
do not establish product, host-tool, profiler or scientific qualification.

Per-package compile checks, targeted functional controls and required codegen belong with their
changes. Static/hygiene checks and relevant composed journeys run once at scope end, with failing
checks repaired and rerun as necessary. No repeated full campaign, mandatory benchmark or
qualification-driven rebuild of unchanged roles is added. Existing product contracts and explicit
force-validation remain in force.

## Packages

<a id="G01"></a>

### G01 — Reconcile actual consumers and inquiry outcomes

Before expensive execution, identify the delivered command/API/host-tool consumer for every
O01–O20 route and the exact prerequisite slices consumed from Plans32/40/49. Use current source,
command grammar and native test inventories; do not infer delivery from a document title,
configuration file or helper's existence. Consumer migrations/deletions are part of functional
packages, not work postponed until this check.

Resolve I01–I12 at their owners. Positive selection includes required integration and a real
consumer; no-adopt includes the reason and supported alternative or explicit unavailable scope.
An optional tool can be rejected without adding another one, but an unavailable response does
not alone satisfy a promised required workflow. Record any dependent rule decision before
claiming the target fixed. Select existing nextest/pytest filters and fixture/resource modes,
not a parallel exact-name acceptance manifest.

Keep ordinary, diagnostic and scientific/reference configuration distinct. Installed Python
extension identity, symbols and actual target/executor coverage must match the selected journey.
Do not silently rebuild/install an ordinary extension beneath a diagnostic run or reuse an old
report merely because its filename looks current.

<a id="G02"></a>

### G02 — Representative composed functional journeys

Use short, contract-directed fixtures and real consumers for the six review scenarios:

| Journey | Required composition | Revealing negative case / limit |
| --- | --- | --- |
| Fresh session and Rust/Python contract change | A/B selection and semantic queries; generator/facade/PyO3 consumers; targeted correctness run read through C03 | Failed activation, stale MCP state, incomplete Python index or mismatched installed extension remains explicit |
| Apparently idle native test | Actual build/admission stages, C02 waits and selected E scheduling/stack/task observation | No lock owner or wait cause inferred from quiet CPU; unavailable tracepoint/task dump remains unavailable |
| Readiness/query regression | D01 production query, schema/index/graph observations, D02 storage snapshot and D04 disposable alternative | Actual parameters preserved; shared metrics not private attribution; LSP grammar refusal cannot invalidate engine-valid SQL |
| Cancellation with retained state | C04 owned lifetime, C03 terminal/drain and C05 explicit disposition; useful MX/stack facts | Unknown external effects/reference or changed owner blocks release; no fabricated pass/ACK; normal resume intent explained |
| Edit causes preparation work | F01 semantic labeling and F02 mathematical/actual physical comparison; selected allocation route if needed | Unmapped Salsa event, repeated physical-node ambiguity and last-census freshness stay explicit |
| Frozen failure to executable case | C03/F03 supported extraction and new explicit execution with strict predicate | Missing provider/codec/executable premise refuses; related diagnostic is not automatically original failure reproduced |

The baseline is zero failures for the selected functional controls. Report actual command, mode,
selection, fixture/tool populations and outcome; a diagnostic failure, target failure and
scientific failure are different fields. The short pipeline cases must still exercise the real
owner boundaries and declared perturbation. No production-capacity repetition multiplier is
needed merely because the workstation has sixteen cores.

Use one actual mixed Python/Rust/native journey to establish useful captured frames and one
small scheduling/async/allocation control for the corresponding new meaning; reuse applicable
package evidence where its conditions still hold. Do not repeat a full native/physical/scientific
campaign to validate CLI rendering. Plan40e/49h retain their independent acceptance and may share
named evidence without being declared complete.

<a id="G03"></a>

### G03 — Scope-end static and manual checks

After all selected functional scope is implemented, run the relevant `just hygiene` bundle and
repair failures to zero. Select the actual required default/native/no-default Clippy, Python
Pyrefly/Ruff/import, codegen, feature/family and agent-configuration coverage from changed scope.
Use existing recipes and pinned tools; do not substitute global checkers. Run the manual
`just governance`, `just docs`, native contract/data and powerset lints where relevant, without
duplicating checks already established under the same actual conditions.

Parallelize independent ready checks on the workstation. Preserve the known artifact-lock
constraint between incompatible Clippy feature graphs; this is not a general rule to serialize
heavy commands. Fix failures structurally at their owner, never introduce baselines/ignores to
declare success. Source/generator changes require regeneration through `just codegen`, not hand
editing generated output. Documentation-only edits after qualification do not trigger another
product/static campaign.

The root runs `just turn-end` when ending a turn that changed files. It remains formatting/index
maintenance, not a commit or merge gate and not product qualification. Missing host permission
for an active diagnostic is an explicit prerequisite, not a silently skipped successful test.

<a id="G04"></a>

### G04 — Publish enduring operation and close the series truthfully

Move enduring command/environment/session mechanics to the environment guide, query/MX/module
operations to the substrate guide, capture/comparison/reproduction behavior to the diagnostic
guide and verification scope to the qualification guide. Update architectural contracts only
where changed, using the authorized decision/design route and blueprint revision row. Keep
accepted ADRs immutable and proposed decisions distinct from implemented behavior.

Reconcile the coordinator's package, opportunity and inquiry rows. Its final Outcome records
what was built/deleted, actual corrected mistakes, deliberate deviations and relevant evidence
labels/conditions. Preserve original failed/interrupted/not-run evidence where it still explains
a repair or limit; do not copy per-command rerun logs into the plan.

Keep quantitative benefit statements separate. No universal speed, memory, capacity or agent-
effectiveness gain is required or claimed from delivering the diagnostic workflows. A chosen
measurement names the actual baseline/workload and observed result, including capture overhead.
Plan closure does not close Plans32/40/49 or qualify unexercised science.

Update native lifecycle bindings/current-work selection as scope changes. Before retiring the
completed plan/review, carry surviving meaning/obligations to owners and repair actual inbound
consumers; Git is the archive. Do not retire the source review while it still supports selected
work, and do not create another status ledger or review obligation.

## Completion criteria and current state

Completion requires actual supported consumers for all selected O01–O20 scope; explicit I01–I12
outcomes; required replacement removal; representative composed acceptance and zero-target
scope-end checks; and enduring documented contracts with bounded final evidence. Optional
mechanisms are not required adoptions, but their selected investigation/disposition is required.

Current state is proposed/unexecuted. No functional test, profiler experiment or assembled
qualification ran because these documents were authored. Documentation checks performed during
authoring establish only document consistency/publication. Sources: the
[qualification guide](../dev/validation-assessment.md), [diagnostic guide](../dev/simulation-diagnostics.md),
[document lifecycle guide](../dev/documentation.md#metadata-and-aggregate-scope), AGENTS execution
rhythm and the coordinator's source/opportunity mapping.

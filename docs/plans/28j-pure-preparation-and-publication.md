# 28j: Pure preparation and explicit publication

## Responsibility, decisions and baseline

This companion develops the pure/effect boundary, complete reusable preparation and owned
portable description contracts for PA02/PA03. [Plan 28](28-surrealdb-unified-substrate.md)
owns finding dispositions, accepted decisions and combined readiness. [28i](28i-runtime-validity-and-interruption.md)
supplies receiving-runtime premises and interruption where needed; pure same-process
preparation does not wait for an arbitrary-host replay guarantee.

[28a](28a-canonical-substrate-and-revisions.md) owns guarded canonical admission,
reachability, staging and recovery. [28b](28b-selected-compilation-and-reuse.md) owns selected
dependency eligibility, persisted discovery/reconstruction and fresh source binding.
[28c](28c-durable-execution-and-studies.md) and [28f](28f-shared-numerical-preparation.md)
own actual workflow/numerical consumer migration; [28e](28e-rebuild-retirement-and-qualification.md)
owns assembled acceptance and U02 evidence. This document owns J packages; existing companions
own their separate integration packages rather than duplicating J status.

The maintainer accepted RC02/RC03 on **2026-10-08**, together with RC01/RC04. The
[coordinator's decision record](28-surrealdb-unified-substrate.md#preparation-rule-decisions-2026-10-08)
owns the outcome and authority-change route. The target below is **Proposed**, not implemented.
The source baseline is dirty `main` at `2410880efc5ab20e623006fde78e624044d3358d`; source and
frozen assessment artifacts differ as recorded in the review's supporting evidence.

Current source already retains immutable checked selections, mathematical bodies, solver
views and artifacts through bounded owners. Value rebind, current attribution and private
numerical state are useful foundations. However, `canonical_workspace` creates a fresh
compiler before view lookup. A tracked `semantic_body` invokes `CanonicalBodyRetention`,
which observes the runtime and performs synchronous canonical publication even on a memory
hit. Portable/dependency encoding and blob construction precede exact acknowledgment lookup.
The repeated work is established by source; neither duplicate persisted rows nor wrong
mathematical results were demonstrated.

## Foundation assessment and selected direction

Prefer a complete immutable prepared basis using existing retention, flights and allocation
owners, with fresh current-consumer attribution and numerical bindings. This follows the
existing view/rebind pattern without automatically retaining a globally mutable compiler.
First make canonical acquisition and publication independent of whether a pure query runs.

Do not cache current `PreparedModeling` or `ModelingPreparation` wholesale under a structural
key. The former contains instantiated members, demand chains, values and original closure
terms; the latter also carries `Solved` lineage and consumed-source metadata. J0 establishes
which immutable subset is substitutable and which fresh wrapper binds its current use.
Returned products must continue to own their allocations independently of workspace rotation.

| Alternative | Fit and selection/revisit condition |
|---|---|
| Complete immutable basis plus fresh consuming wrapper | Default direction. Removes pre-view specialization/projection on compatible uses while preserving current meaning. J0 must establish complete dependencies and attribution construction. |
| Bounded single-writer Salsa accelerator | Eligible when useful pure work cannot yet escape as a complete product or retained product lookup still repeats it. Select only for a named gap; no globally locked database or duplicate authority over equivalent products. |
| Pure Salsa persistence | Optional bounded library investigation when serializable pure state supplies a concrete restart capability not already supplied by canonical descriptions. Current feature selection does not enable it; qualify exact locked APIs, transitive inputs, accumulation/GC behavior and storage limits before selection. Never persist native handles or publication permission. |
| Fresh scientific preparation | Correct baseline/fallback for changed or unowned premises; may be simpler for small or opaque requests. It is not sufficient as the sole route for unchanged supported studies/restarts. |

Salsa, Symbolica/Numerica evaluator construction, existing DataFusion retention and native
solver lifetimes remain eligible foundations. Preserve library-owned grouped/demanded
construction and private evaluator/factor state; faster hashing or another generic cache is
not a substitute for changing the repeated obligations. Use pinned capability material and
Context7/current primary documentation when a consequential library contract needs research.
The review's capability leads do not qualify a new exact-release API automatically.

## Complete operation and internal contracts

The runtime composition owner performs effects explicitly around pure preparation. These
responsibilities can be ordinary operations in existing modules; they do not require five
new services, a parallel schema or public Python API changes.

| Operation | Consumed context | Product/effect |
|---|---|---|
| Resolve/admit current selection | Current roots, demand, interpretation, original stop/clock | Checked immutable semantic inputs plus actual source protection; positive, absent and membership dependencies remain explicit. |
| Acquire receiving products | Current selection/dependencies and 28i's actual receiving eligibility where required | Qualified exact canonical descriptions reconstructed outside tracked queries; owned admitted mathematics can populate pure retention. |
| Obtain pure prepared basis | Complete checked semantic inputs, structural bindings/demand, physical/provider/formulation/profile and admission inputs | Immutable specialization/projection/body/layout products and complete description requirements; no ambient host observation, store call or publication. |
| Bind current consumer | Basis plus current revision/instance/occurrence/spans and numerical values/status/bounds | Fresh attributed wrapper and demanded view; rebuild only facts that consume changed inputs, retain original physical assessment. |
| Encode immutable descriptions | Compiler-issued recipes plus encoding/interpretation identity | Owned reusable payload/envelope/descriptor material; not producer eligibility, source protection or acknowledgment. |
| Publish or settle | Reusable material, exact current dependencies, actual eligible producer and operation controls | Exact committed rooted descriptions or typed failure; this effect runs on pure hits as well as misses. |

Keep protection live through new publication and release it through the existing settlement
path. Receiving lookup/reconstruction and publication cannot remain hidden inside tracked
body callbacks. A prepared basis must expose every required description independently of
whether a memo ran: bodies, implicit systems and original/supplier products cannot disappear
from publication merely because their pure queries hit. Retention lookup/accounting continues
to preserve compiler-issued witnesses, complete body meaning and retryable transient refusal.

Ordinary numerical values, current source attribution and publication authority must not
pollute stable mathematical identity. Values actually consumed as structural literals do
participate. J0 decides the precise subset rather than excluding all values by assertion.
Fixed/free, bounds, selected modes, derivative/output demand and order, provider/context,
absence/membership, admitted quantity meanings and formulation/profile changes remain
consequential where consumed. Do not retain a `SelectedRead`, attempt fence, cancellation
token or mutable evaluator in a cross-operation basis.

## Canonical descriptions and exact settlement

Reuse immutable recipe/envelope bytes under their complete semantic and encoding identity.
Share dependency bytes and blob descriptors only when their complete contents coincide.
Selection-bound request assembly, dependency qualification, producer admission and canonical
effect settlement remain current operations. Cached bytes never establish permission.

Preserve `product_acknowledged`'s existing exact rooted reuse: matching problem, request,
payload, dependencies, producer and interpretation may settle an earlier rooted product
without a new proposed key/revision. The current consumer keeps fresh attribution; it does
not rename the stored product or demand another row/root solely because a revision differs.
That settlement can recover an exact committed acknowledgment after protection expiry
without admitting anything new. New admission after expiry still refuses. A released root,
changed exact dependencies, corruption or another store cannot be accepted from a remembered
in-memory published flag.

28a/A5 determines whether descriptor-first or grouped canonical admission removes repeated
encoding/transfer while preserving the current transaction, conflict and recovery units.
Group independent publication only where the actual atomicity promise permits; do not make
one long preparation transaction, reintroduce complete per-body copies, or infer visibility
from successful transport. A changed identity/metadata/commit contract follows the decision
route before implementation; unchanged frames are not silently reinterpreted.

## J0 — Complete basis and effect design

Settle four concrete questions before dependent reuse:

1. Which specialization/projection inputs consume values structurally, including modes,
   fixed/free state, data documents and demanded original/supplier views? Establish a complete
   basis key and the fresh binding contract. A conservative exact-request basis is legitimate
   initially, but ordinary value sweeps require an explicit route that avoids rebuilding it.
2. How does a basis expose all required portable descriptions on a memo hit? Trace the
   actual body/implicit/original products; do not invent an exhaustive symbol inventory.
3. How is current revision, instance, span and occurrence attribution rebuilt without full
   specialization or borrowing old scientific permissions? Distinguish equivalent mathematics
   from equivalent lineage and visible scientific results.
4. Which encoded representations already have allocation owners, and what material does
   canonical admission require before exact acknowledgment can settle? Establish reusable
   bytes/descriptor boundaries and safe transfer of charges without duplicating caches.

Use the existing compiler/workspace, runtime `math/{modeling,retention,portable,products}`,
workflow modeling/view/binding entry points and canonical selection/ack operations. Inspect
decisive source and smallest revealing scenarios. Use focused library/design advice or a
probe only where it changes the choice. If a premise remains open, name its settling evidence
and block that dependent reuse package; do not mark the whole review disproved or implemented.

J0 completes with selected pure/effect boundaries, complete basis identity, fresh attribution,
full description discovery and canonical integration inputs. Document a chosen alternative
and its observable revisit trigger. A type name or a solver-view hit counter is insufficient.

## Graph/hash extension — J3 indexed description settlement

This **Proposed** extension addresses [Graph/hash F01](../design_review/reviews/design_review_graph-compilation-kernels-and-hashing_2026-10-09.md#f01).
The [coordinator](28-surrealdb-unified-substrate.md#graph-and-hashing-review-integration)
owns its disposition. The earlier baseline above describes the original preparation
correction; current J1/J2/B7 complete-basis reuse is implemented. This extension removes
residual identity discovery on that working path, rather than rebuilding its architecture.

### Foundation assessment and target

At `d0f2c41818a34539a910654dfea4760771603f45` plus the preserved working tree,
`settle_preparation` iterates portable bodies and linearly searches `PreparedBasis.descriptions`
for each identity. `PreparedModeling::portable_bodies` constructs a new ordered map over
primary and original body inventories each time. Exact basis reuse, immutable descriptions,
current `matches_read` and actual-store acknowledgment are suitable foundations. Under AP-07,
the repeated immutable discovery should be removed without weakening those current effects.

Retain a canonical, identity-ordered portable inventory once per immutable prepared view,
including its primary and original products. Preserve the existing sealed-body identity and
deduplication meaning; direct implicit bodies still have no invented portable identity.
Derived original views must expose their own required inventory rather than reuse a parent's
inventory indiscriminately. The compiler product supplies this view; J3 owns its integration
with the runtime basis and description settlement. It does not wait for B8 supplier adjacency.

Keep retained descriptions in canonical identity order and resolve matches by ordered lookup
or a linear merge over the two inventories. Prefer this over adding a hash dependency or a
second cache. An empty/partial description inventory remains valid: unmatched bodies follow
the existing qualified publication path. Equivalent identities retain the existing exact
read/encoding interpretation, not a new fingerprint-only equality contract.

The resulting operation consumes the retained inventory/descriptions and the current read,
then produces the exact settled descriptions or the existing typed failure. Matching reads,
rooted acknowledgment, producer qualification when needed, expiry, cancellation and original
deadline still apply on every use. An acknowledgment error cannot become absence. Shared
bytes never retain permission, current source lineage or a publication flag.

Reserve inventory/index construction through existing allocation owners before allocation,
include their retained storage in product/basis accounting, and keep charges alive through
escaping views, eviction and drain. Avoid independently charging shared mathematical payloads.
There is no schema, persisted frame or Python API change.

## Outcome

### What was built

**Implemented:** J0 settled complete exact basis identity and fresh attribution. J1 separates
pure frontier/body/preparation computation from each current consumer's asynchronous
acquisition and publication. J2 retains complete immutable preparation and encoded
descriptions in the existing bounded cache, with generation fences, escaping leases and
completion-owned pure flights. A5/B7/C8/N11 and receiving-root consumers use this path;
the canonical compiler workspace and effectful retention callbacks are removed.
Numerical values and mutable workers retain their own downstream owners. Exact actual-store
rooted acknowledgment precedes new material processing; guarded same-revision qualification
receipts never confer permission after pin expiry or replace current publication settlement.

**Tested:** pure frontier/reuse, complete-key and current-source controls, actual-store
acknowledgment/expiry, sixteen protected readers, revision-receipt admission and affected
conformance, fitting/mode and initialization controls are recorded with commands and
zero-baseline results in [28e's correction outcome](28e-rebuild-retirement-and-qualification.md#outcome-recorded-after-implementation).
That owner records the rebuilt scientific journeys and repaired composite qualification;
focused controls do not imply unexecuted whole-plan qualification or measured benefit.

### A mistake made and corrected

The first integrated continuation exposed redundant requalification of already established
premises and unpaced same-process protected transactions. Guarded identical-revision receipt
adoption and short per-problem transaction pacing correct those paths while preserving
changed-row qualification and additional acquisition dependencies. Subsequent investigation
identified duplicate cold inventory hydration before the pure admission flight and repeated
whole-study paging during nonterminal polling. Cold qualification retains private current
reads under a bounded exact-request/revision turn; completion polling reads only the header
until the existing terminal result checks apply. No transport error is treated as success
or authorization to replay an uncertain operation.

### Deviations from the plan, deliberate

Complete exact basis retention proved sufficient for the supported composition. No persistent
or global Salsa accelerator, generic second cache, shared mutable scientific state or
new permanent instrumentation framework was introduced. Existing instance identity remains
consequential; fresh spans/source wrappers and case values bind separately. The maintainer's
failure-only qualification boundary retains historical measurements and defers unrelated
Plan 28 measurements/assessment. Solver stopping remains unchanged; historical final-result
comparisons use the authorized ±10% relative allowance.

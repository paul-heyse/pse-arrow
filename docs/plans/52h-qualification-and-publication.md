# Plan 52h: Qualification and publication

## Completion meaning and rhythm

**Proposed:** close the selected Plan52 capabilities through actual consumers, honest inquiry
outcomes, scope-end checks and enduring publication. The
[coordinator](52-agent-effectiveness-and-engineering-workflows.md) is the sole package/opportunity/
inquiry status owner. Authoring and document checks establish none of the production delivery.

Required capabilities cannot disappear behind a tool non-adoption. A conditional candidate may
close with its supported alternative, reason and observable revisit condition; positive adoption
requires real integration before closure. I03 has lexical and semantic decisions; I06 has native
and modeled branches. Preserve those separate conclusions. No unresolved support claim becomes
implemented because an adapter/configuration file exists.

During implementation, compile affected code and run targeted unit tests, with force-validation
for every actual Arrow-consuming correctness closure. Generate changed declarations as part of
the change. Remove replaced code/callers/tests/fixtures when the replacement is proven and its
consumers migrate. Keep regular coherent commits. Do not run broad static/integration checks per
package or after documentation-only updates. No command is a commit/merge gate.

## Assembled consumer journeys

Select the smallest real populations exposing each distinction. These are behavior scopes,
not production lane/parameter counts or a full Cartesian product of tools/configurations.

| Journey | Required distinction and actual consumer |
|---|---|
| Resume and change a contract | Fresh Codex context identifies current owner/dirty delta, traverses multiple actual generation chains, previews a supported edit, rejects stale/partial edits, regenerates and runs targeted checks. |
| Retrieve a rationale | Source-fresh lexical query distinguishes current/historical material, reflects dirty/deleted sources, finds a pre-window active session and related worktree, and preserves historical attribution. |
| Design/library investigation | Exact-version packet identifies patched API/semantic unknown; compare two real design arrangements and follow declared versus uncertain consequences. |
| Challenge correctness | Analytic covariance/coordinate or preparation sequence catches plausible wrong behavior; selected mutation/fault, coverage omission and reduced regression retain their actual roles. |
| Explain numerical failure | Legal-step derivative/value workbench exposes an intentional discrepancy; authored-domain reduction preserves the selected issue and rejects a different smaller failure. |
| Observe and resume work | Exact run watch reconnects with truthful gaps, cancellation leaves work running, result/drain remain distinct, feature campaign resumes unchanged combinations and invalidates after a repair. |
| Research/evidence workbench | Supplied-source comparison preserves failure→pass, missing/renamed/unmatched populations; derived knowledge links a question to actual evidence and rebuilds without changing native facts. |
| Selected experiment | Pure historical replay has distinct producer attribution; deterministic bisect includes untestable revisions; noisy/incompatible measurements stay inconclusive; owned disposal leaves unrelated state intact. |
| Database/tool isolation | Two deterministic representative fixtures have fresh credentials and read-back settlement; interrupted setup/cleanup remains truthful; any selected sandbox proves its narrow environment scope. |
| Diagnosis | Host pressure/placement facts retain identities/intervals; finite trace capture shows supported continuity and explicit missing links with independent workload/restoration/cleanup outcomes. |
| Agent/operator integration | Describe→command→watch→read→compare→closeout works with bounded structured results, an environment failure and unrelated dirty edits. Optional transport/model/UI is exercised only if adopted. |

Actual Rust/Python/public CLI paths matter where delivered behavior crosses them. A host-only
composition does not need native solver compilation; a claim about native callback lifetime or
public scientific reduction needs its actual linked consumer. Miri/fuzz/sanitizer/Loom each retain
their instrumentation/observation bounds. Full solver-fleet qualification is not implied.

## Work packages

<a id="H01"></a>
### H01 — Reconcile actual scope, consumers and inquiry outcomes

Inspect delivered producers/consumers against 52a–g, source O01–O30 and accepted RC01–RC09.
Confirm that every required capability is implemented, each conditional inquiry is settled with
its supported path, and replacements are deleted. Reconcile early contract slices with their
final consumers; interface agreement is not consumer migration. Check generated/schema ownership,
private fixture/resource lifetime and offline source/result access with service unavailable.

Update the coordinator at its existing tables; do not create a second completion ledger. This
is normal integration reconciliation, not an automatic broad diagnostic or recommendation audit.
Required ADR/design review boundaries still apply to actual governed changes. Preserve Plan32,
Plan40e and other independent scope and qualification. Do not narrow missing required behavior
merely to make completion green.

<a id="H02"></a>
### H02 — Assembled functional qualification

Run the relevant journeys above after all selected functional packages/targeted checks are ready.
Choose current recipes and [qualification guidance](../dev/validation-assessment.md) for actual
Rust/default/native/Python/host/offline contexts. Reuse applicable valid evidence only through
its existing source-bound contract; historical replay is not current-source qualification.
Do not sum overlapping counts into a fabricated coverage total.

Record commands, modes, scopes, actual zero-target failures, exclusions and not-run cases.
Repair failures through target-aligned owners rather than loosen physical admission, incomplete
outcomes, reduction predicates or stale reuse rules. A complete failing report and a passed
command with missing reports remain different. Capture/tool/setup/target/scientific/cleanup
outcomes stay independent. No new quantitative speed/productivity claim is required for functional
completion; making one requires its representative baseline, conditions and actual measurements.

<a id="H03"></a>
### H03 — Scope-end static and manual checks

After functional delivery, run `just hygiene`, fix every error/warning against zero and rerun
failing recipes. Include relevant `just governance`, `just docs`, native-boundary and feature/
powerset/manual checks selected by the qualification guide. D02's complete feature enumeration
and reused/fresh accounting must cover the required campaign; a representative package matrix
alone is insufficient. New dependencies retain exact pins/locked resolution and one Arrow/
Parquet/object_store/DataFusion family. Do not wholesale re-resolve dependencies.

Use the current machine/environment settings, retaining one Cargo driver for overlapping graphs
and allowing genuinely independent safe work to run concurrently. `just ready` runs only after
its documented environment/dependency/tool selection change or environment-shaped failure.
Pyrefly/Ruff/clippy/generation checks apply to affected delivered code at scope end, not repeatedly
to this document-authoring engagement. Keep unknown/unrelated historical cleanup effects separate;
never delete unowned resources or weaken terminal truth to make a bundle pass.

<a id="H04"></a>
### H04 — Enduring publication and actual Outcome

Move implemented contracts/workflows to their current owners: agent environment, diagnostic and
substrate guides; architecture §19.4/§23.1/§24.1/§24.2 where meanings change; native rules/skills;
and typed API documentation. Architecture edits use explicit design-edit authorization and a
revision row; accepted ADRs are immutable. Accepted RC directions are not accepted ADR statuses.
Publish real supported/unsupported model, bridge, replay, instrumentation and trace boundaries.

Write the coordinator's implementation Outcome only from actual work: what was built with evidence
labels; a mistake made and corrected; deliberate deviations and their required decision route.
Keep local Tested, assembled Tested and Measured claims distinct. Update native status/lifecycle/
current-work selection, preserving independent plans. Retire completed companions/source review
only after live readers and surviving meaning are reconciled; Git is the archive and the highest
numeric coordinator remains until a newer one exists. Do not retire plans merely because this
series was authored or because another plan's number is lower.

## Current verification boundary

**Interface-checked:** source owners and prior Outcomes establish the baseline and feasible
integration seams described in this series. **Proposed:** all production packages, inquiry
results and acceptance above. Documentation validation/publication establishes plan usability
only. No product tests, model/service probes, compiler campaign or scientific qualification was
run to author these documents; actual authoring checks are reported in the handoff.

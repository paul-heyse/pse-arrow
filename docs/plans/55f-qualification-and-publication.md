<a id="F01"></a>
### F01 — Representative actual-consumer journeys

Once their consumed capabilities work, compose the following journeys through the actual Codex
attachment and shell-using agent. A fixed-inventory host may use canonical invokers; no special
new host feature or speculative task protocol is required. Source-only capability/workspace
access must work without native extension preparation or database service. Native model
`source_only` comparison still requires its validated native child and source admission;
that flag changes comparison semantics, not infrastructure requirements.

| Journey | Behavior to establish | Revealing control |
|---|---|---|
| Independent CLI access | Current checkout help/description, operation compatibility, hidden selection and exact invocation | Stale/missing host attachment, old command wire, explicit null/empty and absent endpoint |
| Safe recovery | Distinct launch/prerequisite/uncertain-work diagnosis; follow original durable reference | Lost ACK never replays; endpoint edit handle never becomes durable by assertion |
| Change planning | Generated output resolves to its producer, real consumer/contract/evidence paths and affected population | Unrelated same-generator declaration and unknown/dynamic relationship stay distinct |
| Model development | Compare changed sources/defaults/overrides and inspect native lineage before solve | Different physical closures; source-only unknown impact; inadmissible case; changed policy |
| Protected nested result | A representative real value becomes readable with enough exact physical context | Parent-null/list distinctions, changed manifest/window/path, partial/cancelled/unusable result |
| Invocation diagnosis | Locate preparation versus subject stage, counts and remaining original drain | Missing/partial telemetry, stale separate observation, inclusive/sampled timing limits |
| Investigation handoff | New connection reopens the question/copied selections and follows original owner | Unavailable/deleted owner, incompatible source or incomplete copied population |

Include advanced CLI editing, structural migration, experiment and query packet journeys only
when positively adopted by D03/D05/D07/E04. Otherwise assess their explicit inquiry dispositions
and practical existing route, without relabeling optional delivery as tested. Static native API
availability is insufficient evidence of actual host use. If attachment is unavailable, record
the fresh-client boundary and keep actual-host acceptance open rather than claim equivalence.

Use independently specified expected meaning where loss is at risk: explicit argument values,
real declaration relationships, known metric populations and selected scientific cells/context.
Generator/schema round trips establish consistency but can share the bug being challenged.
Keep fixtures representative: a small functional subject is enough to test supervision and
handoff. Do not couple it to production pool sizes or spawn a broad compiler/scientific campaign
just to produce a result reference. Restore authenticated owned resources and retain original
outcomes when a controller fails. Never delete unrelated data/worktrees/caches for a gate.

<a id="F02"></a>
### F02 — Scope-end functional and static qualification

During functional packages, use relevant compile checks, targeted units and required codegen;
commit coherent slices without waiting for this package. Once all selected functional scope is
implemented, run relevant integrated/component/public Python journeys and `just hygiene`, fix
scope-owned failures structurally and rerun the failing recipe. All actual Arrow-consuming
correctness routes carry force-validation. Native consumers use their original selected setup;
source-only agent tooling must not acquire a native dependency just for its tests.

Select the existing Rust runtime/boundary/modeling/result-inspection targets and Python/tooling
tests that exercise changed contracts, along with affected environment/codegen/CLI tests. Use
`just check-package`, `just unit-package`, `just setup-test` and the applicable public Python/
native boundary recipes where they fit; the implementation identifies exact current filters
from the changed tests. A runtime-only targeted pass does not establish public Python or actual
host acceptance. New mechanisms get meaningful tests with their functional change.

Run relevant manual checks: `just governance`, `just docs`, `just lint-native-contracts`,
`just lint-native-data` and inspect feature/powerset command declarations when changed.
Codegen drift belongs in hygiene. No fresh exhaustive feature matrix,
whole solver fleet, IDAES parity, wheel/distribution or other-platform campaign is automatically
required. If a concrete changed contract exposes one of those risks, name its decision purpose
and scope before adding the check; preserve the original failure baseline of zero.

Report command, mode, source/consumer scope, failure/warning count and exclusions with the
repository's evidence vocabulary. An interrupted check remains interrupted; native/export/
telemetry/settlement observations retain separate claims. Do not introduce quality baselines,
ignores or historical-pass substitution to close a failure. When an issue lies outside authorized
scope, preserve it and state its effect rather than silently changing unrelated work.

Performance/productivity benefits remain qualitative unless a specific measurement would change
a design/adoption decision. Any selected experiment names its comparable conditions and what
it can establish. Printed bytes, schema size and cache hit counts alone do not prove a faster
development workflow. No standing benchmark campaign is a completion requirement.

### F03 — Publish the actual delivered target and close the series

Update the enduring interface/environment/validation guides for the supported CLI invocation,
schema regeneration, diagnosis/reconnect, lifetime limits, native inspection, exact knowledge
queries and investigation questions. Explain tool selection non-prescriptively. Keep detailed
native meaning with its architectural owner; update architecture only through the applicable
decision/design route and blueprint revision row. Do not amend accepted ADRs in passing.

Reconcile O01–O16 at the coordinator: selected delivery, completed inquiry, positive adoption,
deferral trigger and evidence boundary must agree with package-owned state. An inquiry may finish
while its optional feature is deferred. An adopted feature remains incomplete until its actual
acceptance; a precise refusal alone does not close new readable-result scope. Resolve misleading
current instructions exposed by the delivered change, without rewriting unrelated historical
outcomes or creating another status ledger.

Update native lifecycle bindings/current-work publication as packages change. Record actual
Outcome evidence, a mistake made and corrected, and deliberate deviations when implementation
closes. Transfer enduring meaning before retiring completed documents/reviews with no remaining
consumers; Git is the archive. The source review is retained while this series consumes it.
Remove only authenticated owned temporary resources; no bulk cleanup is implied by publication.

**Acceptance:** documentation navigation and lifecycle projections agree with native status
owners; every selected capability has an actual operating/reader route and honest support limits.
Documentation-only publication does not rerun native/static qualification. Use `just turn-end`
for authored turn-end formatting, and commit coherent closeout with actual checks named.

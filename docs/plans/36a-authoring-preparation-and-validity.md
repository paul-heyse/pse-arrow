## Target and decisions that source can settle now

Expose numerical binding directly over an admitted source revision; keep authored edits as explicit revision-producing operations. Give current canonical preparation an operation lifetime, and keep its eligibility separate from retained mathematics. Encode complete acquired premises once and store unchanged mathematical payload separately from its current reachability/eligibility record. Compute declared fixture demand during the existing semantic specialization and complete executable preparation once. Share observed image evidence without turning it into current admission. Preserve full source-revision identity before considering a compositional replacement.

These choices do not depend on a complete incremental checker. They remove demonstrated work on numerical edits and stable studies, while retaining complete checking for structural changes. The original request to choose Salsa versus plain functions is a separate structural-edit decision. The audit correctly rejects the premise that two differently scoped retention mechanisms automatically violate DP-09. Retained detached products and short-lived compiler memoization have distinct roles. Correct the unsupported across-authored-edit backdating claim now; do not delete the compiler's real public subsequent-revision behavior merely because runtime callers currently use fresh workspaces.

Source settles overlay semantics: `workflow/bindings.rs::admit_overlay` admits finite physically typed assignments to admitted independent Variable/Parameter members. `cases.rs::resolve_starts` applies binding members after defaults, predecessor, named case and continuation values, before unresolved start annotations and temporary fixes. It therefore handles parameter coordinates, fixed-variable coordinates and free-variable starts. It does not directly express lower/upper limits or fixed/free status. Parameterized bound annotations can change indirectly and must be reevaluated. Structural literals, domains, indices, discretization, variable state and shape use the structural or existing case-state route; do not silently reinterpret them as scalar assignments.

Source also settles the duplicate-preparation design blocker. `specialize_with_discretizer` instantiates the root, including physically resolved fixture semantics, before processing `bindings.demand` (`pse-modeling/src/specialize.rs`). Extend this same pass to ensure the resolved fixture specification paths required by declared execution, rather than guessing from raw source or launching a second semantic specialization. A declared caller can then pass its already prepared product into case resolution. Generic case preparation still computes its explicit demand before its one full preparation. Integration must preserve path resolution, unit conversion, fixture policy, applicability, required lazy members and diagnostics.

Stat-only content certification is not settled positively by source. Existing file observations compare bytes, mode and canonical path. A timestamp tuple is an invalidation hint, not equivalent assurance. The safe target carries a process-shared replay candidate and requires scoped complete current qualification at actual persisted acquisition/new eligible publication. Pure retained mathematics and unchanged bindings do not need this admission. A stronger fast path needs a separately qualified unchanged-premise owner; it is not assumed here.

## P-A1: direct numerical binding with exact lineage

Producer: `ModelingPackage`/`bindings.rs`, reusing `PointOverlay`, `AdmittedBinding` and existing physical admission. Consumers: Rust declared solve entrypoints, `pse-py/src/workflow/modeling.rs`, `python/pse/_modeling.py`, study operation preparation and result lineage projection. Expose the operation as solving a named admitted case with typed assignments; users need not understand cache lifetimes. Admission can use one ordinary prepared parent initially, so a persistent engagement is an optimization rather than an API prerequisite.

Check exact revision, physical context, member role and admitted-input eligibility. Resolve submitted paths once, reject duplicate targets even when expressed in different forms, convert through `CanonicalConversionPlan`, preserve supplied spelling/unit as attribution and canonical IEEE bits as value meaning. `AdmittedBinding.identity()` excludes source spelling/unit and does not include the revision; its enclosing source/context association therefore remains mandatory (`OperationSource::check`, `validate_binding`). Results name parent revision, exact binding, current physical/provider context, start receipt and all applied seed/predecessor dependencies. A transient solve never changes what reopening the parent means; persisting values is a separate explicit source edit or named case.

Each bound point reevaluates value-dependent numerical hints, class/coefficient facts, presolve, bounds, provider requirements and independent PS-10 outcome checks. Immutable bodies/case topology may survive; numerical factors may not. Reuse the `bound_case`/`rebind_scoped` Unchanged/Sharing/Rebuild behavior and shared executable memo. Attempt workers/evaluators remain fresh unless a separate native session contract permits reuse.

Targeted acceptance: compare fresh and bound parameter/fixed-coordinate/free-start solutions and exact lineage; include unit/basis/datum/subject mismatch, nonfinite, duplicate, missing/internal target, wrong revision, parameterized bound change and structural literal controls. Existing `binding_admission_unit` and source-revision tests are starting controls. Count no compiler-workspace construction or description publication on a warm direct binding, using existing preparation counters. Remove the Python declaration-inventory/whole-JSON round trip from this operation, not the intentional full replacement API.

Prerequisite: approved new boundary intent; ordinary parent admission suffices. P-A2/P-A3/P-A5 deepen reuse but must not delay correct value binding.

## P-A2: delta ingress and complete affected-reference invalidation

Producer: parent-qualified edit/document intent at `workflow/modeling.rs` and authoring document owner. Consumers: `canonical.rs::persist`, `SourceIndex`, source selection, data suppliers, Python edit/reload surfaces. Consume exact parent and explicit add/change/remove sets. Validate all newly submitted rows at the boundary, and retain unchanged version keys, data and fit ownership. Omission is not deletion in delta mode. Complete replacement retains its documented deletion domain: omitted modeling/record/physical-scope-document members, not arbitrary inherited fit/data objects.

Re-extract outgoing references whenever any changed row's reference-bearing expression/type/path/requirement field changes. `x==a` to `x==b` is the mandatory counterexample to the original name/parent/kind/import-only prescription. Then invalidate other lookups affected by additions, deletion, shadowing, parent moves, kind changes, imports and membership/namespace changes. Positive and absent lookups, duplicate and cycle witnesses must remain complete. A conservative affected-scope scan is acceptable for a namespace-changing edit; a stable spelling is not proof of unchanged binding. Use `named_children`, children/import/root indexes for data closure without losing same-name/duplicate resolution. Re-derive `record:` suppliers only when their declaration/data closure or document interpretation changes.

Parent-preserving text reload compares exact document checksums, reparses changed texts with existing owned parser/span APIs, updates added/removed document ownership and preserves the problem lineage. Initial loading still creates a problem. IR edits invalidate obsolete document text/spans under their current owner; do not retain text as if it authored changed generated declarations. This operation needs exact parent/CAS handling and atomic edit publication: interrupted parsing creates no partially admitted revision, and an uncertain committed edit settles by original identity rather than minting another.

Preserve `ModelingSourceRevisionV4`: ordered row semantic frames, document content hashes, physical identity and physical-name bindings. Member payload versions also include representation/reference/attribution and cannot be substituted mathematically. Initially stream/frame the full merged logical row sequence where V4 requires it; avoid re-decoding data/revalidating unchanged tables merely to obtain that sequence. Any resident immutable ingress view retains its allocation/parent owner and is evictable; cold edits may hydrate sufficient parent metadata. Do not promise strictly change-proportional total work while the full frame is retained.

Acceptance: no-op returns exact old revision; unrelated objects preserved; explicit removal exact; stable-name changed expression reference selects the new dependency; previously absent/shadowed/imported names, duplicate/cycle/delete controls; changed data bytes/physical names change identity; unchanged tables are not readmitted; reload shares problem identity and reparses only changed documents. Compare against clean full ingress as an independent behavioral control. Delete `full_source` from the ordinary delta route and redundant Python encode/decode/encode of whole inventories; retain it only where complete export/replacement actually consumes it.

## P-A3: one declared executable preparation and bounded candidate lookup

Move the resolved declared fixture's required path demand into its existing specialization, before executable projection. Migrate `declared_execution`, `prepare_declared`, `prepare_bound_operation`, `resolve_case`, initialization/inspection callers and conformance consumers together. A retained declared product is checked against exact root/instance, structural bindings, limits, physical/provider/registry identity and complete demanded view. Generic caller cases pass demand before preparation; direct bindings by member do not invent new structure. Do not substitute raw authored fixture extraction for physical specialization. Do not force check/integrate/shooting procedures through an algebraic solve product.

For candidate history, preserve A/B/A and early rejection. Under the fresh selected read, resolve bounded windows of common premise keys once and compare candidate requirements locally. Merge only the accepted candidate's complete premises; a rejected candidate must not poison the consumer read. Share observations between searches before/after the qualification turn only when the same protected immutable premises still apply. Avoid materializing the entire union of every retained candidate unconditionally. Changed/new object hydration can reuse exact retained source versions, while namespace/absence evidence remains freshly established.

Acceptance: nonempty and empty/already-covered fixture demand both make one complete plan/completion and one canonical establishment; physically converted fixtures, lazy referenced members and unknown paths remain correct. Exercise E=1/E=8 candidate histories, out-of-closure edits and A/B/A; request counts should follow bounded distinct premise windows rather than repeated overlapping per-candidate calls. Existing `checked_selected_admission_rechecks_fresh_protection_and_retains_a_b_a` remains a preservation control. Remove the second declared `prepare` and its separate temporary basis/description inventory. Counts are planned evidence, not results.

## P-A4: content, complete receipt and eligible roots

Keep the complete identity frame and complete selected/acquired dependencies first. `ProductDescription::prepare` currently snapshots/clones/serializes full premises per body and `product_blob` combines payload with them. Introduce shared immutable encoded selection material with its existing byte/accounting owner. Store mathematical payload content once per body/producer/reconstruction contract; each current product/root names that content and the shared full receipt. Payload integrity, producer compatibility, selection eligibility and reachability are different facts and retain distinct framed identities. Do not delete domain-separated hashes just because bytes overlap.

Producers: runtime `portable::{encoded_body,describe_body,publish_description}`, `PreparedBasis` descriptions and operations staging/selection. Consumers: product discovery, exact acknowledgment, portable reconstruction, result/source retention and root reclamation. Registry/codegen declarations own durable shape; regenerate instead of editing generated queries. Plan controlled artifact activation/rebuild and historical access explicitly under the final chosen schema contract; no inferred destructive migration or compatibility backend.

Acquisition still checks current interpretation, full receipt plus acquisition delta, exact payload integrity and independently qualified receiving context. New eligible root creation requires live protection. Existing exact rooted acknowledgment preserves original provenance and may settle its original request after source expiry; it cannot create a new root or revive released ownership. Use keyed descriptor/store-issued identity lookup rather than history-wide discovery where its semantic key is available. Store planner/index choice belongs with coordination integration and I-A2, not an assumed `FOR UPDATE` simplification.

Targeted acceptance: B equal bodies across one consumed edit reuse payload bytes while fresh receipt/root association names the new selection; one premise encoding is shared/accounted once; changed absence/interpretation/acquisition delta refuses reuse; corrupt storage bytes fail at reconstruction; released roots cannot authorize republication. Existing `ordinary_preparation_rechecks_additional_acquisition_absence_before_basis_reuse` and `ordinary_preparation_exact_basis_hit_rebinds_current_attribution_and_settles_released_roots` remain preservation controls. Remove payload-plus-full-premise copies per body only after replacement consumers move.

## P-A5: held current consumer and study/sample adoption

The engagement owns a currently protected exact selection, not a cached permission flag. Key it by problem/revision, root/instance, structural bindings, limits, acquired dependencies, physical/provider identity, validation/EngineFactory/Registry identity and demanded preparation. Existing `SelectedRequest`/`BasisKey` retain those owner Arcs; pointer identity without lifetime retention is insufficient. Hold basis, views, shared receipts and exact settlement state only while actively engaged.

Lifecycle: Establishing → Active → Closing → Drained/Released. Active acquisition/publication requires a live nonexpired protection and applicable lease. Renewal validates and extends that same protection; it never recreates an expired/released pin. Lease/renewal failure stops new admissions. Already dispatched effects retain original immutable operation identity/deadline, payload/receipt allocations and cleanup owner through uncertain settlement/drain. Cancellation drops no charges or source pins before native/private receiving work drains; pure shared-flight waiters may detach independently. Idle/disconnected owners close and become evictable. Durable run/source roots, engagement pins and immutable cache allocations are separate lifetimes.

Study workers retain one immutable input engagement per matching study operation rather than reopening revision/context/declaration and acknowledging B bodies for every point. Preserve `DeclaredStudyAdmission`'s existing descriptor/path/member membership cache and do not rebuild it under a new name. Each point admits exact binding and seed need, reevaluates changing value/policy/provider facts, rebinds and obtains independent assessment. Horizon adoption reuses structure only; arrivals/windows/controller/estimator state and mutable native sessions remain sample/attempt owned. Changing any engagement premise closes/replaces it with a new properly admitted owner.

The committed target is synchronous exact settlement once per live engagement before preparation succeeds. Its active lifetime permits subsequent value binds/stable points to consume that settled preparation without repeating establishment. All currently promised canonical effects and durable-result completion remain. There is no automatic background queue, deferred publication, separate weaker success result or skipped settlement for ephemeral execution in this target. I-A5 separately investigates whether optional reusable-product publication, changed completion outcomes or ephemeral omission would be useful and conforming; these are unselected alternatives requiring an explicit operator decision and effects contract before implementation. Existing source admission, uncertain-outcome settlement and result-policy obligations apply regardless of that future choice.

Prerequisite: coordination package must close pin/root creation versus reclamation in both commit orders, with creation fences and affected-pin conflict registration; a longer lease alone is insufficient. Acceptance: independent lanes/readers/root creators/reclaimer, expired/released pin, lease failure, wrong context, uncertain acknowledgment, cancellation with live native work and cache pressure. A stable many-point study performs one input establishment/settlement per engagement; only point-owned changing work repeats. Remove per-point reopen/two-prepare/per-body acknowledgment route after these consumers migrate.

## P-A6: distinct receiving, outer and native assurance owners

Receiving image: process-share the observed replay candidate keyed by actual artifact anchor/role and complete supported configuration. It is evidence, never current permission. New actual acquisition/publication performs existing full `qualify_replay`/`qualify_receiving` once under the held consumer, then loader-excluded reconstruction remains bounded. Strict producer receipts retain their stronger independent path. Changed/unknown context refuses local replay; fresh admission/history remain available. Changed image never silently renews the old producer namespace. Late load/unload, anonymous/JIT/deleted mappings and uncontrolled interposition retain current support limits. RTLD_GLOBAL promotion is not proved absent by counters/maps and is not fixed by rehashing either; retain the controlled-root exclusion unless separately redesigned.

Outer observation: move `observe_deployment`/complete checkout capture outside the GIL using the established detached/scoped native-job owner. Stream source files instead of materializing every byte where this preserves exact framing. Report it as checkout context observed at a stated admission time, separately from loaded artifact/build identity. If startup context is shared, label it startup context; obtaining current run/deployment context remains explicit. Installed source-unavailable and strict receipt outcomes remain truthful. No git dirty indicator silently replaces an exact dirty content digest.

Managed primary: fuse repeated generation/script/worker verification within the existing ensure-primary admission owner, retaining actual process/nonce, executable association, storage database, generation and placement checks. Move unscoped synchronous hashes off Tokio executor threads and make remaining full captures cooperative under the original admission deadline. Do not pass caller digest strings as independent receiver evidence. A launch/readiness transfer may carry established immutable generation identity only when its owner excludes managed mutation and actual executable association is checked. Otherwise retain full verification at the changed trust boundary. Native installation already pins before verification, hashes outside publication coordination and remembers admission once per real operation. Preserve that boundary; cross-operation elimination is I-A3, not a demonstrated missing cache.

Acceptance: chunk cancellation never seals; late persistent and transient loading/configuration changes refuse; changed path/link/mode/same-inode bytes refuse; wrong process/nonce/generation/database/placement refuses readiness; interrupted startup drains. Separately exercise multiple Runtime objects with shared candidate evidence, no current claim from stale startup context and current outer context captured outside GIL. Warm binding/stable points should need no full host hash because they create no new eligibility, rather than because checking was weakened. Remove repeated capture at unchanged internal crossings only after the replacement owner discharges that exact guarantee.

## Contracts and implementation decisions

Use the existing ownership boundaries and pinned library APIs. Differentiation
stays in Symbolica/Numerica; faer owns sparse structures and products. Derivative
admission uses the actual Taylor multiplication structure and supported primitive
expansion, with checked preallocation and post-build reconciliation. Let bindings
retain block outputs instead of repeatedly substituting expression trees.

Separate compiler-generation storage, immutable products, active scratch/foreign
allowances and completed results. DataFusion reservations and the existing joined
job supervisor remain the accounting owners. Retain relaxed configurable defaults;
neither reservation accounting nor foreign allowances claim to measure process RSS.
Sparse fitting preserves exact declared support, duplicate contributions and
independent final candidate qualification. Dense diagnostics are separately bounded.

Reuse consumes immutable admitted products and complete varying dependencies.
Native callbacks use prepared index mappings and attempt-owned buffers. Constant
evaluation uses Symbolica's direct operation. Work counts guide implementation;
comparative timings occur only in P18.

Ordinary commands require no plan receipt. Native test selection belongs to nextest
and pytest, not duplicated exact-name manifests. Factual reports distinguish
executed, unchanged-input reuse, reviewed transfer and not-run. Review documents
remain judgments, without digest-bound verdict gates. Criterion 0.8.2's csv_output
feature supplies raw samples; private JSON formats are removed from the collector.

## Disposition commitments

- Retain bounded native query reuse, declaration-owned validation, scoped parent
  accounting, finite output ports and bounded diagnostic plan serialization.
- Retain native catalog operations and exact publication/dependency/retention
  guarantees. Keep canonical Arrow-content identity separate from schema semantics.
- Remove fictitious null/kernel policy claims, unused rule scheduling/projections,
  ScalarKernel and InferenceCache, duplicate parsing and private B-tree layout math.
- Retain coherent document parsing/editing and pse-rules' actual Python inspection
  and xtask invariant-validation role. No production mathematical rule engine claim.
- Remove orphan mechanism relation families through the declaration generator;
  retain authored, result/storage and supported tooling meanings.
- Remove phase/receipt/verdict ceremony, stale command consumers and the unsupported
  release stub; preserve historical reports and shared build caches.

numeric sparse Gram product. Duplicate contributions accumulate before multiplication.

1,000-coordinate sparse admission, pool-pressure diagnostic refusal, shared ownership
and joined-stack accounting pass. Dense support remains dense when actually declared.

under their own preparation reservation. Prepared fits and oracle consumers share
one immutable product, avoiding deep copies and retaining admission until its last
owner drops. Targeted clone/drop and full-pool refusal controls pass.

P15 direct Symbolica constant evaluation replaces per-constant optimized evaluators.
Native admission consumes a compiler matching witness only after checking current
IDs, equality membership and matching edges. Dynamics prepares conversion/index maps
once and reuses derivatives by exact time/state/parameter bits within an immutable
mode/provider/program owner. Cancellation precedes cache lookup; failed evaluations
clear the cached point. Diffsol JVPs use faer sparse multiplication and attempt-owned
direction storage. Targeted matching, JVP, invalidation and failure-recovery controls
pass. The change removes reconstruction; no timing speedup is inferred.

P17 additionally removes duplicate method bans and the custom Rust masking lexer.
Clippy owns method/type bans; ast-grep owns scoped syntax/literal rules with positive
and negative fixtures. Cargo declarations replace blueprint exact-pin parsing and

catalog journey rather than source-spelling assertions. Review reports remain judgment.

P18's expanded workload implementations preserve the original 23 shapes and add

the raw report preserves the remaining work instead of implying that reuse is free.

removal of reconstruction and simpler attempt-owned mappings/scratch; this campaign
does not assign individual optimization speedups. Sparse fitting at 32 and 1,000
coordinates is an observed growth comparison for the declared sparse fixture, not
a claim that all fitting problems have sparse support.

## Outcome

### What was built

**Implemented and Tested:** P14 gives derivative growth, shared compiler/prepared
products, job stacks, sparse fitting and optional diagnostics explicit allocation
owners. P15 uses prepared structural facts, direct Symbolica constants, faer sparse
products and attempt-owned callback reuse. P16's obsolete mechanisms and orphan
relations are deleted, with the surviving authoring/query/storage contracts listed
above. P17 replaces phase/receipt ceremony and bespoke source checks with ordinary
runner-owned execution, explicit applicability, Cargo/Clippy/ast-grep and Criterion
CSV. P18 completed local default/native/Python/scientific/tooling qualification and
the 33-case measurements. The carried-forward P10–P13 publication/DML fixtures are
repaired and covered by the final default/native suites.

### A mistake made and corrected

**Tested:** Final qualification exposed a hard-coded `"1"` alias for bare numeric
literals. The compiler now resolves the registry's neutral dimensionless unit;
the analytic-power test and recycle case exercise a registry without that alias.
The document container allowance also caused false pool refusals for bounded parser
inputs; it now uses known payload sizes plus an explicit finite opaque-entry policy.
The ownership audit found prepared fitting metadata/layouts outside their own lease;
they now share one admitted `Arc` product until the final owner drops. Its new test
initially required Ipopt in the default feature graph; an all-fixed fixture now
exercises the same lifetime/refusal contract in both default and native suites.
Finally, warm-case teardown was initially labelled too broadly: the final benchmark
records per-case retention and final runtime release separately and was remeasured.

### Deviations from the plan, deliberate

**Implemented:** Actual query, dependency-capture, catalog and inspection consumers
justify the P16 retentions; no line-count-driven deletion or replacement framework
was introduced. Opaque foreign/container allowances remain policy rather than private
allocator-layout guesses. Optional dense rank diagnostics can refuse capacity while
preserving sparse candidate evaluation. P15's simpler-ownership benefit is explicit;
no incomparable historical speedup is substituted for missing before-evidence.
Observed qualification repairs caused affected reruns with reviewed applicability
transfers, not repeated complete execution after every edit.

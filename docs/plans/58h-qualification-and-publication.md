# Qualification and publication

## Purpose and preserved limits

**Proposed:** establish the native target through original product and host journeys once selected functional scope is implemented. O11 supplies the original opportunity; [I14](../plan_improvement_reviews/plan58-rust-hard-cutover-2026-10-28.md#I14), with I01–I07/I10–I12, reshapes acceptance around retained science, model-driven durable work and lean native operation. The coordinator owns dispositions; companions own local evidence. Baseline is `c3b7f136d`.

This is neither a continuation of Plan57 qualification nor a demand to reproduce every old fixture, registry, recovery or build-observation failure mode. Existing passes, failures, unresolved SIGSEGV and full-matrix deferral retain their original conditions. Deliberately retired requirements have explicit coordinator dispositions; renaming a test or silently deleting a retained assertion establishes no acceptance. Scientific adequacy, interface implementation and measured benefit remain distinct.

### H02 — Native scientific and durable-model journeys

With first-party Python and MCP unavailable, exercise author→prepare→execute→inspect, value/structural edit→re-solve, supported initialization/recycle, dynamics/events, fitting/sensitivity and study/diagnostic compositions within actual supported limits. Scientific calculation/progress observations, original-space outcome assessment and meaningful diagnostics remain. Read protected retained results through a data-only capability and browse/control through connection/authentication alone; neither constructs unrelated mathematical services. Exercise selective relational queries, retained output after reader close and failure mid-delivery.

For a persisted study, create a definition/revision, realized points and a dependency before activation. Replace or interrupt its worker/client and resume selection from canonical state; later analysis must read the same scientific lineage and result references. Bounded paging/maintenance continuation cannot be reported as exhaustive no-work. Exercise two workers competing for one assignment, preparation/resource admission before execution claim, and claim refusal after prepared seed/dependency/cancellation premises change. Do not imply live dependency graph mutation or bit-portable regeneration from a seed; recorded-point replay remains the contract.

Original submit/cancel/status/reconcile distinguishes exact replay, changed intent under one identity, actor refusal, committed effect with lost acknowledgement and absent receipt. Notifications can wake work but missed/lagged events require authoritative catch-up. Observe actual native entry before cancellation where claimed, then original task/thread/process exit, result publication and physical release. Include observer disconnect without scientific cancellation, explicit stop, concurrent studies, partial startup and unavailable database/manager. Stop only authenticated owned resources and preserve unknown ownership. Failed acceptance triggers no blind retry or data reset.

### H03 — Bootstrap, development, migration and independent assurance

Cold bootstrap and passive diagnosis work without first-party Python, native solvers, Arrow/product schema initialization or database startup. Verify selected host control on actual systemd255/user manager, delayed/lost job signals, reconnect, original unit identity, descendants, borrower ownership and release after physical settlement. Compare zbus job results against unit/kernel state. Adopted notification paths must establish readiness; absent-socket send success alone does not. Ordinary host operation retains configured parallelism, without a new daemon, CPU cap or blanket serialization.

Exercise native sccache cache hit/miss and ordinary compiler failure. Under the operator-selected contract, cache-service loss alone does not invalidate an otherwise valid compiler result; actual compilation failure and owned-process cleanup remain meaningful. Native compiler/Cargo/nextest diagnostics replace bespoke build observation. No live build-stage/freshness telemetry, cache-identity watchdog or derivative build alert is an acceptance requirement. Useful scientific observation and optional native telemetry configuration remain independent of scientific admission.

Test real typed fixtures for successful creation, cleanup after scientific success or failure, and reconstruction of explicitly owned disposable state. Preserve useful failure diagnostics outside that state; cleanup is not scientific success, and `Drop` cannot establish a passing assertion. Shared-service borrowing tests belong only to selected shared adapters. Nextest groups schedule rather than grant capabilities. Distinguish setup failure, scientific assertion failure, missing reports and actual resource leaks through ordinary native outcomes, without a universal terminal/evidence reconciler. Setup-dependent compilation/listing prerequisites and enclosing fixture teardown remain explicit. Preserve actual target/host Arrow-leaf force-validation, original child exits and doctest coverage; statistical measurement remains separate from nextest success counts.

[D05](58d-canonical-control-and-connectivity.md#d05) must deliver a working minimal schema/migration owner during the cutover. On disposable data, exercise an ordered adjacent-version transformation, incompatible predecessor refusal, interrupted migration with explicit pending/closed admission, and the selected behavior of already-open handles/in-flight attempts as admission closes or interpretation changes. Verify supported schema/version publication and retained identity/transaction semantics. Reconstruct regenerable development state without porting every historical converter or recovery branch. These tests do not authorize resetting existing stores or cover full historical production recovery.

Run independent Python science references only in their explicit isolated environment. Native candidate execution exchanges explicit cases/results with that reference side rather than importing the retired `pse.Runtime`/generated facade. Keep independent numerical interpretation/tolerances and test a deliberately wrong candidate result. Native tests cannot manufacture their expected scientific answers from their own production transformations.

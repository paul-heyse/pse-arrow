# Integrated acceptance and closeout

**Proposed.** Qualify the actual Plan72 target across its changed producers and consumers,
then carry enduring contracts to their owners and remove what the replacement supersedes.
The [coordinator](72-surrealdb-functional-improvements.md) owns overall completion. This
companion owns integrated receiving and closeout, not a second progress account for 72a–h.
No legacy plan's qualification or unfinished scope is imported.

## Acceptance basis and boundaries

Core 3.4, efficient architecture 1.0, process-simulator 1.5 and test assessment 1.2 apply through
the repository binding. Blueprint §20/§21/§23/§24 own current publication, results, diagnostics
and qualification meaning. Plan66 retains scientific implementation and assembled scientific
acceptance; Plan71 retains test infrastructure and original evidence. Their available journeys
can receive changed Plan72 contracts without their entire scopes becoming Plan72 prerequisites.

The user authorized a hard pivot to a superior design on clear source/architectural reasoning.
Do not turn qualitative benefit into an extensive proof obligation. Package-local tests establish
new behavior and required correctness; additional comparisons/probes are necessary only where
an unresolved premise creates a serious correctness or performance degradation risk. Quantitative
claims still require appropriate measurements if such claims are chosen.

**Interface-checked baseline.** The existing native fixture provides logical database ownership,
independent client use and physical disposal; canonical readers provide original payload protection
and interpretation; Plan71 supplies selected reports and diagnostics. These are reusable foundations,
not fresh qualification. Contract-specific source evidence is retained in 72a–h. Source inspection,
plan publication and accepting an ADR establish neither runtime correctness nor physical settlement.

## I01 — Receive complete useful operations

Use the selected 72a–h target, not every investigated alternative. Trace adopted review O01–O18
through their actual producers, changed consumers, public interpretation and physical owner.
An implemented prerequisite is available when its meaningful consumer works, not when a type or
document exists. Resolve shared contract disagreements before running the corresponding journey.
Do not wait for unrelated Plan66 physics or all Plan71 delivery to exercise an already available lane.

Select representative integrated cases that distinguish the changed guarantees:

| Journey | Required receiving distinction |
| --- | --- |
| Author/change → inspect → install/evolve → write/read | Owner-generated vocabulary and operation inputs agree with represented engine semantics; native values retain required identity/precision/presence. A chosen migration has original data effects, conformance and activation separately established. |
| Submit canonical operation → readiness/progression → reconcile original outcome | Explicit isolation and selected policy composition preserve positive/absent/range dependencies, stale authority refusal and unknown acknowledgement recovery. Do not remove semantic fences by proving only a happy-path transaction. |
| Select corpus → search/rank → explain/continue | Late matches, high-degree/cyclic/multiple-occurrence graphs and denied records preserve stated membership, evidence, ranking and cursor scope. A useful path is not reported as complete dependency closure. |
| Follow snapshot → change → reconnect/rebuild | The initial snapshot race, leaving a live predicate, permission loss and refresh failure do not present stale state as current; a selected feed handles identity, duplication and expiry without redefining scientific time. |
| Publish/protect → selected result consumption → release | Exact original descriptors and independent Arrow/Proto interpretation survive the adopted storage/transport route; transfer capability lifetime, held readers, uncertain attachment and physical reclamation have their chosen complete owner. |
| Developer/operator → focused contract/test/diagnostic → retrieve/release | Database assertions and independent native consumer disagree when they should; infrastructure, assertion and cleanup failures remain distinct, with Plan71's existing references and retention. Static inspection performs no hidden query or preparation. |

Reuse the existing fixture and selected scientific receiver where they establish those distinctions.
Add a revealing malformed, denied, interrupted or concurrent case for a changed serious boundary;
do not instantiate an entire scientific population merely because a byte representation changed.
Expectations for exact membership/value meaning must be independent of the transformation under test.

<a id="I02"></a>
## I02 — Complete relevant qualification at functional scope end

During implementation use scoped `scripts/pse check PACKAGE --all-targets` and targeted
`scripts/pse test PACKAGE --lib -E 'test(=NAME)'` or an explicit integration target. Keep required
force-validation. Registry/generator changes include `just codegen` with their source change.
Do not defer necessary consumer migration or replacement deletion to this package.

Once adopted functional scope is implemented, select the relevant native service/component,
operator/CLI, subscription/recovery and protected-result integration journeys above. Select
scientific, solver or isolated Python reference work only where Plan72 actually changes the
consumed scientific boundary; this cannot close Plan66's broader acceptance. Reconcile active
Plan71 fixture/report behavior so the selected result actually describes this checkout/selection.

Run applicable repository scope-end static/governance/docs/native/feature checks under the
existing execution rhythm. When hygiene and governance share the same prepared context use
`scripts/pse run-all hygiene governance-tests`; choose narrower documented checks where only
that scope is relevant. None becomes a per-companion ceremony or a commit/push/merge prerequisite.
Fix failures against the zero target and rerun the checks whose evidence the fix changes.

Maintain one short risk decision per actual unresolved degradation concern in its owning package:
state the behavior at risk, why source evidence is insufficient, and the smallest discriminating
control. Examples include unsafe guard removal, native unsigned-wire loss, presigned access outliving
protection, a subscription snapshot gap or new mixed-load starvation. A speedup proof, default
before/after comparison, old-version replay and mandatory full benchmark campaign are not required.
If no serious unresolved risk remains, reasoned design plus targeted correctness acceptance is
sufficient. Report actual command, mode, selection, conditions, failure count and zero baseline.

## I03 — Close the implemented target without losing open decisions

Check the coordinator's source opportunity/discovery correspondence against the actual package
outcomes. An investigation closes with a supported decision and its branch consequence; it does
not close by forgetting the candidate. Deferred/nonselected branches keep a meaningful reason,
owner and observable trigger. Accepted target behavior cannot be hidden behind an unbounded future
investigation. Independent package completion does not imply an O reference is fully resolved if
its required integration or evidence remains.

Verify replaced code, callers, tests and fixtures are removed in the changes that prove replacement.
Keep no compatibility implementation or legacy fixtures as evidence. Confirm source-built selections,
generation and active consumers agree with the chosen target; do not create a second production
transport, store or report ledger as a fallback for a conditional option.

Move enduring meaning to the actual architecture/developer contract owners through their required
decision route, recording blueprint revisions and superseding accepted ADRs where necessary. Keep
operating guides exact about preparation, effects, recovery and release. Do not edit Plans66/71
or declare their outstanding work complete. Historical Plan68 remains inactive legacy and supplies
no imported obligation. Retire Plan72 and consumed reviews only when surviving meaning and open
decisions have their established owners under the document lifecycle.

The final Outcome records what was built, a mistake made and corrected, deliberate deviations,
and the evidence vocabulary with actual named checks/conditions. Separate **Implemented**,
**Tested** and **Measured** claims; no measured benefit is required where no quantitative claim
or serious regression concern exists. No product test or qualification was executed by authoring
this plan, and publication does not approve production implementation.

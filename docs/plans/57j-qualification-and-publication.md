# Plan 57j: Qualification and publication

## Purpose and claim boundary

**Proposed:** establish the selected series' actual integrated behavior after its functional
packages and necessary decisions are complete, then transfer enduring meaning to its owners.
This companion owns joined acceptance, scope-end checks, benefit-selection decisions and
publication. The [coordinator](57-library-leverage-and-correctness.md) owns CBO dispositions;
each implementation companion owns package evidence and migration state.

Authoring baseline is `93946f572`, product source `4f52fd239`, updated comparative/input accounts
`93946f572` and retained counterexamples `1540fd164`. The selected standard is Core 3.4,
efficiency heuristics 1.0, Process Simulator 1.5, test-assessment companion and pse-arrow binding.
Loading those criteria does not start a new audit. Existing review probes and earlier plans'
qualification remain evidence only at their recorded conditions; they do not qualify this target.

No product build, native supplier rebase, test campaign, host mutation or benchmark ran for
this plan's authoring. All checks below are future acceptance, except document-authoring
checks reported by the coordinator's final handoff. Do not publish an implementation Outcome
or label the series Tested merely because these planning documents build.

## Preparation, reuse and actual integration scope

Reuse current independent scientific verification, canonical fault peers, native lifetime
fixtures, host-operation test support, Python public assertions and actual CLI/MCP journeys.
Extend their discriminating cases when behavior changes rather than wrapping every package in
another test harness. Preserve original assertions and failure receipts; do not replace expected
results with the transformation being tested. A shared helper's unit test does not establish
that all consumers migrated.

When an artifact, native supplier or Python extension changes, construct it through its owning
route. Do not add per-read source/image revalidation, a watcher, a daemon, an evidence manifest
or a new source-truth registry. Retain the existing explicit selected build/mode, canonical
service authority and original admission through cleanup. Publication of authoritative design
sections follows its decision/design route and revision row; accepted ADRs are not rewritten.

The selected assembled target is this repository's supported local Linux Rust/Python/native,
canonical storage and host workflows affected by Plan57. Keep other-platform, distribution,
fleet, remote CI, full historical reference breadth and performance claims separate. If a
consumer/feature route is excluded, say which actual contract remains unexercised. A narrower
pass is useful evidence, not closure of an untested obligation.

## J04 — Decide and attribute benefit evidence

Separate removed structural work from measured benefit. The plan expects fewer duplicate
reads/row hydrations, repeated declarations, forwarding and process launches where the migration
actually removes them. Those are Interface-checked/Implemented claims once present; they do
not establish elapsed speed, peak memory, capacity, compile/startup savings or portability.

Choose a measurement only when it changes a consequential decision: registry startup/compile
tradeoff under the selected replacement, IPC live working set under the complete envelope,
observed fallback frequency before adding exact split sizing, or process/capture costs before
a deferred replacement. State the decision, baseline, modes and representative operation before
running it. Coordinate scientific timing/reference exclusions rather than partitioning the
workstation. Retain original immutable outputs and failed/incomplete attempts.

It is acceptable to decline a campaign that would only restate curiosity. Record that the
benefit remains unmeasured, with the meaningful future trigger. Measurements that are necessary
to select a remedy remain with that inquiry; optional comparative quantification is not an
automatic completion gate. The old registry timing sample and one-host determinism probes keep
their original attribution and do not become new-platform predictions.

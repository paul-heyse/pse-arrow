# Explicit-measure expectation studies

## Outcome and baseline

**Proposed.** This companion of [Plan73](73-symbolica-ecosystem-improvements.md) delivers O10: an engineer requests an expectation under a declared measure and receives the estimand, estimate, statistical uncertainty, convergence interpretation, original member outcomes and replayable provenance. It owns scientific operation/result declarations, protected publication and independent reading needed here; unfinished Plan66 work is not a prerequisite.

The new capability is an explicit-measure expectation operation with both fixed Monte Carlo and adaptive integration. It changes study admission and iteration orchestration, introduces measure/estimand and estimator result declarations, and extends the native operation and retained-result readers together. Existing typed model authoring, physical overlays, case preparation, solver routing, occurrence identity, covariance propagation and canonical custody remain the foundations. The implementation adds probability-law and estimator meaning to those owners; it does not reinterpret an existing DOE seed or covariance matrix as a probability distribution. The inspected study/sampling/uncertainty owners do not already implement this expectation operation. Deletion below removes superseded integration or provisional delivery paths if introduced, while retaining those existing distinct capabilities.

**Interface-checked.** Baseline `baadc7e32` supplies quantity-typed physical overlays in `workflow/sampling.rs::DesignRequest`, ordinary case operations, independent study lanes and retained occurrence results. Covariance propagation in `workflow/uncertainty.rs` establishes local response meaning. DOE and covariance do not specify an adaptive expectation. Reuse those owners without a second study service or probability framework.

## Selected scientific contract and first consumer

Deliver an ordinary authored constant-cp heater study: cp30 J/(mol K), inlet300 K, outlet uniformly310–330 K, and independent flow alternatives1/2 mol/s with probabilities1/4 and3/4. Requested outputs include duty and molar enthalpy difference. Independent mean duty is1050 W. Author the law with its validity interval and enthalpy datum; the operation accepts other lawful admitted cases rather than hard-coding this integrand. Existing authored unit and caloric vocabulary supply the first consumer.

The request names original source/context, scientific operation/settings, quantity-typed coordinates, measure/transform, selected outputs, estimator controls and replay policy. Initial measures are products of bounded continuous uniforms and finite categories with explicit normalized probabilities. Reject negative/nonfinite probabilities, zero total mass, invalid bounds, incompatible units and conflicting assignments before execution. Keep category identity and sampled occurrence separate even when realized values coincide.

An admitted transform maps the base unit cube/categories into physical coordinates, retaining its definition, domain and induced law. T=310 K+20 K·u² is a different law from uniform T; its independent mean duty is875 W under the same flow probabilities. Pushforward expectation applies no additional density Jacobian; integration against a declared physical density is a distinct meaning and is not silently inferred. Dependent inputs require an explicit joint transform, not a covariance-based independence guess.

Each output has its own estimand/availability. Retain failed scientific members. Default behavior withholds a completed expectation when a required positive-weight evaluation lacks that output; never drop and renormalize. A separately requested failure-probability estimand may explicitly classify scientific admission/domain/solve outcomes. Cancellation, infrastructure failure and unsupported interpretation are not physical failures. Statistical uncertainty is not an enclosure or truth claim about the model.

## Library composition, iteration and replay

Use Numerica 3.0.1 `ContinuousGrid`, `DiscreteGrid` and nested `Grid` for adaptive samples, and one `StatisticsAccumulator` per physical scalar output. The library's sample weight is the reciprocal **proposal** density/mass. It does not encode the authored target probability law. `Grid::add_training_sample(sample, eval)` multiplies `eval` by this proposal correction internally; `StatisticsAccumulator::add_sample(eval, sample)` merely accumulates its supplied value. [F03](#F03) fixes their distinct composition, adaptation target and iteration semantics. The [focused differentiation/integration account](../library_leverage/libraries/numerica/differentiation-and-integration.md#adaptive-integration-and-combinatorial-output) supplies orientation; the [selected numerical integration source](https://docs.rs/crate/numerica/3.0.1/source/src/numerical_integration.rs) owns the consumed API behavior. Qualify the actual maintained supplier source when its patch differs from that published release.

Workers receive compatible frozen iteration grids. `clone_without_samples`, `is_mergeable` and `merge` support collecting compatible observations; update the adaptive grid only at declared barriers. Do not independently adapt workers and interpret their weights as a common frozen distribution. Independent lanes own mutable scratch; compatible mathematical products share immutable backing.

Start with scalar ordinary case execution and fixed-weight Monte Carlo as a simple explicit realization/reference. Adaptive integration is selected as another realization, without a universal variance-improvement claim. General solves remain independent scientific members; C's qualified pure batch operation is integrated only for eligible arithmetic, preserving ordinary solve semantics. Initial pointwise derivatives use existing demands; derivatives of expectation need a separate estimator/interchange contract and are not implied by differentiating the sampler.

Controls specify iteration/sample limits and selected estimate/standard-error interpretation, with absolute/relative output-unit precision targets. At a limit report the actual estimate and unmet target. `MonteCarloRng::new(seed,stream_id)` plus state export/import support stream reproduction. Retain points, categories, weights, iteration identity and selected RNG/grid state through existing custody. Initial replay reproduces the sample population and its interpretation. Bitwise accumulation needs the same ordering and conditions; a seed alone is insufficient.

Cancellation stops issuance, settles live members and publishes incomplete original outcomes, not a completed expectation from a convenient subset. Restart uses the original retained iteration boundary or a distinct attempt, without silently mixing populations.

Admission cannot convert an arbitrary display label into an executable coordinate or assign a different source revision at execution time.

**Scientific meaning to implement.** Represent the initial law as normalized Lebesgue probability on a finite unit cube combined with a finite ordered categorical population carrying explicit masses. Continuous uniforms map base coordinates affinely into finite physical intervals. Categories retain their original identity, including zero-mass categories, and carry finite values admitted against the target coordinate. Require explicitly normalized probabilities, accepting only the declared numerical normalization tolerance; retain submitted and admitted mass interpretation. Refuse negative/nonfinite mass, zero total mass, invalid bounds, unrepresentable assignments, overlapping/conflicting targets, missing outputs and incompatible physical types before issuing scientific work. Zero-mass categories stay in provenance but need no scientific evaluation.

An explicit joint transform may map these base variables to dependent physical assignments. Its authored function and domain use the same physically typed mathematics and validity checks as the case; the transform is executable meaning, not a string to be reparsed by a result reader. This supports the selected correlated-transform branch without introducing a new distribution framework. A pushforward computes `E[f(T(U,C))]` under its declared base law. For the heater, `T=310 K+20 K·u²` changes the temperature law; adding a physical Jacobian to this expectation would change the estimand. Direct integration against an independently declared physical density needs its own density/change-of-variables contract and is outside the initial admitted request.

**Steps and resulting interface.** Declare the new request/admitted meaning under the runtime scientific owner, then its authored/result vocabulary in `crates/pse-schema/src/catalog/modeling_analysis.rs` and the relevant operation declarations in `catalog/operations.rs`. ### F03 — Adapt a shared proposal without changing the target measure

**Supplier contract and readiness.** This package consumes F02's execution/reduction interface and the actual selected Numerica source. In 3.0.1, `DiscreteGrid::sample` returns inverse selected-bin probability multiplied by a child sample's inverse density; `ContinuousGrid::sample` returns the inverse density on the unit cube. Thus `Sample::get_weight()` is `1/q(c,u)`, including all nested proposal factors. `DiscreteGrid` starts with equal bin probabilities, independently of authored masses. `add_training_sample` internally adds `eval×weight` and passes an unweighted `eval` into child training. The library grid accumulator therefore estimates the supplied training integrand, not every requested physical output. See the [integration source and inline controls](https://docs.rs/crate/numerica/3.0.1/source/src/numerical_integration.rs).

The installed source also exposes `ContinuousGrid::new_with_min_probability_density`, a mixture with positive uniform density; qualify this maintained API through B's supplier-control route and retain its effective source revision. Consume its reciprocal **mixture** density, with no extra mixture correction in the application. Set a finite, admitted `DiscreteGrid::new(..., max_prob_ratio, false)` ratio of at least one to retain categorical support and a continuous mixture floor `0<epsilon≤1` to retain cube support. If that API is not in the source actually selected for the workspace, deliver the targeted supplier change before adaptive execution; an application-private substitute is not the target. Admit finite learning rates in `[0,1]`, positive bin counts/evolution, finite sample limits and physical adaptation scales before grid construction rather than relying on undocumented constructor validation.

Source inspection exposes another prerequisite: the inspected 3.0.1 `DiscreteGrid::clone_without_samples` clears each bin accumulator but discards the result of `bin.sub_grid.as_ref().map(|g| g.clone_without_samples())`. Pending nested child samples therefore survive that call. Correct recursive child replacement at the supplier owner under B's control contract, with a nested regression test, before using it to fork worker grids. Do not assume the method name establishes this guarantee or work around it with a second grid implementation.

**Target/proposal composition.** Build a nested discrete grid for ordered positive-mass category coordinates, ending in a continuous grid for the unit-cube coordinates. Purely discrete requests omit the continuous child; purely continuous requests use it directly. For original retained zero-mass categories, keep a mapping from active grid index to authored category identity. Let `p(c)` be the product of the declared categorical masses, `T` the admitted physical transform, and `w=sample.get_weight()`. The base continuous probability density is one. Each output's corrected contribution is

`z_j = p(c) × (f_j(T(u,c)) - b_j) × w`.

Feed the centered interval contribution `z_j` to its own `StatisticsAccumulator::add_sample(z_j, Some(sample))`; report the physical estimate as `b_j + mean(z_j)` and its standard error from the centered accumulator. The declared target law is normalized, so adding the reference back is exact independently of realized proposal-weight sums. For point quantities b_j is a mandatory admitted reference point; for linear/difference outputs the initial default is zero. Retain the reference with the result and replay state. Do not divide by an estimated sum of weights: the declared measure is already normalized. No physical interval width or transform Jacobian is added for this pushforward. By contrast, training receives the **uncorrected** scalar integrand described below; passing `z_j` to `add_training_sample` would apply `w` twice. A constant-one output under unequal categorical probabilities is a required normalization control and must estimate one even while proposal probabilities adapt.

**One adaptation target for several dimensioned outputs.** The request declares positive characteristic interval scales `s_j` and reference values `b_j` for selected training outputs. Linear quantities may use zero; affine point quantities require a physically meaningful admitted reference. Admit reference/scale conversions with the corresponding output coordinates; never add watts to joules per mole or divide an affine point by a point-valued scale. Select the dimensionless scalar target `a(c,u)=p(c)×max_j |(f_j(T(u,c))−b_j)/s_j|` over the explicitly selected training outputs. The duty/enthalpy-difference heater uses zero references. Pass `a` to `grid.add_training_sample(sample, a)`; Numerica applies proposal correction internally. The max-norm and physical references/scales make adaptation meaning invariant under equivalent output representation changes. Retain the selected outputs, references, scales and target rule in attribution. A signed output still contributes its signed `z_j` to its own statistics; the same admitted references center the output accumulators, and are added back only after reduction as specified above. This preserves the normalized physical estimand while making finite point estimates and uncertainty covariant under affine representation changes. Grid statistics describe `a`; they never substitute for physical output statistics. If a required training output is unavailable, do not train on a fabricated zero: settle that iteration as incomplete and withhold its grid update. Ordinary per-output availability remains visible independently.

**Iteration algorithm and ownership.** Freeze one proposal snapshot and its interpretation at the start of an iteration. Assign deterministic stream IDs and occurrence ordinal ranges to independent lanes. Each lane receives a qualified `clone_without_samples` grid and its own unprocessed output accumulators; all lanes sample this same frozen proposal, accumulate training observations and join their ordinary scientific members. A lane never calls `update` independently. At the barrier, check the original iteration identity, law/transform, training references/scales, grid settings and stream/ordinal partition, then require `Grid::is_mergeable` before `Grid::merge`. The native check covers proposal structure/PDF compatibility; it does not know physical meaning. Reject a duplicate lane contribution or already-merged ordinal range before mutation. `Grid::merge` uses non-resetting sample merges, so retrying it is not idempotent.

Merge each physical output's pending lane samples once with `StatisticsAccumulator::merge_samples`, retaining deterministic lane/ordinal merge order. Only after required members settle, close the physical accumulators with `update_iter(false)` and update the training grid once through `Grid::update(discrete_learning_rate, continuous_learning_rate)`. Retain completed iteration counts; never use `update_iter(true)`'s estimated-variance weighting as an unstated change to the estimator. Require at least two samples for a closed statistical iteration and explicitly handle insufficient samples instead of accepting the library's false update result as convergence. Check stopping on the declared physical estimates/errors; a library training chi-squared or zero-error field does not certify model truth or a confidence enclosure. No general variance-improvement claim is made.

**Replay, stop and restart.** Retain points, active-to-authored category mapping, target masses, proposal weights, transform/version, iteration/lane/ordinal, selected supplier realization and RNG/grid boundary state. `MonteCarloRng::export/import` reproduce a stream state; a seed without stream assignment, consumed positions and proposal snapshots cannot reproduce an adaptive population. Use supported supplier serialization for grid/accumulator state with a versioned application envelope, or a source-qualified supplier state interface if required features are absent. A checkpoint seals a completed merged iteration with no unconsumed lane observations and is published once. Restore that original boundary and resume the next iteration, or start a distinct attempt; do not restore half-applied merges. Mid-iteration interruption retains original member outcomes and sample attribution but does not claim a new committed adaptation boundary. Cancellation stops issuance and joins lanes before sealing incomplete output. Same-order replay may reproduce accumulation under the same arithmetic conditions; population replay alone promises no cross-platform bitwise sum.

**Footprint and completion.** Put this composition beside the runtime study execution owner, consuming shared preparation from A and the qualified pure batch operation from C only where F04 admits it. Supplier fixes remain in the controlled Numerica source; runtime code contains scientific target/proposal policy and existing lane orchestration, not a copied VEGAS implementation. Remove provisional application grid/statistics implementations when the supplier path and all consumers pass their targeted tests. Ready acceptance covers unequal categorical proposals, constant-one normalization, the 1050 W and 875 W laws, outputs in different unit scales, signed/constant outputs, nested child clearing, incompatible proposal merge, duplicate-merge refusal, stream separation, stopped iteration, restored sealed boundary and unmet precision at a limit. Independent finite contribution calculations must expose an extra `p`, extra `w` or unwanted Jacobian; reproducing only the production formula in a test is insufficient.

### A02 — Settled shared contracts

The scientific question, submission, prepared structure, evaluator, factorization, start, attempt, result and product have different identity purposes. The following consumed-dependency contract governs future implementation; equality of a hash or storage encoding is not evidence of compatibility.

| Product | Consumed meaning and invalidation |
|---|---|
| Semantic question | Physical model/data/conditions, active roles, enforced requirements, branch/regime and requested scientific products/evidence; documentary labels and numerical guesses do not define the question |
| Submission | Exact selected question plus required/advisory MethodRequest and starts; actual execution has a separate attempt identity |
| Symbolic preparation | Selected authored expressions/functions, topology/incidence and active structural roles; a late value change does not invalidate structure unless specialization consumed that value |
| Numerical evaluator | Prepared DAG, parameter/function/provider layout, numerical realization, derivative shape/order and consumed optimization choices; mutable evaluation buffers stay attempt-owned |
| Symbolic linear analysis | Complete sparsity/layout/ordering and consumed algorithm choices; equal dimensions alone are insufficient |
| Numeric factors | Actual matrix values and consumed numerical settings as well as compatible symbolic analysis; repeated right-hand sides can reuse valid factors |
| Starts and retained runtime products | Exact selected point/branch/context and actual compatible service/resource owner; portable scientific identity does not grant runtime admission |
| Derived product | Original operation/step/member/reference point where applicable, quantity, requested coverage and mathematical assumptions; unavailable point/coverage cannot be filled from another same-quantity product |

Use the existing revision, identity and retention owners to express these dependencies. Remove duplicate derivation where an existing tracked query can wholly own it, but retain runtime custody/pressure accounting where it supplies a different responsibility. No second universal cache or serialization-defined semantic hash is selected.

The first operation mapping is explicit: source/declaration inspection requires no numerical state; semantic topology and declared structural diagnostics require selected admitted meanings but no successful solve; square Solve consumes its admitted case; initialization returns the full report, including successful prior attempts; point analyses require their actual reference point and local assumptions. Extremize/Infer/Expect and broader dynamics enter only through supported operation contracts selected by D/E/G. Profile labels alone do not authorize unsupported inequalities, branch enumeration, derivative orders or certificates. Mandatory unavailable products refuse; optional unavailable products remain explicit.

An outcome owns task-level analysis products and zero or more numerical members. Structural findings are qualified by their inspected scope and analysis evidence, not candidate-use permission. Point-derived products combine exact original point permission with local validity through C05's shared owner. Diagnostic visibility, scientific reuse, response readiness, native termination and physical drain remain separate. Values/duals/sensitivities reconstruct only where retained transformation assumptions and mappings support their meaning.

### A04 — Assigned corrections and required discrimination

DA-062 remains applicable to the inspected ordinary-variable interval paths: `pse-backend-native/src/quality.rs` already owns physical tolerance violations; causal acceptance uses it, while initialization's final variable check is strict. **Selected correction:** C07 reuses the quality operation for ordinary free-variable intervals and migrates affected conditional/initialization consumers, retaining strict domain/sign/fixed-specification checks. Numerica interval arithmetic and SMT do not replace this policy. No new general numerical subsystem is needed.

DA-063 remains applicable: authored `surreal_study_workbench.rs::publication` consults the pending global capture gate and execution/control writers reach that guard. **Selected replacement design:** G08 captures exact membership, protections and an idempotent receipt in one bounded transaction. Capture reads a preexisting publication-witness record with commit-conflict registration; every selector/membership/metadata-changing writer updates that witness atomically, including creates and removals that could change future matches. Lease-only renewal does not. Cancellation never waits for capture but updates the witness when it changes captured facts. Concurrent relevant publication invalidates capture and causes bounded retry; it does not wait for capture's pending state.

Start with one conservative publication witness rather than unproved selector partitioning. Record-level `FOR UPDATE` does not guard query predicates: completeness comes from the complete writer set changing the witness, plus the transaction's snapshot and protected-result retention. Read-only selection, missing witness, writer bypass or independently committed protections cannot satisfy this contract. A scoped-witness optimization requires its own selector-closure evidence. The new design removes the durable pending gate and open-capture RPC, not exact manifest/result protections or authenticated failed-owner cleanup. Existing pending captures must settle/drain under their original owner before any production cutover.

Critical feasibility evidence is still required at G08 before adoption: selected-engine conflicts/retries, concurrent new matching and metadata mutations, rollback on a failed module call if that branch is selected, lost acknowledgement replay, unchanged identity/different body refusal and actual shutdown/drain. Installed SurrealDB's `select_for_update_test.rs` shows a concurrent witness writer committing and the registered reader failing at commit, with a plain-select countercontrol; that test is RocksDB-specific and is not selected-backend qualification. Consequently neither DA-063 nor G08 is declared repaired here.

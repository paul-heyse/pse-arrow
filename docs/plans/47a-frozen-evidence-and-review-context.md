# Plan47a: Frozen evidence and review context

## Target and assessed foundation

Own the explicit distinction between live observation and frozen recorded review, descriptive scientific context, exact related-member inventory and immutable document ingress. The [coordinator](47-pipeline-diagnostics-and-review-artifacts.md) owns review F01–F03, RC01–RC03 and inquiry decisions; this companion owns A01–A05 progress. RC01/RC02 are accepted. Earlier selected acceptance and the historical completion audit are recorded below; the corrective Outcome closes A05. The coordinator retains composed finding disposition.

**Implemented, qualification suppliers — 2026-10-19:** 47f's assembled controls exposed
missing standalone initialization/recycle context and dynamic segment-statistics transport.
Explicit selection now copies original joined facts into the existing charged context owner.
Initialization retains original block/predecessor identities, failed and committed stages;
recycles retain effective controls, numerical policy/targets and native records. Mandatory
scientific/event result ownership precedes optional copying, whose refusal remains independent.
Unrequested copying is absent; unsupported standalone context stays explicitly unavailable.
Dynamic native statistics retain original run and segment/reset identity without fresh getters,
including when the compact live metric catalogue reports curtailment. Supplied handoff admission
checks actual native payloads against its selected permission. The [47f Outcome](47f-qualification-and-design-publication.md#outcome)
owns actual assembled tests, measurements and limits; these additions create no replay authority.

**Interface-checked:** `pse-runtime/src/inspection.rs::inspect_image` combines interpretation with current monotonic projection and sibling checkpoint lookup. `pse-diagnostics/src/inspection.rs::select_window` already consumes a supplied endpoint; summary expiry marks stale and does not erase current/cumulative facts. Runtime `inspection_comparison.rs` takes borrowed invocation documents. `workflow/replay.rs` and workflow diagnostic source-map/result owners hold substantial explanatory context but have different execution/admission contracts. These are suitable foundations after separating their consumed operations, rather than moving storage/scientific dependencies into the low diagnostic crate.

Blueprint §23.1 owns current live diagnostics and blueprint §19.2 owns scientific context/replay. The [review reader control](../design_review/evidence/pipeline-diagnostics-and-review-artifacts-2026-10-18/README.md) confirms that an old raw checkpoint can retain recent events which live interpretation legitimately excludes. Its scratch `clock=null` fallback is a control, not the intended replacement. Do not edit saved raw data or disable live clock mappings to manufacture frozen semantics.

## A01 — Establish the accepted shared contracts

Specify and route the RC01/RC02 contract changes before the new consumers rely on them. Live reads observe current time and known local publication; frozen reads consume a recorded endpoint/interval and an explicit immutable member resolver. Descriptive context reports what was submitted/retained without admitting another numerical execution. A pack's completion is independent of scientific/capture completion. Preserve existing replay, live-summary and invocation-clock meanings.

Put the enduring contract in its actual architecture owner through the authorized design/revision route. Amend relevant proposed rationale, or create a short ADR for genuinely new relation/kernel/binding contracts; accepted ADRs are not edited. Do not manufacture a new crate or broad ADR merely for ordinary API composition. The coordinator's accepted decisions are sufficient target choices; implementation or new rule decisions are not inferred from their existence.

Identify the actual serialization/declaration owner before adding public records and migrate generated/schema consumers with that declaration. Define explicit format/version, source identity, temporal scope, availability and recorded selection meaning without a universal solver schema. **Targeted acceptance:** local contract fixtures distinguish live/frozen requests and recorded-context/reconstruction eligibility; unknown versions and unsupported interpretation return explicit failure. No runtime/store/native startup is needed for those tests.

<a id="a02"></a>
## A02 — Read frozen evidence at recorded time

Add an explicit runtime frozen-reader operation, using copied inputs and the existing pure interpreter. Its request selects an exact operation or invocation and either a recorded endpoint/lookback or an explicit source-clock interval. Default frozen checkpoint inspection anchors at that checkpoint's recorded operation `read_at`; it never advances to the reader's wall or monotonic time. A last-minute question means a minute within recorded evidence, not a minute preceding today's inspection.

Resolve related documents only through supplied member identities/relative membership. The offline resolver never falls back to neighbouring live checkpoints, attaches a process, opens the scientific store or searches arbitrary original paths. Keep live checkpoint discovery/inspection as a distinct valid operation. Original paths and process locators may remain descriptive source facts; they are not offline resolution authority or process-control capability.

Use recorded clock mappings and uncertainty only where they justify cross-process alignment. Otherwise retain independent source-clock views and state that ordering/alignment is unknown. Preserve recorded freshness/coverage and distinguish it from present live eligibility; frozen readback neither renews an expired hub summary nor asserts that the producer still runs. Selection retains needed predecessor baselines, coherent records and generation/reset coverage; no interpolation reconstructs missing points.

Migrate runtime/Python saved-image consumers onto the explicit route when their purpose is recorded review. Remove duplicated saved-file current-clock/sibling-lookup glue; do not remove the live implementation or weaken its expiry behavior. **Targeted acceptance:** the same fixture/interval yields identical selected rows, coverage and evidence references at changed reader times and after relocation. Test absent/unknown clocks, crossing/reset/gapped windows, an exited producer, stale-as-recorded input and a conflicting sibling file which must never be consulted. Preserve original raw bytes.

<a id="a03"></a>
## A03 — Export descriptive model and run context

Create a descriptive projection at the existing workflow/scientific export boundary. It accepts exact run/attempt/invocation or retained operation selections and requested explanatory scope, and emits the available authoritative model/source/input/settings/start/outcome context with references and explicit unavailable items. It does not call reconstruction admission, instantiate custom factories, reevaluate equations or run solvers to complete missing facts.

Include the selected original authored equations/relations and physical/provider definitions, numerical/fixed inputs and starts, actual effective settings and selected method/profile, requested outputs/derivatives, units/bases/reference states, original assessment/outcomes and known source mappings. Retain model revision/run/attempt/step/native-attempt identity when present; a failure before those identities exist retains its actual earlier operation/source error. Opaque caller-supplied executable capabilities can be described as unavailable with the recorded descriptor; do not claim their unrecorded implementation or reconstructibility.

Refactor shared fact gathering with Replay where it removes duplication, while keeping descriptive availability separate from Replay's stronger all-or-refuse build/runtime/factory predicates. Descriptive output must remain possible for a reviewable failure which cannot be rerun. Record actual known native version/fork/options and queried defaults where retained; repository image pins do not prove which backend executed. Missing execution detail stays unknown rather than launching an environment proof campaign.

For I05, preserve exact event/native/source transformations and their validity. Static source maps can include aliases, gathers, fixed/eliminated coordinates and shared arithmetic contributors, but cannot supply a universal dual/stationarity pullback or executed branch. Existing retained context is preferred over new preparation. If an explicitly requested static map requires preparation, expose that work/deadline before export; any fresh numerical diagnostic remains a separate operation with its actual origin and independent permission. Plain offline reading performs neither.

Stream selected sources and bounded metadata from existing protected owners; avoid simultaneously cloning whole Replay, native history and result payloads. Expose missing required explanatory context to D01 rather than disguising it as an empty closure. **Targeted acceptance:** a non-reconstructible custom capability and failed pre-handle request still produce descriptive context; missing fields remain unavailable; selected physical semantics/settings/starts are exact; no factory, residual/provider/derivative callback or solver is invoked. Different scientific product availability remains independent.

<a id="a04"></a>
## A04 — Select actual related members and attempts

Supply a bounded, pageable inventory for the selected review scope, using actual scientific/diagnostic identities and existing relationship/protected-read owners. Explicitly distinguish current-attempt selection from selected retained historical retries. Existing managed current-attempt readback and a finite occurrence prefix remain useful, but do not establish all-history membership. I07 settles any additional retained enumeration needed for the selected claim.

Retain actual preparation/pre-handle operations, parent/shared-producer/waiter links, native children, fitting experiments, dynamic segments/replay/backward work, horizon foreground/background roles, surrogate/fidelity correspondence and later result-access operations when selected. Do not fabricate a complete tree: missing/evicted references, unavailable history and clock uncertainty remain enumerated gaps. An exact child never binds to a convenient current root or another attempt merely because its name matches.

Selection captures immutable metadata and actual known readable prefixes/fences at the owner boundary. It does not hold a global scientific lease or stop execution to assemble an atomic cross-process graph. Growing live work can produce an explicitly bounded prefix selection; subsequent facts form a different selection, not silent mutation of the first. Preserve current result/protection and resource drain rules.

**Targeted acceptance:** current versus retained retry selection; absent parent/child; shared-flight waiter; more members than one page; one early finished child and one active/failed child; overlapping horizon background; exact selected empty result; failure before handle; and unrelated same-name members. Each inclusion or omission must be attributable to selection/retention/availability, without service/native dependencies for pure inventory logic.

<a id="a05"></a>
## A05 — Admit recorded documents without live runtime handles

Expose immutable file/document ingress for checkpoints, invocation evidence, descriptive context, detail/capture documents and supplied membership. It must be usable by 47c/47e and the pack reader without `RunResult`, native handles or source-store access. Use existing versioned codecs and schema declarations; preserve exact UInt64 identities, tagged nonfinite/unavailable values and source JSON-pointer/event references. A parse success does not establish semantic compatibility or cross-clock alignment.

Keep finite input/decoded/view allocations and cancellation with the reader operation; reject unsupported versions or inconsistent/duplicate identities rather than silently coercing them. Do not build a second retention store or generic schema-inference layer. Omitted/partial document sets remain inspectable under their stated available scope, while analysis needing an absent premise reports a limitation.

Adapt live callers through existing pure helpers without a parallel numerical-policy implementation. **Targeted acceptance:** invocation explanation/comparison from saved documents only; missing sources, conflicting identities, unknown versions and exact large integers; repeated readers after original runtime destruction; and no filesystem lookup outside supplied members. Tests exercise actual public Rust/Python ingress rather than only helper serialization.

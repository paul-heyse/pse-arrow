## Acceptance architecture and library use

Keep distinct local adequacy, generated projection fidelity, protocol interoperability,
native ownership/settlement, physical conservation, independent reference agreement and
measured benefit. Shared fixtures reduce setup duplication; independent expectations must
still expose a correlated mapper/oracle bug. Native correctness routes retain explicit
Arrow force-validation. Do not make a local semantic assertion require unrelated native
database/solver preparation, or replace actual effect boundaries with mocks.

Library-based generation and randomized inputs supply an assurance role, not an oracle.
Use Buffa generated/independently authored malformed messages to challenge boundary admission;
native constants and independent reference drivers define expected physical meaning. See
[CR04](../plan_improvement_reviews/plan64-65-contracts-and-runtime-analysis-2026-11-06.md#CR04)
and [S07](../plan_improvement_reviews/plan64-65-scientific-extensibility-analysis-2026-11-06.md#S07).
Selected Proto validation, Arrow/DataFusion, solver and runtime contracts are detailed at their
actual A–K owners, not restated as a qualification library catalogue.

Measure complete operations only for claimed benefits: preparation/edit/re-solve, a selected
large query through release, original evidence export/inspection, and a representative campaign.
Include examined work, retained buffers, failed/retried effects and disposal. Keep configured
unbounded host width, incremental compilation and normal compiler caching. A microbenchmark
or cold-build interruption cannot establish or refute whole-operation benefit.

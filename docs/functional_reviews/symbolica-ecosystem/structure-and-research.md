# Structure, analytical products and mathematical research

Inspected 2026-11-09 at `7d89d16f` with concurrent operations/codegen edits preserved. **Interface-checked** means representative source and exact supplier reads, not compilation or numerical execution. All recommendations are **Proposed**, with qualitative expected benefits; no performance improvement is Measured. Standard: core3.4, efficient architecture heuristics1.0, process-simulator1.5 and pse-arrow binding from `standard.toml`. This assessment applies AP-04/AP-07, H2/H4/H8/H12/H15 and PS-01/05/06/07/10/11; it is a functional review assessment, not a diagnostic audit or implementation authorization.

## O11 — Selected analytical mathematics as a developer result

**Recommend a bounded analytical inspection operation over a selected admitted expression or small equation block**, sharing the original resolved mathematical product and its symbolic definitions. A model developer should be able to ask for a derivative, remainder-aware local series, exact coefficient/identity check or parameter-dependent analytical form, and receive source-linked mathematics with its physical context, assumptions, unsupported conditions and evidence level. Start with exact derivative/series/identity operations already native to the supplier; treat symbolic integration and approximation as explicitly different requested products rather than automatic simplification.

This has concrete scientific value beyond an API inventory. The authored `packages/reference/methods/models/caloric.pse` already exposes cp, enthalpy and entropy with reference values and temperatures. `ideal-caloric-state.pse` retains distinct component functions and physical validity ranges. A developer can inspect whether a caloric primitive differentiates back to the selected cp law, whether an entropy derivative has the expected temperature dependence, and how a constitutive expression behaves near a declared reference state. These are proposed developer activities, not claims of present defects or a supplier-proved empirical envelope. Existing code in `pse-math::numerics::caloric` separately shows why temperature resolution, datum-bearing enthalpy and consuming energy requirements must not collapse into anonymous scalar algebra.

**Preferred realization:** select through the current compiler/model owner, retain one qualified exact expression/definition set, call native Symbolica derivative, `AtomCore::series` and polynomial/rational operations, and return a typed analysis artifact under the existing product/tooling/result path. A series result retains its order object; rendering the polynomial is a view. Preserve source occurrence and physical interpretation outside Symbolica. An expression that cannot flatten across providers/branches may return a supported local region with explicit scope, or refuse the requested whole-expression product. Do not invent an opaque whole-model scalar CAS path to make every request succeed.

**Alternatives:** exporting formulas to an independent notebook remains useful for free-form research, but repeats name reconstruction, loses ready access to physical/source support and creates manual interpretation work. Automatically injecting derived closed forms into production definitions would reduce some hand work but silently changes model authority and is rejected. Implementing a local derivative/series engine is worse than composing the native machinery. A thin operation in the product owner is preferable to a standalone CAS service or a new generic analysis framework.

**Machinery and lifecycle:** this can consolidate ad hoc exact conversions, expression dumping and manual verification setup around a selected original product. The source inspection establishes possible duplication categories, not an already counted set of local implementations to delete. New work is request/result meaning, supported-operation selection, bounded supplier invocation and a source/physical presentation projection. Do not run product semantics inside the independent native host; blueprint §21.7 keeps scientific interpretation at its explicit product owner. The original source/premises must remain associated with the artifact after later edits, and interrupted or unsupported analysis cannot be published as a successful certificate.

**Conditional extensions within this result:** symbolic integration via separate `symbolica-integrate` can propose antiderivatives once its exact native release compatibility and resource behavior are established. Differentiate the candidate back, retain the reference constant and domain, and separately check interval/pole/branch conditions for any definite integral. A Padé approximant or truncated series changes the model unless it is explicitly a separate approximation product with stated use/domain; formal series order is not a uniform numeric error certificate. Built-in special functions can improve analytical expression support without requiring every execution backend to accept them. The report should expose unavailable numerical realization rather than invent a fallback.

**Interfaces/rule impact:** add selected analytical request/result variants within the existing scientific operation owner, not public raw Atoms as an alternative authoring authority. If a derived result is promoted into an authored law or an executable approximation, it must use ordinary typed edit/admission and its decision route. This recommendation itself requires no changed scientific correctness standard; durable new contracts or widened primitive semantics follow existing decisions.

**Demonstration:** selected caloric law with reference enthalpy/entropy, independently expected derivative and series coefficients; a domain boundary or provider region that is honestly scoped/refused; changed source whose old artifact remains historical; an approximation visibly distinguished from exact identity. Symbolic agreement alone must not claim physical validity across an unsupported temperature interval.

## O08 — Native indexed mathematical canonicalization

**Recommend a bounded indexed-expression capability within the analytical operation, with optional numerical preparation for supported pure contractions.** A constitutive developer should be able to compare two tensor-like expressions differing only by legitimate dummy-index naming and obtain a common mathematical representation without implementing graph isomorphism or index normalization in the application.

The maintained `tensors.rs::canonize_tensor_product` already converts indexed expressions into `TensorGraphNode` structures, handles open indices, rejects indices contracted more than once, invokes Graphica `canonize`, and reconstructs canonical mathematics. `AtomCore::canonize_tensors` returns external/dummy-index information and honors index groups. Source tests `open_index`, `nested_sum` and symmetry/renaming cases were read, not executed. This is an actual native cross-library composition, not a request to build its equivalent using low-level Graphica APIs.

A useful first activity is canonicalizing a small indexed constitutive contraction under renameable dummy indices while keeping species/component labels and external axes fixed. After canonicalization, ordinary exact simplification or shared evaluator preparation can see equal mathematics rather than independently expanded variants. This can remove application-owned dummy-index walkers and separate graph serialization *where such an operation is introduced*; there is no claim that the current product contains a bespoke general tensor canonicalizer.

**Compare complete alternatives:** current scalar/formal expansion is simpler for small fixed arrays and retains direct axis attribution. Native indexed canonicalization is preferable for mathematical equivalence/collection with real index structure because it keeps the algebraic owner in one library. Spenso is a distinct conditional realization when actual tensor-network contraction order, sparse tensor storage or large intermediates dominate. Its `Contract`, `DenseTensor`/`SparseTensor` and `TensorNetwork` capabilities warrant selection for a named contraction workload; they are unnecessary machinery for comparing two scalarized sums. Do not adopt Spenso or replace faer matrices simply to gain the word tensor.

**Conditions and rule impact:** only declared dummy groups may rename; physical ports, species identities, provenance and fallible provider operations are not dummy indices. Mathematical symmetries need valid properties, and external-coordinate maps survive preparation. New indexed authoring or executable tensor kernels would need explicit quantity/shape/admission contracts and the existing architecture decision route. A first analytical product can avoid inventing a second tensor authoring language or solver representation.

**Demonstration:** two equivalent contractions with renamed dummy indices canonicalize together; changing an external component/index group prevents equivalence; invalid multiple contraction refuses; source/physical annotations remain attributable. Compare retained scalar versus structured representations for the operation; no speedup should be asserted from the common form alone.

## Mapped mathematical-template reuse

**Recommend strengthening the existing definition/prepared-product reuse route with explicit parameter/input/output/derivative-axis binding transport.** A study or model author creating repeated mathematical instances should reuse qualified symbolic preparation while preserving distinct physical occurrences. Use the existing typed/resolved model definitions and canonical formal parameters as the first template authority.

The compiler `workspace/modeling/executable.rs` obtains numeric/guard read sets, creates ordered physical `Formal` entries and prepares selected residual regions. `pse-math::library::exact_evaluator` receives ordered parameters and named aliases jointly. `LocalPartials::new` builds demanded local partial definitions. Supplier `FunctionMap` distinguishes aliases expanded in caller-local scope from ordinary functions whose explicit parameters shadow global inputs. These are concrete interfaces through which one template and many instance bindings can retain native sharing without introducing a second optimizer.

A complete transported product must include axes/demand and output mappings, with current original guards, physical contracts and provider/context dependencies qualified by their owners. Instance source attribution remains per instance. Changed values can bind to one reusable mathematical template; changed definitions, shape, demanded derivatives or provider premises may invalidate it. Reusing preparation is not deduplicating scientific results.

**Alternative rejected as default:** canonicalizing every flowsheet on every prepare would add graph conversion, combinatorial search and a second cache-eligibility check before showing that existing definition sharing misses valuable reuse. Current `pse-structural::FlowGraph` intentionally keys semantic IDs, port physical contracts, explicit connection occurrences and tear groups. Its semantic key is not a defective unlabeled-topology key. Existing petgraph/rustworkx/POUNCE duties must remain distinct from isomorphism.

**Conditional extension worth retaining:** for independently authored but mathematically equivalent motifs that cannot use the same definition identity, a role-colored incidence graph can make units, ports, connections, scalar bindings and decision groups separate vertices. Graphica's vertex permutation then transports those records despite the missing canonical edge map. Equal canonical graphs are a candidate index; the mathematical owner validates actual expression/physical/provider equivalence. `c_B^{-1}∘c_A` yields a mapping but does not prove unique physical interpretation. HiddenData excludes metadata from equality, not canonical ordering or visibility. Converting additional entities into vertices can cost more than rebuilding a small evaluator.

**Demonstration:** two repeated authored instances share one qualified derivative/evaluator template with different parameter values and source identities; a changed guard or port role invalidates/refuses inappropriate reuse. Then compare independently authored motifs including parallel connections and grouped decisions to establish whether graph-assisted matching finds additional useful reuse. No generic canonical-cache interface is recommended before that second case exists. A changed prepared-product identity contract would follow D3/D4/D14 decisions; binding transport alone must not weaken them.

## O09 — Finite topology exploration

**Recommend a deliberately bounded candidate-generation workflow for a selected open or closed network family, not a universal process synthesizer.** The user is a process researcher exploring structural alternatives, not an operator expecting every generated graph to be feasible. This is valuable functionality even without a current generator to replace: Graphica can supply constraint-driven enumeration and isomorphism deduplication together, avoiding a new bespoke graph search.

Prefer `Graph::generate` with typed half-edge signatures and explicit vertex/equipment inventory bounds. Combine monotonic partial `filter_fn` checks with exact completed-candidate constraints. Convert surviving candidates into ordinary typed authored declarations; existing physical/model admission, structural analysis and scientific workflows determine feasibility. Use native exact mathematical screening only for supported admitted blocks. Reuse mathematical templates across candidates where their actual bindings agree. Expose a candidate-set outcome with complete/incomplete status, rejected/unsupported candidates, original generation premise and explicit stable output ordering.

**Alternatives:** manually authored candidates suit a tiny known set but do not provide systematic coverage; a generate-all-then-deduplicate application loop repeats native search/canonicalization responsibilities. A general mixed-integer superstructure optimizer is not equivalent to enumeration and may be better when useful process/economic relaxations guide a huge design space. Do not represent this feature as replacing SCIP or flowsheet tear selection.

**Feasibility limits constrain the selected family:** signature patterns are reusable allowed kinds, not exact equipment counts; internal nodes receive Default and signatures have no named-port order. `max_loops` alone does not make degree-two cycles/subdivisions finite. Generation retains a result map, abort polls at connected completed candidates, and progress does not transfer ownership. Root/valence-one bridge conventions are not physical flow; closed candidates with valid bridges need explicit settings. These are reasons to select a small finite family and admitted capability envelope, not reasons to mislabel partial enumeration complete.

**Interfaces/rules:** candidate-set request/result and conversion into ordinary authored models belong to the scientific/research owner. Graph generation grants no physical or solution authority. Durable candidate identities must use application source/interpretation and sorted canonical objects, not HashMap iteration order or hidden metadata serialization. Adding a workflow/new authored contract follows normal decisions; no host memory partition or smaller workstation allocation is proposed.

**Demonstration:** a restricted circulation family with independently expected tiny topology population, both externally anchored and closed forms, exact equipment count, parallel-role distinctions and a physical-invalid candidate. Include cancellation with explicit partial population and source provenance. Each admitted candidate's original science is verified independently; symmetry cardinalities are not probabilities or numbers of scientifically identical trials.

## O13 — Native mathematical presentation

**Recommend using Symbolica native printer options for derived mathematical expression views**, retaining physical/source labels and namespaces in a separate product projection. The current authoring renderer remains authoritative for DSL round-trip text; replacing it with a CAS printer would lose declarations, units and lexical meaning. Native math rendering is a useful companion to the analytical products above, reducing the temptation to maintain a parallel mathematical pretty-printer.

`printer.rs` supports native LaTeX/Typst modes; the current Plan66k native-view contract already distinguishes physical stream/species/phase identity, units/datum, partiality and provenance. Extend that existing view consumer rather than introducing a CAS-specific report authority. An equation rendering is not a lossless symbolic codec, model identity or evidence of verification.

The Typst plugin's native payload/math_display/typst_ast modules are a conditional future option for annotated rich reports requiring structure not available through native printer output. Its development/package version distinction, additional dependency closure and attachment/callback custody make immediate adoption a weaker choice than the already linked printer. WASM is a deployment alternative for a selected interactive preview, not a reason to move native scientific execution into a browser. Demonstrate expression/source/physical correspondence, unambiguous namespace printing and excluded or unknown fields honestly, using the protected original result rather than recomputing science while formatting.

## Interaction and priority

The strongest near-term functional addition in this lane is selected analytical inspection with native presentation: it offers visible developer/scientific value while using existing resolved authority and mathematical primitives. Mapped mathematical reuse should advance with the review's shared-demand/evaluator recommendations rather than create another preparation service. Indexed canonicalization is a bounded mathematical subproduct; tensor-network execution remains conditional. Finite topology exploration is a separate opt-in research outcome with genuine additional domain/interface work, and should not block simplifying current mathematical operations.

All recommendations keep the authority chain explicit. Their original source, quantity/validity premises, derivative demand and current numerical product remain authoritative; library representations and workflow outputs are derived. No current implementation package or plan status is changed by this assessment. Source evidence establishes enabling contracts and plausible value; delivery demonstrations above remain proposed, not performed.

# Native tools and agent access

Rust APIs own scientific execution, canonical operations and physical lifetimes. The Python
product, Python MCP endpoint, generated capability CLI, retained frontend sessions and
reconnect helpers are retired. Agent startup requires no repository Python MCP attachment.
Current implementation and qualification obligations belong to
[Plan58](../plans/58-rust-owned-system.md).

## Direct owner routes

Use `just --list` and `just --usage RECIPE` for current commands. Prepare the independent
host explicitly with `scripts/bootstrap-host`; `scripts/pse-env --explain` and host help
never build missing tooling. `scripts/pse-env -- COMMAND` selects environment and original
physical containment. `just activity [UNIT]` observes manager/kernel facts directly.

The [native workflow guide](native-workflow.md) describes model construction and results;
the [operational store guide](operational-store.md) describes canonical projects and studies.
`just project-build` explicitly builds the dedicated Rust project operator;
`just project --help` invokes that prepared executable. `just evidence-build` builds the
independently disposable evidence operator; `just evidence --help` reads its grammar.
Canonical service construction belongs to the Rust application, described in the
[substrate guide](surreal-substrate.md#setup-and-state-ownership).

Use ordinary editor/shell operations for source navigation. Native xtask owns documentation,
ADRs, lifecycle and register operations. `just workspace-sources --selection FILE` builds a
bounded source-only knowledge corpus from explicit JSON selection. Its coverage and source
identities do not authorize execution or establish scientific correctness. There is no
universal replacement agent server or operation catalogue.

## Native schemas, actions and protected reads

A typed request, actual prepared artifact and performing owner establish their own premises.
Generated Rust relations and JSON schemas describe documents and data; they grant no service,
placement or release authority. `just codegen` publishes declared outputs, and
`just codegen-check` checks drift. Change the declaration/generator rather than generated files.

Native handles retain cancellation, join and physical settlement when an observer disappears.
Runtime result readers retain original run/attempt/manifest identities and protected payload
lifetimes. Read completeness, successful transport and scientific success are independent.
See [qualification commands](validation-assessment.md) for scope reporting and
[typed inspection](simulation-diagnostics.md#typed-inspection-and-reader-ownership) for copied
diagnostic evidence. Offline review reads supplied members; it does not follow source paths
to reopen a model or database.

## Typed telemetry investigations

`just telemetry inspect` passively inspects the selected installed service.
`just telemetry install`, `setup`, `start`, `stop`, `reconfigure` and
`recover-configuration` are explicit operator actions; see
[optional native telemetry](agent-environment.md#optional-native-telemetry).
`pse_host::telemetry` resolves bounded settings without installing an SDK or starting a service.
The process-owned Rust telemetry host owns exporters and its independent loss/shutdown facts.

The former Python configuration/health, trace lookup, watch, investigation and selection
wrappers are retired. Existing backend data/rules are retained where configuration permits;
no native query/watch CLI equivalence is claimed. Operators may use the backend's own tools
with explicit credentials and selection. Such reads acquire no scientific ownership, and an
empty response cannot establish nonexecution, sampling, loss or expiry.

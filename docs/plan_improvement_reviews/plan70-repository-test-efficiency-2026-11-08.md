### <a id="i01"></a>I01 — Reuse graph analysis within one correctness admission

**Proposed · A01.** The correctness adapter traverses the transitive compiler graph
independently for every selected root to decide where Arrow validation must propagate.
It also traverses the union before and after feature admission, including the case

## Rust build and reuse judgment

The [Rust caching guide](../libraries/utilities/rust_caching.md) and its addendum
identify three distinct questions. Cargo may reuse a fresh unit in a checkout.
Incremental compilation can reduce work inside an edited unit. Managed sccache
0.19.0 can recover compatible outputs for eligible compiler calls when Cargo
needs them. The [build guide](../dev/build-performance.md) and
[Plan67d](../plans/67d-cargo-variants-and-sccache-reuse.md#outcome) record the
repository's pinned nightly workspace feature unification, content freshness,
checkout-local target roots, and managed cache with its patched local backend.
They also record the limit on build-script file freshness and the retained
incremental versus explicit non-incremental choices. The guide's older sccache
discussion supplies orientation. Use the selected 0.19.0 source and managed
probe for actual behavior. [Release-specific Rust compiler implementation](https://github.com/mozilla/sccache/blob/v0.19.0/src/compiler/rust.rs) ·
[Managed source patch](../../scripts/sccache-source/managed-disk.patch) ·
[Retained probe](../../scripts/sccache-source/probe.sh)

For a focused warm test, narrow unnecessary admitted units, binary work and
fixture work before changing the cache policy. For small source edits, compare
the actual incremental path and the critical path after the edit. For fresh
checkout or campaign recovery, separate eligible cacheable compiler work from
final links, build-script execution, rustdoc, native tool preparation and case
execution. Use Cargo timings, native phase observations and cache-stat deltas
only for a named route where the comparison could affect the recommendation.
Specify target/profile, features and providers, pinned tools, source edit,
cache state and competing work. For an absent-output comparison, use the managed
release's machine-readable statistics to distinguish hits, misses and
non-cacheable invocations. Use Cargo's timing overlap to see whether metadata
streaming and dependency pipelining affect the compiler critical path. These
diagnostics are more specific than aggregate cache hit rate. Treat a cached artifact and its later
authenticated lease as different operations. Test verdict, fixture readiness

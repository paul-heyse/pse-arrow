# Graphica canonicalization and generation boundaries

Reusable type: `graphica/labeled-canonical-generation`. **Interface-checked**, 2026-11-09 against locked 3.0.1 source and inline tests; no execution evidence.

Graphica canonicalizes labeled mixed-direction multigraphs under consistent `Eq`, `Ord` and `Hash` payload semantics. `canonize()` returns a canonical graph with original-to-canonical vertex map, vertex orbits/generators and an exact integer group size. Ordinary graph comparison remains stored-index comparison. `canonize_edges()` normalizes edge order under fixed vertex identities. `HiddenData<T,U>` excludes U from identity but retains and displays it; choosing ignored metadata and merging it after deduplication remain caller responsibilities.

`generate()` combines compatible typed half-edges and allowed incident multisets with structural bounds and partial filters, then canonicalizes connected completed graphs. Internal vertex labels use `N::default()`. Named port ordering and signature-specific internal payloads need separate encoding. `filter_fn` is called on partial graphs with the completed-vertex boundary: rejection discards every extension, so sound pruning cannot reject a currently missing feature that later construction may add.

Operationally, generation returns `Ok(map)` after completion and `Err(map)` after abortion. Both own accumulated canonical graphs and symmetry sizes. At least one of max vertices, max loops, progress or abort is required; bridge limits alone do not satisfy the termination check. `abort_check` is polled after a completed candidate is found connected, before bridge validation/canonicalization. `progress_fn` runs upon a unique graph's insertion. Neither supplies bounded cancellation latency through recursive search or a canonicalization call. Canonicalization stores discovered leaves in a map with no inspected explicit cap; generation retains discovered graphs even when progress consumes them. A bounded output count does not establish bounded intermediate search memory.

Spanning-tree connectivity is weak connectivity, and `external` means valence one rather than caller-specified boundary membership. Chain decomposition precedes bridge queries. Group size combines vertex symmetry with identical-edge permutations and contributes an extra factor of two only for each undirected self-loop. Directed self-loops do not receive that factor. The earlier account incorrectly included directed loops; the November9 addendum refresh checked and corrected this against the locked source. These conventions are not interchangeable with a graph application's physical boundary or multiplicity definitions.

These details are observed 3.0.1 implementation and documented API conditions. They identify useful capability and remaining contracts, not a guaranteed performance advantage.

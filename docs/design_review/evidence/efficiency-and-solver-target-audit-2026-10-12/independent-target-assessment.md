## 1. Principal judgment

**Revise the review and the proposed target.** The original review identifies important work amplification and a valuable direction: let admitted immutable model products serve local calculation, retain preparation at its true validity lifetime, separate numerical warm state from workspace retention, expose real native resource conflicts, and replace scattered numerical preferences with a coherent composition seam. These improvements serve edit/re-solve, studies, recycles, dynamics, model/solver extension, and an actual-dependency development loop.

The review does not establish that those improvements require a new journal, explicit-only publication, a single project writer, an embedded database, or retirement of the existing server. It sometimes treats proposed mechanisms as prerequisite contracts, understates working mechanisms already present, and turns plausible numerical heuristics into universal prescriptions. Its target also leaves consequential durability, reader, replay, and numerical-state premises unresolved. Those are substantive design issues, not reasons to preserve the current architecture unchanged.

The strongest common target is **local immutable scientific preparation plus one explainable numerical decision/composition seam, with publication and placement as independent consumers**. A problem's physical meaning, admissibility, required accuracy, branch/start permissions, and original assessment remain with their existing scientific owners. The common seam chooses and composes fitting native capabilities, requests only the preparation it consumes, interprets typed observations, and records the actual decisions. Durable persistence may consume the same compact record; it does not govern every numerical operation.

Architectural fitness of the current composed paths remains deficient, particularly in store-coupled local operations, dispersed method/composition decisions, and retention at inconsistent lifetimes. Successful current numerical checks would not remove these structural concerns. Conversely, this audit finds no new demonstrated false-solution bypass in the inspected original-assessment paths. Whole-product scientific adequacy is not established by this source pass. The recycle-history MUST is a concrete unmet obligation. The original review's broad gate passes and narrow G2/G7 accusations need the corrections below.

Adding an ordinary unit/property instance should extend its semantic owner; adding a solver should extend integration and selection without reproducing workflows. Pure admission/selection tests and compilation should depend on what those operations actually consume.

No capability removal is inferred from the unresolved premise.

## 4. A common dynamically routed solve pipeline

The user-facing outcome is one coherent explanation of what was requested, which method/representation was selected, why an attempted method stopped, which permitted successor was chosen, and whether original physical requirements were met. The design need not make every solver or scientific workflow implement one universal instruction language.

### 4.1 Responsibilities and useful products

**Scientific problem binding** consumes the immutable authored definition, case values and structural choices, physical/provider context, analysis mode and request permissions. It produces an immutable original-problem contract and explicit owned correspondences for any representation. That contract owns output goals, tolerances/nominals, domains/branches and the independent result-use criterion. Dynamics, fitting and continuation retain their scientific meaning here.

**Preparation** derives reusable semantic/form/pattern products and executable programs at their actual validity lifetimes. It produces owned bundles with complete dependencies and mappings. A value rebind changes values and value-dependent evidence; it does not automatically rebuild the body, conservative incidence or compiled program. A discrete/fixed-free/event-mode edit invalidates the relevant layouts. Prepare structural study variants lazily when selected rather than necessarily enumerating every possible structure up front.

**Capability/admission** distinguishes scientific incompatibility, unresolved evidence, missing prepared products, profile incompatibility, and executable placement. Preserve the current router's richer contextual states. An explicit request for an unsupported inner width can be a profile refusal; many serial solvers on independent study lanes are not scientifically incompatible merely because the study is parallel. Preserve pending class evidence where it is necessary to know the requested semantics.

**Selection/composition** consumes owned features and permissions plus injected available profiles. It returns the next candidate or preparation demand, effective controls, transition rationale, start translation and finite remaining budget. The same semantic seam absorbs existing Auto choices instead of adding another decision system alongside them. Representation-specific builders supply facts and product requirements; adapters own actual native option/capability meaning. The seam may be ordinary pure functions and compact values.

**Execution/placement** leases compatible workspaces, assigns actual native resources and runs one admitted operation. It does not redefine problem class, silently change branch policy, or interpret scientific success. Workspace compatibility covers program/native layout, parameterization, bound/equality classifications, derivative scheme, representation/scaling, provider lifecycle, options and terminal-state reuse rules. Numeric factors, pivot/scaling strategy latches, quasi-Newton memory, bases, predictors and native histories are reused only under an explicit numerical-state policy.

**Assessment/transition** always assesses a new candidate in the original scientific scope before granting result use. A root-to-least-squares route may produce a start proposal but cannot turn a stationary least-squares point into a root. Bounds do not imply VI complementarity. Global search, certification, multistart, reformulation and branch changes need their own request permissions, not merely a class-compatible solver. Contract/infrastructure/panic/resource failures and external cancellation remain terminal unless a separately declared recovery contract applies.

**Observation/publication** consumes one typed record containing the actual effective choices, available native facts, original assessment, starts/reuse and relevant environment. Synchronous bounded observation used by policy is independent of lossy progress delivery. Presentation, compact local history, durable storage, replay export and analytics are consumers. Their failure semantics are explicit; an optional analytics sink cannot silently become a precondition for mathematical execution.

### 4.2 Dynamic decisions without eager census or invisible policy

Use cheap reliable definition/pattern facts first. Request expensive derivative/class proofs, condition estimates, checkpoints or diagnostics only when a candidate/consumer needs them. A condition estimate obtained at the first factorization is a new observation that can trigger a bounded transition, not a fact every initial plan possesses. Keep unknown distinct from false and avoid assembling a full Jacobian where a selected native Jv capability suffices.

Provide a complete baseline deterministic selection policy, but do not prohibit all resource-aware policy by definition. Scientific admissibility and branch/accuracy constraints remain fixed. An explicitly selected policy may choose among equivalent permitted profiles using available placement, width, history or observed effort, provided its effective choices and result-affecting context are recorded. Resource pressure alone must not silently change the meaning of the answer. Queuing/placement is often sufficient; profile substitution is a separately visible choice.

A common pipeline should orchestrate native operations at useful grain. It should not reconstruct line searches/Newton/globalization, step a native integrator one primitive at a time merely for logging, or make each semantic phase a separate transaction/thread. Native batches, retained sessions, matrix/multi-RHS actions and library-owned internal planning should remain available where their complete contracts fit.

The pipeline's shared budget includes preparation attributable to the request, native attempts and original assessment. Expensive failure analysis needs reserved or separately requested scope. A hard deadline or cancellation does not authorize a diagnostic successor. Budget allocations, skipped opportunities and unavailable evidence are recorded honestly; finite budgets cannot promise that every admitted candidate eventually runs.

### 4.3 Applying the common seam to the required journeys

* **Edit/re-solve:** retain admitted source and pure preparation; bind current values; re-evaluate value premises; reuse compatible allocation; reset numerical history unless the recorded start policy permits it; assess the new point independently. Bound-value edits may update compatible native maps; classification changes rebuild the affected profile/session.
* **Studies/sensitivity:** freeze owned prepared bundles and an effective policy snapshot. Independent points share neutral preparation, while declared continuation chains carry explicit predecessor state. Requested sensitivity outputs determine derivative actions and validity checks. Structural variants are demand-prepared under separate identities. Do not let lane count invent continuation chains.
* **Fitting/optimization:** jointly choose algorithm, derivative mode and required experiment products. `FitOracle` already caches a point and upgrades to adjoint work when demanded, while transient experiment execution rebuilds workers/integrators. Retain per-experiment contexts where safe, and avoid a value-only oracle evaluation computing response/Jacobian/trajectory material the selected algorithm does not consume. Exact-Hessian, Gauss-Newton, covariance/profile and event-sensitive derivatives retain distinct contracts. Parallel experiments use bounded contexts and an explicit reduction policy; they are not generic independent results that can be summed in arbitrary order.
* **Recycles:** preserve the tear witness, unit representation and original residual acceptance. Record map evaluations separately from true accepted outer iterates and finite-difference perturbations. Qualify an appropriate baseline/accelerated profile; bounded restart handles domain failure without copying library numerical machinery. Opaque maps need repeatability and suitable preconditioning before JFNK is a credible successor.
* **Dynamics:** reuse one authored definition with mode-specific owned layouts and consistent initialization. Retain live native integration history for pause/continue where supported; state-only restart, a discontinuity, a new parameter experiment and process recovery are different operations. Streaming observations may seal complete prefix chunks without claiming the whole horizon succeeded. Event mode, derivative and branch semantics constrain permissible method transitions.
* **Extension/development loop:** a new unit/property instance supplies its semantic declaration/provider contract, a new solver supplies its integration/capability/profile mapping, and new policy composes existing operations. Pure selection tests inject profiles/features and need no store/native initialization. Actual Cargo/dev/build dependency closures must also narrow; removing a runtime call does not remove unrelated build dependencies.

## 5. Correcting numerical and lifecycle prescriptions

The native audit's exact-source conclusions materially change the companion. I independently inspected representative decisive native implementations, including Ipopt 3.14.20 scaling registration, bound re-query/allocation and restoration-aware iterate access; SUNDIALS 7.1.1 fixed-point and stop-time paths; and the pinned FERAL state fields. The following are source-backed constraints, not convergence qualification.

**Retained native state.** Ipopt's bounds callback is re-queried and allocates internal arrays; retained TNLP/session objects do not make a second solve allocation-free. Classification/map compatibility is the right rebuild boundary, rather than freezing all bound values. SUNDIALS KLU and ordinary Ipopt factorization paths can repeat native symbolic work despite retained project allocation. A custom retained `SUNLinearSolver` is a plausible project seam, but only for the remaining measured/useful contract gap and after library-owned alternatives are compared.

**Hidden numerical policy state is broader than factors.** FERAL's pinned `numeric/solver.rs` documents `mc64_retry_not_adopted`, a pattern-keyed latch that may suppress a later rescue although MC64 depends on current values, plus cached auto scaling choices. This state is retained for configurable/admitted Auto profiles when the same actual backend/pattern is reused and the prior application ends without a pool-discard outcome or quality escalation. The project's `retained::Lease::multi_solve` marks FatalError unhealthy, but a Singular status can be recovered by the outer regularization path without necessarily escalating backend quality; unchanged-pattern `initialize_structure` skips native reinitialization. Forcing a new numeric factor therefore does not reset the latch. Native `Solver::factor` resets these fields on pattern invalidation. An actual trigger sequence and its numerical effect were not executed here. This extends F07 with a distinct closure condition (A03), rather than establishing a separate false-solution finding: reset, explicitly permit, or record value-sensitive policy under the numerical-state contract. Require profile-specific history-independence evidence where promised.

**Stops and continuation.** Ipopt finalization during restoration may return the pre-restoration original point, but its intermediate accessor explicitly understands restoration and can capture an original-space iterate. It does not provide every restoration slack. A mandatory stop takes precedence over diagnostic completeness. KINSOL fixed point defaults to returning the last function-evaluated point on ordinary exit unless `KINSetReturnNewest` changes that; negative callback failure still requires last-successful-map handling. IDAS can continue with retained memory after ordinary/stop-time output; `IDAReInit` is not required for every pause. `IDA_NORMAL` output can be interpolated at `tret`. Diffsol must have its own continuation contract. Native resumable state, a transferable start and a scientifically usable result remain separate products.

**No-HSL method choices.** Preserve the supplied no-HSL/free-to-obtain scope as an input, not a license judgment. Ipopt registers `none`, `user-scaling` and `gradient-based` without MC19; gradient-based is its default. Nominal-based user scaling is a useful choice, not the only surviving NLP scaling. SPRAL/MUMPS linear-system scaling does not substitute automatically for NLP physical scaling. Pardiso's pinned inertia implementation supplies a concrete caution; validate the entire convex formulation or the explicit curvature-test profile rather than treating a convex objective alone as sufficient. FERAL `n_tiny=0` is a useful screen, not a theorem establishing exact inertia. Matching HSL libraries would not itself establish iteration-path parity; honest solution-level physical comparison is the appropriate declared scope independently of that choice.

**Roots and blocks.** NLEQ-ERR is not generally SSLS-only; that restriction belongs to a particular VI composition. It is not a singular-Jacobian cure. Use a concrete qualified native trust-region root capability, such as PETSc's square-root SNES contract where fitting, rather than a generic optimizer named TrustRegion. `block_solve` scaled residuals alone do not repair variable scaling, pivot, recoverable-domain or bound semantics. An affine block may require one factorization and bounded refinement; “exactly one linear solve” conflicts with refinement. Brent needs continuity/evaluability plus a verified sign change. Certified polynomial roots require an exact coefficient meaning and authored branch mapping; exact isolation does not lose its certificate merely because a nearby perturbed physical polynomial has a sensitive root count. The assembled result still receives the fresh original criterion.

**Parallel semantics.** faer uses an ambient configured Rayon scope when installed, rather than necessarily its global pool. FERAL owns a pool and explicitly claims bit-neutral sequential/parallel execution for particular paths; that claim is source-backed, not this audit's proof. The target's universal serial-unless-process-width rule is unjustified. Derive bounded actual width/configuration and determinism qualification per path. Include nested SCIP/Ipopt/MUMPS, optional Clarabel backends, BLAS/OpenMP and real loader instances in shared-resource scope. Process-exclusive PETSc solves can be isolated independently; that is not MPI decomposition of one solve. A layer-wide budget must remain charged until work physically ends, including children, queued work, and cancellation/drain.

**Advice and determinism.** A recorded snapshot/permutation explains policy dependency; it does not grant branch-switch permission or guarantee identical native execution. On multiroot/nonconvex problems, two converged answers may each satisfy residual tolerances while representing different physical branches/local stationary points. A tolerance class must state the actual comparison/branch contract. Wall-time stops, nested numerical history and provider noise can change executed transitions even with the same initial plan. Distinguish reconstructing inputs, replaying decisions, rerunning within the declared physical tolerance, and exact native continuation. Advisory ranking needs an explicit estimand; terminal failure, budget exhaustion, observer preemption, user cancellation and infrastructure interruption are different outcomes. Position/start conditioning does not eliminate survivor bias. Begin with conservative descriptive cohorts and a complete baseline policy; more ambitious estimators are optional.

## 6. State, publication and complete alternatives

Separate working authority, edit durability, attempt-record durability and cross-session publication visibility. Local immutable calculation can coexist with the current shared durable backend. Eager background journaling cannot promise an acknowledged edit survives an immediate native crash unless the acknowledgement waits for required durable commit or an independently surviving writer. Durability belongs at the promised acknowledgement boundary; it cannot be made free by describing work as off-path.

Append-only facts simplify authority but do not replace effects. A completion occurrence must be idempotently settled after a lost acknowledgement, compared with its original immutable intent, and rejected after retirement/owner succession where appropriate. Content deduplication cannot resurrect a retired occurrence. Readers and published artifacts may borrow a shared payload after its producing run retires. Files outside the database are not protected by database reference constraints.

Compare the whole alternatives before choosing a topology:

| Complete alternative | When it fits | Main remaining burden |
|---|---|---|
| Local admitted snapshots plus current remote store for publication/coordination | Strong incremental choice while writers are unresolved; preserves independent clients and durable consumers | Server and transport remain for actual shared obligations; remove their use from unrelated local calculation |
| One project/study owner plus child numerical workers and embedded catalog | Single-owner lifecycle with runner restart and process isolation | Writer succession, late workers, durable acknowledgement, catalog/head arbitration across logs, reader/GC and backup |
| Local snapshots plus a library-owned same-host transactional catalog, such as SQLite WAL, and immutable bulk files | Independent same-host writers with serialized commits and concurrent reads | Busy/checkpoint policy, external-file atomicity/GC/backup, exact-version/binding fit; comparator is unqualified here |
| Per-writer immutable logs plus shared commit arbitration | Mostly append-only independent publication with small shared semantics | Discovery, heads/order, retire/reference closure, owner succession and GC may recreate a database |
| Shared SurrealDB coordination plus immutable bulk files | Remote/independently surviving workers or concrete shared mutation benefit | Locked read-dependent transitions, unknown outcomes and external-file publication/recovery remain |

This is not a recommendation to adopt all alternatives. It shows why server removal is neither necessary nor sufficient for the target's local solve improvements. A database-free Parquet manifest log must earn its simpler complete lifecycle; Parquet alone supplies no multi-record atomicity or writer succession.

For file-backed publication, persist/seal referenced immutable objects before exposing the exact manifest; acknowledge the committed occurrence; preserve pre/post-commit crash distinctions. A directory listing is not a snapshot. Use independently sealed chunks or recoverable journal segments for partial trajectories, with explicit terminal state, gaps and committed prefix. A paused reader either retains a strong snapshot/pin/open-file capability under the supported platform contract or receives a deliberately weakened retired/partial result; a grace period is not a universal strong read guarantee. Pause GC before taking the catalog snapshot and retain its reference closure through backup, including unpublished journals/start/provider/input objects promised by the recovery APIs. Neither eager persistence nor file format choice discharges those boundaries automatically.

## 7. Further material improvements and unresolved design defects

These audit-local identifiers identify additional corrections or opportunities; they do not schedule work or create a parallel backlog.

**A01 — Decouple the prerequisite graph.** The review makes state/writer/journal redesign prerequisite to retained sessions and solver composition. That amplification is not supported: a lane can retain allocation with current durable publication, a pure selector can consume current immutable products, and a replay export can use an existing destination. Prerequisites are complete scientific dependencies, compatibility/reset rules, ownership/drain and specific consumed evidence. Fix this before planning, otherwise a large storage migration becomes an unnecessary barrier to direct functional improvements. AP-01/AP-03/AP-07, H12/H25/H28.

**A02 — Close acknowledgement, snapshot and borrowed-payload semantics.** The combined target's crash-safe edit promise, one-writer claims, weakened reads and split backup do not yet form a complete preservation contract. These decisions can lose acknowledged work, change public result/history behavior, or retire data still consumed if implemented literally. The review must either preserve those outcomes with explicit boundaries or present each intentional capability change, including unpublished/journal discovery and independent artifact promotion. G5/G6, H1/H23/H24/H25.

**A03 — Separate numerical-state policy from the name of the cache.** A neutral allocation pool can retain value-sensitive native policy latches and stale setup; a content/pattern key cannot by itself establish neutrality. Extend reuse profiles and attempt evidence to cover such state. Promise actual branch/answer equivalence where required, rather than treating a declared bitwise/tolerance/statistical class as proof. G6, DP-09/DP-11/DP-19, PS-11.

**A04 — Common pipeline owns effective policy, not every scientific responsibility.** Introduce one common candidate/transition seam with representation-specific builders, injected capability inventory and effect binder. Include algorithm/derivative co-selection, per-block profiles, presolve/dynamics/recycle/native method defaults, and start/branch/global permissions. Do not create a second registry/walker or force dynamics/fitting controllers into a universal instruction interpreter. This is the highest-value additional design direction for effective dynamic routing. AP-01/AP-03/AP-04/AP-06, PS-09.

**A05 — Reduce preparation and output demand before adding caches/threads.** Derive only selected profile products; keep Jacobian actions distinct from full matrices, output observations distinct from solver residuals, and exact/Gauss-Newton/adjoint/forward needs distinct. The current fitting oracle's point/upgrade behavior is a preservation basis; inspect unnecessary derivative work on value-only calls. Keep trajectory/attempt detail proportional to consumers and use already retained typed batches.

Read-only library/source audit; no probes, builds, tests, services, or performance measurements. ## Decision-relevant conclusions

The target's separation of allocation, structural reuse, numerical warm state and independent acceptance is valuable. Keep it. Correct the universal zero-allocation, bound-freezing, stop/resume and pool restrictions before using the target as an implementation contract. Several existing library mechanisms can close these gaps without recreating solver machinery.

1. **F07's allocation-free second solve is unattainable as a universal contract with the chosen Ipopt implementation.** Ipopt 3.14.20 `TNLPAdapter::GetBoundsInformation` allocates four arrays per invocation; `PardisoMKLSolverInterface::InitializeImpl` frees its prior native state and value array and initializes again. Retaining a session does not remove these allocations. Specify retained project preparation/workspaces and measured reductions per profile; do not promise zero native allocations or zero repeated analysis. This matters even for identical inputs. Sources: `IpTNLPAdapter.cpp:1386–1410`, `IpPardisoMKLSolverInterface.cpp:190–250` under source root I below.

2. **Fact I is a compatibility hazard, not a reason to freeze every bound value forever.** `TNLPAdapter::GetSpaces` builds fixed-variable, equality and finite-bound maps only outside `warm_start_same_structure`; `GetBoundsInformation` deliberately re-queries bounds and updates values for already-fixed variables. A target session may refresh bound values when its full classification/maps remain compatible; rebuild when fixed/free, finite/infinite, equality/inequality, treatment, or other layout premises change. Merely equal dimensions/nnz are insufficient. Today's bridge freeze is safe but overly restrictive as a best-in-class edit/re-solve target. Source: I `IpTNLPAdapter.cpp::GetSpaces`, `GetBoundsInformation`; project `crates/pse-ipopt-sys/bridge/pse_ipopt_sequence.cpp`.

3. **Stop fidelity must name the stop mechanism and distinguish native finalization from observation.** Fact H is supported for Ipopt's ordinary final return during restoration: `RestoMinC_1Nrm` throws `RESTORATION_USER_STOP` before copying the restoration trial back. But `TNLP::get_curr_iterate` explicitly handles `RestoIpoptNLP` and exposes original-space primal/dual information during the intermediate callback. Snapshotting that information gives a better start/diagnostic than the final returned point. It does not expose every internal restoration slack through that accessor. Inspect the native restoration data only if those slacks are truly needed; do not promise them from `get_curr_iterate`. A diagnostic policy must not postpone an external deadline/cancel indefinitely while waiting for restoration to exit. Source: I `IpRestoMinC_1Nrm.cpp:322–342`; `Interfaces/IpTNLP.cpp:587–730`. Preserve immediate external stopping and label partial diagnostic evidence.

4. **IDAS pause/continue is different from restart.** The table's “IDAS, Diffsol … resuming needs IDAReInit” is incorrect as a library statement and applies an IDAS API to a different library. IDAS can continue calls with the live memory/history; its stop-time return clears the reached stop time, rather than requiring reinitialization. `IDAReInit` is appropriate for a new initial-value problem, discontinuity, or reconstructing from a retained state-only snapshot, and loses multistep history. `IDA_NORMAL` output may be interpolated at `tret`, rather than an accepted internal mesh point. Callback failure, requested stop-time, accepted-step boundary, and process restart need separate rows. Diffsol continuation depends on retaining its solver/state; do not infer its semantics from IDAS. Source: S `idas/idas.c::IDASolve`, `IDAStopTest1` (around 5550–5580), `IDAReInit`; project `dynamics/idas.rs::solve` uses `IDA_NORMAL` and `segment` sets stop times. Recovery after arbitrary callback failure remains unqualified by this audit.

5. **Use KINSOL's existing fixed-point output control.** Fact G's accelerated-step convergence diagnosis and Newton callback-failure behavior are supported. However, SUNDIALS 7.1.1 defaults `kin_ret_newest = SUNFALSE`; `KINFP` returns the last function-evaluated iterate on normal exit unless `KINSetReturnNewest` requests the newly accelerated point. On a negative callback failure, the current attempted point still has no successful G evaluation. Therefore “current accelerated iterate with G unevaluated” is not the unconditional output contract. Retain a last-successful-map snapshot for failure, use `KINSetReturnNewest` explicitly, and record raw `G(x)-x` in the callback. This avoids unnecessary screening caused solely by a mistaken default. Sources: S `kinsol/kinsol.c:277, 2856–2872, 2919–2956`; `kinsol_io.c::KINSetReturnNewest`. Project `kinsol.rs` has no `KINSetReturnNewest` call in the inspected source.

6. **Do not turn current pool implementation limits into universal numerical requirements.** FERAL at the pinned fork owns a persistent pool sized from `RAYON_NUM_THREADS` or available parallelism. A pool exceeding a lane's allowance is a resource problem. It does not establish that FERAL must run serially unless its width equals the whole process size. Its pinned implementation explicitly separates a structure-selected solve core from bit-neutral execution strategy; factor documentation also claims bit-exact sequential/parallel multifrontal drivers. These are source-backed implementation claims, not this audit's executed proof. A per-profile width/determinism qualification is appropriate; a universal width-sensitivity claim covering all FERAL paths is not. Prefer an explicit per-solver pool-width/configuration seam if wide lane execution is desired; no such setter was established here. Source: P `vendor/feral/src/numeric/solver.rs:415–445, 670–707, 2138–2160`; project `pounce.rs::feral_pool_threads`, `feral_threads` implements today's admitted-width gating.

## Actual project retention: preserve the existing mechanism

The actual project POUNCE path **does retain actual FERAL backends across solves**, despite upstream default `TnlpPresolveSession` not doing so. `crates/pse-backend-native/src/pounce.rs::Session` owns `factors: Rc<RefCell<retained::Pool>>`; it installs role-specific factories for main/restoration. `pounce/retained.rs` leases exclusive actual backends by phase and ordinal; unchanged actual patterns skip backend InitializeStructure, each new application forces first numeric refactor, fatal or quality-escalated leases are discarded, and project Panic/Evaluation/Invalid/Numerical outcomes discard the pool. This directly supports the review's project-retention claim. Preserve/refine this mechanism rather than replacing it based on upstream defaults. Its local tests were read, not run.

Portability caveat: upstream P `pounce-rs/src/session.rs::run` calls `optimize_tnlp`, and P `pounce-algorithm/src/application.rs:4652` constructs a fresh algorithm bundle/default backend factory; `default_backend_factory_with_sink` creates a new FeralSolverInterface. Application/wrapper retention alone cannot establish factor retention in another consumer. My initial message to the coordinator overstated this default-upstream observation as a project defect; the project custom factory resolves it.

## Method rules and advantageous existing capabilities

- **No-HSL does not leave user scaling as the only NLP scaling capability.** Ipopt 3.14.20 `IpAlgBuilder.cpp:318–350` registers `none`, `user-scaling` and `gradient-based` unconditionally, defaults to gradient-based, and conditionally registers MC19 equilibration. User scaling from scientific nominals is a defensible target choice, but “compensated only by user scaling” is an unsupported exclusivity claim. Compare scientific nominal scaling with the existing gradient-based option, including start-dependence and derivative magnitudes; do not imply removing HSL removes all other automatic NLP scaling.
- **Pardiso's caution has a concrete pinned-source reason.** I `IpPardisoMKLSolverInterface.cpp:608` sets `negevals_ = Max(IPARM_[22], numberOfNegEVals)`, which can mask a deficit of negative eigenvalues before the later equality check. Thus the curvature-test/nonconvex caution is substantive, not a license or generic-library rejection. “Convex only” should still be understood as a proposed conservative profile rule, not as Pardiso's general mathematical domain. A convex objective alone is insufficient to certify convex NLP constraints/formulation.
- **NLEQ-ERR is not globally SSLS-only.** It is an affine-covariant line search, usable with ordinary Newton line-search composition. The SSLS-versus-RSLS restriction belongs specifically to a VI composition, not to all unconstrained square roots. PETSc 3.24.0 `src/snes/linesearch/impls/nleqerr/linesearchnleqerr.c` describes general Newton use and has optional VI projection. F13's “with SSLS only” needs that scope. NLEQ-ERR is damping, not a singular-Jacobian cure.
- **Trust-region roots need a concrete qualified owner.** PETSc has SNESNEWTONTR at the same 3.24.0 baseline, with native nonlinear globalization; the project's C bridge already creates SNESNEWTONTR children. Distinguish square-root trust region from TAO bounded optimization/BRGN least squares. Generic “argmin Newton/TrustRegion” names do not establish a complete root-solver contract. A bounded-LS stationary point is never automatically a root. This is a higher priority than speculative new solver families.
- **KINSOL difference-quotient Jv is a real native path.** S `kinsol_ls.c::KINSetJacTimesVecFn` chooses native DQ on NULL; kinLsInitialize sets kinLsDQJtimes. Project KINSOL currently installs analytic jvp for every Krylov option. Exposing the native alternative is plausible for opaque maps with repeatable residuals, suitable perturbation/scaling and a preconditioner; Picard has an explicit DQ limitation in the native initialization path. Do not label every opaque model suitable for unpreconditioned JFNK.
- **Certified polynomial roots need exact coefficient semantics.** Symbolica 3.0.1's `poly/univariate/roots.rs` exposes certified isolation for exact rational/complex-rational defining polynomials and reusable root certificates. A float-parametric expression must say which exact polynomial it certifies, how it maps back to authored physical parameters, and how branch/uncertainty screening works. Root-count sensitivity under coefficient perturbations near multiplicity does not mean exact isolation itself loses its certificate. This distinction matters to physical branch selection.
- **Affine block wording is too literal.** “Exactly one linear solve” is incompatible with the same row's optional iterative refinement. Prefer one direct factorization plus bounded solve/refinement and original-space acceptance. Numerical nonsingularity is value-dependent. A relative pivot test alone does not establish a reliable forward error or stable physical branch.
- **SPQR is not a semantic drop-in for SVD diagnostics.** `crates/pse-math/src/diagnostics.rs` defines rank by singular values above `max(rank_absolute, sigma_max*rank_relative)` and reports corresponding left/right near-null singular modes, including rectangular null spaces. Sparse QR numerical-rank/diagonal thresholds and pivoted basis vectors do not reproduce that contract. Use SPQR as a named sparse diagnostic tier with its own rank convention, residual validation and limitations; retain bounded SVD for the established singular-mode interpretation. No SPQR API/build qualification was performed here, so capability selection remains unresolved, rather than silently weakening existing findings.
- **POUNCE batch completeness matters.** The native batch docs say callers must install restoration provider and a suitable backend via configure, and should select inner-serial FERAL. Binding the function alone is not binding the complete present solver recipe. It can serve cold/one-shot independent cases, while project retained sessions serve repeated related cases; performance comparison remains unmeasured.

## Shared resources and scope qualifications

- Ipopt's `mumps_call_mutex` is a static in its MUMPS interface and is conditional on C++11 and absence of `IPOPT_MUMPS_NOMUTEX`. The inspected build recipe has no NOMUTEX override; it selects sequential MUMPS 5.9.1, Ipopt 3.14.20, SPRAL 2025.09.18 and MKL 2026.1.0, no HSL/loader. This supports per-call serialization inside that libipopt instance, not a universal mutex covering every unrelated direct MUMPS consumer or duplicate loaded libipopt. The actual selected compiler macros/runtime library were not revalidated here. Treat nested SCIP Ipopt as participating only when it resolves to the same interface/library.
- faer 0.24.4 uses spindle 0.2.6's ambient Rayon scope; inside a configured Rayon pool it need not use the global pool. `diffsol-la` enables faer rayon on this target, despite workspace faer defaults being disabled. Sources: faer `src/utils/mod.rs::thread::join_raw`; spindle `src/lib.rs` around 210–280; diffsol-la Cargo.toml target dependency. Replace “Par uses the global pool” by “uses ambient pool, global when not explicitly installed,” and use explicit scoped pool installation as a library-owned opportunity.
- SUNDIALS 7.1.1's public context header explicitly conditions thread safety on each thread having its own context. This supports isolated contexts; it does not settle sequential context migration between threads.
- The supplied PETSc 3.24.0 MPIUNI configuration supports process isolation of independent solves; it does not become an MPI decomposition of one solve by launching independent processes. No claim of general thread-safe PETSc objects is justified by this audit.
- “SCIP is free per context” needs a transitive-resource qualification: THREADSAFE SCIP can still invoke nested Ipopt/MUMPS, BLAS/OpenMP and plugin/library-global state. Likewise Clarabel's QDLDL versus optional Pardiso/SDP profile changes its native dependencies. A top-level library name alone is not a complete shared-resource declaration.
- The table's OpenMP per-thread setting is too compressed to cover all resource semantics. `omp_set_num_threads` and MKL-local/global controls, pre-created worker teams, runtime wait policy and subprocess inheritance need separate applicability. libgomp, MKL internals, HiGHS scheduler/Uno exclusivity, IBEX globals, and selected live loader closure were not independently audited here. Preserve these as source leads, not newly established facts.

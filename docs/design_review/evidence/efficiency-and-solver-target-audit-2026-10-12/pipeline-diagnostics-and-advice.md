## Main architectural judgment within this boundary

A composable solver pipeline is justified independently of a state/journal replacement. Current pure admission and strategy operations provide usable foundations; the defect is the incomplete model and dispersed ownership of suitability, candidate composition, effective method choices and numerical transition reasons. A planner should govern those decisions while existing scientific owners continue to own formulations, derivatives, branch/start permission, accuracy and original assessment. It should not become a universal controller for all scientific workflows or a mandatory durable instruction interpreter.

Prefer one decision vocabulary and common composition seam, with representation-specific builders and typed observations. Ordinary pure functions and compact typed plan values are sufficient. Keep native numerical algorithms inside fitting libraries. A durable journal may support a separately justified recovery target, but neither preference rules, cooperative stopping, recycle history, failure localization nor an exportable replay package requires one.

The existing design is stronger than “class plus constant rank” alone suggests. `routing::admit` checks static hard compatibility; `assess_static`, adapter assessment and the runtime preparation loop additionally establish contextual settings, structure, representation, budgets and pending evidence. The target must preserve that whole admission contract. Its statement “existing admit, unchanged” is safe only as preservation of semantic eligibility, not reuse of that function as the complete admission authority.

## F09: retain the diagnosis; tighten the replacement boundary

**Decisive source.** `crates/pse-backend-native/src/routing.rs::admit` (799), `assess_static` (894), `Requirements::decide_assessed` (1014) and `select_assessed` (1201); `crates/pse-runtime/src/math/solves.rs::automatic_operations` (651), `automatic_backend_alternatives` (866), the reduced-space pick (735–745), and `complete_context` (2715–2741); `crates/pse-runtime/src/math/strategy.rs::next_automatic` (88).

The initial route and successor inventory each reconstruct rank/class preference. `automatic_operations` orders supplied products, causal map, reduced space, blocks and direct execution by statement order, then has a POUNCE-specific recovery branch before generic ranked backend alternatives. The generic walker mostly interprets numerical terminal categories and start permission, not observer evidence. The diagnosis of policy spreading across binding, routing, adapters and workflows is supported under AP-01/AP-03/AP-04/AP-05. Repeating hand-built `Requirements` values is not by itself a design defect; repeated interpretation of selection semantics and unavailable composition inputs is the material issue.

**Correction to breadth.** `solves/blocks.rs::PreparedBlocks` has one backend and copies the original profile into every conditional solve: adaptive per-block choice is absent there. But `math/initialization.rs::PreparedInitialization::strategies` (45–133) already assesses routes independently per block from its contract and structural witness using a common profile. “Per-block choice impossible” should be narrowed to the automatic complete-block route and the inability to supply independent profiles/settings and suitability policy. Do not replace functioning per-block contextual admission with a new centralized assumption.

**Corrective contract.** Given an immutable problem/representation context, request constraints, available profiles and capabilities, and current numerical observations, the selection owner returns an explained preferred candidate or bounded transition. Each candidate retains its own contextual admission state: refused, pending evidence, supported but unprepared, or ready. The effect binder constructs only the selected candidate's missing products. Preference may choose which admissible evidence/preparation demand to satisfy next; it must not equate missing evidence with incompatibility or silently skip mandatory scientific requirements. A better suitability model need not retain today's accidental rank barriers in every situation, but it must explicitly resolve scientific class uncertainty before relying on that class.

One pipeline should absorb the reviewed subselectors: algebraic route/rank, supplied/reduced/block/direct composition, POUNCE recovery, fitting Hessian and derivative-mode defaults, dynamics Auto, recycle defaults, presolve Auto and native linear-method defaults. Representation builders supply owned facts and required products. They should not each reinterpret global/reformulation/branch/start permission. Conversely, an event-capable transient fitting builder or a continuation endpoint still owns its scientific constraints; the planner consumes them rather than redefining them.

`routing::admit` currently treats `threads != 1 && !parallel` as ineligibility (809). The companion simultaneously proposes keeping admit unchanged and moving shared-resource matters to placement. Resolve the distinction: scientific eligibility, profile compatibility and executable placement are separate questions. A serial-capable solver on one lane should not become scientifically ineligible merely because the enclosing study has several lanes. An explicitly requested inner width that a profile cannot honor is a profile refusal. No resource inventory implementation is assumed here.

**Transition safeguards.** Class inclusion does not establish scientific equivalence. A root-to-least-squares solve may produce a useful proposal but only original root acceptance grants result use. A VI requires authored complementarity semantics, not merely a two-sided box. Global/certifying escalation, reformulation, multistart, changed branch and changed start each require the relevant explicit permission, independent of mathematical eligibility. Explicit backend selection should prevent substitution, while allowing only specifically authorized same-backend profile transitions; current automatic alternatives already return empty for explicit selection. Keep terminal cancellation, contract, infrastructure, panic and resource failures terminal as current `permits_numerical_continuation` and walk do.

**Best-start contract needs more than “best merit.”** A failed filter NLP may have incomparable objective/violation tradeoffs; objective alone can select a domain-invalid or highly infeasible point. Define merit within an original-problem scope, normalized by the declared physical budgets, with finite/domain screening, tie policy and branch/start provenance. Keep a bounded incumbent summary rather than every iterate. Projection is a new transformation, not a harmless transfer: re-screen after projection, record the change and fall back to the original permitted start when no admissible transfer exists. A policy-stopped point never acquires result permission because the planner likes its merit.

**Per-block rules remain conditional.** Affine conditional blocks need current upstream coefficient values, nonsingularity and original residual checks; body/pattern facts alone cannot authorize the solve. Near-singularity is a value fact, but a first-factor condition estimate may arrive only after an initial method has begun; represent that as a typed observation/transition rather than pretending every plan knows it at binding. Bounds alone do not select a polynomial branch. Merging neighboring blocks or restarting simultaneously needs explicit correspondence, updated admission and finite budgets. The assembled point must always receive the fresh original check already present in `blocks_step`; a polish runs only when needed and permitted, and failure cannot leak partly committed specification changes.

## F10: history is a concrete gap; the proposed universal default is not yet established

**Decisive source.** `workflow/strategies/requests.rs::RecycleRequest::from_model` (71–128) selects the checked tear witness and defaults to Anderson depth zero and damping one. `pse-backend-native/src/recycle.rs::CausalMap::sweep`, `map`, and `original_residual` (303–395) do not record a convergence trajectory. `math/initialization.rs::ConditionalUnitSession::evaluate` (725 onward) uses a fixed initial root and retained allocation, with no submitted warm start. `pse-backend-native/src/kinsol.rs` separately records counters and final original residual quality, not a tear-indexed iteration history.

PS-08's iteration-history requirement is unmet on this route. That diagnosis and a bounded map-callback history can be corrected independently now. Describe the current method as unaccelerated, undamped fixed point; “weakest” is an unsupported universal numerical ranking. For a strongly contractive map, extra damping and Anderson preparation can add work and slow convergence. Delayed Anderson with damping is a plausible profile/default candidate, not a correctness consequence of missing history. A noisy or discontinuous map, branch-sensitive unit solves, poorly scaled tear variables and inner tolerance changes are revealing cases for qualifying its default suitability.

**Exact library check within this advice.** Context7 `/llnl/sundials` current documentation confirms native Anderson depth and delay controls but includes newer 7.5.0 behavior; it was used only for discovery. The exact `sundials-sys@0.6.2/vendor/src/kinsol/kinsol.c::KINFP` in the native-solver skill corpus (2825–2970), representing bundled SUNDIALS 7.1.1, computes the stopping norm from `unew - uu` after Anderson. The genuine unaccelerated defect must therefore come from evaluating `G(x) - x` in the successful map callback. This independently supports that part of the companion without relying on its A–I table. The repository's final `original_residual` remains the acceptance oracle.

The callback history contract must identify attempt, iterate/point, tear identity, original units/scales, evaluation success and whether the sample belongs to an actual outer iterate or another evaluation. Future JFNK perturbations, repeated calls and final validation are not consecutive accepted fixed-point iterations. Compute contractions only over comparable successful samples with a fixed map definition, inner accuracy, scaling and damping policy; observed ratios are evidence, not proof of global contraction. Record drop/partiality without letting telemetry loss silently drive a transition.

The proposed restart on every residual increase is too strict for an accelerated method: a nonmonotone temporary increase can be legitimate. Use a declared safeguarded window/threshold, bounded restarts and a finite method budget; clear native Anderson state through its actual supported lifecycle. Domain failure, actual divergence, stagnation and noisy inner solves need distinct causes. Increasing Anderson depth, tightening inner tolerances or adding damping is not an automatic cure. Tightening inner tolerances changes the effective map and its cost and must remain inside the common budget. Retain the currently useful fixed-start behavior of conditional units until result-affecting retained state has an explicit policy.

## F11: typed evidence and cooperative stops are sound; several claims/remedies need narrowing

**Decisive source.** `pse-backend-native/src/solve.rs::WorkEvidence`, `Evidence`, `SolveReport` (1844–2000); `kinsol.rs` native counter projection (1378–1426); `pounce.rs` statistics projection (763–781); `highs.rs::Session::update` (521–597), `Session::solve` (718–783); `execution/highs.rs` reuse string (40); `pse-ipopt-sys/bridge/pse_ipopt_sequence.cpp::intermediate_callback` (113–130); `pse-uno-sys/bridge/pse_uno.cpp` terminal callback and poll paths.

Missing typed native iterations are a real mismatch with `WorkEvidence`'s documented absence semantics, even when raw statistics are available. Promote meaningful counts with family-specific semantics; node counts are not iterations, and outer nonlinear iterations do not measure nested factorization work. Maintain unknown versus zero, and inclusive versus disjoint work. The current strategy ledger already charges owner-issued work and enforces aggregate limits; the attempt record must consume that ownership rather than establish a competing accounting authority.

**HiGHS G7 claim must change.** The `execution/highs.rs` statement “native coefficient/bound updates with compatible layout” is supported by `Session::update`, which calls `Highs_changeColCost`, `Highs_changeColBounds`, `Highs_changeCoeff`, `Highs_changeRowBounds`, objective-sense/offset updates and Hessian upload. `Highs_clearSolver` in `solve` clears retained solution/basis, but does not make model coefficient updates fictitious. It is legitimate evidence against implicit solver-state/basis retention. Moreover, an explicitly supplied compatible warm payload is subsequently installed via `Highs_setBasis`. Thus neither “native updates are untrue” nor “basis cannot be reused” describes the whole route. The opportunity is controlled basis retention/transport under declared start policy, preserving independent-point semantics, not unconditional removal of the clear.

The richer numerical observations are justified when consumed by a transition, diagnosis or user-facing explanation. The enumerated full family schemas are not all mandatory always-on work. Separate an inexpensive decision summary from optional trajectories and expensive diagnostics. Missing inertia, condition estimates or phase times must remain absent with capability/provenance meaning; do not parse text into decisions or infer unavailable evidence. The existing optional typed POUNCE statistics plus metric projection also suggest an opportunity to avoid retaining the same numerical payload in several representations when one typed owner can supply presentation.

The bridge throw paths invalidate reusable/final candidate state, so a cooperative policy-stop path can preserve better proposals. But one `StopRequest` still needs reason and precedence: policy stop, user cancel, hard deadline/resource limit, trial evaluation failure and fatal contract failure must remain distinguishable. The adapter declares what point and statistics survive each reason and what reuse is safe after it. A library that cannot interrupt an indivisible native operation must report that limitation and keep the work charged until drain. Do not promise immediate cooperative stop or candidate fidelity generically.

**Live versus persisted evidence.** Layer-2 transitions must consume a small synchronous in-memory observation independent of optional telemetry delivery. A dropped telemetry event must not change policy or become a fabricated lack-of-progress signal. T0 counters/timing need no per-iteration persistent flush. “Always journaled” is a proposed durability policy, not a prerequisite of truthful records. Define whether recording failure affects numerical execution, result publication or only analytics completeness; avoid turning a local database outage into an unrequested numerical failure.

## F12: richer diagnosis and reproducibility are justified; a journal is one realization

**Decisive source.** `workflow/modeling/diagnostics.rs::FindingKind` (182–208) and disposition (260 onward) already declare the 25 numerical/structural categories. `pse-math/src/diagnostics.rs::analyze_matrix` performs bounded matrix/SVD analysis. `workflow/modeling/diagnostic_nonlinear.rs::explain_nonlinear` (83) owns explicitly requested bounded local obstruction analysis; its policy has physical nominals, attempt cap and joined time limit. `workflow/diagnostics.rs` already projects routing, candidate-validation and scientific workflow failures into typed, model-associated diagnostics. Therefore “diagnosis only on request” applies to richer catalogue analyses, not to all failure diagnosis.

A cheap automatic failure summary should reuse already available residual, bounds and typed causes. Rank/SVD, derivative checks, deletion filters, elastic subproblems and exports are additional operations with their own admission, memory, cancellation and scope. They are not free consequences of a failed solve. After the common hard deadline/resource budget is exhausted, either emit an explicit unavailable/partial diagnosis from retained evidence or use a separately requested/reserved diagnostic scope. A limit cannot silently buy more unrestricted numerical work.

**Restoration stop condition needs correction.** Waiting for restoration to exit to preserve attribution may be a bounded, discretionary policy-stop choice while budget remains. It must never override user cancellation, deadline, resource exhaustion, fatal callback failure or required drain. If the solver cannot expose valid restoration slacks at a mandatory stop, record that absence and diagnose from the available original point. No prospective diagnostic completeness requirement justifies prolonging hard-stopped execution.

Replay is a separate consumer contract, not equivalent to native session resumption and not guaranteed by a journal. A replay package needs the original model/case/provider closure or stable available references, effective numerical controls, permitted and actually used start, profiles/options/build, transformations/coordinate maps, branch context, executed decisions and available observations. Recorded advice permutation avoids dependence on recomputing aggregates, but does not by itself reproduce observer-driven decisions affected by wall time, scheduling or noisy providers. State the intended replay level: input reconstruction, decision replay, numerical rerun within tolerance, or exact execution. Exact native continuation may be unavailable. Native model export supplements rather than replaces authored physical semantics. Retention must cover referenced inputs for the promised replay duration; the library/storage worker owns further retention assessment.

A compact failure bundle or existing record/export seam can establish this contract before a journal redesign. Do not require durable full trajectory recording to replay an interactive failure, and do not capture full provider/model payloads per attempt if immutable references suffice.

## Advisory history: retain it as optional, result-affecting policy input

The companion improves the original review by distinguishing terminal failures from budget censoring and recording plan position/start kind. It still overstates “only budget exhaustion is censored.” First define the estimand. A naturally terminated solver failure is a completed failure outcome. A policy-preempted run, user cancellation or infrastructure interruption is neither a natural algorithm failure nor necessarily ignorable censoring; it may be an excluded/competing outcome or a censored observation depending on the question. Observer-triggered stops are informative, so ordinary right-censoring assumptions do not automatically hold.

Conditioning on plan position and start kind is necessary but does not remove survivor/selection bias: later methods see cases earlier methods failed, with points produced by those methods. Adaptive policy then changes future exposure. Treat history as descriptive advisory evidence, not a causal comparison of solver superiority. A sound initial implementation can use conservative within-profile/cohort summaries and ties, leaving more ambitious ranking estimators for a demonstrated need. “Minimum sample” is a policy parameter needing rationale, not a theorem.

History can reorder only choices the deterministic scientific policy permits; same tier must have an explicit meaning. On a multiroot or nonconvex problem, method order can change the selected branch or stationary point. A recorded snapshot explains that dependency but does not grant branch-switch permission. Explicit selection stays untouched. Hold one effective policy snapshot through a study/resumption, retaining effective permutation/tunings; immutable in-memory snapshots or materialized advice tables suffice without a log-prefix dependency when history is not needed for recomputation. Advice failure or absence must recover the defined baseline policy.

Budget slices are result-affecting too. Unequal budget allocations can prevent otherwise admitted candidates from being attempted; “never skips an admitted option” must mean retaining the allowed candidate set, not falsely promising every candidate executes within finite total budgets. Record effective limits and the policy that allocated them. Across methods, time comparisons require comparable environment/placement and a defined treatment of preparation, queueing, retries and final assessment; work counters are not universally exchangeable cost units. Wall-time observers cannot promise identical plan execution merely from identical inputs and a frozen history snapshot.

## F13: retain conditional library opportunities; remove blanket integration obligations

Unused native capability alone does not establish a G8 failure. The current source inspected here delegates iteration and factorization; no concrete reimplementation defect was found in this bounded pass. New wrappers or custom iteration must still be challenged under G8/PS-09. The proposed methods should be selected by a consumed contract and revealing workload, not by completing a binding list. Capability declarations, exact release/build compatibility and scientific admission precede preference. New solver integrations need not await a new durable store.

The companion's distinctions are valuable preservation constraints: arbitrary bound guards are not VI complementarity, a bounded least-squares point is not a root, branch choice belongs to authored semantics, and batched execution is not automatically compatible with retained sessions. The exact conditions for PETSc, Ipopt KKT choices, Uno, POUNCE batching and the shared resource claims remain subject to the library worker's evidence. This advice intentionally does not promote those source leads into qualified methods.

## Preservation, prerequisite order and verification that would settle the remedies

Preserve `quality.rs::attach_nlp`, original-coordinate qualification and certificate checks (`qualify`, 581 onward); `strategy.rs` independent `OriginalConclusion`, terminal vetoes, original assessment before use and aggregate owner-issued work; `solves/blocks.rs::blocks_step` fresh full-original evaluation; and initialization stage overlays that never mutate the authored specification. Preserve proposal versus result permission, feasible versus stationary versus certified assurance, branch provenance, and explicit selection. These are independent obligations; a common result schema or a successful residual check cannot certify derivative correctness, domain preservation, event-sensitive dynamic accuracy or all native status mappings.

No additional false-solution bypass was established in these inspected code paths. PS-G2's structural admission is supported locally, but callback fitting/dynamics and transformed representations still need their actual applicability witnesses; do not infer whole-product PS-G2 from one algebraic route. PS-G3 may retain a narrowly justified original-assessment strength, while PS-08's missing history remains an unmet MUST. The original solver review alternates between a recycle PS-G3 failure and a blanket PS-G3 pass; reconcile that scope explicitly rather than treating independent residual checks as proof of every numerical-integrity obligation. G8 pass is bounded to machinery actually inspected, not certification of proposed custom restart/controllers.

Useful prerequisite order is semantic rather than store-first:

1. Correct misleading claims and promote existing native counters; add bounded recycle history and typed terminal/policy-stop distinctions while preserving current acceptance.
2. Define candidate context/admission, request permissions, branch/start transfer, effective profiles and typed observation meaning. Refactor duplicated selection/transition policy behind one composition seam using current storage and preparation products.
3. Add conditional per-block/profile methods and safeguarded transitions. Share stable structural facts at their actual lifetimes; this needs suitable immutable inputs, not necessarily principal F06's entire proposed structure-plane architecture.
4. Add bounded failure diagnosis and an exportable replay contract through existing record/export paths. Persist compact records to the existing destination if suitable. A future journal can realize the same contract after separate justification.
5. Introduce advisory history only after actual records/conditioning and explicit dependency semantics are correct. Its absence must leave a complete deterministic baseline policy. Durable study recovery, parallel placement and wider state redesign remain separately assessable work.

Meaningful later verification conditions, **not run here**:

- Pure selection tests cover the same problem under explicit choice, missing artifact versus refused capability, root/VI/least-squares/global permissions, branch constraints and per-block profiles. Scripted adapters demonstrate observer-caused transitions without a native solver or database.
- End-to-end small cases demonstrate that a failed or policy-stopped first candidate yields a screened proposal, every successor shares the aggregate deadline/work cap, cancellation never triggers more recovery/diagnosis, and only independent original acceptance grants result permission.
- Recycle checks include a contractive map, oscillation, accelerated nonmonotone progress, a domain-leaving trial, noisy/branch-sensitive inner unit solves and dropped history. Recorded `G(x)-x` is distinguished from the native accelerated step and final validation. Compare candidate defaults before claiming robustness or speed.
- Basis-reuse checks distinguish allocation/model update from implicit solver state and explicit submitted basis; independent points do not inherit previous numerical state unless requested and recorded.
- A hard stop during restoration terminates within supported native fidelity; attribution explicitly reports absent slacks. T2 at exhausted budget produces retained-evidence diagnostics or a separately admitted bounded analysis, never hidden work.
- Replay reconstructs original physical inputs and effective policy without reading current mutable history. State its reproducibility level and demonstrate missing-reference/provider/build failure honestly.
- History tests preserve terminal failures, policy stops and external interruption as distinct outcomes; nonconvex branch permission remains enforced under reordering; removing unavailable advice restores baseline order. Measurements, if later desired, compare representative complete workflows and classify preparation/queue/execution/assessment consistently.

## Additional independent check: retained HiGHS update grain

The coordinator asked for an independent challenge of a potential AP-07/DP-10 finding. **Interface-checked:** the concern is real within compatible retained coefficient sequences, and has an independent remedy. It is best described as an additional manifestation/subfinding of F07's native execution-grain concern, or a separate narrow finding if the principal needs a distinct closure condition. It is not evidence that F11's HiGHS native-update capability claim is false. F07's proposed session retention alone does not correct it.

**Complete consumed path.** `workflow/staged.rs::execute` (284–350) submits successive prepared original problems through the same `NativeSession` and requests `SessionDisposition::RetainCompatible` after original assessment. `math/staged.rs`'s native worker loop owns one `Retained` across requests (577 onward). `math/solves.rs::admit_step` (3900 onward) clears on `ReusePolicy::Fresh`, so the concern specifically applies when reuse is allowed and the prior outcome permits retained state. `MathService::execute` (3784 onward), `coefficient_step` (4351 onward), `execution/runner.rs::coefficients` (408) and `Transported::new` (481) transport the coefficient problem to native coordinates, then `execution/highs.rs::execute` (131–192) calls `Retained::session` with an update callback invoking `Session::update`. `Compatibility::same_session` (`solve.rs`, 910) intentionally permits numeric-data changes when layout/profile/backend agree. This is a production path, not only a direct `Session` test seam. It does not establish that all ordinary independent study points retain sessions today.

**Observed avoidable work.** `highs.rs::Session::update` (521–597) writes sense, every column cost and clipped bound, every sparse stored coefficient, every row bound, objective offset and the Hessian for each compatible update, even when the new problem differs in only one bound. The session stores structural arrays/domains and a compatibility stamp but no previous numerical snapshot or consumed delta (`Session`, 42–53). Thus it cannot currently skip numerically unchanged entries. Each vector is sent through scalar calls, despite an existing bulk-cost use in `restore_objective` (217–243). The exact `highs-sys-1.15.0/HiGHS/highs/interfaces/highs_c_api.h` declares cost, column-bound and row-bound Range/Set/Mask operations (1611–1767). This independently corroborates the coordinator's API evidence; no new version or performance claim is inferred.

**Materiality and limits.** Repeating calls over every stored coefficient and vector entry for a localized compatible edit is structural work amplification at the native boundary under AP-07/H8/H12/H13, especially for repeated sparse LP/QP sequences. Its correction does not require a new solver, preference model, journal or global retention redesign. However, it would overstate the diagnosis to claim the whole solve becomes proportional to changed entries: coefficient transport and admission already consume broad input, `solve` runs `verify_upload` before execution, and postsolve original assessment is still necessary. Native setters may themselves avoid some no-op work; no setter-internal speed, invalidation or complexity claim was established here. Whether this dominates complete workflow latency remains unmeasured. Whole-vector bulk updates alone remove many crossings without needing a delta protocol and are a credible simpler first alternative.

**Proposed corrective contract.** The adapter receives the complete admitted native-coordinate problem plus, if justified, a predecessor-bound trusted delta or a compact previous uploaded numerical view. It applies actual changed costs/bounds using the appropriate bulk operations, changes only affected matrix coefficients where that API is suitable, and avoids Hessian upload only when its exact native content is unchanged. A full-update/build fallback remains appropriate for broad changes, unsupported mutation or incompatible structure. Choose delta detection and snapshot retention only when their scan, memory and invalidation obligations earn their benefit; do not introduce per-entry hashes or a separate persisted update ledger merely to achieve local edits.

Changes must be defined after the existing normalization/coordinate transport, preserving source variable/row order, sparse structural identity, objective sense/offset and every nonzero change including transitions to zero. `domain_bounds` (245–253) clips binary variables to `[0,1]`; bulk/delta updates must compare and submit those effective bounds, not raw authored bounds. The exact certificate/admission and original readback/quality protections remain. Native mutations from lexicographic restoration or diagnostic operations must be restored or invalidate the cached uploaded-content premise. A reused allocation does not authorize retention of an old basis, numeric factor or incumbent: preserve the separate explicit start/warm policy and actual submitted-basis receipt.

**Failed update boundary.** Apply the new compatibility/content stamp only after every requested mutation succeeds. Any partially failed native update must make the session unusable until rebuilt or completely restored; do not trust the old stamp on a partly new model. Current `execution/highs.rs` reduces update errors to `Ok(false)`. `Retained::session` clears/rebuilds on this result when rebuilding is allowed, but under `RequireReuse` returns a reuse refusal before clearing the held session (`execution.rs`, 895–918). No subsequent false-result bypass was established: the current complete update runs again before dispatch and ordinary assessment failure can discard retention. Nonetheless, a proposed delta implementation cannot rely on that incidental repair. It must explicitly invalidate on partial mutation even when rebuild is forbidden, and retain the original typed update error rather than flatten every failure to “structure.”

The coordinator and three independent inquiries read both external reports. ### Native option and refinement cautions

All six R2 deep-dive options (`timing_statistics`, `print_timing_statistics`, `print_info_string`, `output_file`, `file_print_level`, `derivative_test`) are unreserved raw options in this adapter. Exact3.14.20 `IpoptApplication::Initialize(istream)` reads the output filename/level and opens the output file after this bridge has applied its options, despite upstream documentation's file-only warning. Initial direct passthrough therefore has a source route. No execution here establishes resulting logs or changes to an already initialized retained application; qualify that lifecycle separately. Logging is an explicit file effect. Derivative checks are selected expensive experiments, not ordinary passive inspection.

| Option | Value and specific boundary |
| --- | --- |
| `timing_statistics` | Boolean or native yes/no text; enables detailed collection |
| `print_timing_statistics` | Boolean or yes/no text; native printing also enables collection, while visibility depends on journal verbosity |
| `print_info_string` | Boolean or yes/no text; adds native iteration output tags, not fields in the structured intermediate callback. Project default `print_level=0` may suppress console iteration output |
| `output_file` | Text path, set before first initialization; an explicitly requested output effect |
| `file_print_level` | Integer used by the file journal, with native fallback to print level |
| `derivative_test` | Text enum such as second-order; adds numerical diagnostic callback work and does not establish independent whole-provider qualification |

The bridge reserves `option_file_name`, disables undeclared input option files and initializes once. That does not prohibit explicitly requested output files. Native structural options are immutable after first optimize; reconfiguration follows the appropriate rebuilt/new session contract. Evidence: `Native::option`, bridge option admission/solve and exact-release `IpIpoptApplication.cpp`, `IpOrigIterationOutput.cpp`, `IpIpoptAlg.cpp` and `IpTNLPAdapter.cpp`.

Ipopt maximum-versus-POUNCE minimum tolerance aggregation implements different native convergence floors; matching raw option numbers is not equivalent acceptance. KINSOL setup interval10 is a maximum under native monitoring, not a promise of ten stale iterations. Inner implicit already selects interval1. POUNCE's `refine_target` prechecks the unrefined solve; do not describe it as a general residual stop inside FERAL correction iteration. A limited-memory interior-point carve-out cannot silently disable the only SQP backend refinement.

Current RR β/z/K constants are dimensionless regularization/clipping/smoothing controls. Physical nominal multiplication is not a safe universal correction. Any ε-continuation, numerical equilibration or bound projection needs its actual mathematical/physical role and original assessment preserved.

### Read-only host observations

`lscpu -e=CPU,CORE,SOCKET,NODE,CACHE` showed CPUs0–7 and SMT siblings16–23 in one L3 group; CPUs8–15 and siblings24–31 in the other. Sysfs reported `98304K` and `32768K` for CPU0/CPU8 L3. This agrees with the report's topology **on this machine now**. It does not prove either group's performance or justify hard-coded numbering on every host.

`kernel.perf_event_paranoid` was2 and `kernel.kptr_restrict` was1. Lowering paranoid to1 still does not enable all CPU-wide/raw/ftrace use. CAP_PERFMON and symbol disclosure have separate scope; choose permissions for the selected observation. No permission change or PMU feasibility test was performed. The existing CPU capture uses user-space `cpu-clock:u`,99Hz,DWARF sampling; switching to hardware counters/frame pointers/higher frequency changes the observation and needs its own feasibility/perturbation check.

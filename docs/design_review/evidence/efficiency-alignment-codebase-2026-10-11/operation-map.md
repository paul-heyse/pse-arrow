## 0. Cross-cutting mechanisms (used by all three operations)

| Python→Rust blocking bridge | `crates/pse-py/src/workflow.rs::blocking_on_with_recovery` | [V] Loops `py.detach(|| executor.block_on(timeout(100ms, &mut future)))`. The GIL is released for each ≤100 ms slice and reacquired between slices to call `py.check_signals()`. On a signal it runs the `cancel` closure and keeps polling until the future completes. ## (a) Warm value edit → re-solve (durable runtime, default)

Python journey traced: `pkg.declarations()` → edit one row → `pkg2 = pkg.with_declarations(rows)` → `pkg2.prepare_solve(case, settings).start().wait()`. `solve_case` takes the same Rust path: `ModelingPackage::solve_case` = prepare + `start()` + `wait()` [V]. **I found no separate value-only edit API.** `with_declarations` is the edit API, and it is a complete-source replacement (`test_native_workflow.py::test_revision_edit_is_atomic...` passes the full row tuple) [V]. Value changes that do not create a revision exist only as study bindings (part b) and initialization overrides. `authoring_driver/document/edit.rs` (`apply_edits`, `assign_ids`) is not on this path; searched `pse-py/src` and `pse-runtime/src/workflow` [V].

### a.1 Read inventory — `ModelingPackage.declarations()`
- Owner: `pse-py workflow/modeling.rs::NativeModelingPackage::declarations` → `pse-runtime workflow/modeling.rs::ModelingPackage::declarations` → `modeling/canonical.rs::declaration_inventory` [V].
- RPCs [V]: `protect` (1) → loop over `membership_page` (1 per page; page size is set in pse-operations [?]) → for each chunk of 64 versions, `selected_objects`: `selected_object_batch` (1), then `selected_object_blocks` repeated until every payload is complete (≥1; blocks of `SOURCE_BLOCK_BYTES` = 512 KiB), then `finish_selected_object_batch` (1) → `read.finish` (release).
- Per-row work [V]: serde_json decode of each `(Declaration, FieldSpans)` payload and one lease each. Rust then JSON-encodes all rows (`documents::encode`). Python `codec.decode_json` + `codec.document_rows` builds one attrs row per declaration.

### a.2 Edit admission — `with_declarations(rows)`
- Python [V]: a cattrs `converter.unstructure` per row, then `encode_json`, `decode_json` and `encode_json` again (`_modeling.py::ModelingPackage.with_declarations`).
- pse-py [V]: `documents::decode::<DeclarationEdit>` (bounded at `workspace_bytes/2`) → `blocking(ModelingPackage::with_declarations(rows))`.
- `workflow/modeling.rs::ModelingPackage::with_declarations` [V]:
  1. `full_source()` (`modeling/canonical.rs`) **rehydrates the complete previous revision**. Its rows are discarded (`let (_, scope, documents, sources, _)`). RPCs: `protect` (1); `physical_context`; for physical scope documents, `resolve_kind_scope` + `selected_objects` per 64; a `membership_page` loop plus `insert_members` per page; `resolve_kind_scope("document")` + `selected_objects` per 64 + `objects()` for the `data:` documents (`resolve_logicals` + `selected_objects`). Each data document is decoded (`decode_selected_data`) and its bytes cloned (`bytes.clone()`). Then `resolve_kind_scope("package")` + objects and `resolve_kind_scope("fit")` + objects. It builds Arrow `documents`, `packages` and `fit_cases` batches with registry builders.
  2. It clears `field_spans` and rebuilds the `authored.documents` batch with `source_text = None` (a full `Row::rows` decode and re-encode).
  3. `canonical::persist(runtime, rows, physical, scope, documents, sources, fits, Some(previous))` [V]:
     - Reserves `(rows.owned_bytes + fits)*8 + documents` bytes.
     - **Builds a full `modeling_declarations` Arrow batch with registry validation and drops it** (validation only).
     - `selected_source::physical_bindings`, then `math::modeling::source_revision` (BLAKE3 over every row via `SemanticFrame`, every data document's content hash, the physical key and the names).
     - Builds a `SourceIndex` over all rows; `index.references(row)` per row.
     - Builds one `edit()` per row: a serde_json payload, then **BLAKE3 over the payload, logical id and references per row**.
     - `index.data_closure()`. If any data rows exist: a **fresh compiler workspace + `MathService::modeling_revision`** (compiler admission of the data rows) to derive `record:` supplier edits.
     - Context, physical-scope, per-document scope, package, document, `data:` and fit edits are each hashed the same way.
     - With `previous` [V]: `protect(previous)`, then a `membership_page` loop over **all members of the previous revision** (16 MiB scratch per page). Edits whose logical/scope/name/version are unchanged are dropped, and deletions are added for absent `modeling:`/`record:`/`physical_scope_document:` members. If nothing changed and the identity is equal, the previous revision is returned.
     - `store.edit(problem, parent, operation, edits)`: `stage_edits` (bounded staging RPCs; count [?]) + `activate_source_stage` (1 activation RPC with retries). The new revision keeps the same `problem`.
- Output: a new `ModelingPackage { revision, ..clone }`. Physical, accelerators and providers are shared `Arc`s.

### a.4 Execution — `PreparedOperation.start()` / `RunHandle.wait()`
- pse-py `NativePreparedOperation::start` [V]: `py.detach` + `executor.enter()` → `workflow/run.rs::ModelingSolvePreparation::start` → `Runtime::launch(vec![self.clone()], false, None)`.
- `launch` [V]: `attempt_for` → durable: `DurableAttempt::new` (mints the attempt id; `Streamer::new` **spawns a progress writer task**). `progress_for` → `Progress::tapped`. `tokio::spawn` runs the supervisor task. `RunHandle` is returned immediately.
- Supervisor task (durable branch) [V]:
  1. `admit` → `DurableAttempt::register` → `register_selection`: `Operations::put_physical_rows` (on a `physical_cache.rows` hit, `protected_rows` [RPCs ?]; on a miss, one `store.edit` per IPC block of each physical relation plus 1 for the context) → `store.begin_run` (`ensure_writes` file read + 1 protected RPC; on error, settlement RPCs) → `store.claim_run` (`ensure_writes` + 2 RPCs). The request/provenance JSON (`request_inputs`, `request_context`, `identities`, `request_provenance`) is built locally.
  2. `DurableAttempt::start` → `Heartbeat::spawn` (**one Tokio task; `renew_attempt` = 2 RPCs every `policy.heartbeat`**).
  3. `staged::Staged::open_queued` → `open_session_queued` (job permit, `reserve_entry` wait, **OS thread spawn**).
  4. For each step: `workflow/staged.rs::Staged::run` → `execute`:
     - `ModelingPackage::assessment` → `observation_program` (cache `Observation(PreparedViewHash)` [I]) for the PS-10 checks.
     - `with_point_accuracy`, two `reserve`s.
     - `NativeSession::step` (`math/staged.rs`) → `step_initial`/`step_bound` → sends a `Request` over `std::sync::mpsc` to the session thread → `MathService::execute` (`math/solves.rs`) → `admit_step` (seed selection/check) → `run_step` → by adapter representation: `coefficient_step`, `recognized_step`, `factorable_step` or **`callback_step`** (NLP/roots) → `case_worker` (`MathService::worker`: `attempt_providers` per provider + `assembly.worker_scoped`; program assembly through the memoized `assemble`) → `pse-backend-native execution/runner.rs::nlp`/`roots` (structural check, presolve policy) → adapter (Ipopt via `pse-ipopt-sys` sequence FFI with a persistent TNLP in `Retained`; POUNCE/Uno/KINSOL/...).
     - **Per callback per iteration** [V] (`pse-backend-native/src/tnlp.rs::eval_f/eval_grad_f/eval_g/eval_jac_g/eval_h`): `normalization.physical_point(x)` allocates a `Vec`, `vec![0.0; n]` scratch, the oracle evaluation (CaseWorker programs), a per-element normalization multiply/divide (`checked_product/checked_ratio`), a `finite` scan and a `copy` into the solver buffer. Callbacks go through `callback.rs` `catch_unwind` + admission observe. The C ABI callback types are in `pse-ipopt-sys/src/sequence.rs` (`Objective`, `Gradient`, ...). Retaining a `RetainCompatible` session spans steps of **this** run only.
     - The assess closure runs `Assessment::assess` (PS-10 original-model evaluation) on the session thread, then `ModelingResult::from_assessment`.
     - Progress events: `Tap::observe` → bounded `mpsc::try_send`. When the channel is full on a non-Tokio thread, `runtime.block_on(timeout(heartbeat, send))`. On overflow the run is cancelled.
  5. `staged.close()` (joins the thread).
  6. `RunResult::finished` → `DurableAttempt::finish` [V]:
     - `Streamer::finish` (drains the writer). The writer batches ≤`policy.batch` (≤512) events per flush window into JSON, then `append_result_batch` (`ensure_writes` + 2 RPCs) per batch, splitting when larger than 512 KiB.
     - `store_tables`: **for each relation in `RunResult::table_ids()` (22 for a modeling run: 3 common + `accuracy_goal_assessments` when completion is ok + 18 modeling relations; `workflow/results.rs::table_ids`)** it runs `cursor_by_id(rows=1024)` (`ResultCursor`, a producer future + bounded mpsc; encodes from the in-memory report; per row `Rows::push_ref` registers a `MemoryConsumer` and clones the row) → `result_projection::store_result_table` → `store_result_chunk` per cursor batch:
       - Empty relation: 1 IPC block (`encode_result_block`), then `append_result_block` (`ensure_writes` + 2 RPCs).
       - Scalar-indexed relations (`solve_variables` width 10, `solve_constraints` width 8): per window of ≤1024 rows, `scalar_cells_at` (**per row it constructs `View::from_checked` and emits `width` `ResultCell`s**, each with a formatted key and partition string), `result_cell_metadata_extent` per cell, then `metadata_prefix` bounds the rows per block by the 128 KiB `EXECUTION_METADATA_BYTES`. Each block is encoded with `encode_result_prefix` (Arrow IPC `StreamWriter`, `preflight_block` re-parses it, `visible_size` scan; it halves on overflow). `result_payload_digest` (BLAKE3) is computed in the runtime; then `append_result_block_cells` → `append_execution_batch` recomputes the payload digest, BLAKE3 over the cell/block/output metadata, `validate_result_block` (digest computed again) and `validate_result_cell` per cell, then encodes every cell to a SurrealDB `Value` → `ensure_writes` + 2 RPCs. **Each scalar cell becomes one indexed SurrealDB record.** Rows per block [?] (they depend on the cell metadata extent).
       - Other relations: blocks without cells, through the same append path.
       - `simulation_samples` uses `store_trajectory` (not on this path).
     - `store_seeds` [V]: `canonical_run` (1 RPC); per accepted step, `seed.materialize`, `serde_json::to_vec(SeedDocument)`, `write_chunks` (`append_result_batch` per 512 KiB chunk) and `register_result_seed` (RPCs).
     - `terminate` [V]: `canonical_attempt` (1) + `canonical_run` (1); completion JSON → `write_chunks` (≥1 append); `close_result_ingestion` (`ensure_writes` + 2 RPCs + control query); `Operations::settle` → `reconcile_closed_attempt` (1 sets query + ⌈batches/64⌉ batch-page queries **per result set** + manifest via `protected_execution_query`, 2 RPCs) → heartbeat stop/join → `seal_attempt` (RPCs) → **`Operations::record` re-reads the sealed attempt**: `read_results` (4 RPCs: run+attempt, revision, protect, manifest transaction), `read_chunks` for the completion when it is not inline, and a `result_seed_page` loop with `read.renew` (1 RPC) per page.
  7. `sender.send_replace(result)` → the waiter's `RunHandle::wait` returns.
- Live state held across stages [V]: `ModelingSolvePreparation` (prepared structure, values, providers) cloned into `RunRequest`; `RunResult` (full report in memory, owned by `RunHandle`); the session thread for the duration of the run; `SelectedRead` protections are released at the end of `prepare`.
- Python `RunResult.table(name)` on the in-memory result → `NativeRunResult::table` → `into_table_cursor(name, 1024)` → `TableStream::from_result` [V]. This re-encodes from the in-memory report on every call; `EncodingState` memoizes only failures.

### a.5 Ephemeral variant (`Runtime(..., ephemeral=True)`)
[V] `attempt_for` returns `None`. `Staged::open` (non-queued; `try_acquire` job slot, refused immediately when none is free; still spawns the session thread). No register/claim/heartbeat/progress streaming/table/seed/terminate. `RunResult` stays in memory and tables are encoded lazily on read. **Unchanged from the durable branch:** a.1–a.3 (canonical source revision persistence by `with_declarations`, canonical selection protect/recheck RPCs, portable description acknowledge/publish RPCs). `NativeRuntime::new` connects the canonical store for both classes.

## (b) Durable value sweep — point N+1 after point N

Entry points [V]: `ModelingPackage.admit_study(request)` → `admit_study_sources` (Python receives a `StudyDefinition` JSON). Then one of:
- `pkg.study(defn, runtime=rt)` → pse-py `start_study` → `Runtime::start_defined_study` → `StudyHandle`. Points then run in `rt.work()` (`NativeRuntime::work` → `Runtime::serve(until_idle)`).
- `pkg.study(defn)` on a durable runtime → `study_execution.rs::study_durable`: `ensure_managed_primary` (**spawns a `supervisor_executable supervisor_script ensure-primary` process** and waits for JSON readiness), `operations.sources`, `start_defined_study`, then **polls `handle.terminal_inventory()` every 100 ms**. The managed primary executes the points; its internal command was not traced (`scripts/surreal_server.py::ensure_primary`) [?].
- On an ephemeral runtime, `study_inner`/`execute_lane` runs in process (local batches, including the POUNCE batch owner `execute_batch`). Not traced in detail.

### b.1 Prepared once per study — `workflow/study.rs::Runtime::start_defined_study` [V]
`operations.put_sources(physical docs)`; `store.revision(modeling_revision)` (1); `physical_source` (cache + RPCs); `modeling_revision` (`SourceRevision::open`: protect, context object, release); **for each point**, `binding.identity()` check + `operation.admit_binding_seed_need(&package, binding, &mut admission)` (structure-free admission; shared `admission` across points); then for each point, mint the point run id and `document(...)` (JSON + `pse_ids::document::of` hash); `store.create_study(key, request, metadata, points)` (bulk; RPC count [?]). No native view or solve preparation is retained for the study as a whole.

### b.2 Worker loop — `workflow/worker.rs::Runtime::serve` [V]
`width = min(cores, jobs/2)` lanes, run with `FuturesUnordered` on the shared executor. Each lane calls `work_once_scoped`; only lane 0 of a round does recovery. When a lane finishes and the round is not idle, another lane is pushed. In-process lanes share the `MathService` caches, `CanonicalStore` and `ProblemTurns`.

# C2 challenge: numerical and scientific guarantees in the principal draft

> **Supporting evidence** for [Design review: in-use-library remediation of the first design-principle audit](../../reviews/design_review_in-use-library-remediation_2026-10-21.md).
> Role: Independent challenge C2 of the first draft (numerical and scientific guarantees).
> Baseline: source `a791c533e`, audit publication `0530dcaa1`, 2026-10-21. Paths under `/tmp/...scratchpad/` refer to the review's working copies; their published equivalents are in this folder. The principal review owns the judgment; this file is input to it.

The baseline is `a791c533e`, read at HEAD `0530dcaa1`. All checks were read-only: no edits, builds or tests. I read the brief, the checkpoint notes, the draft (§§2.4, 4.4–4.6, 5–9, 12, 14), `probe-worktree.md` with its diff and module (`probes.diff`, `probe_math_probe.rs`), and the source and library code cited below. I used no excluded paths.

**Bottom line.** Most of the draft holds up. The serious problem is R7: as written, it would weaken guard survival, and the speed-up it claims was measured on a program with the guards removed. Several other recommendations need explicit conditions so they do not quietly change derivative, start or reuse semantics.

## What is sound

- **F02 and R15.** The cached header confirms `UNO_INFEASIBLE_SMALL_STEP = 5` and `UNO_FEASIBLE_SMALL_STEP = 4`, and 4 maps to `FeasibleOnly`. Mapping 5 to `Numerical` matches Ipopt and removes the false least-infeasible label (`quality.rs:558-570`). Qualification still ignores native status (`quality.rs:584-600`). The remedy-open conflict on SQP-LBFGS is stated honestly.
- **Uno hunk classification.** The tolerance, `qp_regularization_value = 0`, feasibility-LP seed and Hessian-materialization hunks are correctly called numerics; materialization applies only to an admitted positive-definite operator. The scope, deadline and memory hunks, including the HiGHS `kTimeLimit` throw, are integration: they produce TimeLimit, not an accepted step.
- **R4 numerics.** The lowering matches `scalar_predicate` (finite guard, zero-normalized comparisons; `result_projection.rs:242-273`). `Inexact` pushdown re-filters after pruning, so exact bits survive. Removing locators keeps replay protection, because the batch digest, row count and full block-row equality still authenticate a replay (`surreal.surql:1026-1031`), as long as the statistics live on the block rows as proposed.
- **R8.** It does not touch numerics: values stay out of Salsa, evicted memos keep their dependency edges, and rejecting Salsa `persistence` is correct.
- **R10 and F01.** The drain is preserved (`FuturesUnordered`, no abort-on-drop), the F01 child-token fix is correct, and P2 durable lanes stay on the worker tree.
- **R14 (rest).** KINSOL keeps iterating, each POUNCE rung is separately admitted and qualified, and refusing the library's private ladder correctly protects PS-10 attempt visibility.
- **R5 and C4.** Recording closure → conservation-row relationships strengthens PS-03. The draft correctly names the PS-03 cost of the deferred per-instance specialization stage.
- **F05 truthfulness.** Covariance withholding (PS-12) stays independent of the solver's status.
- **Gates.** PS-G3 Fail on F02 is justified. PS-G1 and PS-G2 are honestly left unresolved for scope reasons. Apart from R7 and the items above, no recommendation lets a non-converged or partial result be published as a solution.

**Unresolved.** I could not establish whether the BT_PR substitutable outputs actually carry Domain or Require stages, because probe A did not log `probe_stage_kinds()`. A probe that logs them, and re-runs variant (d) with obligations counted, settles how large the High issues are. It does not change the correction itself.

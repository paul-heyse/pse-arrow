# Scientific lifecycle assessment for the comprehensive SurrealDB target review

Supporting evidence for the [principal SurrealDB lifecycle review](../../reviews/design_review_surrealdb-lifecycle-and-integration_2026-10-12.md). The principal owns the reconciled judgment and final finding identifiers; local SCI labels below identify this bounded assessment.

This is bounded supporting analysis for the coordinator's principal review, not a separate overall simulator verdict or a new disposition ledger. The coordinator owns publication and finding disposition. No implementation is authorized by this assessment.

**Baseline:** source initially inspected at `ff5a4aa2f` with the then-present worktree; the coordinator reported those changes captured by `677394474a543c884a8a21d1a2626a6820ff834e`, and a final read of `git rev-parse HEAD` confirmed that current baseline. No repository edits, probes, tests, service operations, or delegation were performed. The coordinator published this supporting document from the read-only assessment.

**Standard:** Core 3.4, its efficient-architecture heuristics and review template; Process Simulator 1.5 and its review additions; the pse-arrow binding. Tier design, purpose target, bounded subsystem scope. The criteria are the standard and the functional outcome: concurrent local workstation use, interactive edits and re-solves, studies/optimization/fitting, recycles, dynamics from shared definitions, and responsibility-local extension and testing. Current plans, ADRs and rules describe the subject; they are not acceptance criteria. The white paper is a set of leads, not library evidence or a preselected architecture.

**Bounded judgment:** Revise the scientific lifecycle target. The implementation has valuable and substantive run/attempt, publication/permission, semantic-reuse/allocation/durable-retention separations. These should be preserved. Its retirement unit cannot express ordinary selective retention/promotion. Its explicit-seed selection is currently late-bound at worker acquisition, without a durable seed-preservation promise established by this review; choosing early-bound retained scientific inputs would expose an additional missing retention dependency class. Permanent study/request history is also broader than a minimal replay fence, with no independently owned release boundary in the inspected paths. The selective-retention and scientific-history limitations are AP-04/AP-07 target-design defects even when current solver answers and Plan 36 controls are correct. The explicit-seed issue is an unresolved binding/availability choice, not an established violation of an existing preservation promise. Numerical pause/resume remains a separate unresolved product decision; existing recovery is truthful bookkeeping recovery and should not be described as numerical checkpoint restart.

## 1. What the current model gets right

The schema in `crates/pse-schema/src/catalog/substrate.rs::declare` has distinct canonical problems/revisions, immutable versions and changed membership intervals, bounded staging, scoped protections, retained revision roots, portable prepared products, semantic runs, fenced attempts, result sets/batches/manifests, result indexes, analyses, studies, point occurrences and readiness hints. This is materially more than domain-named output records:

- `pse-operations/src/canonical_execution.rs::begin_run` and codegen `surreal_execution.rs::fn::pse_execution_v1::begin_run` establish exact source selections before native work. `claim` owns the generation, lease and attempt; `writer` checks current authority. Actual worker ownership, result membership closure and terminal scientific classification are separate decisions.
- `canonical_results.rs::ResultRead` carries an exact run/attempt/manifest protection. `read_results`, result block admission and guarded continued reads prevent a copied receipt from granting future database permission. A decoded copied Arrow value may outlive that permission because it owns its bytes. `durable.rs::AdmittedSeed` deliberately has the same property: copied completion/warm/prediction values remain usable for an already-authorized start, while later acquisition obtains current permission.
- `canonical_execution.rs::SeedEligibility`, codegen `surreal_execution.rs::{seal,seed_eligible}`, and runtime `durable.rs::admit_seed` separate terminal lifecycle from complete original seed inventory and per-step scientific permission. The selector filters eligibility before its cutoff. This review does **not** repeat the older pre-eligibility cutoff defect or treat a cancelled partial export as a seed.
- `canonical_analyses.rs::persist_analysis` consumes protected `ResultRead` selections and hands their protection to durable `canonical_analysis_inputs` in `surreal_analyses.rs::begin`. It validates the actual result's source closure and retains source roots. An analysis may be staged but not active; activation checks membership. Retirement drains edges before nodes, then inputs and roots, and settles the immutable creation grant before header deletion. That is an existing useful reference-transfer pattern.
- `canonical_retention.rs::{retain_revision,drop_retained_root}` permit generic callers to manage deliberate history while lifecycle owners mint/release their own roots. Caller-supplied revision sequence is not retention authority. Source reclamation is interval-aware and preserves receipt/tombstone meaning.
- `surreal_retention.rs::{settle_protection,settle_analysis,collect_run}` now settle acquisition authority and collect append-operation residue. It would be incorrect to claim that every protection or append tombstone still accumulates forever. Plan 36's original P-B7 problem statement has been partly replaced by current source.
- `study_policy.rs::{admit,candidate_action,transition}` owns pure study semantics. Ordering, usable-result and continuation dependencies differ; equal bindings do not merge occurrences. Adapters establish observations and authority rather than independently deciding scientific policy. Policy-level reasoning/tests do not inherently require a database or solver.
- `workflow/study_operations.rs::{DeclaredStudyAdmission::binding_key,StudyPreparationLane::prepare}` retain the structural target membership rather than numeric binding values. The lane holds one preparation engagement across adjacent compatible cases; values do not select a new structural admission. `workflow/modeling/preparation.rs::establish_preparation` can rebind unchanged semantic bodies to a fresh source selection and use exact rooted acknowledgments. These paths are counterevidence to the assertion that every value change necessarily recompiles all structure.
- `workflow/study_operations.rs::{OperationRequest,PreparedStudyOperation}` compose declared-case, simulation, fit and horizon operations through their existing scientific owners. The store is not choosing a numerical method from table names. `workflow/local_analysis.rs::{reason,record,Rows}` carries qualification/withheld reasons for KKT-derived quantities rather than reading all solver success as unrestricted sensitivity/covariance permission.

These strengths establish source-traced implementation routes, not executed behavior or performance. Existing test bodies were inspected as potential controls, not rerun evidence.

## 2. Consequential distinctions and proposed smallest sufficient taxonomy

A lifecycle class should be a current obligation or selected policy, not an intrinsic property of a numerical payload or its origin run. The minimum useful distinctions are:

| Meaning | Governing owner and operation | Lifetime/retention consequence |
|---|---|---|
| Authored definition and immutable revision | Modeling/source owner: admit, edit, select | Head, explicit history and dependent products/runs protect required source closure; a new case does not mutate the definition |
| Case binding and analysis demand | Scientific operation owner: bind values, choose mode, declare outputs | Value changes can change numerical work and result identity without changing structural preparation |
| Prepared scientific description | Compiler/preparation owner: establish, rebind, reuse | Semantic dependencies and producer compatibility govern reuse; cache residency and durable source obligations remain independent |
| Logical execution request | Workflow owner: admit selected inputs, requested operation/output, retry policy | Stable across allowed attempts; consumed seeds remain attributable dependencies; early-bound external inputs require retained exact selection/copy, while late-bound IDs require explicit availability semantics |
| Actual attempt | Execution owner: claim, renew, cancel, close, settle | Private mutable work belongs here; expiry revokes authority and recovery records truthful loss rather than inferred success |
| Immutable observed result and original assessment | Scientific publication owner: append privately, close exact membership, assess, publish | Result is evidence of what happened; demanded absence differs from empty; lifecycle success is not a scientific permission |
| Reusable start artifact | Start/solver compatibility owner: qualify selected seed, apply transformation, consume | Seed bits, layout/backend and consumed numerical/branch dependencies stay exact; producer run retirement must not erase an independent admitted borrower |
| Numerical restart checkpoint, if supported | Relevant simulation/horizon owner: capture at a declared boundary, validate, resume | Must name sufficient restart state and compatibility; it is not implied by a partial trajectory, seed, progress event or DB backup |
| Derived scientific analysis | Analysis owner: select protected inputs, derive, activate, retire | Exact input references protect only the scientifically required closure; original inputs may be releasable only under an explicit self-contained-result contract |
| Retention obligation / promotion | Owning workflow/user/project reference: retain selected artifact, release obligation | A result, seed/checkpoint or baseline can have several simultaneous obligations; promotion installs a durable reference to existing immutable content |
| Effect settlement / replay fence | Substrate lifecycle owner: settle original grant, close replay authority | Preserves uncertainty and prevents late resurrection; it need not preserve the complete scientific report/request forever |
| Disposable test execution | Test/fixture owner | Fixture disposal is a distinct authority; passing/failing or age alone is not deletion permission |

This is a semantic taxonomy, not a proposal for one table, crate, trait or service per row. A few typed references plus existing immutable content/manifests may implement most of it. The proposal should remove independent consumer interpretation rather than add a universal workflow language.

Physical semantics at this boundary are predominantly **preserve**, not **formulate**: exact source/case/model identities; units, basis and reference states in admitted Arrow schemas/rows; original numerical assessment/usability; exact used-start identity/bits and compatibility; analysis method/configuration; requested versus returned extent. The substrate must preserve these and their dependency closure. It cannot certify physical validity from a hash, manifest closure, lease or terminal flag. Well-posedness and scientific post-solve checks belong upstream; their numerical adequacy was not audited in this bounded review.

## 3. SCI-01 — External seed IDs are late-bound selections without durable borrower obligations

**Priority:** High if the target selects early-bound scientific inputs for pending/retried/restarted studies; otherwise a material availability-contract decision. **Principles:** AP-04, AP-05, DP-07, DP-09, DP-19, DP-21; PS-08/PS-11. **Gates:** G9 is unresolved for this scenario until binding/availability semantics are selected; G6 (Transformation and reuse) is implicated only if required reuse behavior is changed or lost without a valid contract. No G5 (Consistency and recovery) failure is established merely by an honest unavailable-seed refusal. **Diagnosis:** Implemented source route; absence of a durable borrower relation is source-established within the inspected paths. The early-bound remedy is Proposed, and neither a runtime failure nor an existing public preservation promise is established.

`workflow/study.rs::start_defined_study` persists the full `PointPolicy`, including `StartPolicy::Explicit { seed: SolutionId, ... }`. Admission validates binding identity and seed roles/consumption, not that the named external seed currently exists. Its parent and point `RunRequest.sources` contain the selected physical revision; the modeling revision is primary. It installs no reference to the seed's producer attempt/manifest/batches. The actual seed is acquired later in `prepare_study_candidate_in_lane` through `Operations::seed`. For continuation it obtains the predecessor attempt's latest eligible seed. `surreal_studies.rs::claim` validates point and immediate predecessor revisions, then stores opaque `start` bytes and claims the consumer run; it does not mint a seed retention edge.

In contrast, `surreal_retention.rs::forget_run` checks live result readers, parent/point study obligations **of that run**, and `canonical_analysis_inputs` **for that run**. It does not inspect another study's explicit seed reference. `collect_run` deletes the producer's seed chunks/descriptors and original completion. No canonical seed-dependency relation exists in the inspected substrate declaration or these owners.

A concrete source-predicted trigger is a seed from terminal run A that exists when its ID is named in admitted study B. Before B acquires that seed, A's own retention obligations are released and A is retired. B's later pending/retry/restarted acquisition then finds the selected ID unavailable. Current admission does not bind existing seed bytes or promise to preserve them, so this scenario does not by itself establish a correctness regression. It distinguishes the target alternatives: early-bound durable input versus explicitly late-bound availability. Same-study continuation is currently protected coarsely by the source study's run-retention rule; a distinct study/external seed is the revealing case.

**Counterevidence and limits:** `AdmittedSeed` copies exact values and completion evidence. An already-authorized in-process solve holding that object remains safe after original retirement; it does not need a renewable DB lease for its copied bytes. Explicit seed absence is diagnosed rather than silently replaced by a fresh start. The finding is not use-after-free, not a claim that every disappearing seed produces a wrong solution, and not a request to require current producer permission every time already-owned immutable bytes are used. Missing-at-submission selection can remain admitted intent followed by honest acquisition-time refusal under an explicitly late-bound contract. No public promise that admission durably preserves that seed was established. The independently useful architectural diagnostic is that a seed ID is provenance/selection intent, not an independently expressible durable borrower lifecycle; retained consumer work alone does not change that fact. The principal should decide whether this is adequate for the functional target rather than infer an early-bound promise from the word admitted.

**Proposed target choice:** First select the binding contract. A legitimate late-bound design keeps explicit seed IDs as acquisition-time requests, clearly states that producer retirement can make pending/retry/restarted acquisition unavailable, and retains the truthful refusal without a silent fresh fallback. It must not claim preserved/reproducible input merely because the study is retained. If the target instead requires early-bound exact scientific inputs, admission consumes an exact admitted seed/start artifact and either installs a durable dependency on its exact original immutable selection or retains a self-contained immutable copied start with its original assessment/provenance and complete compatibility. Under that early-bound option, its consumer can stop rediscovering whether the input happens still to exist. Pending work, retries and restart hold the obligation until discharged by their owner. Retention admission and release participate in both commit orders against producer retirement. The ordinary copied `AdmittedSeed` remains allocation ownership, not transferable acquisition authority.

For the early-bound option, a minimal conservative intermediate remedy is a typed durable dependency on the whole producer run, using the analysis-input handoff pattern. That closes loss but has the coarse-retention cost in SCI-02. A selective start artifact is the stronger target; repeated arbitrary payload copies per point are not necessary. Rejecting all cross-study explicit seeds would remove a useful supported capability and must be an intentional functional-scope decision, not an accidental cleanup side effect.

**Distinguishing evidence:** For a late-bound contract, admit B naming a seed ID, retire A before acquisition, then verify a truthful attributable unavailable/refusal outcome and no invented preservation promise. Also cover an ID absent at submission. For an early-bound contract, admit B from a valid external seed, release A's original study/user obligation, race deletion with B's dependency admission in both orders, restart before B dispatches, and retry after worker loss. Either A's required immutable bytes remain reachable for B, or B owns an exact self-contained copy; deletion-first must refuse early-bound admission explicitly. Verify reference release after B's actual terminal/abandonment boundary and unchanged bit/provenance/compatibility behavior. No such new control was executed here.

## 4. SCI-02 — Whole-run retirement prevents selective scientific lifetimes and promotion

**Priority:** High where growth makes selective retention a routine workstation operation; otherwise Medium design priority. **Principles:** AP-04, AP-07, DP-05, DP-07, DP-19; PS-11/PS-12. **Gate:** G9 fails for selective preservation; truthful all-or-nothing refusal alone does not establish execution fit. **Diagnosis:** Implemented structural behavior; capacity benefit unmeasured.

`canonical_result_retirements` is keyed by run, and `surreal_retention.rs::forget_run` publishes one irreversible run tombstone. `collect_run` traverses every generation, every result set and all seeds; `canonical_result_protections` and analysis input obligations identify run/attempt/manifest, not a selected artifact retention purpose. `RetentionOwner::History` retains a source revision, not result content. `forget_study` releases an entire terminal study obligation; individual run retirement is still required. No inspected operation promotes one selected seed/checkpoint/result block to a reference independently of its producing run.

An engineer cannot keep a qualified final seed, one failed-state diagnostic packet or selected trajectory milestones while releasing unrelated detailed trajectories, previous failed attempts or other sets in that run. A small derived analysis referencing an exact manifest prevents all run retirement, including unrelated attempts and outputs. For a large study or horizon, in-memory compact output demand reduces what is originally produced but does not provide later independent retention/promotion once an existing full result has multiple consumers.

This is a unit-of-lifetime mismatch, not evidence that Arrow blocks are too large, that duplication is always wrong, or that every existing artifact must be deduplicated. It matters because retained scientific inputs and evidence have lifetimes independent of the execution that first produced them.

**Counterevidence:** Runs and source history are already separate; source roots, study references, exact read protections and analysis handoffs prevent premature deletion for their recognized borrowers. Immutable result payloads plus indexes already avoid numerical scalar-cell duplication. Full/compact output demand is an important upstream reduction. Local checked export can preserve copied bytes outside the DB. None supplies an addressable, independently retained canonical start/reference artifact or selective release of existing canonical run content. Export alone transfers the lifecycle and reopening contract to the caller and cannot be assumed equivalent to canonical promotion.

**Proposed correction:** Make retention obligations point at the smallest scientifically sufficient immutable selection, with an exact dependency closure owned by the artifact's scientific contract. Promotion consumes a protected original selection and a declared retention purpose, installs a durable reference atomically, and returns a stable reference identity. It must not rerun science, alter original success/assessment, or copy a payload merely because the purpose changes. Cleanup decides reachability of immutable content/required assessment and provenance from all current obligations; execution lifecycle can terminate independently.

A checkpoint may require a complete restart closure; a final scalar report may require much less; an auditable sensitivity may require the original active-set/qualification evidence. Do not let the caller choose a byte subset and label it scientifically sufficient. The scientific result/start/checkpoint owner decides that closure, while the substrate decides current effect authority and physical reachability.

**Alternatives:** (a) Keep whole-run pins as the simplest conservative initial contract, explicitly accept retention amplification and restrict selective archival claims. (b) Copy one selected self-contained artifact into an immutable canonical reference product, then release the original run. This can be the simplest useful correction when selected state is small, at an explicit copy cost. (c) Reuse immutable content through typed reference manifests, the best target when large trajectory/state payloads acquire several obligations. Compare actual payload layouts and necessary scientific closure; no generic content-addressed chunk store is mandatory.

**Distinguishing evidence:** Promote a seed or selected trajectory artifact, retire its original study/run obligation, retain an independent analysis/reference borrower, then release borrowers in different orders. Original bits, interpretation, assessment and source lineage must remain exact; unrelated detail becomes reclaimable. Test promotion/deletion races and interrupted promotion settlement. A renamed whole-run pin with a nicer API does not close this finding.

## 5. SCI-03 — Scientific request/occurrence history has no independent retention release, even after result retirement

**Priority:** Medium; prerequisite contract for credible disposable/repeated workstation studies. **Principles:** AP-01, AP-04, AP-07, DP-05, DP-19, DP-20. **Gate:** G9 fails for unselected indefinitely retained per-occurrence scientific history. **Diagnosis:** Implemented retained shape; no measured database-growth or latency claim.

`surreal_retention.rs::forget_study` only writes `canonical_study_retirements`. `collect_run` removes result payload/indexes, completion and append receipts/guards, but it retains run/attempt headers and non-append execution operations. `canonical_study_points` retains the immutable operation descriptor/binding, policy, facts, outcome, selected start and per-attempt history; dependencies/readiness/cursor records also remain. The schema describes these as permanent scientific occurrence/outcome receipts, and the public retirement API explicitly promises their preservation.

These records are not all minimal effect identities. A descriptor embeds scientific operations/settings/binding values; point outcomes include scientific facts, diagnostics and an attempts vector. `canonical_runs` retains request/source-selection/outer attestation bytes. Repeated exploratory studies therefore have a permanent footprint proportional to occurrences and selected scientific history even after a user releases all result obligations. Bounded cleanup pages bound one operation; they do not bound retained history or make that scientific retention an independently owned choice.

**Counterevidence:** Current `settle_protection` deletes settled grant rows after a monotone floor, `settle_analysis` can remove every analysis-owned row, and `collect_run` now deletes append receipts/guards and clears completion. These are real simplifications. This finding does not restate their earlier uncollected-tombstone defects, require erasing legitimate audit lineage, or infer disposal authority from age, size or a pass label. Retaining exact selected study definitions/outcomes is valuable when an engineer requests an auditable experiment. The missing distinction is deliberate scientific-history retention versus the minimal state needed to fence settled effects.

**Proposed correction:** Give scientific study/run history an explicit owner and release operation distinct from payload retirement and replay settlement. Define what remains after release: enough immutable identity/fence/terminal attribution to prevent late resurrection and identify unavailable history, while complete operation definitions, diagnostics, occurrence graphs and attempts history are retained only for a current scientific/user/project/test obligation. Unknown or unresolved effects and borrowed state remain protected. Compact/archive or delete settled physical bookkeeping only after authentic authority closure; a universal expiry scheduler or automatic audit destruction is unnecessary.

It is acceptable for an audit-retained study to keep detailed outcome history indefinitely. It should be an explicit policy/obligation whose scope can be inspected, rather than a consequence of having once run a disposable experiment. Minimal semantic receipt identity may remain permanent; complete JSON payloads are not automatically minimal receipts.

**Distinguishing evidence:** After explicitly abandoning or releasing a terminal exploratory study and settling all grants/effects, inspect exact fixture-owned records. Requested scientific/audit obligations survive, unresolved effects remain recoverable, and unselected descriptor/diagnostic/readiness state can drain with restartable cleanup. Replaying an old identity must neither recreate scientific payload nor silently reinterpret a receipt. Test a deliberately audit-retained study as the counterexample that cleanup must preserve.

## 6. Numerical restart is not established by existing recovery, seeds or replay

This is **SCI-U01**, an unresolved scope/contract decision rather than an assertion that every solver must serialize internal factors or iteration state.

`durable.rs::Operations::recover` observes the current attempt, obtains closed recovery authority and publishes a typed failure/cancellation with `completion: None`, unavailable seed eligibility and transient retry classification when the worker expired before durable scientific completion. `study.rs::recover_study_point` projects those truthful facts into shared policy. It does not load a numerical continuation snapshot. `SeedPayload` contains root primal, NLP start arrays/barrier, or HiGHS primal/dual/basis; `SeedDocument` optionally adds prediction. These are numerical start artifacts, not an integrator/horizon restart closure.

`workflow/study_operations.rs::PreparedStudyOperation::seed_need` treats simulation, fit and horizon as seed-free for this **study start vocabulary**. This does not establish that their internal solvers never warm-start; it establishes that the inspected durable point dependency mechanism cannot express a general dynamic restart checkpoint. Dynamics documents in blueprint §13.5/§13.6 describe shared definitions, initial-condition parameter binding and native in-process integrator reinitialization/checkpointing for adjoints. Those are distinct from durable crash-resume at a committed physical-time boundary. Searching `pse-runtime/src`, `pse-model/src` and the scoped canonical schema/operations found cancellation checkpoints and native/in-process reuse, but no durable scientific restart entity/operation.

If the functional target only requires bounded rerun of an interrupted case, the existing truthful loss/retry contract may be sufficient; its work-amplification consequences remain part of AP-07. If a long dynamics/horizon workload must resume without repeating its completed prefix, the target needs a checkpoint owner and an explicit numerical equivalence contract. A suitable checkpoint would identify definition/revision, case binding/provider/numerical interpretation, current physical time/mode/state/rates, schedule/event position, required quadratures/sensitivity state and horizon estimator/window/accepted-role state as relevant. Each operation decides which state is sufficient and which solver/library state is rebuildable. A library integrator's opaque workspace or a DB historical version is not automatically a portable restart contract.

Capture at a scientifically defined boundary, validate the complete closure privately, then atomically publish the checkpoint and advance a cursor. Resume creates a new attempt with the checkpoint as an explicit dependency; preserve branch/event ordering and original versus reexecuted observations. Promote that same immutable checkpoint by reference if it becomes a baseline. Do not invent a generic serialization framework or mandate every iteration be durable. The missing decision is whether bounded rerun, warm restart from a selected state, or exact checkpoint continuation is promised for each workload, and under what equivalence/partiality limits. The coordinator should retain this uncertainty in the principal decision if resume is a claimed capability.

## 7. Execution fit, concurrency and extension consequences

The meaningful lifecycle work units are source selection/preparation, attempt authority, publication membership, scientific permission, and independently retained artifacts. Current short guarded operations keep numerical work outside transactions. Source/result creator-versus-retirement fencing and immutable grant settlement address real concurrent writers and delayed effects; a local workstation still needs those guarantees. Do not replace them with assumptions that a dropped future or elapsed clock means a request cannot commit.

Current readiness hints and rotating recovery reduce repeated whole-history orchestration. `canonical_studies.rs::advance_study_readiness` processes bounded notifications; claim recomputes pure policy against immediate source revisions. These deserve preservation, not a redesign as a general job scheduler. Whether cross-study scanning under many continuously busy studies is fair/performance-adequate is not settled by this lifecycle reading; operational investigation belongs to the coordinator. No quantitative contention claim is made.

Changing case values should rebind numerical inputs while preserving structural preparation. The inspected lane and semantic-body reuse paths offer that route. They do not alone establish end-to-end interactive latency or value-edit reuse across every dynamics/fit/recycle mode. Current limits (64 immediate predecessors, bounded result metadata/message envelopes, analyses of at most 4096 nodes/8192 edges and bounded input selections) are truthful admission constraints. Their fitness for representative large models is unresolved rather than automatically defective: output bounds do not prove bounded examined work, but no invented SLA justifies declaring those constants too small.

An ordinary new solver start capability should be absorbed by its start/compatibility owner, serialization/admission owner and projection, with the chosen library owning its numerical state. A new result/reference retention purpose should add a typed obligation at the retention owner, not switches through numerical executors. A new unit using existing scientific concepts should not change these lifecycle contracts. Numerical checkpoint continuation is a new meaningful concept and may legitimately require coordinated scientific-owner changes; do not disguise it as a universal field on `canonical_runs`.

Policy and semantic closure rules should remain independently testable with typed observations. Database tests are necessary for both-order conflict, delayed publication and settlement; they are not required to decide fresh-versus-continuation policy. Scientific restart adequacy needs native/model tests and independent physical checks, not only canonical fixture SQL. There is no evidence in this scoped reading that a new crate, trait-object store API or general lifecycle service is required to obtain those boundaries.

## 8. Alternatives and simplification

The white paper correctly suggests separating execution lifecycle from retention lifecycle, promoting references rather than numerical payloads, and treating checkpoint completeness as a scientific contract. Its example entities, scheduled controller, separate databases and native SurrealDB feature suggestions should not be copied wholesale.

The simplest useful path retains existing source/run/attempt/immutable publication machinery, chooses early-bound retained inputs versus explicitly late-bound seed availability (SCI-01), then decides whether whole-run conservation is sufficient or independently retained artifact selections are required (SCI-02). It gives permanent scientific study history an owner (SCI-03) and distinguishes numerical continuation from receipt recovery (SCI-U01). That may be implemented in fewer physical families than semantic concepts.

A store replacement would not by itself repair missing seed dependencies, coarse retirement or permanent history policy. Conversely, if future library research establishes native SurrealDB references/deletion rejection can implement part of the closure, compare them with the current generated explicit operations. Native capability must preserve delayed-creation settlement, exact selection, scientific permission and no-resurrection; `ON DELETE` behavior alone does not supply those contracts. Backend suitability/feature semantics are delegated to the library researcher and coordinator, not asserted here.

An external bulk artifact store plus transactional manifests is a viable physical alternative when payload growth warrants it, but adds publication/reclamation coupling and a second failure domain. Keeping exact IPC in the current store is simpler if its measured ingestion/reopening/reclaim behavior fits. Do not introduce an object store, Redis, job database, global GC graph, scheduler or per-numerical-element persistence merely to make the taxonomy look complete.

## 9. Priorities, prerequisites and preservation

SCI-01 exposes the most immediate input-availability decision: a retained study can name a seed that is unavailable when acquired later. Current admission does not promise otherwise. If early binding is selected, a conservative producer-run obligation can establish preserved availability before selective physical retention exists; if late binding is selected, explicit availability/refusal semantics and truthful claims are the appropriate boundary. SCI-02 is the important longer-term contract for promotion and ordinary growth, not a prerequisite for every current seal/readiness repair. SCI-03 can be designed independently, but actual collection depends on settled replay authority and the full borrower closure. Numerical checkpoint support depends on a workload-specific restart sufficiency/equivalence decision; it should not delay the result-retention and seed-binding contract decisions.

Preserve: clean-room scientific authority; exact semantic IDs and original bits; mandatory per-state scientific assessment; deterministic declared ordering; complete source/provider/start dependencies; separation of mutable attempts from immutable values; scoped source/root/protection authority; two-way creator/reclaimer conflict; immutable grant identity and non-revival; original complete-versus-prefix coverage; no storage-error-to-ephemeral or missing-seed-to-fresh fallback; acknowledged-result reuse and uncertainty settlement; bounded admitted memory and native drain; offline historical interpretation and migration provenance. A new lifecycle taxonomy is not authorization to delete production content, reinterpret historical receipts, silently activate a schema, restart science, or weaken result qualification.

No detailed work packages or new status ledger are proposed. The principal review should name the existing plan/packet as a possible disposition owner only after the maintainer selects scope; stopped Plan 36 does not authorize these remedies.

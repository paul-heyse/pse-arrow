## 6. Common edits: files that change and what fails if forgotten

"Check" column: the command/CI job that would fail. "None" = nothing fails, state silently diverges.

### 6.1 Rename a heading or a column in a bound plan table
| Must change | If forgotten |
|---|---|
| The plan Markdown (author edit) | - |
| `docs/lifecycle.toml` `[[scope_tables]]` entry: `heading =` and/or `headers = [...]` (exact strings), and `id_column`/`status_column`/`owner_column` if columns move; `occurrence` if there are twin tables | `document_lifecycle scope` / `validate` raise `scope selector must select exactly one native table` (whole command fails; **no other item is reported**). **No recipe/CI runs this**, so `just docs`, `just docs-test`, `adr lint`, `lint-agents` all pass. |
| Any `[[relationships]]` `from`/`to` that embed `path::binding::nativeID` (binding `name`, native ID as written) | `aggregate` raises `scope relationship names an unknown native item` |
| Inbound links to the heading anchor | `docs build` does not check fragments; lychee in `docs.yml` checks files only unless fragments enabled (not verified); `reference()` raises if an ADR/exception `doc_owner` fragment disappears (checked at `load_policy`/`interpreted`, i.e. by `inventory`/`validate`/`docs-test`). |

Renaming a column that is not bound has no effect. Changing a status *word* (e.g. "pending" -> "waiting") silently changes the derived state (regex, section 2); nothing flags it.

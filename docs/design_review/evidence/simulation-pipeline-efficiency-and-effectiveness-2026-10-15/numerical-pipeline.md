## Integrated numerical assessment

The current design has real numerical foundations worth preserving: class and contextual capability evidence precede native work; a shared runner normalizes, invokes library-owned solving, recovers source coordinates and independently qualifies candidates; exact-point caches and sparse factors already exist. The target correction should extend those owners across the useful operation lifetime, rather than add another solver engine or a generic model layer.

Two concrete execution-fit defects emerge from the numerical source: IDAS admission substitutes dense state-square work for a known sparse map, and the shared shooting-window path constructs mathematical/provider workers anew for every integration and horizon period. Same-point transient derivative upgrades and exact fit curvature introduce additional repeated integrations; their remedies need a capability-aware native lifetime, because value-only trajectory reports cannot be treated as native checkpoints and cannot retroactively supply tangent history. Multiple shooting also exposes legitimate independent window work, but its startup chain and plant/controller feedback remain causal.

### Candidate N1: IDAS sparse admission is governed by a dense upper universe

**Cause and trigger.** A large sparse ODE/index-1 model selects IDAS, including its Krylov variants. `crates/pse-backend-native/src/dynamics.rs` defines `Profile::native_scatter_bytes` from state count alone. `scatter_storage_bound` at `` sets `entries = states * states`, rounds `2 * entries` up to a power of two and charges 64 bytes per bucket, before any actual sparse support is consumed. `dynamics/idas.rs` refuses this estimate against the foreign allowance before `` queries the oracle's all-mode support and builds the actual sparse union. `PartialSlots::new` at `` stores only that union in its HashMap. The same dense estimate feeds base dynamic preparation (`pse-runtime/src/workflow/modeling/dynamics.rs`), checkpoint admission and second-order admission. Consistent initialization additionally charges `n*n*32` as KLU fill at `dynamics/idas.rs`, even when `request.linear` is SPGMR/SPFGMR and no KLU factor is selected (``).

**Consequence.** A diagonal or banded model with linear-sized support can be refused on a quadratic map allowance; choosing a matrix-free linear solver cannot escape the dense admission premise. This is a source-established scalability defect under AP-07/H5/H9/H11/H15, distinct from native numerical correctness or measured memory consumption. Dense sparse-factor fill is possible and justifies a finite factor allowance; it does not justify charging a known sparse scatter map as dense, or charging KLU fill for a Krylov method. No numerical examples here are runtime measurements.

**Corrected responsibility.** Dynamic preparation should produce/reuse the complete all-mode sparse Newton layout and the maps actually consumed by the selected native demand. Charge its known containers, including construction overlap/duplicate support, before allocation. Native IDAS consumes the prepared pattern, transpose, diagonal and scatter destinations and still refuses an actual derivative outside declared support. Selected direct factors retain a separate finite opaque fill allowance; Krylov admits its basis, headers, vectors and chosen preconditioner rather than an absent KLU factor. An explicit dense fallback remains permissible for genuinely dense or unprepared generic oracles, with its scope visible.

**Alternatives and preservation.** Raising budgets merely postpones the same quadratic refusal. A compact per-column binary search can remove the HashMap if simpler than retaining a scatter table; compare actual map needs and repeated callback lookup work. Neither alternative removes finite memory enforcement, native drain, transpose correctness, nonfinite checks or complete all-branch support. Do not claim input nnz predicts direct-factor fill.

**Verification.** A large diagonal/banded index-1 model with a finite allowance must admit the actual sparse map and Krylov workspace; a genuinely dense model must still refuse an inadequate allowance. Exercise all-mode union, forward/transpose/second-order maps, changed structural support and out-of-pattern refusal. Retain `compiled_scatter_preserves_subsets_transpose_and_outside_support_refusal` (`idas.rs`); its current three-state bound check does not establish sparse-growth admission. Compare actual counter/phase/source paths without inferring native factor counts from callback counts.

**Rule impacts.** No inspected enduring rule requires a dense-square scatter allowance. This corrects realization under blueprint §13.6/§14.3.2 and finite resource ownership rather than replacing those guarantees. If a plan/ADR currently freezes the concrete dense bound, amend that implementation choice; retaining it means retaining explicit sparse-size refusal. Do not weaken finite native admission as the remedy.

### Candidate N2: window composition discards reusable workers and serializes independent trials

**Cause and trigger.** A shooting optimizer requests another trial or derivative at one trial, or a rolling horizon advances one plant period. `crates/pse-runtime/src/workflow/integrated.rs` constructs a fresh `DynamicWorker` and `Anchored` oracle inside both `integrate_window` and `window_gradient`. `DynamicWorker::new` (`workflow/dynamics.rs`) constructs per-function assembly workers, provider workers, binding frames and guard workers. `ShootingOracle` retains only problem/execution/Point (`shooting.rs`); `Point` retains reports/products rather than workers or native owners. The trial loop at `shooting.rs` invokes every window serially. Each trial window consumes its own explicit anchors `p.anchors(k, x)`, so its physical integration does not depend on the preceding trial window. Adjoint windows are similarly serial at ``.

The same construction path is used by `horizon/driver.rs:Plant::period` (``). `Loop::plant` (``) runs on the staged native session thread, but ignores its retained state argument and invokes the fresh window helper each period. Causal feedback itself is necessary; rebuilding unchanged mathematical/provider preparation is incidental. In contrast, fitting already retains owner-affine steady/transient workers and has a bounded `ExperimentTeam` (`fitting/oracle.rs`, `fitting/experiments.rs`).

**Consequence.** Repeated trials/windows/periods repay mathematical/provider/binding construction even when program and physical provider configuration are unchanged. A multiple-shooting trial also imposes a serial integration barrier over independent anchored windows. AP-07/H12/H16/H22 and PS-11 apply. The rebuild diagnosis is established by source; the quantitative benefit and best team width are unmeasured. Small problems or large checkpoint/factor working sets may rightly use one lane.

**Corrected responsibility.** Extend the integrated-window operation to accept an attempt-owned, owner-affine window worker/context. Rebind parameters, anchors, window time/profile and actual execution scope while resetting trial caches and numerical history as required. Keep the compiled mathematical/provider owners when their premises remain valid. A shooting attempt can maintain finite window lanes, with optional admitted independent waves and declared-order reduction; a horizon plant can retain one worker on its existing staged session thread. Native IVPs still initialize/reinitialize under the library contract for a new point/window; neutral worker reuse is not hidden numerical continuation. Destroy unhealthy owners and release charges only after native drain.

**Legitimate dependencies to preserve.** `ShootingProblem::initial_point` (`shooting.rs`) chains each endpoint into the next window to construct a feasible start and remains serial. The horizon measurement→estimator→controller→plant→next-measurement loop (`horizon/driver.rs`) remains causal. Final original trajectory/closure assessment stays independently performed; windows may not publish partial accepted state after a failed sibling. Outer native solver threads, window lanes, inner factor threads and all simultaneously live checkpoint/result allocations share the existing capacity owner. Do not introduce an unbounded Rayon map, a second semaphore or cross-thread movement of IDAS sessions.

**Verification.** Repeated trial/window/period callbacks should construct compiled/provider workers once per compatible lane; changing program/provider/binding meaning or cancellation scope must reset/rebuild appropriately. Compare retained and fresh outputs/derivatives/closure under value, forward and adjoint demands; stress lane failure and cancellation, ordered reduction, charges through teardown and no stale cache across window times/anchors. Count construction and integration separately. Parallel correctness must not depend on completion order or tolerate hidden cross-lane state.

**Rule impacts.** Worker retention and bounded independent execution fit existing blueprint §13.6/§19.4 and ADR-0186's owner-affine/reset semantics; no rule change is necessary for the neutral-worker correction. Extending a public shooting profile with explicit worker choice is ordinary contract evolution. Reusing multistep numerical history across changed IVPs would exceed this remedy and require changing the corresponding fresh-IVP rule; it is unnecessary for the diagnosed worker rebuild.

### Opportunity N3: one transient trial should own its recorded capability frontier

**Observed repeated work.** `FitOracle::evaluate_demand` (`fitting/oracle.rs`) caches exact x and achieved demand, but on a same-x upgrade takes the previous Point only to keep its Reports. `evaluate_experiment` (``) calls a fresh integration or combined forward/adjoint gradient. The Reports are used for physical comparison (``), not native history reuse. Shooting explicitly declares this choice (`shooting.rs`); its `Demanded` versus `EagerFirst` policy already exists at ``. Thus value→forward reintegration is not by itself proof of an ill-fitting default: avoiding eager sensitivities at rejected line-search points is a real benefit.

Integral shooting adds another clear composition: after first-order trial integration, `ShootingOracle::adjoint` runs a new forward+backward window calculation for the integral gradient (``). Exact fit `hessian` (`fitting/oracle.rs`) calls `transient_curvatures(x)` each time; `` calls the integrated second-order route, and `integrated.rs` executes native `hessian_observed`. Curvature is not retained in Point, so calls at unchanged x that vary only objective weight/multipliers repeat this expensive product, as can later KKT analysis. Completed response curvature depends on the fixed experiment/observation/point/direction context; objective weight can be applied after that product is computed. An independent final assessment may intentionally request fresh evidence and must remain distinguishable from ordinary callback reuse.

**Proposed target.** The integration owner should retain a same-point product with explicit recorded capability: primal samples/outputs, eligible checkpoint path, selected forward directions, adjoint results and computed curvature. A later demand consumes recorded capability or performs one explicit bounded upgrade. Cache unweighted exact residual-curvature blocks for native callbacks at the same immutable point and recombine weights/multipliers; evict on point/profile/provider/observation/mode/start/schedule/accuracy change, failure or terminal stop. Preserve physical agreement checks when an upgrade reruns and atomically install coherent products. Do not force checkpoint/FSA retention on every rejected value-only point: compare selected eager order, bounded checkpointed primal, and replay-on-demand against actual native callback sequences.

**Exact library limits, reconciled with the library researcher.** Current IDAS `Session<'a>` is borrowed, owner-affine and !Send, and Drop frees the forward/adjoint state (`dynamics/idas.rs`). IDAS 7.1.1 supports reinitializing a backward problem against a retained checkpointed forward pass. `IDAAdjReInit` deletes checkpoints; the current adapter consequently replays earlier scheduled segments (`idas.rs`). Native source `vendor/sundials-sys/vendor/src/idas/idaa.c` disables stored sensitivities when FSA was absent at first `IDASolveF`; `IDAInitBS` at `` rejects missing sensitivity history. Therefore a primal-only checkpoint cannot be upgraded free to second order. Record required tangents upfront or replay. Diffsol 0.16.2 owns a mutable checkpoint interpolation/replay path; retaining it may still replay intervals and cloning deep-copies state. See [library fit](library-fit.md) for exact source keys; do not assume native history can be reconstructed from Report or serialized across requests.

**Verification and decision boundary.** Record actual value/gradient/Jacobian/Hessian callback orders for representative fitting/shooting solves and separately count integrations, replay segments, first/second sensitivity passes, cache upgrades and retained bytes. At unchanged x, changing only curvature weighting should not re-integrate ordinary callback products. Check failed trials, different observations/directions, schedule boundaries, algebraic consistency, deadline/cancellation and native cleanup. Validate derivatives at nontrivial points with independent perturbation controls. No speed or memory improvement is measured by this inquiry.

**Rule impacts.** Same-point products/checkpoints do not violate ADR-0186/blueprint §19.4's rule that changed parameter trials start fresh IVPs. An implementation policy requiring fresh native state for every callback would be narrowed to changed IVPs and invalid capabilities. Actual history reuse across changed trials is not recommended. Portable checkpoint serialization remains outside scope. Retaining selected tangent history upfront changes the demand/eager preparation policy only when that explicit tradeoff is selected.

## Strengths and conditional opportunities to retain in the principal review

- **Class, selected method, effective controls and verification are distinct.** `routing.rs` derives classes from intent/facts, `` derives derivative demand from capability plus Hessian controls, and `execution.rs` checks setting ownership and admitted method contracts. Root initialization stays root only when actually square/equality. Linear, mixed, convex-QP/conic, smooth NLP and factorable capabilities are not inferred from solver names. Contextual pending evidence remains different from scientific ineligibility; explicit backend selection does not silently fall back. Dynamic whole-contract assessment (`dynamics.rs`) likewise resolves Auto before native work; it is not just an enum default.
- **Library solving and source-space acceptance are composed coherently.** `execution/runner.rs` is shared NLP presolve/execute/recover/qualify; `presolve/pipeline.rs` recovers original coordinates, observes original model and runs requested KKT analysis. `normalization.rs` distinguishes declared scales from derived per-row native feasibility scaling. KINSOL's effective scales derive from frozen physical acceptance rather than tighter work tolerance (`execution/kinsol.rs`), avoiding cancellation of requested tightening. KKT original coordinates, activity, LICQ, curvature, conditioning and withholding are substantive, not native status relabeling (`kkt.rs,1050–1245`). Do not remove them to claim speed.
- **Reusable sparse work is already implemented.** Assembly's per-instance/demand cache compares exact input bits (`pse-math/src/assembly.rs`). DynamicWorker caches function/mode/time/state/parameter point and coherent derivative order and reuses charged CSC snapshots (`workflow/dynamics.rs`). Implicit providers reuse solved point and adequate jets when configuration/selection premises hold (`pse-math/src/implicit.rs`). IFT uses one faer numeric factor and multi-RHS solves for first/second derivatives (`implicit.rs`). Diffsol faer/KLU separates pattern/symbolics/numeric refresh (`dynamics/linear.rs,313–430`); FERAL `factor_into` preserves unchanged-pattern analysis while refreshing numeric inertia (`conditioning.rs`). General retained adapters explicitly distinguish neutral allocations, starts and numerical history, and destroy partial-update state (`execution.rs`).
- **Initialization/recycle/continuation are not a missing generic solver.** Initialization prepares conditional blocks once, uses immutable stage overlays and ready waves (`math/initialization.rs`); original specification commits only after complete stage checks. CausalMap validates explicit graph/port/tear semantics and conservative original support, uses native KINSOL for convergence and reconstructs complete original local state (`backend-native/recycle.rs`). Current causal frozen-start/branch semantics are intentional; warm inner continuation could change the map and is not a free optimization. QP path prediction uses POUNCE native homotopy; arclength uses admitted library correctors/factors and keeps estimated events/proposals distinct from accepted originals (`kkt/path{,/qp,/arclength}.rs`, runtime `math/solves/paths.rs`). No project-owned generic Newton/globalization/factorization defect was established in this inspected scope.
- **Presolve restrictions have a real consumed-contract basis.** `presolve.rs` disables LinearBounds/FBBT execution because source bound reactions are untracked, while `pipeline.rs` can still confirm source infeasibility at acceptance-expanded bounds. The pinned POUNCE fork explicitly lacks general row→tightened-bound provenance; affine-elimination recovery does not repair that gap. Candidate alternatives are native provenance/reaction recovery or an explicitly primal-only capability with original feasibility and withheld dual/KKT analysis, where the outcome allows it. Turning passes on or substituting SCIP global bounds does not supply missing original reactions.
- **Selected derivative actions remain an opportunity.** The implicit provider computes all unknowns' dense jets then projects selected outputs (`implicit.rs,1367–1410`); second-order residual extent is `n*(n+p)^2` before selected output projection (``). For a few consumed output/directional actions this can amplify work even with a sparse factor. Exact Symbolica 3.0.1 supports ancestor-closed sparse hyperdual shapes; selected second contractions require corresponding provider/action/IFT contracts and qualification. Full requested dense output has an unavoidable dense result cost. This is a conditional target opportunity, not an established scientific failure or a claim that all implicit thermodynamic blocks need redesign.
- **Affine root specialization is optional.** Root intent currently yields SquareRoot plus SmoothNlp even when coefficient evidence is affine (`routing.rs`), using KINSOL's native KLU/line-search default. A direct library linear solve could remove nonlinear setup for established affine square equations while preserving source bounds and original residual checks. KINSOL may already do little work here; no benefit was measured and no class-correctness failure was found. This is subordinate to removing whole repeated executions and dense admission.

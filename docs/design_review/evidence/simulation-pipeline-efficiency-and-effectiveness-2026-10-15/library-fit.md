## Composed target and adoption order

1. **First remove whole repeated executions.** A fitting/shooting same-point owner should carry already-computed primal/report plus eligible derivative/checkpoint products, with a clear capability frontier. Value -> gradient -> Hessian demands either reuse recorded capability or pay one explicit upgrade. Hessian response tensors can sometimes be cached before objective/multiplier weighting; recombination still needs exact mode/point/profile/support identity. Current workflow prior Report is not this owner. This is the strongest source-supported numerical composition opportunity, not measured speedup.
2. **Make work follow the consumed action.** Use existing First directional products, sparse-factor transpose solves and multi-RHS where consumer asks for action/cotangent. For implicit second derivatives, replace full residual Hessian with selected contractions only after action-capable providers/IFT mapping are established. This changes representation and work without changing mathematical authority. Retaining a dense ProviderValues contract while doing sparse internals still pays dense output materialization.
3. **Carry library preparation across actual batches.** Keep compatible neutral native model/factor preparation within sweep or optimization lifetime; every point binds numeric values and refreshes required assessment. Existing low-level reset/update code is substantial, so trace actual ownership rather than introduce a second cache. Local computational batching and durable protocol grouping have different semantics; root owns durable effects.
4. **Then qualify faster kernels.** Symbolica JIT/compiled/SIMD should replace interpreter execution only at a useful amortization threshold and valid provider/floating-point/cancellation profile. Parallel independent shooting windows need isolated mutable oracle/native owners and bounded combined checkpoint/factor working sets; arbitrary solver internals are not thread-safe by implication. Batched triangular solve requires trajectory-preservation gate when opportunistic.
5. **Use narrow class routes and presolve where their outcome qualifies.** Do not pay nonlinear callbacks for established LP/QP/conic/root cases. Do not regain speed by silently omitting source-space feasibility, dual reactions or derivative domain checks. If only primal output is required, its distinct eligibility can make tightening useful without pretending to recover unsupported duals.

These recommendations remove executions and expansion before accelerating kernels. Costs include capability/key validation, longer retained leases, trajectory/checkpoint working set, failed-trial eviction, invalidation, native callback borrowing, batch failure semantics, coordinate/scaling conversions and actual destruction/drain. A second generic modeling layer or duplicate cache does not earn adoption without an identified gap.

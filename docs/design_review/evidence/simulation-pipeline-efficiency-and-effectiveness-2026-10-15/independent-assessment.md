# Independent assessment of the complete simulation pipeline

## 1. Decision, target and evidence boundary

**Independent architectural decision: Revise. Behavioral and scientific adequacy of the complete pipeline: unresolved.** The examined implementation has substantial, coherent scientific and numerical foundations. Its material defects concern preparation work, cancellation and concurrent ownership, public local study admission, reuse lifetimes, sparse admission, and result composition. They do not justify replacing authored physics, the numerical libraries, or the entire runtime. A target correction should let intent and sufficient demand survive from authoring through preparation, native execution and result consumption, while keeping original scientific assessment independent.

This is a fresh design-tier, target-purpose assessment under Core 3.4, the selected efficient-architecture companion, ProcessSimulator 1.5 and the pse-arrow binding. The criteria are the standard and the best-in-class functional outcome: physically meaningful reusable authoring; interactive edit/re-solve; studies, recycles, dynamics, fitting and extension; diagnosable failure; credible local compilation and targeted testing. ## 2. Governing responsibilities and useful existing structure

The pipeline embodies real scientific meaning rather than merely domain-named result rows. `pse-modeling` checks lexical and physical contracts, instantiates finite authored operations and carries source lineage. Compiler/workspace preparation derives immutable grouped mathematical bodies and case views. Runtime numerical binding selects class/capability, profiles and scoped attempts. Native adapters own numerical solving and foreign lifetimes. Original-model assessment supplies independent physical permission. Workflow owners compose occurrences, trajectories, fitting and durable effects. Canonical transport and readers own immutable publication, protected selection and hydration.

|---|---|---|

| Structural and numerical admission | `pse-backend-native/src/{routing,structural,execution}.rs`; `pse-structural/src/incidence.rs` | Conservative structural matching is not numerical rank or feasibility; class evidence is not inferred from a solver name. |

These boundaries support consequential extension. Adding a unit from existing physical concepts should change declarations and specialized operations, not copied occurrence policy. A genuinely new physical concept can rightly change admission and interpretation. Replacing a numerical implementation should be absorbed by the capability/adapter owner, exposing unsupported bounds/derivative/start behavior rather than forcing a lowest-common-denominator interface. Changing file representation should affect transport/read integration, leaving physical permission and run identity with their owners.

Local testability is already plausible: checker/specializer and structural policies take explicit source/context; study policy is pure; native correctness needs native integration; durable recovery legitimately needs canonical effects. The public local-study path is the important contrary case: an unrelated recording sink is currently necessary before an otherwise local operation can be admitted.

## 4. AUD39 positions and independently confirmed findings

### IA-01 — Preparation repeats stable lexical and source work (AUD39-01/02)

**Diagnosis: source-established; audit relevance established; speedup unmeasured.** `workflow/modeling/canonical.rs` implements `SourceIndex::imported` by scanning `rows.values()` for each matching import after completeness checks, although insert maintains `named_roots`. `check.rs` constructs broad visible type maps and resolves candidates; it already uses prefixes, so calling it a global inventory scan is inaccurate. `specialize/value.rs` reconstructs this map for typed arithmetic results, and `specialize/functions.rs` reconstructs a base before current environment/function overlays. `SpecializedModel::function_contracts` at `specialize/functions.rs` clones the entire CheckedPackage merely to override generated function contracts.

Use the maintained root bucket with equivalent declaration-ID ordering and completeness/Pending rules. Let one immutable specialization borrow a lexical base and evolving function view, with actual argument/refinement/reader overlays separate. This removes demonstrated unrelated scan/copy work without new dependencies. It must not become a permanent owner-only cache on mutable admission types, cache recursion-context absence, or snapshot generated functions before they change. Root indexing and function/type overlays have related execution causes but different validity obligations.

Further source-established preparation amplification exists in `grouped.rs`: each normalize call rebuilds the same full runtime/formal map. `executable/solve.rs` prepares a full Value CasePlan before selecting requested function rows/coordinates. Share the immutable projection lookup; preserve per-consumer renaming/provenance. Construct selected plans directly under the existing assembly contract, or consume an already-needed full plan where a real broader consumer justifies it. Demand does not license omitting coupled-provider work or guard dependencies. These are target opportunities with unmeasured overall contribution, not additional proven causes of the cold delay.

### IA-02 — Caller cancellation does not reach preparation (AUD39-03)

**Diagnosis: source-established and audit-observed.** `CancelSource::child_with_deadline` at `cancel.rs` takes the minimum clock but creates a fresh unrelated token. `checked_selection_scoped` (`modeling/preparation.rs`) and engagement pass that child into work without the required parent bridge. Existing loop checkpoints cannot observe a different token's event.

Use hierarchical parent→child propagation with upward/sibling isolation and minimum original deadline. A clone would let child cancellation affect siblings; an unrelated new token loses propagation. Change ephemeral-study parent-handling bookkeeping at the same time: its frontier refresh is currently guarded by child-not-cancelled, which becomes false immediately with a true child. Handle parent once independently, stop issuance, refresh blocked/waiting occurrence policy and drain issued futures. Do not attach a shared pure producer to one waiter's token: last-waiter ownership is distinct. Actual native joins remain mandatory where issued work exists. This is the first prerequisite to rerun long dependent cases, not a claim that cancellation makes preparation efficient.

### IA-03 — Shared preparation borrows the first waiter's execution clock

**Diagnosis: source-established; concurrent consequence inferred.** `math/preparation.rs` and `` share frontier/basis work by mathematical/source keys while their producer closures capture the creating waiter's deadline and pass `Some(deadline)` into the actual producer job. `math/jobs.rs` cancels and joins at that deadline. A longer-lived same-key waiter can therefore receive the first caller's expiry even though it remains interested. Ordinary cancellation isolation does not fix clock isolation.

Choose a producer policy with independent consumer deadlines, a compatible execution-clock scheduling key separate from artifact identity, or a typed producer-expiry retry that drains before retrying under the surviving caller's original deadline. Do not put deadlines into scientific content identity or silently renew a caller's clock. A service-owned producer policy requires a finite resource/last-waiter retirement rule; “no caller deadline” alone is not a complete remedy. Short-A/long-B and reversed ordering distinguish alternatives without a full benchmark campaign.

### IA-04 — Compiler mutex waiting occurs after scarce active admission

**Diagnosis: source-established; contention consequence inferred.** `plan_frontier_controlled` dispatches a worker before `with_modeling_compiler` (`math/modeling.rs`) blocks on the synchronous compiler mutex. Selected-function preparation similarly locks from inside a dispatched job (`math/modeling.rs`). Setting a cancellation flag cannot interrupt Mutex acquisition; the join owner waits behind unrelated compiler work while active worker capacity is already held.

Own cancellable compiler exclusion before scarce active dispatch, transferring that exclusive right into the actual worker. Keep head comparison+use atomic, one mutable writer, detached historical/branch workspaces and monotonic lineage. Merely replacing Mutex with an async mutex inside the charged worker moves the syntax and retains the coupling. Neither this finding nor IA-03 was measured as a cause of the single cold run; both matter to legitimate concurrent edit/study workloads.

### IA-05 — Public ephemeral studies require a canonical recording sink (AUD39-04)

**Diagnosis: source-established and public-control failure observed.** Python `NativeModelingPackage::admit_study` calls runtime `admit_study_input_sources`; the latter (`study.rs`) unconditionally calls `recorded_revision`, opens Operations on the canonical store and publishes sources. A lower ephemeral executor does not provide honest public local admission. Synthetic canonical receipt identity is not a repair.

Separate the admitted scientific study intent from its retention placement. A local owner retains actual immutable model/physical premises; a portable durable definition references explicitly published source handles. Both consume the same scientific operation and occurrence policy. A local runtime object need not be serializable, and durable submission must not silently fall back locally. This correction enables admission/testing with actual semantic inputs and addresses AP-01/02/03/06; starting a store solely to manufacture identity perpetuates the dependency.

### IA-06 — Durable point protocol has bounded grouping opportunities (AUD39-05)

**Position: retain the finding as a targeted investigation; do not promote counters into a bottleneck claim.** `durable::finish` performs progress drain, selected export, original completion, ACK reconciliation and seal with renewal. `ResultAppendQueue` already packs compatible blocks and flushes at relation/table boundaries; metadata append accepts bounded batches. A claim that every current append is scalar is false.

Compare grouped compatible file intents, empty memberships and acknowledged immutable registration metadata. Unlike schemas stay in separate IPC files; schema-per-file correctness is independent of grouping metadata calls. Preserve run/attempt fences, immutable payload identity, exact ACK/manifest membership, unknown effect reconciliation, source expiry/retirement protection and short publication effects. A long transaction spanning numerical solve is a worse lifetime. The failed queue test's expectation of no ACK after complete nonempty tables conflicts with the current flush contract; it does not establish corruption. Fixing a benchmark/test oracle needs a settled contract, not suppression of a legitimate earlier ACK.

### IA-07 — Dynamic response evidence is forced through scalar local-analysis admission (AUD39-06)

**Diagnosis: source-established and failed audit journey observed.** `analyses.rs` always promotes LocalAnalysis; `artifacts.rs` correctly requires original `runtime.local_validity`. Forward dynamic response projection supplies response rows but lacks scalar root/KKT validity. The safe refusal is a strength, while the supported analysis composition is incomplete.

The scientific response owner must supply/withhold a family-scoped product: transient time/mode/schedule/event/derivative-method conditions; implicit-root rank/branch/neighborhood; optimal-response active-set/KKT conditions. Dispatch analysis by admitted meaning. Existing Trajectory artifacts already carry response rows and physical context and may suffice for retained response provenance; a new artifact family is optional only if its consumed promise is missing. Do not fabricate KKT certification, let graph reachability certify derivatives, or infer derivative validity from accepted primal integration. Weaker response provenance must stay visibly weaker than certified local sensitivity. Preserve source/run/field coordinates, units, scaling, partial time coverage and independently retained artifacts.

### IA-08 — Metadata/read reservations compose to reject an ordinary retained result (AUD39-07)

**Diagnosis: source-established and managed retry observed.** `connected_results.rs` reserves `3 * MAX_FILE_BYTES`; `results` carries that allowance through `result_selection` into `ResultSnapshot::capture`. `result_snapshot.rs,58` reserves another same-sized allowance per descriptor page while separately retaining exact inventory. Those pages are bounded metadata, not IPC payload hydration. The two real 64 MiB compiler leases are not shown redundant. The observer refusal is honest resource enforcement; ordinary supported read composition is nevertheless unfit.

Distinguish temporary RPC/intermediate ownership, retained metadata, frozen inventory and later file decode. Transfer exact retained allocation to its continuing owner and retire only drained temporary capacity. Derive metadata allowances from actual bounded descriptor contracts, including strings, transport/intermediate copies and overlap. An Arc/future return is not proof SDK router work has drained. Shared pressure coordination can release demonstrably idle optional generations after this overlap is corrected; raising the pool, shrinking opaque compiler reservations without a bound, or marking nonspillable state spillable does not repair ownership. Keep active readers and complete descriptor validation. An empty `0..0` read bypasses the failing page and is an inadequate acceptance control.

## 5. Additional numerical defects and conditional opportunities

### IA-09 — IDAS sparse preparation is admitted against a dense universe

**Diagnosis: source-established scalability defect; benefit unmeasured.** `dynamics.rs` calls `scatter_storage_bound`; `` uses `states * states`, power-of-two bucket expansion and 64-byte allowance before sparse support is examined. `dynamics/idas.rs` refuses that estimate before `` builds the actual all-mode sparse union. The consistent-initialization calculation at `idas.rs` charges `n*n*32` native KLU fill even for SPGMR/SPFGMR selection.

A diagonal/banded model and matrix-free method have a sparse credible route but can be refused by unrelated dense metadata/factor admission. Dynamic preparation should own the complete all-mode Newton layout/maps and charge the real known containers plus construction overlap. Selected direct factors still need a finite opaque fill allowance—input nnz is not fill. Krylov should charge basis/vectors/preconditioner and not an unselected KLU factor. A conservative dense fallback may remain explicit for genuinely dense or generic unprepared oracles. Binary search in compact CSC versus an indexed scatter map is a legitimate physical alternative; preserve out-of-pattern refusal and forward/transpose/second-order maps. This defect is independent of cold authoring and result-pool problems and should not be hidden behind “conservative accounting.”

### IA-10 — Integrated window composition discards reusable mathematical workers

**Diagnosis: source-established repeated construction; quantitative materiality unmeasured.** `integrated.rs` and `` construct fresh program workers/Anchored oracles for each integrate_window/window_gradient call. `DynamicWorker::new` (`dynamics.rs`) rebuilds function assembly/provider workers, frames and guard workers. `ShootingOracle` retains Point/reports rather than those workers. Horizon Plant also calls this helper on the existing session thread while `Loop::plant` (`horizon/driver.rs`) ignores retained state. Fitting already shows a better local precedent with owner-affine transient workers.

Retain a compatible attempt/window-lane mathematical worker, rebind actual coordinates/time/profile/scope, clear numerical caches on changed IVPs and initialize native state under the library's reset contract. This is neutral preparation reuse, not hidden continuation. Multiple-shooting trial windows are independently anchored and may use bounded admitted waves; their startup endpoint chain, horizon feedback and deterministic reductions remain causal. Parallelism is an optional opportunity, not necessary to close the repeated-worker defect, and combined checkpoints/factors may make one lane best. Do not demand new services, unbounded pools or moving !Send native sessions across threads.

### IA-11 — Exact fit curvature is not retained across same-point Hessian callbacks

**Diagnosis: source-established repeated complete numerical product; frequency/benefit unmeasured.** `FitOracle::hessian` (`fitting/oracle.rs`) calls `transient_curvatures(x)` on every exact-mode callback; `` maps transient experiments through the integrated second-order route. Point carries predictions/response/Jacobian/trajectory/adjoint but no curvature. A repeated callback at identical x with different objective weight/multipliers can therefore redo transient second-order work whose underlying experiment/observation result is unchanged.

Retain the applicable exact curvature product at the existing point owner, then apply changing solver weighting separately. Its key includes experiment/observation/point/directions/provider/profile/mode/schedule/accuracy and derivative meaning; failure or point change invalidates it. Do not describe the current product as wholly unweighted: the residual/measurement cotangent is already point/observation-dependent. Cache at the actual stable level, or deliberately retain a broader response-Hessian tensor only when its extra storage/use earns the cost. Independent final original assessment may intentionally request fresh evidence and remains a separate mode. A same-x changed-observation/weight case is essential to avoid a fast but stale curvature cache.

### Conditional numerical opportunities, not missing foundations

Fitting and shooting already cache exact-point achieved demand. It is false that every value/gradient/Jacobian callback reintegrates. Value→forward upgrade deliberately trades extra replay for avoiding unused sensitivities at rejected trials. Shooting integral adjoints do run a separate forward/backward route after ordinary trial integration, and native checkpoint retention can remove repeated forward work for a same-point capability frontier. That target is **Proposed**: reports are not checkpoints; IDAS cannot retroactively provide tangent history from a primal-only pass; Diffsol checkpoint interpolation may replay intervals; retaining history costs memory and owner lifetime. Choose replay-on-demand, eager requested directions, or checkpointed same-point retention against actual callback demand, without pretending that changed parameter trials are the same IVP.

Implicit provider second derivatives form residual jets of extent `n*(n+p)^2` before output projection (`implicit.rs`), although sparse LU and multi-RHS solves already exist. Selected contractions/directional/provider actions can avoid expansion for consumers requesting few actions; full requested dense Hessians have unavoidable result size. This is a conditional capability opportunity until the consumed output/action contract, exact higher-order conventions and providers are settled. Symbolica JIT/SIMD/compiled evaluation is likewise a later candidate requiring exact-version feature, floating-point/FMA, cancellation, provider, executable-allocation and amortization qualification; it is not a correction for repeated whole executions. Affine square-root direct solves may avoid nonlinear setup, but no class-correctness defect or measured advantage over current KINSOL was established.

Keep presolve's original reaction contract. General FBBT/tightened-bound dual provenance is absent from the pinned POUNCE fork; affine-elimination recovery does not fill it. Either qualify native provenance/recovery, or expose a distinct primal-only path with source feasibility and withheld dual/KKT output when acceptable. Simply enabling passes or substituting SCIP global bounds cannot supply original reactions.

## 7. Coherent corrective target, alternatives and priorities

The corrections fit together when they extend existing owners rather than introduce a pipeline-wide cache or new solver architecture. Keep one scientific intent with explicit physical/source premises; derive demand-shaped immutable preparation; retain mutable workers at actual attempt/lane lifetimes; give same-point numerical products explicit capabilities; admit physical sparse/native work; assess each new original numerical state; publish/retain/select results under honest scientific families and exact effects.

Several superficially similar remedies would conflict. A permanent broad type cache conflicts with evolving admission and optional/refined state. Eager all-order derivative compilation conflicts with demand-selected trials. Retaining every checkpoint conflicts with the combined working set that IA-08 already exposes. Making shared producers children of the first caller conflicts with other waiters. Releasing a response allowance on returned future alone conflicts with transport suffix ownership. Parallel windows without whole-operation resource admission conflict with native owner affinity and checkpoint/factor bounds. One long durable transaction conflicts with numerical solve lifetime. These are reasons to define the corrected operation, not abandon useful reuse.

Consequence priority differs from prerequisite order:

1. **Restore reliable stopping and caller isolation:** IA-02 before long retries; IA-03/04 before claiming concurrent preparation behavior. Source-index/overlay work does not fix these lifetimes.
2. **Restore supported public result/study composition:** IA-05/07/08 are functional blockers. Settle local versus recorded study intent and response-family meaning before editing API/artifact oracles. Establish actual allocation/transport lifetime before shrinking allowances. These are independent defects and can proceed through their existing owners.
3. **Remove structural amplification:** IA-01 and IA-09 address independently established preparation and sparse-growth problems. Lexical/function overlay invariants precede caching; sparse layout and selected-method demand precede native accounting changes.
4. **Extend useful operation lifetimes:** IA-10 neutral worker reuse and IA-11 same-point curvature retention remove demonstrated repeated work. Native checkpoint frontiers and optional window waves need demand/lifetime design and focused evidence, not immediate blanket parallelism.
5. **Investigate protocol and kernel tuning:** IA-06 grouping, selected derivative actions, JIT/SIMD and affine routes stay conditional. Do not prioritize them from misleading whole-operation counters or assumed kernel dominance.

No numerical speedup, throughput target or fixed batch size is selected. Native/library substitution remains eligible where it can honor the consumed contract, irrespective of licensing. Existing BTreeMap/Salsa/library operations already solve many local needs; a larger framework is not justified by these findings. Library versions/features may be changed if exact capability evidence and total integration cost make that better, with family/type/floating-point/native ABI effects explicit.

# Plan38a local authority and scoped validity target review

## Decision and inspected scope

**Accept at the target-document level.** The independent design-reviewer assessed proposed
ADR-0183 and architecture revision160 against Core3.4, its efficiency heuristics, Process
Simulator1.5 and the pse-arrow binding. No blocking target defect or additional rule decision
was identified. This document publishes that independent assessment, not implementation acceptance.

Baseline: `32d5165c05100a40a655993ddf7de6aa97f80989` with the ADR-0183, revision160 and38a
checkpoint edits. Immediate suppliers/consumers inspected were Runtime/ModelingPackage,
canonical source/delta/recording, compiler lineage, scalar admission, validation contexts and
checked-batch handoffs. Numerical policy, final storage topology, disk memo implementation,
unit/property fidelity and assembled qualification were excluded. Functional drivers are
edit/re-solve, study reuse, one model across modes, extension locality and independently
usable responsibilities. No builds, tests, services, probes or measurements ran.

## Responsibilities, authority and composition

The admitted immutable revision owns authored declarations/documents, consumed data and exact
physical/provider/interpretation/validation context. Pure preparation consumes it; canonical
import/recording is an explicit integration. A receiver token checks exact local parent;
semantic identity governs compatible computation; local lineage/generation owns a mutable
compiler accelerator; canonical origin supplies actual attribution and durable parent CAS.
None substitutes for another. Attaching origin preserves local identity.

Current `SourceRevision` retains neither declarations nor admitted package state, so delta
application protects and rereads its canonical parent. Making a store optional alone would
leave that dependency intact. Complete ownership plus the existing delta semantics removes
it without creating another authoring interpreter. Independent bounded mutable compiler
lanes and detached products avoid treating cloned Salsa handles as historical snapshots.

| Revealing scenario | Target response |
|---|---|
| PSE-S05 service-free authoring/preparation | Explicit ephemeral construction needs only actual model/engine dependencies. |
| PSE-S03 value or mode change | Reuse compatible structure; invalidate consumed role/form/operator facts and check new numerical states. |
| PSE-S07 historical/sibling edit | Immutable older receivers fork; concurrent head advancement cannot overwrite another accepted head. |
| PSE-S04 disconnect after import | Complete local closure computes; required recording remains acknowledged or honestly uncertain. |
| PSE-S02 provider/UDF/native change | Actual consumed context/trust changes invalidate affected reuse. |
| Independent Stable-check admissions | Children share one scope; independent scopes obtain fresh sensitive evidence even at equal timestamps. |

New units extend semantic declarations/providers, rather than publication prerequisites.
Recording transport changes belong to its adapter, rather than mathematical identity.
These variation axes justify the composition boundaries.

## Execution, library fit and lifetime

Separate incidence, validity/execution, objective coupling, form facts and operator products.
Equal incidence does not prove equal executable body or objective separability. Numerical
value changes need not rebuild unchanged symbolic structure. Existing ScalarCache keys exact
expressions, parameters and optimization; retaining compatible immutable scalar products under
existing allocation/flight/pressure owners is a fitting extension. Mutable evaluators stay
exclusive and lazy; original guards/coordinates/checkers remain.

The Stable-check diagnosis is source-supported: NativeValidation prepares using captured
SessionState query time, while prepared contracts and checked readmission can reuse evidence
under that native owner. Actual-owner equality alone is insufficient for invocation-sensitive
meaning. row_checks already rejects volatile expressions. Retained bound expressions and
scope-specific preparation preserve actual UDF/configuration semantics without reparsing SQL,
substitute sessions or weakening rejection. Immutable evidence can still reuse exact premises.

Owned local data, foreign pure memo and native executable generations require distinct trust.
Removing duplicate observation inside an unchanged operation does not skip a new receiving
qualification. Cancellation after dispatch retains the original effect obligation and drain.
Relevant efficiency considerations include authority/invalidation, scoped evidence and
effect-sized exclusion/recovery; no new accounting or proof machinery is required.

PS-G1/PS-G2/PS-G3 pass only for preservation within this boundary: exact physical context,
structural/operator distinctions, guards/derivatives and independent numerical checking remain
required. Model fidelity, numerical execution and assembled scientific behavior are unexamined.

## Findings and implementation obligations

No new blocking finding. Preserve these consequences of the accepted target:

1. Advance local head/generation atomically; concurrent siblings serialize coherently or branch.
2. Receiver tokens grant neither semantic equivalence, durable CAS, protection nor native trust.
3. Own the complete consumed closure, absence/context/provider premises and leases before releasing import protection.
4. Classify sensitivity from bound expressions and actual functions before simplification; sensitive handoffs compare scope and actual owner.
5. Keep failed candidate/evaluator mutations invisible; historical and array borrowers retain charges.
6. Preserve original effect identity/deadline/settlement after dispatch; recovery repeats no science or unrelated mutation.
7. Internal transforms share one captured scope; independent public admissions obtain new scope ownership.

## Alternatives, rule impacts and follow-up

Keeping canonical compute authority retains unnecessary service dependence. Removing only
constructor connection leaves editing/preparation coupled to it. A separate local backend
would duplicate semantic operations. Shared local producers plus explicit current recording
adapters are the simplest viable inspected target. Existing library preparation retains native
semantics without a bespoke CHECK interpreter or optimizer.

No impacts beyond accepted RC01/02/08/09/11, embodied by ADR-0183/revision160. This selects no
server removal, new durable format, weaker reader, disk memo or numerical method. Architectural
fitness and specified behavioral adequacy are accepted independently of implementation.
Plan38a owns targeted implementation evidence; Plan38 owns finding disposition; Plan38g owns
assembled scientific/native/Python qualification. No speed or whole-product claim follows.

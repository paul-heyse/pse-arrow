# Plan39 guarded pure macro channels

**Decision: Accept the target at Proposed strength.** Behavioral adequacy and architectural fitness pass for the bounded compile-time assurance design. This does not accept its implementation or qualify a simulator deployment. The accountable coordinator reconciled a fresh independent same-model design assessment with the owner sources and real compiler counterexample. Current disposition belongs to [Plan39b B1/B5](../../plans/39b-deployment-assurance-and-preparation.md).

The target is an efficient edit/re-solve and development loop with scientific identity that retains consumed code, separately from external-I/O completeness. Scope is Paste 1.0.15, Pest/pest_generator 2.9.2 and py_literal 0.4.0, their selected executable helpers/features/compiler contexts, and the strict producer consumer. Ordinary Local, numerical models, native solver algorithms and the full remaining Plan38 campaign are preserved and unexamined here. Apply Core 3.4, Efficient Architecture 1.0, Process Simulator 1.5 and the pse-arrow binding.

Source inspection found one Paste ambient branch shared by paste/item/expr (`Segment::Env`, `std::env::var`). Stock Paste has no pure mode. Stock Pest derive always asks the generator to include file grammar; py_literal uses `grammar.pest`. **Tested:** a standalone pinned-rustc probe of exact cached Paste source forwarded `$selector:tt` with unchanged caller text through all three entry points. Two `PSE39_MACRO_SELECTOR` values produced different symbols and successful executions, while actual `.d` files contained only the fixture source, without the selector environment dependency. Artifacts are `/tmp/pse39-b1-paste-tlj8htis`; this is a bounded counterexample, not qualification.

Select guarded owners that reject every Paste Env segment before access, and reject Pest file attributes before using the existing generator with file inclusion disabled. py_literal's exact grammar becomes one inline literal authority; delete the replaced grammar file/include constant. Actual supplied tokens, including generated selectors, are checked by the owner. “Tokens-only” includes compiler token/span interpretation under the qualified compiler; it does not promise context-free token bytes. Complete exact owner/helper/feature closure review remains required. Scientific caller code still participates in scientific identity. Unknown or changed channels remain conservative.

Stock owners with whole-caller review are simpler to maintain but retain manual amplification after unrelated edits. Syntactic projection is unsound for generated arguments. A new compiler-observation framework has a larger unestablished boundary. The selected small patches keep library-owned parsing and generation, permit local compiler tests, and enforce the assurance distinction where the external input would occur. Upstream upgrades require review and explicit replay of guard controls; no latency benefit is measured.

G1–G9 pass at target strength: no weakened scientific identity or fresh-receiving premise, explicit unsupported compile-time forms, consumed library algorithms, independently attackable channel checks and appropriate responsibilities. PS-G1–PS-G3 are not applicable to this bounded compile-time change; formulation, derivatives and numerical outcomes are not changed or assessed. No blocking design finding was established. Implementation must still prove generated-form rejection, normal parsing, source/helper/feature invalidation and no historical grant reinterpretation.

Rule impacts: **RC01** changes blueprint §5.3/§14.3 whole-caller/grammar-input assurance rules only for exact source-qualified enforced pure owners; stock and unknown owners retain their current conservative obligations. **RC02** constrains supported Paste Env/Pest file forms, preserving py_literal's runtime grammar/public semantics. Dependency realization changes are recorded with their exact pins and provenance. [Proposed ADR-0189](../../adr/0189-pure-macro-producer-channels.md) records this choice; its status is not implementation acceptance. Full compiler integration, strict role capture, actual imported-byte journeys and all scientific/performance qualification remain with Plan39b/39d.

**RC03, independently assessed follow-up:** replace the blanket root-patch prohibition with exact repository-local source selection for transitive dependencies. Require `vendor/<package>` ownership without symlink escape, matching vendor package name/version, only explicit path/version selectors and one selected sourceless lock entry. Keep replacement/configuration-path overrides forbidden. Cargo's committed lock records the actual local packages; a workspace dependency declaration alone cannot replace a transitive implementation. This is a bounded source-realization rule, not permission for implicit or unrecorded substitution. The independent assessment accepts this target at Proposed strength; the implementation controls check actual manifest/lock selection.

## Responsibility model

| Meaning or operation | Owner | Consumer contract |
|---|---|---|
| Scientific meaning | Authored relations and production admission/preparation | Challenge actual admitted models; do not reconstruct preparation policy. |
| Permission and final header | Original assessment and composed Completed product | Rust, Python and publication copy the same completed meaning. |
| Integrity implementation | Typed declarations and production producer | Independent family witnesses challenge mechanisms; actual catalog controls bind declarations. |
| Generated freshness | Complete xtask regeneration comparison | Product tests do not repeat weaker checks. |
| Mutable effects | Requesting test/fixture | Isolate files, databases, runtime state and teardown. |
| Execution evidence | Runner selection, recipes and one terminal composer | Preserve actual selection, outcomes, inputs and native provenance. |
| Transport | Result-owned synchronized cache and existing encoders | Consume immutable completion; transport failure cannot alter permission. |

The target captures permission versus transport success, invariant semantics versus producer provenance, and execution versus applicability. It introduces no competing model registry, scientific acceptance engine, test selector or per-test impact graph.

Completed trajectories retain one clone-shared immutable snapshot; accepted() derives composed permission. Final kind/header are bound by private construction. Shooting consumes the coherent joined optimizer report and enclosing header rather than relabeling dynamics. Successful-map publication is transactional; metadata is admitted before growth and escaped batches retain ownership. Direct retry never reexecutes science; outer RunResult retains its sticky encoding-error contract.

Invariant origin is read-only native derivation metadata. Only the actual producer stamps generated bindings. Origin does not replace canonical queries, severity, inputs or keys, and does not enter durable/hash semantics. Independent family witnesses, actual catalog binding and admitted production candidates establish different risks. A validator's presence alone does not justify deleting an old independent control. The narrow raw boundary remains necessary for hostile representations refused earlier by admission.

Effects follow explicit setup. Checkout polling cannot causally attribute concurrent edits; disposable-input contents/modes provide an actual prohibited-write control. Immutable preparation may be shared; mutable runtime/database state belongs to its fixture. The complete xtask comparison remains stronger than the removed governance regeneration test, including extra/untracked outputs. Scoped receipts retain real selection, terminal outcomes and native identity; unknown input scope is conservative. Failed, interrupted, missing, skipped or unexecuted work cannot become passing evidence. Measurement prerequisites name recipe scopes rather than reconstruct runner selection.

## Revealing changes and alternatives

| Scenario | Required response | Judgment |
|---|---|---|
| Add another declaration in an existing integrity family | Change production binding locally; reuse family witness and intact catalog enforcement; add independent expectations for new authored semantics. | Avoids a second catalog. |
| Change runner or feature mode | Recipes configure mode, runner selects, composer reconciles; feature absence stays distinct. | No false mode equivalence. |
| Edit unrelated prose, then a consumed lock/native provider | Context changes alone do not invalidate; consumed inputs invalidate relevant evidence; unknown scope is broad. | Conservative applicability. |
| Export, clone and drop accepted/refused results | One permission/header; shared successful buffers; no partial cache or changed science after encoding failure. | Coherent separate failure domains. |
| Store test beside checkout edits | Isolated database/files and explicit teardown. | Local effects without attribution machinery. |
| Retire empty shell/name-only parity | Delete registrations and obsolete obligations; preserve structural algorithms and scientific comparisons. | Removes no supported mathematics. |

Keeping the baseline preserves mutable projections, repeated setup and duplicated freshness. Universal impact graphs, second test catalogs and per-relation export add machinery without a demonstrated need. The selected design composes production owners, established runners and the complete comparison directly. Whole-map first export can refuse under a budget that fits one relation; conservative scopes can rerun more work than precise impact analysis. Both costs are explicit. Neither supports an unmeasured speed/memory claim.

## Verification and decision

Implementation must establish accepted/refused/incomplete projection agreement, coherent Shooting headers, concurrent clone export, budget retry and escaped lifetime; independent integrity mechanisms plus intact catalog enforcement; complete missing/extra/untracked freshness controls; and isolated effects plus failure/interruption/input-identity reconciliation. Syntax checks cannot establish these properties. ADR-0160 supplies the governance/crate/compatibility authority route, superseding ADR-0051's duplicate test responsibility while preserving complete regeneration equivalence. ADR-0092 remains in force. Architecture and relationship-to-IDAES text must agree with the retired historical name obligation.

Behavioral/semantic adequacy: **Accept at Proposed design level**. Architectural fitness: **Accept**. Overall: **Accept** the bounded Plan 26/ADR-0160 design, based on explicit responsibility decomposition challenged against decisive baseline interfaces and revealing changes. This neither closes the earlier diagnosis nor establishes implementation or unexecuted scientific qualification.

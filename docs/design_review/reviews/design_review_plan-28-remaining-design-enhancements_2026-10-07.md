## Findings

### <a id="f01"></a>F01 — Stored-study creation repeats declared admission

**Principles/gates/scenario:** AP-07, DP-10, PS-11; G9; S01. **Diagnosis: Implemented, source-inspected. Remedy: Proposed.**

[`Runtime::start_defined_study`](../../../crates/pse-runtime/src/workflow/study.rs) calls `StudyOperation::admit_binding_seed_need` for every point. [`study_operations.rs`](../../../crates/pse-runtime/src/workflow/study_operations.rs) constructs a fresh `DeclaredStudyAdmission`, reaching `ModelingPackage::declared_execution` and [`ModelingPackage::prepare`](../../../crates/pse-runtime/src/workflow/modeling.rs). Checked selected-admission retention does not prevent this later workspace/preparation repetition. The ordinary durable study and Python routes reach this owner.

Authoring already retains an adjacent operation-scoped basis in [`admit_operation_overlay`](../../../crates/pse-runtime/src/workflow/bindings.rs). `declared_admission_reuses_one_basis_for_thousand_physical_points` covers that authoring path, not stored-definition readmission. A large value-only stored definition therefore repeats preparation before claims or numerical dispatch. Its contribution to the unfinished Python run is unmeasured.

Retain the existing compatible declared basis within stored creation; validate every decoded binding, source association, descriptor, physical context and seed role independently. Changed structural premises replace it, releasing superseded state. Fresh protection and occurrence identity remain. This uses the existing admission owner, not a global cache or second checker.

**Owner/verification:** 28f N2/N4 with 28c and selected preparation. Exercise actual stored/default durable creation over many bindings; show structural preparation is shared, occurrences remain distinct, invalid later bindings refuse, and changed route/settings/layout/source replaces or refuses the basis. Pure authoring controls alone cannot close this route.

### <a id="f02"></a>F02 — Default persisted preparation replay remains strict-only

**Principles/gates/scenario:** AP-02, AP-05, AP-07; G9; S02. **Diagnosis: Implemented, source-inspected. Remedy: Proposed target decision; RC01.**

Python defaults to `producer=None` in [`Runtime::new`](../../../crates/pse-py/src/workflow.rs); worker [`deployment::open`](../../../xtask/src/bin/support/deployment.rs) obtains producer evidence only from an explicit receipt. Without it, [`CanonicalBodyRetention::get`](../../../crates/pse-runtime/src/math/retention.rs) returns a miss before querying persisted products. Unqualified publication still persists descriptions. Qualified reconstruction requires actual association and the supported producer profile through [`QualifiedProducer::from_deployment_receipt`](../../../crates/pse-runtime/src/math/portable.rs).

[28e's optional campaign policy](../../plans/28e-rebuild-retirement-and-qualification.md#development-phase-evidence-and-optional-artifact-requalification) preserves historical evidence and ordinary execution. It does not enable default prepared-body replay after restart. The restart/edit/re-solve target consequently depends on strict qualification for this capability; durable results and process-local reuse are different guarantees.

Prefer narrowly scoped **exact deployment-local replay**, with optional broader producer qualification remaining distinct. One admission owner must independently establish the actual executable/interpreter and consumed native/runtime context. Executable bytes alone omit mutable shared libraries and runtime inputs. Both guarantees must use the same protected acquisition, complete dependency checker, portable representation and scientific reconstruction. Missing premises refuse cache reuse while fresh execution and historical result access remain available.

The smallest adequate admission mechanism is unsettled. Existing deployment/native observations may discharge parts of it; do not assume complete coverage, reinterpret unqualified records, invent caller-minted eligibility or use outer source hashes as authority. A changed deployment can cause a preparation cache miss without forcing a rebuild/campaign or invalidating historical results.

The simplest safe alternative is strict-only replay with an explicit ordinary-development limitation. Automatic strict recapture imposes additional work; weaker JSON/hash matching omits consumed premises. A legitimate installed application without its authored checkout must either establish deployment-local compatibility independently or prepare afresh, rather than be barred from ordinary execution.

**Owner/verification:** 28b B3 and 28h L3 settle the guarantee; the coordinator adopts RC01 through the decision route. Actual default worker/Python restart controls must prove reconstruction rather than fresh admission, with changed native/configuration, wrong artifact/role, corruption and current protection controls. Optional strict qualification stays separate.

### <a id="f03"></a>F03 — Immutable receipt permissions leak into Cargo output

**Principles/gates/scenario:** AP-02, AP-03, AP-05; G9; S03. **Diagnosis: Implemented, source-inspected, consistent with retained operational failure. Remedy: Proposed ordinary fix.**

[`seal_generation`](../../../scripts/native_cache.py) correctly removes generation-file write permissions. [`root_isolation`](../../../crates/pse-backend-native/build.rs) copies `.complete.json` into reusable Cargo `OUT_DIR` using `fs::copy`, which [also copies source permissions](https://doc.rust-lang.org/std/fs/fn.copy.html). Inspected destinations are mode 444. The [native-test log](../../../build/assessment/plan28-efficiency-qualified-stable-20261007/native-test.log) fails with `PermissionDenied` after announcing that receipt, before test execution.

Installation immutability has crossed into another owner's replaceable derivation. Consume verified bytes and materialize writable Cargo output through owner-local replacement, including an existing read-only destination. Preserve unchanged bytes/mtime where useful and leave sealed source permissions intact. Standard filesystem operations suffice; target cleanup, installation permission repair and a provider rebuild address the wrong boundary.

**Owner/verification:** 28h L4 and 28e E2/backend-native. Cover repeated invocation, changed receipt, existing mode-444 destination and untouched source bytes/permissions, then run the affected native route. Successful compilation alone is not numerical qualification.

### <a id="f04"></a>F04 — IDAS repeats factorization of one sample matrix

**Principles/gates/scenario:** AP-07, DP-10, PS-11; G9; S04. **Diagnosis: Implemented, source-inspected. Remedy: Proposed.**

[`Session::jump`](../../../crates/pse-backend-native/src/dynamics/idas.rs) evaluates one local RHS partial matrix, then passes that same matrix to [`eliminate`](../../../crates/pse-backend-native/src/dynamics.rs) for the first adjoint jump and every Hessian direction. Each call reconstructs the algebraic transpose, symbolic analysis and numeric LU. Only right-hand sides differ within that sample.

Factor once at the sample owner and solve each right-hand side through faer. Sequential solves against one factor are sufficient; batching is optional when additional live storage is justified. Preserve first-order multipliers used by curvature, differential masks, coordinate ordering, algebraic-zero enforcement and finite/singular refusal. Changed samples/states/modes require current numeric factors; broader symbolic reuse requires compatible structural premises.

[faer 0.24.4](https://docs.rs/crate/faer/0.24.4/source/src/sparse/linalg/lu.rs) supplies numeric factor storage and multiple-RHS solves, already consumed by other adapters. No bespoke factorization or new service is warranted.

**Owner/verification:** 28f N3/N4, native dynamics/IDAS. Show one factor construction per sample with distinct directions, first/second-order production-basis correctness, changed samples and singular/nonfinite recovery. Source proves repeated work, not a wrong derivative or measured speedup.

### <a id="f05"></a>F05 — Dynamic workers reconstruct program-fixed layouts

**Principles/gates/scenario:** AP-07, DP-10, PS-11; G9; S05. **Diagnosis: Implemented, source-inspected. Remedy: Proposed.**

[`DynamicWorker::new`](../../../crates/pse-runtime/src/workflow/dynamics.rs) reconstructs coordinate-scale chains, sparse support, refill correspondence and `AssemblyMatrix` structure from admitted programs/coordinates. [`IntegratedExperiment`](../../../crates/pse-runtime/src/workflow/integrated.rs) creates workers separately for integration, gradients and Hessians. [`AssemblyMatrix::new`](../../../crates/pse-math/src/sparse.rs) canonicalizes the sparse structure and derives its refill map each time. These layouts do not depend on trial parameter values.

Retain checked immutable function-layout metadata with the admitted dynamic program. Attempts instantiate private matrix values, evaluators, providers, guards and execution scope. Reuse existing sparse assembly mechanics; preserve mode/function identity, constants, scales, derivative order, structural/provider dependencies and complete allocation accounting. Changed layout rebuilds; changed values refill. Concurrent attempts must not share mutable values or candidate acceptance.

**Owner/verification:** 28f N1/N3/N4, runtime dynamic preparation and fitting/shooting consumers. Show retained layout identity, independent concurrent scratch, changed coordinate order/scales/constants/support and extent refusal. This diagnosis concerns metadata construction, not every evaluator allocation. A frozen template supplying fresh mutable storage is a viable local alternative to a broader sparse-layout abstraction. Charge retained metadata and private worker storage separately; remove displaced derivation. The principal assessment initially kept layouts conditional; supplemental independent inspection and the admitted-input-only construction settle this narrower correction. Choosing a different evaluator remains separate.

Library research used Context7 followed by exact release sources for consequential contracts. Moving documentation and obsolete examples were not treated as pinned proof. **Transient fitting:** [`FitOracle::evaluate`](../../../crates/pse-runtime/src/workflow/fitting/oracle.rs) first integrates gradient-only transient predictions without sensitivities. The adjoint route then invokes the combined gradient operation and discards its returned forward report. A gradient request can therefore execute an ordinary forward followed by checkpointed forward/backward work. Existing completed-point caching already avoids repeated callbacks at the same cached point.

The fitting demand owner should assess consuming the combined report/gradient when both are requested, versus cheap objective-only execution and bounded later upgrade/recomputation. Eager backward work for every objective-only trial can add work and memory. Preserve coherent trial identity, included observations, weighted cotangents, physical conversions, frozen policy, endpoint/event restrictions, checkpoint admission, outer deadline and foreign-memory charging. The duplication is source-established; the best complete replacement remains unresolved. No library continuation across changed parameters is assumed.

**Storage:** SurrealDB's [3.3.0 query stream](https://github.com/surrealdb/surrealdb/blob/v3.3.0/surrealdb/src/method/query.rs) emits provisional rows and statement-end results; rows alone do not prove completion. Its channel limit counts items, not bytes. Replacing bounded calls with a long stream changes snapshot/protection, buffer and failure/drain lifetimes. It is not automatically cheaper. Existing [native query evidence](../evidence/production-execution-efficiency-2026-10-07/surreal/README.md) supplies leads on compound indexes and correlated selection, not measured scaling of current bound queries. Small answers and one RPC do not establish little examined work. Use selected/empty/skewed query-plan evidence where it can settle an actual remaining choice; no automatic graph/index/transport pivot is recommended.

**Creation cancellation:** `study_durable` accepts cancellation but awaits `start_defined_study`, which creates a fresh cancellation source, before its cancellation loop. Caller cancellation does not govern that admission loop. Settle creation-phase support alongside F01: stop prepublication work through its owner and preserve acknowledged effects truthfully after publication. This is an unresolved contract obligation, not an established corruption or stall diagnosis. [Tokio's blocking-task contract](https://docs.rs/tokio/1.53.2/tokio/task/fn.spawn_blocking.html) reinforces why native resource ownership lasts through actual drain.

# Automatic simulation and solve pipeline

**Revise for the requested automatic-composition target.** Plan 25m supplies substantial
mathematical producers, library integrations and a bounded driver for declared strategies.
It does not yet construct the decomposition and numerical composition from the simulation
problem. Several existing integration defects also need correction: block scheduling loses
control dependencies, actual accuracy evidence cannot satisfy strategy admission, and original
assessment does not supply its cause or work to the driver. Three explicitly required native
capabilities have no production binding.

The right continuation is a resolver over the existing mathematical products and driver,
with complete consumed contracts. It is not a new numerical engine. Preserve library-owned
iteration, globalization, sparse factors and surrogate management; preserve independent
original scientific permission. Appropriate method selection means satisfying the requested
guarantees with avoidable preparation, proof and execution work removed. This review makes
no claim that one backend or composition is universally fastest.

## Ownership and the minimum integrated design

The existing separation is useful: authored relations own physics; compiler/math producers
own structure, support and reconstruction; native libraries own numerical algorithms;
runtime owns bounded dispatch and resources; workflows own scientific acceptance, adaptive
statistical/control policy and durable effects. The missing responsibility is constructing
an admissible composition and carrying its actual products between these owners.

**Proposed:** one resolver consumes the original problem, analysis intent, required guarantees,
authored choices, available producer/native capabilities and operational policy. It produces
an inspectable resolved composition with semantic maps, demands, prerequisites and rejection
reasons. Ordinary domain operations are sufficient; this does not require a serializable
planning language, generic search framework or new service.

| Owner | Consumed contract and owned decision | What downstream consumers can stop deciding |
|---|---|---|
| Simulation/compiler | Original roles, physical rows, objective, bounds, guards, port conventions and complete inventories | Rediscovering local residual/unknown inventories and interpreting topology as solvability |
| Math decomposition | Numerical incidence **and separate** execution/validity dependencies; coupling; selected reconstruction/regularity contracts | Selecting blocks or elimination from sparsity alone |
| Composition resolver | Admissible alternatives, capabilities, demanded products, start/branch constraints, final guarantees and finite policy | Hand-assembling backend-specific recovery and decomposition in every workflow |
| Mathematical producer | Actual point/action accuracy, validity and correspondence to the original | Treating prepared support, derivative provenance or a surrogate estimate as a point certificate |
| Native adapter/library | Admitted representation, effective settings, native layout and observed numerical work | Interpreting option strings, library statuses or KKT offsets outside the adapter |
| Shared driver | Actual starts/products, scoped observations, transitions and inclusive work | Duplicating numerical retry policy in consumers |
| Scientific workflow | Independent original assessment, statistical/control policy and publication permission | Inferring a complete scientific result from auxiliary/native convergence |

Capability is conditional: bounds/domain support, derivative source/order/actions, smoothness,
class evidence, sparse layout, factors, setup reuse, available starts, cancellation and
observable work all matter. Separate immutable eligibility from a failed trajectory and
point-dependent regularity. Preserve explicit backend/profile and scientific branch choices
as constraints. Distinguish a mandatory choice from permitted alternatives: bounded causal
inputs may make a map inadmissible while a constrained simultaneous solve remains valid.
Choose the latter only when alternatives are allowed; a required map or incompatible forbidden
tear needs explained refusal. An automatic decision must explain incompatibility rather than erase them.
Backend details remain in the integration owner; a semantic workflow must not know FERAL
factory ordinals or POUNCE KKT offsets.

Avoid preparing every possible method before selection. Resolve inexpensive structural and
capability facts first, request only the selected products, then reconsider using actual
observations. A costly optional certificate may be unavailable without invalidating an
otherwise admissible direct solve. Required guarantees cannot be silently downgraded.

### Physical semantics and well-posedness

The following are preservation constraints, not new physical definitions. Their authorities
remain blueprint §8–§9, §14, §17–§18 and §19.

| Element | Dimension/unit and basis | Convention/reference | Validity | Owning operation |
|---|---|---|---|---|
| Variables, parameters and port values | Declared quantity and material basis; explicit conversion | Authored quantity/port conventions | Physical intervals and provider envelopes | Modeling case binding and causal port programs |
| Balance/residual rows | Original physical row units | Authored signs, closure and contribution identity | Original guards and applicability | Case compilation and independent modeling assessment |
| Objective and inequality/bound rows | Original objective/coordinate scales | Objective sense and lower/upper orientation | Original feasible set | Original contract, reduced oracle and original assessment |
| Selected implicit properties | Declared provider quantities | Authored root-selection meaning and sheet | Complete selection obligations, chart and regularity | Regime selection, reconstruction and proof producers |
| Time-dependent states | Declared time/state units and differential/algebraic roles | Authored dynamics versus explicitly artificial flow | Consistent state, events and domain | Dynamic compiler, IDAS and derived-flow preparation |

Roles, fixed specifications, equality/inequality distinctions and complete incidence support
must govern degree-of-freedom analysis and admission before execution. Matching/BTF proves
structural facts, not numerical rank, a regular implicit sheet or separability of an objective.
Connection topology offers tear candidates, not a complete mathematical dependency graph.
Cross-block objective/inequality coupling remains simultaneous or is carried through a valid
reconstruction. Diagnostics should name original model elements through semantic maps.

Objective-only reduced optimization can be well-posed with no retained original constraint
row; an objective-free root problem with unconstrained retained coordinates is different.
Selected root, DAE initialization and artificial flow likewise require their own conditions,
not a generic square-matrix test. AF-01 and AF-08 expose current admission/scheduling limits.

### AF-01 — High: derivative sparsity is not a complete block schedule

In [execution.rs](../../../crates/pse-math/src/execution.rs), `Support` distinguishes
first-derivative support from controls. `Stage::Branch` analysis puts guard inputs in controls
but merges only branch-expression numerical dependencies into output first support.
Applicability/domain obligations also have controls. In
[workspace.rs](../../../crates/pse-compiler/src/workspace.rs), `structural_plan` exports only
`first_for_output`. Initialization ordering consumes this projection; conditional assembly
fixes outside-block variables. `Blocks::stages` in
[initialization.rs](../../../crates/pse-runtime/src/math/initialization.rs) commits assembled
values after local block checks without a complete original reevaluation.

A static revealing case is `x = if y > 0 then 1 else -1`, another row setting `y = -1`,
and an initial `y > 0`. Numerical incidence permits independent square blocks; solving `x`
first can become stale after solving `y`. Local acceptance does not establish simultaneous
satisfaction. This is a fidelity defect even with explicitly selected decomposition.

**Proposed correction:** preserve a separate execution/validity dependency projection for
ordering, merging or invalidation, while numerical incidence keeps matching/Jacobian meaning.
The completion owner independently assesses the reconstructed full original point. Do not
fabricate derivative edges through guards. A guard on a fixed parameter remains a validity
input without creating another unknown; conservative body-wide dependencies may be used
initially without claiming precise output attribution.

AP-04/AP-05; DP-07/DP-08; PS-05/PS-06/PS-10. Settle with the branch-controlled case,
a nonnumerical domain obligation and a fixed-parameter negative control, preserving sparse
derivative patterns and original residual refusal.

### AF-02 — High: original refusal is lost from the shared transition observation

`NativeSession::step` in [staged.rs](../../../crates/pse-runtime/src/math/staged.rs) invokes
original assessment but builds `Assessment` with the native observation and
`strategy::cause(outcome)`. Workflow `Staged::execute` returns the scientific point/completion
plus `StepRetention`; its refusal reason cannot enter that observation/cause contract.
Thus native convergence followed by rejected original physical/knowledge checks can leave
a `Converged` observation and stop without the independent cause. Candidate permission still
refuses use: this is not evidence of false final publication. The
[opaque direct boundary](../../../crates/pse-runtime/src/math/opaque_strategy.rs) already
accepts an `original_failure` callback, showing the seam can carry the distinction.

**Proposed correction:** original assessment returns its semantic conclusion, composed
permission and typed cause to the common driver. Preserve native status separately. Distinguish
recoverable numerical failure, original scientific refusal, invalid contract, resource exhaustion,
cancellation and operational failure. Local-native infeasibility is not an original-model
infeasibility proof; that distinction is also required by AF-06 second opinions. Do not make
every scientific refusal retryable or infer original feasibility from a different backend.

AP-02/AP-03/AP-04; DP-21; PS-10. Settle with native convergence plus original refusal,
recoverable local infeasibility, and terminal original/contract/cancel controls. Check both
transition choice and preserved diagnostic/public trace, not only permission.

### AF-03 — High for strict limits: assessment work is outside an apparently complete evaluation count

`strategy::work_native` copies native report counters. `run_inner` charges that work before
calling assessment. Modeling `Assessment::evaluate` in
[assessment.rs](../../../crates/pse-runtime/src/workflow/modeling/assessment.rs) then performs
a fresh compiled `constraints(values)` evaluation. The injected assessment signature returns
no work charge. A finite strategy evaluation cap can therefore consume a present native count
while missing actual independent assessment work. In contrast, `opaque_strategy::direct`
truthfully reports unknown composite counters.

**Proposed correction:** producer-owned inclusive work or separate disjoint assessment charges
must enter one ledger exactly once, including unsuccessful and abandoned work. Keep phase
and charging ownership explicit. If a composite counter cannot be observed, it remains unknown
and cannot satisfy a strict counter requirement. Check the enclosing scope before and after
indivisible assessment; the existing deadline checks are a strength, but do not repair a
numerical work count. Do not charge the same nested callback in both parent and child totals.

AP-02/AP-05; DP-19/DP-20/DP-22; T6/T8. Settle with a strict cap spanning native and
assessment calls, a failed assessment, and nested inclusive/disjoint counter controls.

### AF-04 — High integration gap: produced accuracy never becomes an admission fact

`PreparedRung::accuracy_evidence` and `PreparedDerived::accuracy_evidence` in
[derived preparation](../../../crates/pse-runtime/src/math/solves/derived.rs) return empty
evidence. That is truthful for immutable preparation. However, `NativeSession::step` snapshots
these empty vectors and its facts closure never updates them. Actual reconstruction accuracy
is recorded only in trace products after execution. `strategy::admit` checks the strategy's
accuracy demands against each rung's facts before dispatch. Consequently a nonempty accuracy
list refuses production rungs before the evidence producer can run; a required rung stops.

Producer-level `ReconstructionAccuracy`, point/action refinement and reduced-oracle checks
remain implemented. The diagnosis is an unconsumed shared contract, not fabricated certification
or proof that those producer checks fail.

**Proposed correction:** distinguish a producer's admitted capability to produce evidence from
a consumer's requirement for already produced point/action evidence. Carry actual results in
an owned execution product state with product, point, normalization, class and allowance;
admit each consumer against its prerequisites. Bind prerequisites and produced-evidence
obligations to their actual operations/products: updating the facts vector alone cannot repair
a global demand list applied to every rung. A producer must not require its own output as
an entry certificate. Promotion/refinement updates or replaces evidence under the same scope;
support preparation never invents zero error. A certificate for another point, weaker class
or incompatible normalization must still refuse the consumer. Avoid a second independent
certificate registry beside the actual producer.

AP-03/AP-04/AP-05; DP-15; PS-07; T5/T8. Settle with a real producer followed by a
consumer demanding its actual certificate, plus wrong-point, weak-class and tighter-demand
controls. Pure admission tests alone cannot establish this integration.

### AF-05 — High target gap: automatic routing does not construct automatic composition

`PreparedSolve::numerical_strategy` in [solves.rs](../../../crates/pse-runtime/src/math/solves.rs)
defaults to one direct attempt. `NumericalStrategy` is an ordered caller declaration.
Backend Auto chooses admissible class/backend candidates by published ranks and readiness;
it does not select decomposition, derived preparation, predictors or a recovery composition.
Fitting/shooting use `opaque_strategy::direct`, so sharing observation machinery does not
give them a reusable target-execution operation for composed strategies.

Similarly, `ModelingFlowSelection` and `RecycleRequest` require caller-supplied units, tears
and local realizations. The compiler already derives local residual/unknown inventories, but
admission compares those with caller assembly rather than constructing the alternatives.
Reduced preparation validates an explicitly supplied factory, retained columns, eliminated
rows, realization and accuracy. These are coherent low-level operations; they do not fulfill
the newly requested automatic target.

**Proposed correction:** add the resolver described above over existing operations. Compile
admissible decomposition candidates from full mathematical facts, then resolve demanded
products and bounded strategy policy. Explicit author choices remain constraints. Give
consumers a reusable execution contract for one supplied mathematical target; retain statistical,
control and durable loops with their workflow owners. Do not replace a profile-likelihood loop,
sampling policy or event controller with generic numerical recovery.

KKT activity-path/QP predictors and `SecantHistory` currently have definitions/local controls
but no production workflow consumer. `ModelingResult::root_prediction` is a real public
producer; horizon has a real KKT predictor consumer. Selectively integrate these through the
same start/proposal contracts, without equating prediction with a qualified endpoint.

A qualified connection-map recycle is also narrower than a full flowsheet result:
`UnitWorker::evaluate` discards local trial coordinates and returns output ports. Automatic
handoff needs complete original-state reconstruction, including non-port unknowns, and
original assessment. Do not reinterpret the existing `DeclaredRootReport` as already providing it.

AP-01/AP-03/AP-04/AP-06; PS-05/PS-08/PS-09. This broader target requires reconciliation
with blueprint §17.4's explicit alternatives through the decision/design route. Settle with
one automatically compiled connected case with a stiff/coupled block, a second workflow
consuming the same target execution, and explicit branch/backend/forbidden-tear controls.
Include `NoPriorStart`, explicit entry identity and separately authorized recovery origins:
forbidden inherited starts do not automatically forbid fresh task-produced recovery.

### AF-06 — High completeness gap: required native families lack consumed bindings

Plan 25m's method table and P6/P9 require the following actual execution routes. Exact
POUNCE 0.12.0 source supplies them; repository production searches and inspection of
[pounce.rs](../../../crates/pse-backend-native/src/pounce.rs) establish these missing bindings.

| Obligation | Current evidence and consequence | Proposed integration and legitimate limits |
|---|---|---|
| M8 visible second opinions | Hidden retries are pinned off; direct `optimize_tnlp_without_presolve` bypasses the builder ladder. No `second_opinion_rungs` consumer exists. | Bind library-owned pure rung descriptions to the existing driver. Preserve each noncumulative baseline including unset options, actual effective options, start permissions and work. Local infeasibility eligibility needs AF-02; terminal scientific/resource failures remain terminal. |
| M17 solver KKT Schur | Sensitivity Schur operations exist; no `set_kkt_schur_block` caller supplies the solve partition. They are different products. | Derive semantic separator mapping after project presolve **and** native TNLP classification into actual `x,s,c,d` layout. Use the library classification with the same fixed-variable treatment. Expose requested and actual use/fallback; reserve Schur-owned factors separately. |
| M18 partitioned quasi-Newton/FD Hessian | Typed Hessian modes expose Exact/LimitedMemory/GaussNewton; POUNCE lowering maps exact or limited-memory and reserves raw approximation options. Library `Partitioned`/`FiniteDifference` modes are unreachable. | Add typed admitted approximation modes and their real demands, structural elements, work and provenance. Library owns updates/differences. They cannot inherit exact-Hessian claims or silently relax original final accuracy. |

Library seams are `second_opinion::second_opinion_rungs`, `IpoptApplication::set_kkt_schur_block`,
`TNLPAdapter::classification` and `HessianApproxChoice`/algorithm builder, at the versions
declared by Cargo. Public Schur documentation emphasizes exact Hessians, but inspected builder
gating admits assembled modes beyond exact; source-backed partitioned/FD combinations need
their own admitted contract rather than blanket rejection from that shorthand. Exact-only
initial integration is a legitimate explicitly scoped choice. Limited-memory/incompatible
linear profiles and unsuitable partitions must expose refusal/fallback.

The inspected library exposes partition submission but not a complete public Schur-use statistic.
Actual-use telemetry therefore needs a fitting observer/integration seam; submission alone
is not evidence of use. Schur factors are independent objects, so retained ordinary FERAL
factory ownership does not automatically account for them. Account for coupling/action
scratch, dense separator buffers, refinement matrices and failed Schur work followed by
ordinary fallback; the separator-fraction guard is not memory admission. No performance gain is asserted.

Second-opinion availability must reflect the actual typed FERAL configuration. The current
custom factory is built from `settings.linear`; merely changing library option strings can
leave it unchanged. Lower each library description into an effective typed per-attempt
profile and rebuild main/restoration factories and factor identities. Reconstruct from the
immutable typed declaration and option set-ness, not the report's resolved option values.
Partitioned modes need conservative objective/constraint element support and explicit
oversized-element degradation; FD modes need analytic First support, a conservative Hessian
pattern, finite probe work and preserved terminal callback/domain semantics. Neither mode
can satisfy a certified-error demand without actual supporting evidence.

AP-02/AP-04; DP-13/DP-15/DP-22; G7. Settle each sub-obligation with a native execution
control showing actual consumer behavior, complete effective configuration and original
permission. P6/P9 packet completion must be reconciled when these findings are adopted;
an upstream API or local mathematical test is insufficient completion evidence.

### AF-07 — Medium: causal preparation asks for whole-case First before consumer selection

`ModelingPackage::prepare_recycle` in
[conditional.rs](../../../crates/pse-runtime/src/workflow/strategies/conditional.rs) resolves
the whole case at First order before selecting explicit/conditional unit realizations.
Case resolution propagates that order to bound inner providers. The resulting outer tear map
and explicit input/output programs consume Value; conditional units have separately admitted
native demands. A legitimate Value-only selected property/map can thus be refused or acquire
unnecessary proof and derivative preparation before its consumer is known.

**Proposed correction:** resolve source meaning and structural/control evidence first, then
propagate each selected consumer's actual demands. Preserve required First support for a
conditional native solve, authored partials and genuine inner residual requirements. Existing
provider-demand propagation and immutable upgrades are the implementation basis. This is an
admission/construction issue, not a measured speed regression.

AP-02/AP-04; DP-10/DP-15; PS-07. Settle with an explicit Value map containing a Value-only
selected provider and a conditional First-demand negative control; inspect actual prepared
products, not merely a synthetic oracle route.

### AF-08 — Medium: reduced admission rejects valid objective-only optimization

`DerivedFamily::reduced_space` in [derived.rs](../../../crates/pse-math/src/derived.rs)
rejects an empty retained original-row set. Minimizing `(x-2)^2 + (y-1)^2` subject to a
regular selected equation `y=x` yields a legitimate one-coordinate objective after eliminating
that equation; it needs no further original row. Downstream `ReducedOracle` composes the
objective/gradient and eliminated-coordinate bounds, and `OracleContract::validate` does
not require nonempty rows.

**Proposed correction:** permit empty retained rows in mathematical family construction when
the reconstruction is valid. Target/native admission owns whether optimization, bounded
feasibility or root guarantees are satisfied; do not add solve intent to the mathematical
family or reject legitimate objective-free feasibility. Preserve eliminated equations as
reconstruction obligations, original
bounds, inequalities, objective and full assessment. Reject objective-free underdetermined
root work by its intent/guarantees rather than a universal row-count rule.

AP-02/AP-04; DP-02/DP-08; PS-11. Settle with the objective-only reduction, eliminated
coordinate bounds and an underdetermined objective-free refusal.

### Proof cost, accuracy and retained state

The PR validation friction involves more than an algebraic expression: selected nonlinear
roots, competitive exclusion, neighborhood regularity and demanded derivatives impose proof
work. It is inappropriate to infer a solver's C1 limitation from an attempt that requested
only First, or to remove bounds or final physical checks to get a fast receipt. Equally,
blanket derivative demand and repeated preparation must not be accepted as unavoidable.

Inspected regime-selection/refinement code distinguishes chart/sheet selection, numerical
point refinement and bounded action enclosure; actual work and deadline checks accompany
these products. Preserve complete original selection obligations, winning-sheet regularity
and original cancellation/deadline ownership. Competitive exclusion need not make every
losing root a regular winner. Retain valid chart/proof products separately from point/jet
accuracy, and request only what the selected consumer needs. A wide useful local chart is
not a global competitive cover. No new defect in the recent chart predictor was established
by this review; AF-04/AF-07 are concrete integration improvements.

Use identity dependencies appropriate to each product: immutable structure/programs,
binding-dependent eligibility, selected sheet/proof, point/jet accuracy, native symbolic
setup, fresh numeric factors and escaping result allocations. Existing keys, shared leases,
exclusive worker sessions, cancellation teardown and poisoned-state discard are strengths.
Value edits do not automatically invalidate structure; a changed branch or consumed bound
may invalidate point-dependent admission and products. Never retain an artifact merely
because candidate permission permits use, or discard all immutable products merely because
one numerical attempt failed. New Schur state has its own lifetime/accounting obligations.

## Change scenarios and alternatives

| Change/scenario | Intended local response and revealing acceptance |
|---|---|
| Add a unit/provider using existing concepts — instance/binding | One semantic declaration and specialized provider behavior; existing inventory, demand and resolver operations derive execution. No consumer-authored duplicate local equations. AF-05/AF-07. |
| Connected recycle with a stiff block and coupled inequalities — composition | Choose admissible tears/blocks from complete facts, preserve coupled mathematics and complete-state reconstruction; never identify connection residual permission with full flowsheet permission. AF-01/AF-05. |
| Replace a backend or linear solver — mechanism | Adapter owns effective profile/layout/lifecycle; resolver sees conditional capabilities, workflows see the same target/assessment contract. AF-06 Schur mappings cannot escape. |
| Value edit versus structural edit — binding/instance | Rebind values and affected admissibility; retain unchanged prepared structure. Rebuild structural decomposition after changed rows/membership. Wrong-sheet/point evidence refuses reuse. AF-04. |
| Active-set crossing/fold/competing sheet — mathematical composition | Retain partial transport and actual coverage; nonlinear correction and selected-branch permission remain separate. Do not extrapolate a truncated path as a connected endpoint. |
| Fit/study/horizon/shooting — workflow composition | Supply mathematical targets to reusable numerical execution while keeping statistical stopping, control application, sampling and durable occurrence policy local. AF-05. |
| Dynamic start/event — domain composition | Preserve differential/algebraic roles, consistency and event localization; artificial time cannot silently replace authored dynamics. |
| Missing capability, invalid trial, stationary non-root, cancellation or pool refusal — policy | Optional local refusal differs from required/enclosing exhaustion; no terminal failure becomes numerical recovery. Original cause and inclusive failed work survive. AF-02/AF-03/AF-04. |

Retaining current explicit assembly is the simplest supported implementation but fails the

# Simulation performance diagnostics

**Decision: Revise.** The current diagnostic mechanisms are useful foundations, but they do not yet serve the requested operation: inspect any simulator context during a long operation, understand what is running and what it has cost, explain what changed in the preceding minute, and retain a useful explanation after completion or interruption. Important preparation precedes the public run handle; local progress retains a beginning prefix; persisted public progress requires a closed terminal attempt; and causal context does not consistently cross native threads, shared producers and managed processes. A long silent interval therefore remains compatible with several materially different causes.

The appropriate target is a small common observation contract for navigating actual operations, current state, cumulative work, recent changes and coverage, composed with context-owned scientific and native detail. Ordinary operations should collect lightweight current/cumulative observations and bounded recent context from operation start, so a late inspector can answer a retrospective question. Explicitly disabled collection must report that coverage limit. Deep callback detail, costly operator/plan capture and sampling remain opt-in; engine `ObservationPolicy::Off` need not become expensive diagnostic capture. Existing tracing, progress taps, native counters and result distinctions should supply it. Optional timelines and sampling profiles deepen an explanation; they cannot supply missing scientific meaning or reconstruct uncollected history. This recommendation does not require a collector service, mandatory dashboard, universal numerical progress score or event for every arithmetic primitive.

Architectural fitness against this target is **violated**. Behavioral diagnostic adequacy is **incomplete**, with concrete live/history and coverage failures and unresolved profile capability. The review does not find that existing native observations are themselves qualified scientific solutions, and does not reassess whole-simulator numerical correctness. No performance speedup or latency target is established.

## What should own the explanation — slots 2 and 3

The consequential domain is not simply “a metric.” It includes an operation requested for a purpose; preparation and execution attempts; producers and waiters; current versus completed work; native trials and accepted scientific states; and observations with a declared source, interval and completeness. These distinctions must govern the read operation, rather than appear only as labels in a final report.

| Responsibility | Owned decisions and consumed/exposed contract | State/effects and local test boundary |
| --- | --- | --- |
| Scientific/context owner | What was requested, which model quantities and transforms apply, why a stage/analysis is needed, what was accepted or withheld | Existing modeling/analysis owners retain authority. Diagnostic projection can be tested with actual typed observations without starting an unrelated solver or store. |
| Execution owner | Actual prepare/admit/queue/run/join/drain boundaries; task, child and shared-producer relationships | Runtime, worker, native-child and transport owners publish facts they observe. Trace identity never changes mathematical/cache identity or attempt fences. |
| Native/library adapter | Safe checkpoints, applicable counters, native phase/coordinates, reset and stop meanings | Mutable native state remains owner-affine. The adapter publishes bounded immutable observations; an inspector does not call foreign getters concurrently. |
| Diagnostic observation/read owner | Current snapshot, cumulative facts, recent/history coverage, interval selection and source links | Composes observations, reports unknowns and losses. Does not decide convergence, reuse eligibility, retries or scientific permission. |
| Presentation and optional profiler | Compact explanation, native detail, timeline or sampled stacks | Rust/Python/CLI views consume the same meaning. Subscriber/exporter and sampling choices belong at composition roots. A profile owns only its actual capture interval and coverage. |
| Result/publication owner | Scientific qualification, partial result permissions, coherent sealing and terminal read | Existing closed-result admission remains intact. Live diagnostics have a separate permission and lifetime, not provisional scientific-result access. |

This is a responsibility model, not a proposal for six services, crates, registries or independent copies of policy. An ordinary function or compact owned state may implement several responsibilities while preserving their contracts. The runtime is a plausible composition owner; it must not make every scientific owner depend on canonical storage or global subscriber installation merely to expose useful local observations.

### Physical and numerical interpretation

| Quantity or observation | Dimension/unit, basis and convention | Authority and limitation |
| --- | --- | --- |
| Elapsed/CPU/native time | Seconds, with explicit wall/CPU/system clock and inclusive scope | Producing clock/adapter. Parent/child time and CPU/system/wall totals overlap; sum only when the contract permits. |
| Physical variable, residual or tear | Existing physical unit/basis/reference convention, model identity and original/transformed correspondence | Authored model and context owner. A native normalized residual is not a physical balance defect. Detail may be partial. |
| Objective, stationarity, barrier and restoration measures | Method-specific normalization, phase and tolerance convention | Native adapter and formulation. Neither objective decrease nor callback traffic establishes original feasibility. |
| Dynamic time and step/order | Scientific time units; internal mesh, returned time, current/proposed versus last accepted step | Integration adapter. Output-grid samples are not native accepted steps. |
| Work, memory and reuse | Method-specific counts; pool reservation, process/cgroup observation and retained capacity separately | Actual producing owner. Static expression operation count is not executed work; shared pool peak since last reset is not an operation peak; process VmHWM is lifetime high-water. |

Well-posedness and formulation remain with their existing owners. Diagnostics must show structural rejection, named offending elements, numerical infeasibility and native execution as different phases/outcomes. This review does not establish every pre-solve structural gate; it requires a projection to retain the gate's actual result rather than rediscover or rerun it. Inspection must not silently evaluate residuals, properties, derivatives or original-space checks to fill an otherwise missing chart. Such evaluation would be a separately requested scientific operation with its own cost and outcome.

## Complete-context diagnostic target — slots 4 and 5

A useful answer should state: observation scope and freshness; current phase/active child or last checkpoint; elapsed and available cumulative work; changes over the actual recent interval; a supported explanation or unresolved hypotheses; and coverage limitations. The completed answer adds outcomes, failed/partial work, produced/withheld members, publication and drain. It must answer “unknown” usefully when a native phase is opaque.

## Findings — slot 7

The findings describe distinct obligations that must compose. F01 supplies the operation relationships needed by F02–F05; F03's time/scope semantics and F04's scientific interpretation constrain their outputs. F02's coverage and lifecycle protect all views. F06 is an exposed execution-fit defect outside the main diagnostic correction; it is not a prerequisite for delivering useful diagnostics. Priority follows user consequence, while prerequisite order follows the meaning consumers need.

### <a id="f01"></a>F01 — Expensive work lacks a continuous inspectable operation and causal context

**Priority:** high. **Principles/gates/scenarios:** AP-02/AP-03/AP-04/AP-05/AP-06, DP-04/DP-05/DP-21, G9; S01, S03, S07–S12.

**Cause and evidence — Implemented, source-inspected:** preparation in `ModelingPackage::declared_execution_with_demand`, `prepare_analysis_attempt` and `finish_case` awaits expensive work before `RunHandle` exists. `MathService::{submit_source_timed,admitted}` create submission/admission async boundaries; `admitted` also creates the named native thread with runtime/compute ownership but does not restore caller span/dispatch in that closure. Engine `TaskTracer` explicitly does restore both, demonstrating that activity ownership and trace propagation are different contracts. Fitting lanes and native-child/managed-process boundaries likewise lack an established end-to-end diagnostic relationship in the examined launch paths. Native-child `Hello/Request/Response` supplies execution/request identity but no live progress protocol; its execution creates `Progress::new(0)`. Shared flights own producer cancellation, but do not export a producer/waiter diagnostic graph.

**Consequence:** minutes before start, or a slow nested/managed worker, can appear as one silent parent wait. A global subscriber might capture unrelated-looking thread spans without identifying which actual producer the caller awaits. A caller-local zero does not establish remote reuse or no work.

**Corrective contract — Proposed:** create inspectable operation identity/lifecycle before the first expensive effect, link its actual preparation/execution children and dependency waits, and propagate diagnostic context through the owners that create tasks, threads, children and requests. Show shared producer execution once with distinct waiter links. Existing run/attempt/model identity may be referenced; it need not become one new universal identity. Owners publish boundaries and reasons they know; consumers navigate them without reconstructing dispatch policy or modifying cache keys.

**Preservation and revealing countercase:** two callers may share a preparation while only one cancels. A single-parent tree or cancellation tied to diagnostic-reader lifetime would misrepresent or stop valid shared work. Preserve current flight and native join ownership, scientific identity and standalone library use without global subscriber takeover.

**Verification — Proposed:** inspect a preparation before start; trace one nested operation and one managed/native child; join two waiters to one producer and cancel one. Establish visible relationships and explicit propagation gaps using small controlled operations, not comparative timing or host equivalence proof. Safe process-local access and cross-process transport remain design decisions to settle.

### <a id="f02"></a>F02 — Prefix retention and terminal admission cannot provide recent live history or interrupted coverage

**Priority:** high. **Principles/gates/scenarios:** AP-02/AP-04/AP-05, DP-19/DP-20/DP-21, G2/G5/G9; S06–S12.

**Cause and evidence — Implemented, source-inspected:** `Progress::push` appends up to its limit and then increments a dropped count; `snapshot` returns that beginning prefix. `Runtime::progress` calls closed canonical `read_results` and describes a terminal stream. Durable writes can occur earlier, but this public reader intentionally does not follow provisional rows. Benchmark `Phases::on_close` accumulates closed spans in memory and `native_process::process` writes after `group.finish` and retained cleanup. `ExecutionTrace::record` returns success without a coverage marker at 1024 observations or reservation refusal.

**Consequence:** a late inspector can see unchanged early iterations while later activity is lost; remote public history remains unavailable until terminal closure. A killed benchmark can lose its explanation. A short engine observation collection does not establish complete coverage. An open opaque phase may accrue no closed-span duration while dominating elapsed time.

**Corrective contract — Proposed:** current/latest state, cumulative facts, recent interval history and terminal evidence have distinct semantics. Retain bounded recent observations or compact interval aggregates adequate for a last-minute question, with actual interval, freshness, omitted ranges and reset boundaries. Expose read-only live diagnostic access separately from closed scientific results. Collect the cheap current/cumulative/recent facts from operation start in ordinary runs; a late attachment can request deeper capture but cannot reconstruct a previously uncollected minute. An explicit opt-out advertises that history as unavailable. Declare survival under ordinary cancellation/drop, writer failure and hard death; preserve a useful prefix/current state where the chosen sink can, and say when it cannot. Loss of detailed capture must be visible even when collection returns successfully.

**Preservation and revealing countercase:** a rolling suffix alone loses costly early preparation; a terminal record alone loses current visibility. Preserve cumulative facts plus selected history, and existing nonblocking tap, diagnostic pool, scientific sealing and writer/science separation. A deliberately unsampled expensive phase remains “unobserved,” not zero-duration.

**Verification — Proposed:** saturate detail retention, inspect two recent windows and an open phase, fail the optional writer, cancel during drain and interrupt an owned capture. Check loss/freshness/survivability claims without requiring every event to be durable. Exact history cadence and public live transport are still to be designed.

### <a id="f03"></a>F03 — Cost observations lack a shared scope and interval interpretation

**Priority:** high for causal explanation; its contract is a prerequisite for useful cumulative/window views. **Principles/gates/scenarios:** AP-02/AP-04/AP-05, DP-05/DP-21, G2/G9; S01–S03, S07–S12.

**Cause and evidence — Implemented, source-inspected:** `CallbackState` owns per-demand counts and inclusive completed callback seconds, exported by `finish`; native Ipopt CPU/system/wall observations explicitly overlap. `Phases` aggregates creation-to-close lifetimes by static span name without parent/exclusive accounting. `SharedRuntime::report` separates pool reservation and shared peak since last reset from process VmHWM; neither is per-operation allocation attribution. Cache lookup miss, shared-flight production, construction, reuse and waiter delay are distinct existing mechanisms, not interchangeable counts. The benchmark metadata's blanket “absent phases performed no work” claim is stronger than selective span filtering, thread propagation and close-only collection can establish.

**Existing strength:** `native_process::observations::Count` emits a total only when observations exist and none is unknown, and the aggregator explicitly says inclusive owners must not be added together. F03 is the missing joined live/time/window contract, not a claim that this numerical work aggregator already double-counts or zero-fills unknown work. Preserve these controls.

**Consequence:** summing parent and child times without those scope controls double-counts nested work; concurrent work does not sum to critical-path latency; global-counter subtraction contaminates concurrent operation attribution. A missing phase can be mistaken for no work, and a lifetime peak for memory caused by a recent case.

**Corrective contract — Proposed:** every displayed observation retains producing owner, unit/clock, operation/attempt/segment scope, accumulation/reset semantics, availability and overlap. Window deltas require compatible snapshots and an actual interval. Publish actual producer work once; retain each waiter's latency separately. Distinguish inclusive time, proven exclusive categories, process CPU samples and wall latency. Exclusive time, when useful, accounts for the union of child intervals; do not infer it by blindly subtracting parallel totals. Keep resource observations at their actual owner/process/cgroup/shared scope and leave unsupported attribution unknown.

**Preservation and revealing countercase:** one callback can legitimately include an inner solve while two callers await one construction. A universal additive “cost” total erases those relationships. Retain native units and current unknown-counter handling; do not invent factor counts from iteration/Jacobian counts or dynamic work from static expression size. No new resource caps or accounting framework follow from this finding.

**Verification — Proposed:** construct nested and shared timed/counted observations with known overlap, a reset/retry and concurrent operations. Check interval arithmetic and non-additive presentation locally. Inspect actual owner boundaries for one real operation only if an ambiguity remains; no statistical performance campaign is required.

### <a id="f04"></a>F04 — Native progress facts are not yet a live explanatory contract across numerical contexts

**Priority:** high. **Principles/gates/scenarios:** AP-02/AP-04, DP-15/DP-21, PS-07/PS-08/PS-10/PS-12, G2/G7/G9; S02–S10.

**Cause and evidence — Implemented, source-inspected:** the shared Ipopt callback publishes native objective, primal/dual errors, restoration, steps and trials; `NativeSnapshot` retains partial submitted-coordinate detail and is explicitly not resumable state. KINSOL fixed-point iterations count attempted maps, and its typed current snapshot can be absent. IDAS and Diffsol observations distinguish returned/internal time and current/proposed versus last accepted steps. Fitting emits complete experiment evaluation after it finishes. Many richer native counters/timers are completion-owned or not projected into live inspection. Presence of a callback or terminal getter does not establish a user-visible live stream for that context.

**Consequence:** the new target cannot reliably explain whether the last minute brought accepted scientific progress, rejected trials, restoration, repeated inner work, event settlement or recomputation. Reusing one generic iteration/objective chart would flatten meaningful differences and could imply convergence or physical validity that the observations do not establish.

**Corrective contract — Proposed:** context owners project the minimum facts that answer their causal questions, preserving native phase/coordinate/normalization, attempted versus accepted work, original versus scaled criteria, reset/segment scope and availability. Provide latest safe observation/checkpoint and recent change without reading mutable foreign state from another thread. Distinguish observed stagnation/churn/repetition from a solver's typed stop and independent original qualification. The current bridge may leave the inside of a factor/subproblem opaque even when a native library offers candidate progress facilities; investigate exact adapter access and synchronization before promising or denying such facilities. Useful native-coordinate facts need not all be converted to original coordinates, provided their authority and limits are explicit.

**Preservation and revealing countercase:** objective may fall while original feasibility worsens; an event return may precede the internal mesh; a failed map may increment iterations. Preserve method-specific payloads and original assessment rather than a lowest-common-denominator solver API. Do not add residual/property/derivative evaluations silently for display, parse textual statuses, or copy solver iteration controllers to expose observations.

**Verification — Proposed:** select small existing fixtures spanning genuinely different interpretation contracts: transformed NLP/restoration or failed trial; fixed-point attempted map; dynamic event/reset; one nested experiment/analysis. Demonstrate projected meanings and unknowns, plus absence of observer-requested extra scientific evaluations and preservation of the declared scientific contracts. Collection overhead can affect wall-clock-limit exits or permitted parallel scheduling; do not require identical trajectories or termination across those cases. Broader backend coverage is an integration obligation to scope honestly, not a mandate for repeated comparative benchmarks.

### <a id="f05"></a>F05 — Collection and analysis stop short of a usable live-to-terminal explanation

**Priority:** high for the operator's outcome; profile-tool selection is secondary to F01–F04. **Principles/gates/scenarios:** AP-03/AP-06, DP-21/DP-22, G7/G9; all scenarios, especially S01/S08/S11/S12.

**Cause and evidence — Implemented / Interface-checked:** the production spans, terminal typed relations, local progress, activity/resource observer and benchmark aggregates answer separate slices. No complete joined read operation for current work, cumulative cost, last-minute changes and completed explanation was established in the examined public consumers. The benchmark installs its in-memory layer without a formatting layer, so `RUST_LOG` alone does not make phase output appear. A profile can collect and decode timestamps without useful frames, as the bounded late-attach control demonstrates.

**Consequence:** even when data exist, an operator must manually infer scope, navigate opaque owners and decide which unavailable observation could distinguish hypotheses. “Use a profiler” is not a working causal answer. An exported final trace or flamegraph need not support an unfinished run or identify a scientific cause.

**Corrective contract — Proposed:** provide one compact inspect/explain operation over F01–F04, usable during and after execution, with optional time window/detail/profile request. It should identify what is established, the observations supporting it, and the smallest missing observation when causal alternatives remain. Context recipes in the supporting document guide this analysis: locate current owner, compare recent with cumulative work, follow actual nested producer, relate examined structure to requested demand, and preserve scientific qualification separately. A deterministic composition of facts with plain explanations is sufficient; no automated universal root-cause engine is required.

**Preservation and revealing countercase:** late sampling cannot recover earlier convergence history; a flamegraph can hide temporal order; task idle does not identify a wait resource. On-demand sampling/export must report capture interval, target/thread/symbol/frame coverage and loss, and remain optional. Sampling failure must yield partial/unavailable explanation, not an invented hotspot or scientific failure. Inspection must remain possible while a surrogate/native owner is busy.

**Verification — Proposed:** give the read operation a known slow preparation, an active nested child, a saturated recent history and completed partial operation. Verify useful answers and explicit competing hypotheses. Separately settle usable Rust/native sampling and live-readable export with one owned representative control, including an open interval and interruption. Do not rerun the cold statistical campaign to test the profiler.

### <a id="f06"></a>F06 — Affine-row preparation traverses unrelated global coordinates for locally scoped rows

**Priority:** medium for this review's scope; concrete execution-fit defect, not established dominant latency. **Principles/gates/scenarios:** AP-07, DP-10, H5/H12/H26/H28, G9; S01/S12.

**Cause and evidence — Implemented, independently source-inspected:** automatic presolve in `MathService::discover_class` can request missing affine-row facts even for explicit NLP selection. `PreparedCase::prepare_affine_rows` delegates to `CasePlan::affine_row_facts`. `class_evidence::aggregate_expressions` constructs formals for all `plan.columns`, aggregates selected original rows and performs sequential temporary-symbol replacement passes. `prove_affine` differentiates a row against the global formal vector, replacing each formal with zero until a nonconstant derivative rejects it. In repeated independent blocks, later rows therefore examine unrelated earlier coordinates; affine rows examine the whole vector. Relevant local incidence is smaller. The full-program class-routing path is a different demand and is not the same hypothesis.

**Consequence:** adding independent blocks amplifies proof traversal for unchanged local row expressions and can consume proof allowance on irrelevant coordinates. Existing body/artifact reuse does not eliminate this separate pass. This establishes a structural locality mismatch; it does not establish its fraction of the 622-second interval, total asymptotic library cost, or measured benefit of a replacement.

**Corrective direction — Proposed:** within the original affine-proof semantic owner, investigate proving selected row aggregates over their actual dependencies and using a fitting library bulk substitution facility where its exact contract preserves simultaneous binding. Diagnostics should expose selected policy/demand, rows and coordinate scope examined, actual proof/construction work and unknown/refused outcomes. Numerical optimization is follow-up work distinct from this diagnostic review.

**Preservation and revealing countercase:** nonlinear contributions can cancel only after aggregation; aliases, scales and permuted bindings must not change meaning. Restricting work to each contribution independently would be incorrect. Preserve original row aggregation, mathematical normalization, domain obligations, provenance and proof-allowance/unknown semantics. Do not recommend dropping required proofs to produce an attractive timing.

**Verification — Proposed:** source reasoning plus a small two-independent-block case can distinguish relevant incidence from global traversal, including cross-body cancellation and aliased bindings. Compare scientific proof outcomes and actual examined work, not a hard latency threshold. Exact symbolic support/substitution choice needs a bounded library inquiry before implementation. No numerical rewrite is authorized here.

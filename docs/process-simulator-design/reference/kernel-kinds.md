# Kernel Kinds

<a id="source-40a141b58369818a9c84de7d2f7a6f60"></a>

## Analysis kernel

Source: [Notion](https://app.notion.com/p/40a141b58369818a9c84de7d2f7a6f60).

**Examples:** Counts/matching/block structure on unsolved models; supported differential-structure/index analysis; local sensitivities, linearization and eigenanalysis; local identifiability/information rank. No generic promise of global identifiability or complete DAE-index proof.

**Takes:** A source model, selected form or task context; a qualified reference point only when the particular analysis requires one

**Produces:** Structural or local findings with method, assumptions, evidence strength and explicit unavailable results

**Kind:** Analysis kernel

<a id="source-40a141b58369818f8c63d838797032a1"></a>

## Evaluation kernel

Source: [Notion](https://app.notion.com/p/40a141b58369818f8c63d838797032a1).

**Examples:** A process property/reaction provider, compiled symbolic evaluator, admitted surrogate or nested problem. A quantum-chemistry provider remains a deferred specialized adapter, and derivatives are not assumed merely because values exist.

**Takes:** A selected implementation/realization, typed point or batch and explicit product/context demand

**Produces:** Supported values, derivative products or qualified nested-task outputs, with applicability/branch and failure evidence

**Kind:** Evaluation kernel

<a id="source-40a141b583698157a1a3c5c575de2332"></a>

## Lowering kernel

Source: [Notion](https://app.notion.com/p/40a141b583698157a1a3c5c575de2332).

**Examples:** Selected distributed-unit discretization; collocation or shooting; supported index reduction; qualified GDP reformulation; conditional KKT reformulation; Infer loss construction; scenario expansion; explicit tearing/partitioning; serialization to an external tool. General CFD coupling is a deferred adapter profile.

**Takes:** One or more versioned form artifacts plus explicit transformation policy and context

**Produces:** Derived forms/artifacts, source/derivation mappings and a qualified reconstruction contract; the transformation may be exact, conditional, approximate, a relaxation or information losing

**Kind:** Lowering kernel

<a id="source-40a141b58369818a9d89dc12d69c5fab"></a>

## Planner kernel

Source: [Notion](https://app.notion.com/p/40a141b58369818a9d89dc12d69c5fab).

**Examples:** Deterministic preparation rules, explicit user/agent-authored plans or optional cost-based planning. A universal autonomous planner is not a prerequisite for the flowsheet domain.

**Takes:** A selected task/profile, available implementation contracts, required products and numerical/resource policy

**Produces:** One or more explicit candidate plans with contextually checked conditions and unresolved assumptions identified

**Kind:** Planner kernel

<a id="source-40a141b5836981458a80f746cfe7b4e9"></a>

## Solver kernel

Source: [Notion](https://app.notion.com/p/40a141b5836981458a80f746cfe7b4e9).

**Examples:** Qualified root, NLP, LP/QP/conic, mixed-integer and dynamic-integrator routes. Sampling/eigen/specialized solvers require their own declared profile rather than inheriting support from this label.

**Takes:** A contextually admitted form, physical inputs, starts and numerical policy

**Produces:** Native termination evidence and zero or more raw candidate products with coverage; scientific acceptance and usability are separately assessed

**Kind:** Solver kernel

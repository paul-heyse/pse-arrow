Every generated Rust file carries `// @generated by pse-schema <fingerprint>`,
`#![rustfmt::skip]` and a blanket `#![allow(..., reason = "generated")]`. Generated docs
carry `<!-- @generated by pse-schema; do not edit -->`. If a file you are editing has one
of those markers, stop.

Retired query-output paths remain protected against accidental handwritten output.
The owning generator removes stale outputs; there is no SQL query-generation recipe.

`just codegen-check` regenerates schema targets in scratch space, compares the exact
file inventory and bytes in both directions, and rejects untracked output (ADR-0051).
The Rust target includes `crates/pse-authoring/src/generated/`. It is a required CI job.
Generated sources are committed deliberately
(ADR-0031) so that a checkout builds without a code generator run and so that a
regeneration shows up as a reviewable diff — that only works if the committed output is
exactly what the generator emits.

A `PreToolUse` hook blocks writes here. There is no environment escape for it: unlike the
blueprint, there is no legitimate reason to hand-edit output. The workspace-hack manifest
is the exception: its header outside the hakari section is authored, so the hook does not
guard it; change `.config/hakari.toml` and rerun `just codegen` for anything inside.

The Ipopt bindgen arm regenerates from `IPOPT_DIR/include/coin-or` when selected,
or extracts the C headers from the digest-pinned solver image. Both normal regeneration
and `just codegen-check` use the real generator; a placeholder or stale header receipt
cannot pass. The pinned bindgen/prettyplease formatter owns the output.

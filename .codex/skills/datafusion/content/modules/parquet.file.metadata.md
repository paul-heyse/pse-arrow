Parquet metadata API

Users should use these structures to interact with Parquet metadata.

* [`ParquetMetaData`](../operations/parquet.file.metadata.ParquetMetaData.md#op-02f1f382aa720b3a6b89476b): Top level metadata container, read from the Parquet
  file footer.

* [`FileMetaData`](../operations/parquet.file.metadata.FileMetaData.md#op-b5fcc860595f5c38cea8c79d): File level metadata such as schema, row counts and
  version.

* [`RowGroupMetaData`](../operations/parquet.file.metadata.RowGroupMetaData.md#op-f84a9d3c17c9ccf2d622296f): Metadata for each Row Group with a File, such as
  location and number of rows, and column chunks.

* [`ColumnChunkMetaData`](../operations/parquet.file.metadata.ColumnChunkMetaData.md#op-664b3834ca25da410177f90f): Metadata for each column chunk (primitive leaf)
  within a Row Group including encoding and compression information,
  number of values, statistics, etc.

# APIs for working with Parquet Metadata

The Parquet readers and writers in this crate handle reading and writing
metadata into parquet files. To work with metadata directly,
the following APIs are available:

* [`ParquetMetaDataReader`](../operations/parquet.file.metadata.reader.ParquetMetaDataReader.md#op-ecb8df4cd7e741eec25c5144) for reading metadata from an I/O source (sync and async)
* [`ParquetMetaDataPushDecoder`](../operations/parquet.file.metadata.push_decoder.ParquetMetaDataPushDecoder.md#op-e00d43ab5b4fd446b342b085) for decoding from bytes without I/O
* [`ParquetMetaDataWriter`](../operations/parquet.file.metadata.writer.ParquetMetaDataWriter.md#op-897397dc43ac19f9d052fbd0) for writing.

# Metadata Encodings and Structures

There are three different encodings of Parquet Metadata in this crate:

1. `bytes`:encoded with the Thrift `TCompactProtocol` as defined in
   [parquet.thrift]

2. [`format`]: Rust structures automatically generated by the thrift compiler
   from [parquet.thrift]. These structures are low level and mirror
   the thrift definitions.

3. [`file::metadata`] (this module): Easier to use Rust structures
   with a more idiomatic API. Note that, confusingly, some but not all
   of these structures have the same name as the [`format`] structures.

[`file::metadata`]: crate::file::metadata
[parquet.thrift]:  https://github.com/apache/parquet-format/blob/master/src/main/thrift/parquet.thrift

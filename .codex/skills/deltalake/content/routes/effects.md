# Effects and failure boundaries

| Decision | Effects | Error considerations |
|---|---|---|
| [Resolve table names separately from storage and provider freshness](../capabilities/delta.catalog.md) | catalog service lookup; produce table/provider handles | Name not found, auth/service failure and later table-load/protocol errors should remain distinguishable. |
| [Read change data with explicit bounds, images and residual filtering](../capabilities/delta.cdf.md) | read log interval and data/change files; produce insert/delete/preimage/postimage rows | Missing start, disabled/unrecorded CDF, invalid range, mapping restrictions, missing retained files and planning errors are distinct failure modes. |
| [Reason about optimistic commits and errors after publication](../capabilities/delta.commit.md) | write files; publish log version; post-commit checkpoint/cleanup/hooks | Precondition failure, optimistic conflict, publication failure and post-commit failure can imply different visible states. |
| [Update or delete through built-in Delta operations](../capabilities/delta.dml.md) | logical row update/delete; possible log commit | A stale update can conflict with an intervening rewrite even if append retries are allowed. |
| [Separate feature vocabulary, protocol admission and operation support](../capabilities/delta.features.md) | admit/reject access; possible protocol upgrade via mutation | Recognized-but-unsupported, excluded Cargo feature, unsupported table protocol and operation restriction must not collapse into one boolean. |
| [Choose time travel, restore, checkpoints or log maintenance](../capabilities/delta.history.md) | select state; publish restore version; write checkpoint metadata | An old version may have loadable metadata but unavailable files; restoration has its own missing-file policy. |
| [Use kernel snapshots, scans and engine interfaces at the correct layer](../capabilities/delta.kernel.md) | engine evaluation and I/O; selection/filter application | Kernel error and engine adapter error paths do not imply an already completed high-level table transaction. |
| [Merge with explicit key, null, clause and duplicate semantics](../capabilities/delta.merge.md) | rewrite or add/remove data; publish transaction; return metrics | Invalid expressions, ambiguous/multiple matches, protocol/schema restrictions and optimistic conflicts require distinct recovery. |
| [Open, load and select a table version](../capabilities/delta.open.md) | read log and metadata; select snapshot; no table commit | Load errors concern URL, log, protocol or snapshot selection. Missing data can surface later while consuming a scan. |
| [Compact or Z-order while preserving logical data](../capabilities/delta.optimize.md) | rewrite data files; publish layout changes or no-op | Feature/protocol, data read, expression, resource and commit failures remain possible. |
| [Choose a Delta-aware scan or table provider](../capabilities/delta.read.md) | read snapshot files; stream batches | A constructed stream can fail during consumption, including after vacuum removed historical files. |
| [Choose full overwrite, predicate replacement or merge](../capabilities/delta.replace.md) | remove existing logical data; add replacement files; publish log version | Predicate, append-only/protocol, partition or schema validation can reject an operation before publication. |
| [Use transaction markers without assuming replay suppression](../capabilities/delta.replay.md) | persist coordination metadata; may append duplicate rows if retried | A repeated marker and a retryable storage/transaction failure are different conditions. |
| [Preview and execute vacuum with explicit historical-read consequences](../capabilities/delta.retention.md) | delete physical objects; reduce historical/CDF recoverability | Retention guard and missing history/files are material conditions, not proof the current logical table is corrupt. |
| [Preserve schema meaning across Arrow, Delta and schema evolution](../capabilities/delta.schema.md) | cast values; possibly update table schema/protocol | Unsupported Arrow types, incompatible field changes, invalid values and missing protocol features fail at different boundaries. |
| [Preserve session capabilities and configure Delta planning](../capabilities/delta.session.md) | configure planner and runtime; share or derive session state | Resolution rejection and missing functions/planner failures occur before a successful commit; verify table state when diagnosing a failed operation. |
| [Choose object storage and log publication adapters](../capabilities/delta.storage.md) | remote or local object I/O; configure backend factories; publish log through selected backend | Unsupported scheme, absent feature/handler, credentials, network/native dependency and conflict errors are separate prerequisites. |
| [Write batches or a logical plan; distinguish staging from publication](../capabilities/delta.write.md) | write data files; publish log version; may leave unreferenced files after failure | Validation or planning can fail before log publication. A later hook failure can occur after a visible commit; see delta.commit. |
